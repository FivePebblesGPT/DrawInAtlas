# Physically independent Drawing application and Atlas integration

## Owner direction (2026-11-01)
See [[DECISIONS_DRAWING_ATLAS_2026-11-01]]. Drawing is an independently usable Paint.NET/PhotoCraft-like editor; Atlas consumes its package and manages world surfaces, logical floors (ordinary Drawing layer organization), LOD, map entrance interactions and campaign-wide history. Drawing owns snapping and editable text-layer lifecycle. **No historical user-save migration.**

**Status:** plan only, not implemented. T-051 remains open for precise contracts and package topology. Owner Drawing feature inventory is still pending.

## Architecture rule
```text
Standalone Drawing app -> versioned Drawing package
                                    ^
                                    |
                          Atlas consumer app
```
Drawing builds and tests without Atlas code, scenes, autoloads or assets. One codebase implements painting for standalone and embedded use. Atlas may supply a drawing document, layer selection, transforms, optional snap/mask candidates and viewport requests. Drawing must not import Atlas campaign, map, grid or link classes.

## Explicit constraints
- Floors are managed by Atlas as Drawing-layer organization, not as required Drawing domain types.
- Atlas selects authored detail surfaces/levels; Drawing edits requested content without knowing world geography. Mipmaps/pyramids are distinct from separately authored detail.
- Painting takes precedence over link hit testing; double-click with Selection/ObjectSelection or Pan navigates.
- Text only creates a layer upon successful content creation and can be rasterized through an undoable command.
- Maintain one Atlas global history, plus independent standalone Drawing history.
- Do not implement legacy save conversion. New Drawing and Atlas formats must be robust and tested.
- Retire old battlemap/placement paths after safe code cleanup; no migration of nonexistent saves.
- Do not implement projector/collaboration or adopt mandatory native dependencies during core extraction.

## Acceptance
Physically independent Drawing runs, saves/loads, and supports essential paint/edit UX; Atlas consumes a pinned package, organizes maps/floors/LOD and uses the same Drawing editor; global undo and entrance input precedence work; fresh files roundtrip and browser policy are validated; owner accepts usability.
