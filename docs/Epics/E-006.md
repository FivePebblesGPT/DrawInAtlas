# Milestone 6 — Separately authored artwork LOD and detail editing

## Confirmed direction — 2026-10-30
- Automatic “layer zoom” means **artwork-layer LOD**, not automatically switching independent map documents. Enable it by default, with an optional disable control.
- World hexes share the continuous chunked board in [[E-002]]. Empty hexes are not blocked by missing document assignments.
- Detail levels are **separately authored**. Their coordinate relationships and presentation must remain coherent.
- Keep an explicit editing target; automatic presentation changes must not retarget an in-progress gesture.
- **Retire the battlemat/battlemap concept.** Its useful content is another authored detail view of the local map, not a separate document or movable canvas container.
- The previously proposed battlemat bounds/content-following resize policy is superseded. Projection framing is a separate presentation concern in [[E-007]] and [[T-013]].

These are confirmed requirements, including the user's later revision that replaces the earlier local-battlemat-object proposal. Exact LOD thresholds, editing-target presentation and detail data structures remain design work.

## Later architecture direction — 2026-11-01
The accepted target is [[E-009]] / [[DECISIONS_DRAWING_ATLAS_2026-11-01]]: Atlas floors are **Drawing layer groups**, and all authored detail levels share a **continuous map-world coordinate reference**. Missing higher-detail artwork is **blank**, not composited with lower-detail artwork. This supersedes contrary previous fallback/UI assumptions; see [[T-061]]. The implementation and owner acceptance described historically above have not been retroactively completed for this target.

## Later owner contract — 2026-11-02
The owner approved **independent explicit pixel densities per authored detail level** (sensible default progression) within one continuous world-coordinate reference. At an empty high-detail level **artwork is blank**, while **grid and entrance/navigation overlays remain visible**. Zoom-based D-level selection does not hijack the active edit gesture. See [[T-061]] and [[E-009]].

## Round 8 — independently stored per-detail DrawingDocuments
The owner chose **Option B**: one internal DrawingDocument for each map/floor/detail, all aligned to common world coordinates but separately authored at explicit pixel density. Atlas still presents a continuous layer/detail hierarchy, not an “Open D1 file” workflow. Sparse multi-file payloads are planned in [[T-066]]; no per-hex canvases. Blank detail remains blank artwork with navigation overlays.
