# T-190 — Exact sRGB8 quantization and 96px gesture evidence (2026-11-17)

## Scope, cause and rejected experiments

T-189's native sample-delta scan still spent around 20ms per rapid gesture quantizing Hokusai's premultiplied fixed-point channels into straight-alpha sRGB8, partly because `linear_to_srgb` calls `powf`. Hokusai remains the sole native Brush/Eraser engine; the unchanged 512×512, 96px, 100-event fixture retains every interpolated sample, the original 6ms soft input-drain deadline, native history, and the entire time from pointer input to postdraw.

Two earlier same-native-binary candidates were **rejected**. A coarse threshold-search quantizer retained exact pixels but made the initial A/B worse. Preview-vector capacity reuse reduced real allocations (graphical Brush/Eraser: one growth vs six reference) but three matched full-gesture rounds did **not** give reliable latency improvement: pooled optimized cold median became *worse*. Their fail-first, parity, process timing, memory and source records remain in [`raw/`](T-190-2026-11-17-raw/) under `lut/`, `buffer/`, `matched/` and `checks/`; they are **not** included in production.

The retained bounded change constructs a **65,537-byte** monotone sRGB8 byte-boundary table once per process. For any linear channel value in [0,1], if both boundaries of its 1/65536 interval quantize to the same byte, the value is guaranteed to have that byte under monotonic Hokusai sRGB transfer. If they differ, the existing Hokusai `powf` is called, preserving its exact rounding at boundaries. Nonpositive/≥1 values are clamped as before. The original converter remains opt-in only via `DRAWING_T190_POWF_COUNTERFACTUAL=1`, read per dirty-tile scan (not per pixel). No history/selection/source/ABI or input pipeline changes are made. Peak table size is bounded at 65,537 bytes.

## Exactness and native regression

A Rust property test checks **all 65,536 fixed-point channel values** for fifteen representative alpha values including 0, 1, 255, 32768 and 65535, and five positions in **all 65,536 LUT bins** against the original Hokusai `powf`, including hidden RGB at alpha zero. **30/30** Rust tests pass. Real X11 T-190 **77/77** compares the two quantizers in the **same final native binary** for signed raster, partial alpha, hidden RGB, subtracted selection hole, queued/interpolated Brush/Eraser, complete source payloads, native history, Undo/Redo, cancellation and actual .drawing Save/Open. Previous graphical regressions T-181 **19/19**, T-186 **14/14**, T-187 **99/99**, T-188 **63/63** and T-189 **77/77** independently exited 0 on final code. Direct native Brush, native tiles (312 checks), standalone, presets (16) and Atlas native history tests exited 0; Python packaging **18**, profile parser **5** and Ruff/ty passed. The broad `make check` command was interrupted and a `make test-graphical` wrapper returned nonzero despite all pass markers; those outputs are preserved and neither wrapper is declared successful. All six graphical scripts were then rerun separately with confirmed zero exits.

## Complete 100-event rapid benchmark, final released binary

All final runs use exactly the same `libdrawing_brush.so` SHA-256 **`17c4b045c8862fec0e7dfdc6446b53ea28c66ae7b4c5d4356aac093fa1bce582`**, same repo source and Godot 4.8 beta3 llvmpipe/X11. Two reversed-order pairs contain 2 fresh cold processes and one 2-gesture warm process per mode/pair. Each process exits 0 and passes the strict T-146 native Hokusai source, pixel fill, framebuffer, preview and history log validator. Every stroke's source SHA-256 is **`6df89cc963368830befd8dbf061db9bb0f40060556a8dfb127cf5e9681f68ec4`**, all **262,144** source pixels covered, and all retain 100 input events. p95 with n=2 is the maximum, not a population-tail estimate.

This **does not prove** a universal latency, FPS or frame-time improvement. Final first-preview postdraw ranges from **20.3–86.2ms optimized** and **25.6–36.0ms reference**; reference and optimized release→commit times and stage phases are in strict raw trace logs. Native tile bytes exported and texture/preview counts are tracked per run in the summaries, not silently excluded.

## Full workspace / frame and release validation

Two reversed-order mode pairs each exited 0 and passed the T-185 eight-scenario native-workspace validator at 54% and 100% zoom, including held input and Eraser; **all 16 paired source SHA-256 values match**. Each scenario receives 14 real engine inputs and retains valid source/history/preview assertions. At **54% cold Brush**, reference vs optimized postdraw callback interval p95 was **16.2→18.3ms** (pair 1, worse) and **21.5→18.7ms** (pair 2, better); each process still had at least one ≥83.33ms frame (1/41→1/38 and 1/29→1/40). Release→settled was **107.7→157.2ms** (worse) and **110.3→120.3ms** (worse). Native stage CPU was **53.4→54.1ms** and **54.4→53.5ms**. At 54% Eraser, p95 was **40.7→107.1ms** (worse) then **197.6→39.3ms** (better). At 100% cold Brush, p95 was **55.1→18.2ms** then **26.6→31.1ms** (mixed). Requested upload volume is **3,473,408 bytes** for all 54% cold comparisons; native exported bytes **4,521,984** for the same scenario. Max pending real workspace input depth stays 1, and first-preview timings, release→commit/settled, long-frame fractions, FPS estimates, per-phase CPU and peak RSS are preserved per scenario in raw `summary.json`. Full workspace RSS **326,080–326,952 KiB reference**, **328,792–329,312 KiB optimized**, so there is no demonstrated memory improvement.
