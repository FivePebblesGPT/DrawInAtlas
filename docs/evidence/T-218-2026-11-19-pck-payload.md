# T-218 — Complete exported Godot PCK payload verification (2026-11-19)

## Fail-first witness

Before the code change, five new regression cases produced **3 failures and
2 errors** (`T-218-2026-11-19-pck-payload-raw/fail-first.log`): the previous inspector accepted a changed
noncritical payload, accepted a forged optional-resource MD5, and accepted
two overlapping data extents with identical content/MD5. The two positive
cases lacked the new `resources_verified` report field. The original T-217
startup/manifest checks were insufficient to catch these cases.

## Implementation and scope

The Godot v4 PCK inspector now checks **all indexed resource MD5 fields** in
bounded 1 MiB streamed reads. Nonempty file ranges must be disjoint; zero-byte
optional resources are valid but missing/empty required startup and ABI
resources still fail. The inspector reports `resources_verified` alongside its
prior count. Synthetic tests verify optional payload tampering, tampered index
checksums, equal-content overlapping ranges, and valid empty resources. The
real Linux packager test also checks that a corrupted *noncritical* packed
resource is rejected without installing the native `.so`, creating preflight
artifacts, or modifying the ELF/PCK directory.

MD5 is the checksum format stored by Godot; this is **integrity comparison,
not source authentication or code signing**. The parser does not execute packed
resources or prove runtime correctness. The older T-217 witness and Windows
structural-only scope remain unchanged.
