# T-096 — large selection contours and floating Move, 2026-11-07

**Environment:** Linux, pinned Godot `4.8.beta2.official.cafc17a19`, Xvfb
1280×900×24, Mesa 25.0.7 llvmpipe, OpenGL compatibility renderer. Rebuilt
standalone Drawing from canonical `addons/drawing/`, then re-imported resources.
These are repeatable **synthetic pointer/software framebuffer and CPU** witnesses;
physical GPU latency, input-to-photon and owner UX acceptance are **NOT RUN**.

## Root cause and implementation

- The old `canvas.gd::_draw_selection_outline()` draws only the conservative
  enclosing bounds for selections over **4096** source cells. The actual
  `DrawingSelection.allows()` mask was never lost; this was a visualization
  regression. The persistent outline now evaluates actual boolean mask
  scanlines, emitting only viewport-clipped source-pixel boundary segments.
  Replace/Add/Subtract/Intersect operations, holes, disconnected islands and
  signed coordinates preserve exact membership. No enclosing box masquerades
  as a mask. The transient marquee remains a distinct yellow drag guide.
- Rectangle-expression masks take work proportional to **visible rows and
  operation count**, not selected-pixel area; even a 200k×200k selection is
  only traced where the viewport intersects it. Irregular explicit per-pixel
  masks use a 64×64 source-cell cache, with **four new tiles per redraw** and
  an upper cache limit of 4096 tiles. Cached contours retain exact tile-edge
  continuity when zooming or panning. The progressive path is not a claim of
  a fixed full-outline completion deadline for arbitrary enormous pixel masks;
  when more than 4096 tiles are on screen at once, cache saturation stops
  repeated redraw rather than looping forever until the view changes.
- Previously, every Move offset rebuilt a source capture, cleared the full
  selection rectangle and pasted using another full-area scan; this was
  repeated even though the source revision was frozen. The floating gesture
  now retains exactly one immutable `DrawingClipboard` captured on first
  mouse-down, and stages only nonzero selected source pixels (including
  alpha-zero/nonzero RGB) on each new offset. Clearing and pasting remain
  detached and depth-correct. The existing public clipboard API retains its
  semantics for pre-populated edit sessions; failures roll back atomically.
  Escape, no-motion click, stale revision, and drop release the cached source.

## Controlled before/after hot-path witness

`drawing/tests/selection_large_smoke.gd` performed **eight same-document,
same-offset comparisons** on a signed 102×83 selection with a subtract hole,
patterned nonzero RGBA and hidden-RGB cells. The legacy reference path was
executed explicitly as `capture → clear_rect → clipboard.paste`, with a new
edit session on each offset; the replacement used one retained capture and
`move_captured`. Every `_before` and `_after` dictionary compared exactly,
not just visual center pixels. Times below are **CPU milliseconds**, nearest-
rank p50/p95, not GPU-frame or physical-input timings.

| Phase | p50 | p95 |
| --- | ---: | ---: |
| Legacy repeated source capture | 15.046 | 15.334 |
| Legacy full-rectangle source clear | 41.896 | 43.166 |
| Legacy full-rectangle paste | 13.530 | 14.196 |
| New stage against retained capture | **15.388** | **16.277** |

At these offsets, the old path's median cumulative per-update capture/clear/
paste cost was ~70.5ms versus the optimized ~15.4ms staging cost; these
phase medians are not an end-to-end p50 comparison. This exact-byte witness
also checks invalid target rollback and unchanged document history while
previewing.

## Native pointer and framebuffer witness

`drawing/tests/selection_large_native.gd`: **34/34 checks**, root-delivered
mouse down/motion/up plus Escape/Enter under the software display, with source
RGBA and framebuffer readback. Creates a >4096-cell persistent marquee and
subtract-hole/add-island through pointer gestures, then independently samples
visible hole, island and main contours and verifies **no** spurious bounding
edge in the intervening gap. A large floating Move stages eight 4× software
pointer samples, confirms the **same clipboard instance** across a second
cumulative drag, preview before release, one outside-click history commit,
Escape rollback, no-motion payload release, preserved lower layer, and one
Undo/Redo. Additional Move runs at 25% and 786% with Escape and Enter passed.
