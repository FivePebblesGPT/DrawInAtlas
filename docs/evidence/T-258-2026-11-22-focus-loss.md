# T-258 — floating focus-loss transaction cancellation, 2026-11-22

## Reproduction and change

Native Godot 4.8 beta3, Linux X11/Xvfb/Mesa llvmpipe. Start standalone Drawing; float the Colors group. Press the MoveHandle, move the pointer, then deliver Godot `NOTIFICATION_WM_WINDOW_FOCUS_OUT` without releasing the mouse. Repeat at two resize corners/application focus loss; exercise a pending tab cross-drag and a fresh move after a missed release. The same `DrawingFloatingHost` is tested in Atlas embedding.

**Before:** The original `floating_host.gd` lacked a focus-out handler. The new standalone native test reported **13 failures / 25 checks**, including all move/resize restoration/release guards and the pending tab drag. The Atlas test reported **4 failures / 9 checks** for move/resize rollback and stale releases. Missing imported SVGs in the first staged Drawing run were an unrelated test-environment import problem; the exact tests were repeated after `godot --headless --editor --path drawing --import --quit`.

**After:** Restore the pre-gesture rectangle on focus loss, cancel owned tab/cross previews and suppress the stale release. A fresh host/tab press clears that suppression. Re-stage the canonical Drawing package and import its SVG assets before running graphical tests. **30/30 standalone, 9/9 Atlas pass**, both exit 0 with exact pass markers and no script errors. An additional two-floating-host test verifies that focus loss in an idle sibling cannot cancel another host's active move. Exact source revision/dirty flag and dock-owner model remain unchanged.

### Neighbor suites (same staged sources)

The following native regressions passed after the fix:

- Standalone: T-257 canceled move/resize, T-256 context menu, T-255 clipped tab hit-testing, T-091 grip redock, T-091 one-group floating host, T-081 floating panels, T-083 dock persistence.
- Atlas: T-257 floating cancel, T-256 floating context, T-255 floating hit-testing.

The multi-suite command was interrupted by its overall execution timeout after nine successes, so T-255 Atlas was rerun **independently** and passed (14/14). Individual tests' own exit codes were checked; an interrupted aggregate is not counted as a pass.

## Limitations

The runs use real X11 GUI pointer dispatch but **injected** OS-style focus-loss notification. Physical Alt+Tab interactions with an actual window manager, especially on Windows/HiDPI, have not been certified. This neither resolves T-091 hardware acceptance nor grants T-083/T-250 owner approval. No raster/Brush pipeline, release export or hosted CI result is claimed.
