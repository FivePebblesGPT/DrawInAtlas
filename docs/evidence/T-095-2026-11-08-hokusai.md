## Implementation

- Explicit gesture `CAPTURING → DRAINING → COMMITTING` lifecycle, retaining
  frozen source-space samples and paint settings after release; viewport-only
  wheel zoom, middle pan, Pan toolbar and camera setter no longer cancel
  an already released valid stroke.
- A second stroke while draining is blocked with `canvas_error` rather than
  destroying the first stroke. Navigation with the paint button still held
  explicitly cancels for transform correctness. Escape/document/layer/mask
  changes remain deliberate cancellations.
- Optional `NativeHard` class computes swept hard-circle coverage in Rust and
  lets `DrawingEditSession` own selection, clipping, source RGBA8, detached
  preview, atomic history and Undo/Redo.
- Optional `Hokusai` uses four bundled upstream `.myb` presets (hard, soft,
  ink and airbrush) with pin-sized/color controls and fixed pointer pressure.
  Native 64px tiles retain paint across batches; only quantized straight RGBA8
  changed-pixel triples cross the GDExtension boundary. Canonical canvas
  still stages against the original immutable layer pixels; no sparse
  document storage migration.
- Legacy default remains unchanged, Hokusai eraser uses NativeHard, and a
  missing/invalid native extension or preset triggers visible legacy fallback.

### Paired actual-Brush software-rendered workload

Five runs per backend, 120 mouse motion samples each, 60px Brush at 786%
zoom, using existing `drawing/tests/brush_latency_native.gd`.
Times are **milliseconds**, CPU stage totals per stroke and frame stages as
logged by Godot, **not** input-to-photon. These are distinct brush algorithms
and Hokusai is not pixel-identical to the existing hard brush.

| Backend | Stage total p50/p95 | Release→commit p50/p95 | Input→stage p95 | Compose p95 | Max queue |
| --- | ---: | ---: | ---: | ---: | ---: |
| Legacy | 155.493 / 159.339 | 54.068 / 54.101 | 92.055 | 22.301 | 20 |
| NativeHard | 133.385 / 139.976 | 57.276 / 61.651 | 85.897 | 23.122 | 16 |
| Hokusai `.myb` hard | 918.589 / 934.532 | 55.721 / 63.062 | 39.028 | 30.980 | 4 |

All three native Xvfb runs printed `T095_NATIVE_PASSED` (functional witness).
However, **Hokusai staging is about 6× slower than Legacy** on this synthetic
case and its longer main-thread batches can block frames. The better
release-to-commit result in these runs is **not** evidence of acceptable
paint-button-held latency: large strokes continue staging as input arrives.
An earlier naïve full-tile transfer version took roughly seven seconds per
stroke, so changed-pixel delta transfers are a material prototype improvement
but not a complete performance solution.
