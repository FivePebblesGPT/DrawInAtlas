# T-184 — Separate native-backed Brushes panel (2026-11-17)

## Scope and authority

The owner asked for a separate *visual* selector plus actual brush parameters,
not a renamed dropdown. T-182 is Done and T-183's corrected four Hokusai
presets are the native reference. T-184 has no manual-review gate; T-056,
T-059, T-095, Windows/export gates and current-app profiling remain separate.
This evidence covers engineering behavior under software-rendered X11/Xvfb,
**not** physical owner acceptance or the reported 12 FPS.

## Implementation

- The canonical `addons/drawing/workspace.gd` registers one stable `brushes`
  group and one `DrawingBrushPanel` Control in its existing dock/floating model.
  The compact top-bar picker and width field remain accessible, but are mirrors
  of the same workspace settings as the panel. Brush and Eraser both use them.
- Four named, keyboard-focusable preview buttons display transparent 92×32 PNGs
  rendered with the **actual Rust/Hokusai gesture+commit path** in
  `drawing/tests/t184_generate_brush_previews.gd`. They have tooltips describing
  native behavior. The staged Drawing app copies these canonical images, the
  panel scripts and new dock icon; a Python regression prevents dropping them.
- Native width is 1–96 Drawing px (nominal diameter). Opacity is 0–100% of the
  preset's *base* MyPaint `opaque` value; native pressure/velocity maps remain.
  Hardness is 0–100% MyPaint `hardness.base_value`, with each preset's default
  and override kept separately. Width/opacity are global across presets and
  both painting tools. Reset clears only the selected preset's hardness
  override and restores shared 3 px / 100% defaults.
- Scalar brush settings are captured at native pointer-down, and the queued
  deferred stroke dictionary copies preset, width, opacity, hardness and
  selection. Parameter edits cause no document revision, history or dirty
  state until a gesture commits. MyPaint JSON's `version` stays an integer;
  the unmodified native preset bytes are reused for 100%-opacity/default-
  hardness strokes. No Rust ABI or document-save schema was changed.
- Workspace preferences use validated schema v2 (including preset, width,
  opacity, per-preset hardness), with v1 selection-history-only migration.
  Floating/docked layout continues in the independent versioned layout file.

## Parameter-effect and history results

`drawing/tests/t184_brush_panel_native.gd`, native X11: **77/77 checks**.
At nominal 24 px, matched Hard Round gestures produced these committed alpha
sums over the same 160×80 ROI:

| Configuration | Alpha sum | Radial alpha at (0, 11) |
| --- | ---: | ---: |
| 100% opacity, 100% hardness | 400,373 | 226 |
| 15% opacity, 100% hardness | 62,160 | — |
| 100% opacity, 25% hardness | 185,259 | 13 |
| 100%/100%, changed to 10%/25%/Soft/96 px **after pointer-down** | 400,373 | — |

The unchanged in-flight result matches the untouched full-strength result;
low opacity lowers deposited pigment, and low hardness feathers the actual
native edge. With the same live settings, native Eraser decreased alpha
400,373 → 229,967; Undo restored the original exact RGBA8 and Redo restored
that erased RGBA8. The test also verifies panel/toolbar alignment, 96 px,
per-preset defaults, preference migration/invalid-input rejection, queued
configuration snapshots, zero history from settings, keyboard focus, actual
wheel scroll and floating ownership/recovery.

`drawing/tests/t184_native_brush_panel.gd`, native X11: **55/55 checks**
(with two screenshot assertions). An independent path covers visual image
presence, native opacity/hardness changes, focus, hidden floating hosts,
teardown, per-preset reset, versioned preferences and layout round-trip.
Its 60 px comparison yielded Hard Round center/edge alpha 255/254 versus
hardness-reduced 217/43; full-opacity source alpha sum 1,361,713 versus
20%-opacity 156,642. These are **semantic effect tests**, not performance
benchmarks or identical visual paths to T-183.

The legacy dock pointer regressions intentionally hide the new Brushes panel
*within their historical three-panel fixtures*, while the two new T-184
regressions exercise it directly (including floating and restore). This avoids
silently redefining old pointer coordinates; it does not remove Brushes from
production. `color_history_native` explicitly reorders its Colors target into
view because Brushes is the new top group. Temporary Godot import caches,
Rust build outputs, and packaging logs are not part of source control.

### Boundaries not closed here

T-184 does **not** establish physical UX approval, Windows/export behavior,
full native-transition acceptance or any 250/200 ms gesture milestone. T-185
must profile the current full app's reported apparent frame stalls before
T-186 makes a measured optimization. No image or software-renderer test is
presented as an instrumented reference-device FPS measurement.
