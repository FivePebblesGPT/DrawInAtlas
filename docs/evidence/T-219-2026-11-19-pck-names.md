# T-219 — Canonical exported PCK resource names (2026-11-19)

## Fail-first and change

Before the fix, the Godot 4.8 PCK directory inspector returned success for
all **six** negative assertions in the new five-test suite:

- One embedded NUL in a resource name;
- Four surplus zero padding bytes after a resource name;
- Embedded newline and carriage return;
- Embedded ASCII Unit Separator and DEL characters.

All six were present in structurally valid, checksum-consistent synthetic PCKs
that also contained the required native manifest, project configuration and
startup resources. The separate UTF-8 `équipe overview.png` positive resource
passed the original and revised inspector. See `fail-first.log` (exit **1**, six
assertion failures) and `name-regression.log` (exit **0**, five tests passed).

The verifier now requires that the raw index-name bytes equal the decoded UTF-8
name plus **exactly** the zero padding required to reach a four-byte boundary.
It also rejects ASCII control and DEL characters. Existing path traversal,
duplicate-file, resource flags, bounds, full-payload checksum and overlap
checks remain in force. This is a directory-name representation check, not a
signature or content-authenticity test.

A separate native-packager test feeds a PCK with an optional `assets/brush\0alias.png`
entry to actual export preflight. Rejection occurs **before** installing the
Rust `.so`, with an identical before/after exported file inventory and no
leaked `.native-preflight-*` directory. See `native-packaging.log`.
