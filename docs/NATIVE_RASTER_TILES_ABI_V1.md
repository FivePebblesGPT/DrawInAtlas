# Native canonical tile store — ABI v1 (T-148, incremental)

**Scope and status (2026-11-15):** The existing `drawing-brush` GDExtension exposes the real `DrawingNativeTiles` store and the `DrawingNativeBrush.apply_tile_batch` → `commit_tiles` paired transaction. The production `DrawingCanvas` now opts into it for NativeHard, Hokusai and Eraser: `DrawingEditSession.paint_path_native()` calls Rust tile staging without `preview_changes()` or GDScript per-pixel edits; Canvas preview and document publication consume copied native RGBA8 tiles. **This is a per-gesture bridge, not the final permanent native raster-document owner.** Each new gesture creates a store at `DrawingDocument.revision`, imports authorized canonical source/masks on demand, and publishes into `DrawingDocument` packed tile bytes and history, then disposes of its native store. Thus initial/native/published revision numbers match for one transaction, but native history does not persist across strokes. T-148 remains In Progress until durable native raster/history ownership and single revision authority are reconciled; T-149 owns full display/Atlas/persistence integration. Legacy and transitional direct-session compatibility still exist until the scheduled retirement.

## Ownership, byte format and source identity

- `DrawingNativeTiles` is a Godot `RefCounted` holding one Rust-authoritative `TileStore`; production currently instantiates it once per Brush/Eraser gesture rather than retaining it for the document lifetime. Call `configure(storage_stride, initial_revision)` exactly once (`16 <= stride <= 2048`, `revision >= 0`). **Storage** tiles are not the Hokusai internal 64px tiles or the 128px display tile size; normal planned stride is **256**.
- `TileId = (layer: String, tile_x: i64, tile_y: i64)` uses signed world coordinates, `div_euclid` floor division for tile ID and `rem_euclid` for local pixels. World coordinate absolute value must not exceed `2^60`; overflow fails before any draft changes. Layers are independent namespaces, including identical `(tile_x,tile_y)`.
- A tile contains exactly `stride * stride * 4` bytes in **straight** `[R,G,B,A]` order, row-major with row stride `stride*4`; data are **not premultiplied**. Alpha-zero pixels can retain RGB, including through masks, Undo, Redo, read and reimport. A full transparent black tile may be imported with an **empty** byte array, but still counts as an **explicitly authorized** source identity. An absent tile is an error, never implied blank. Imported source identities cannot be replaced in place. Source imports must match the current native revision and the exact buffer length.
- `set_layer_editable(layer, editable)` authorizes non-raster layer authority before an edit; changing it to false before native publication rejects the whole commit. Until Godot document integration, callers must interpret this as the combined visible/unlocked state and fail closed on missing authority.
- Memory limits: at most **128** touched storage tiles per open transaction, **256 MiB** counted across resident source, working drafts, masks and retained Undo/Redo tile snapshots, and **64** retained Undo transactions. History uses reversible full-tile before/after snapshots; these are conservative bounds, not byte-delta/COW subrect compression. Dense RGBA8 bytes are chosen for full-canvas paint over per-pixel string dictionaries; the map of tile IDs is sparse. Out-of-budget requests fail before publication. A full 512² (four 256px tiles) source + one edit with Undo history occupies **3,145,728 counted bytes** at the tested point.

## Native stroke to store transaction

The new path uses **the same** `DrawingNativeBrush` object as T-147. In Godot `Object.call` terms:

| Call | Parameters | Result / behavior |
| --- | --- | --- |
| `tiles.configure` | `storage_stride:int, revision:int` | `bool`; once only |
| `tiles.set_layer_editable` | `layer:String, editable:bool` | `bool` |
| `tiles.import_source` | `layer, tile_x:i64, tile_y:i64, revision:int, rgba_bytes:PackedByteArray` | `bool`; empty bytes explicitly authorize blank, nonempty must be exactly `stride²*4` |
| `tiles.begin_edit` | `layer, revision, selection_required:bool` | `{ok,transaction}`; one active edit; opaque positive 64-bit ID |
| `tiles.import_mask` | `transaction,layer,tile_x,tile_y,mask:PackedByteArray` | `bool`; one already-authorized source tile, exactly `stride²` selection bytes, nonzero = allowed |
| `brush.begin_stroke` | `layer,mode,preset_text,width,rgba,revision,local_clip` | `{ok,handle}`; v1 stroke |
| `brush.append_samples` | `handle,revision,PackedFloat32Array([x,y,pressure,delta_s]...)` | `{ok,...}`; one pending batch |
| `brush.required_tiles` | `handle,revision,stride,anchor_x:i64,anchor_y:i64` | `{ok,tiles:[{tile_x:i64,tile_y:i64}]}` for **pending** clipped samples, bounded to 128 IDs; use to bulk-read/authorize missing source/masks without exporting per-pixel changes |
| `brush.apply_tile_batch` | `tiles,handle,revision,transaction,anchor_x:i64,anchor_y:i64,erase:bool` | `{ok,dirty_tiles}`; entirely Rust-local pigment/hard blending, selection, staging and source verification **and** brush-batch acknowledgement on success / full brush rewind on failure |
| `brush.acknowledge_batch` | `handle,revision,accepted:bool` | `bool`; **only for transitional `preview_changes` path**. `apply_tile_batch` consumes its own pending batch and atomically acknowledges or rewinds; a separate ack must fail. |
| `tiles.dirty_tiles` | `transaction` | Array of `{layer,tile_x:i64,tile_y:i64,dirty:Rect2i,base_revision,generation}`; **tile-local** dirty rectangle `[start,end)` |
| `tiles.read_tile` | `layer,tile_x:i64,tile_y:i64,preview:bool` | `{ok,format:"straight_rgba8",stride_bytes,generation,bytes:PackedByteArray}`; detached immutable **copy**, valid independently of later mutation |
| `brush.commit_tiles` | `tiles,handle,revision,transaction` | `{ok,dirty_tiles,revision}`; validates matching layer/revision and fully acknowledged stroke, then atomically publishes tiles/history and consumes brush handle; a failed validation leaves draft/handle retryable; a no-op returns `{ok:true,no_change:true,dirty_tiles:0,revision:original}` |
| `tiles.discard_edit` + `brush.abort_stroke` | `transaction` / `handle` | `bool`; discard both halves of a cancelled edit |
| `tiles.undo_edit`, `tiles.redo_edit` | — | `{ok,tiles,revision}`; one atomic native history transaction, with monotonically increasing native revision |
| `tiles.list_tiles` | `offset:int,limit:int` | `{ok,tiles:[{layer,tile_x,tile_y,generation}],total,next_offset,revision}`; limit 1..128, `next_offset=-1` means end; persist a stable current-revision snapshot |
| `tiles.stats` | — | `{revision,stride,tiles,bytes_used,ffi_calls,bytes_imported,bytes_exported,pixel_stream_calls,undo,redo}` |

**Per-batch order:** `append_samples → required_tiles → import_source/import_mask (only missing authorized inputs) → apply_tile_batch`; on `apply_tile_batch` error, native brush state and native draft are already rolled back for that batch. Re-append the source samples only after missing input/authority is repaired. `apply_tile_batch` validates **both** brush and edit layer/revision, and builds a detached replacement set; failure cannot partially stage a batch or advance cursor/pigment state. `required_tiles` is discovery, **not implicit permission** to assume a missing tile is empty. `commit_tiles` is the recommended *paired* publication boundary. The older `tiles.commit_edit` and `brush.commit_stroke` are independently callable for direct tests and transitional consumers but must **not** be used as a two-step paired commit in the final producer (one half could otherwise succeed while the other fails).

**Versioning:** `TileStore.revision` is the authoritative content/history version for this new path; `begin_edit`, source import, pending batches, publish and Undo/Redo accept or produce that version. A user gesture that changes pixels increments it **once**; Undo/Redo each increment it once; no-op does not. Tile `generation` changes on commit/history replay; dirty descriptors expose **next** generation and preview `read_tile` reports that generation. `DrawingDocument.revision` currently seeds each short-lived native store and receives its next revision at paired publication. This alignment does not make the native store long-lived authority; T-148 must establish one persistent content/history revision owner before T-149 consumes it.

**Snapshots and display:** `read_tile` exports exactly one whole tile's contiguous copied bytes (not an unsafe pointer); `list_tiles` enumerates canonical identities in pages, and `dirty_tiles` gives the subset needed for screen invalidation. The dirty bounds are a conservative union of changed preview coordinates across accepted batches, suitable for display invalidation, not a minimal post-gesture diff bounding box. UI may cache `ImageTexture`s but must verify revision/generation; row alignment and the 128px display tiling are a **T-149 responsibility**. The original direct Save/Open witness enumerates native tiles and checks bulk-export SHA-256 parity. The newer production Canvas witness also passes a real standalone `.drawing` Save/Open and Undo/Redo using the *document's packed tile snapshots*, not a persistent Rust-owned save store. Atlas/Object integration is not yet proven.

**Measured bridge baseline:** With 99 96px NativeHard pointer samples, the direct Godot→Rust tile path stages a full 512×512 source in 4 tiles using 90.0ms of **native stage scheduling in one measured headless process**, 45 tile-store FFI calls (as counted at the measurement point), and zero `pixel_stream_calls`. This is **not** an editor responsiveness or input-to-photon benchmark; those timings predate the live Canvas cutover. The new software X11 witness measures one 512²/96px Canvas gesture at 536ms Hokusai / 808ms NativeHard, but these single runs are neither calibrated physical latency nor comparable to the earlier multi-process benchmark. See the live consumer evidence for exact transfer counts. See [T-148 evidence](evidence/T-148-2026-11-15-native-store.md) and [T-147 stroke ABI](NATIVE_STROKE_ABI_V1.md).


## Production per-gesture bridge (checkpoint, not final document authority)

1. Canvas captures a frozen selection and source revision and creates a Rust stroke plus `DrawingNativeTiles` at that revision. Tile discovery authorizes only resolved source; corrupt/missing source fails closed. Masks are imported as tile-wide 1-byte/pixel eligibility arrays. A changed selection is rejected even if previously imported masks exist.
2. `append_samples → required_tiles → import_source/mask → apply_tile_batch` produces native dirty tile identities; preview reads detached packed `read_tile(..., true)` bytes, cached until the tile generation changes. GDScript creates no per-painted-pixel stage/history map in production Brush/Eraser.
3. On mouse-up, Canvas checks source object identity and layer editability, exports all dirty packed tiles, and invokes paired `commit_tiles`. `DrawingDocument._publish_native_tile_edit` verifies source, bounds and aligned revision before publishing one tile-snapshot history entry; the rendering and `.drawing` consumers read packed RGBA8 bytes. Cancelling discards both native brush and tile drafts.
4. The native store is then discarded and `DrawingDocument` retains the canonical packed tiles and Undo snapshots. **This is a known T-148 acceptance gap:** the native history/revision is not the durable owner across gestures or mixed non-brush document modifications. Do not infer that Atlas/Object storage, GPU display caches, or real-device responsiveness have passed T-149/T-095.

The measured NativeHard 64px-canvas held/committed witness exported 49,152 tile bytes and imported 16,384 bytes over 10 tile-store FFI calls and 11 Rust-stroke calls; `tile_pixel_stream_calls` is zero. Legacy direct stroke statistics may still count `exported_ints` internally, so this number alone is *not* a proof that the engine computes no per-pixel integer values. See [T-148 live evidence](evidence/T-148-2026-11-15-live-cutover.md).
