# ADR — Drawing package and Atlas document contract (T-051)

**State:** accepted as a *working engineering contract* for extraction; 2026-11-02.
**Authority:** owner choices in [DECISIONS_DRAWING_ATLAS_2026-11-01.md](DECISIONS_DRAWING_ATLAS_2026-11-01.md) take precedence. This ADR does not accept proposed UX on the owner's behalf or claim the new persistence engine exists. Related implementation tickets: [T-052](Tickets/T-052.md), [T-053](Tickets/T-053.md), [T-054](Tickets/T-054.md), [T-060](Tickets/T-060.md), [T-061](Tickets/T-061.md), [T-062](Tickets/T-062.md), [T-066](Tickets/T-066.md), [T-067](Tickets/T-067.md), [T-068](Tickets/T-068.md).

## 1. Decision and implementation boundaries

**Owner-approved invariants:** one Git monorepo, exactly one canonical Drawing engine, physically independently runnable standalone Drawing and Atlas Godot projects, no dependency from Drawing to Atlas; **one generic internal DrawingDocument for each `(map_id, floor_id, detail_id)`** (Option B). Atlas displays `Map → Floor group → Detail group → Layers` but does not expose each internal document as a user tab/file. Standalone Drawing's ordinary files and Object Editor's dedicated tabs use the same generic document engine. A reusable Object Asset is *not* a whole-map document. All authored D-levels on a map share world coordinates, with per-level pixel density. Absent higher-detail art stays blank while Atlas overlays (grid, entrance/hit-test, navigation) work. Atlas owns global history, map binding, object-instance placement, and campaign persistence; Drawing owns generic layers, edit/selection/snap/render and ordinary-document I/O. Desktop Windows/Linux first; no historical-user-save migration.

**Engineering defaults established by this ADR (revisable by implementation evidence):** opaque immutable IDs, explicit document revisions and chunk read requests, strictly ordered prepare/commit for multi-document edits, checked signed integer addressing and camera-relative drawing, single-root generation publication, bounded caches, and a staged allowlist package build. The pseudotypes below described the T-051 proposal. **T-052 now implements an independent, typed generic core in `addons/drawing/`** with the analogous `DrawingDocument`, `DrawingEditSession`, `DrawingRasterTile`, `DrawingResult`, and `DrawingDirtyRegion` APIs. Signatures differ where Godot uses explicit result objects and bounded synchronous operations; see [`addons/drawing/README.md`](../addons/drawing/README.md). T-066 still finalizes the physical format after T-067 measurements.

**Not decided here:** final tile stride, in-memory edit subregion and GPU upload size, blob codec/pack layout, production manifest encoding/extension, asset-browser UX, native acceleration, font binaries/licences, or T-059/T-056 UX acceptance. Do not turn sample paths or initial budgets into purported owner approvals.

## 2. Physical package and independent Godot builds

Current Atlas has `project.godot` at repository root. Godot `res://` is rooted at the active project; a project in a child directory cannot `preload()` parent source outside its own `res://`. Copying two copies of `class_name` scripts under the Atlas root risks collisions and forks. Thus **source is canonical in the monorepo and consumers are staged outside the checkout**:

```text
DrawInAtlas/                         # existing Atlas project root: project.godot
  addons/drawing/                    # ONE canonical generic Drawing source tree (T-052)
    signed_tiles.gd                  # shared signed 64-bit tile arithmetic
    document.gd                      # generic document, layers and lazy load API
    edit_session.gd                  # bounded transactional raster edits
    raster_tile.gd                   # exact canonical RGBA8 storage/codec
    ...                              # snapping, masks, tools, renderer, results
  drawing/app_sources/               # proposed standalone app sources (T-053)
  tools/build_drawing_contract_consumer.py
  tests/fixtures/drawing_contract_consumer/*.txt
  tests/fixtures/drawing_core_consumer/*.txt

<isolated build directory, not in checkout>/
  project.godot                       # staged independent consumer project
  main.tscn / main.gd                # fixture sources, no Atlas scene/autoload
  addons/drawing/*.gd + *.gd.uid    # generated byte-identical *build artifacts*
```

**Package import rule (implemented by T-052):** `addons/drawing/` is now the **canonical** path within Atlas's root Godot project; there is no second `drawing/package/` source fork. Scripts may refer to their canonical `res://addons/drawing/` path in Atlas and independent staged consumers. The allowlist builder stages the same `.gd` and `.gd.uid` source bytes without modifications. No staged copy becomes a second editable fork. A clean export contains *only* staged package + consumer, with no `scripts/campaign/`, Atlas autoloads, Atlas editor plugins, or root `project.godot`. Use namespaced class names (e.g. `DrawingDocument`) without colliding with existing `Atlas*` global classes.

**T-051 reproducible isolation proof:**

```bash
TMP_DIR="$(mktemp -d)"; trap 'rm -rf "$TMP_DIR"' EXIT
python3 tools/build_drawing_contract_consumer.py --output "$TMP_DIR/consumer"
godot --headless --editor --path "$TMP_DIR/consumer" --import --quit
godot --headless --path "$TMP_DIR/consumer" --quit-after 40
# Expect DRAWING_CONTRACT_CONSUMER_PASSED, exit 0
```

The T-051 proof still exercises signed-tile arithmetic only. **T-052 adds a separate 150+-check isolated core fixture** via `--fixture drawing_core_consumer`, covering generic edit transactions, sparse chunks, masks, pixel fidelity, import, clipboard, snapping, lazy verification, document-tree transfer and logical metadata reopen. Neither fixture is a runnable standalone editor, package release or complete project persistence system; T-053 builds the Drawing app, and T-066 defines the physical format and atomic save. Windows/Linux packaging is a later build test.

## 3. Example: two floors and two details, not four user tabs

[`examples/drawing_document_registry.json`](examples/drawing_document_registry.json) is a machine-validated *conceptual example*, **not** a saved-file schema. An Atlas map `map-0042` has the following registry:

| Atlas hierarchy | Durable registry key | Internal Drawing document | Density (pixels/world unit) | Artwork |
| --- | --- | --- | ---: | --- |
| Ground → D0 | `(map-0042, floor-a1, detail-a0)` | `doc-001` | 1 | `layer-01`, signed tiles `(-1,0)` and `(0,0)` |
| Ground → D1 | `(map-0042, floor-a1, detail-a1)` | `doc-002` | 2 | **blank**, no layers/chunks |
| Upper → D0 | `(map-0042, floor-b1, detail-b0)` | `doc-003` | 1 | `layer-02`, tile `(0,-1)` |
| Upper → D1 | `(map-0042, floor-b1, detail-b1)` | `doc-004` | 2 | `layer-03`, tile `(-2,4)` |

`doc-002` exists as a durable *logical identity* without needing a document file, decoded image or texture until successfully authored. Selecting `Ground/D1` shows **no Ground/D0 art**; map/world grid, entrance markers and navigation are independently composited. Only Atlas knows what `floor-a1` or `detail-a1` means. Atlas presents one hierarchy by projecting the registry into UI groups, rather than serializing Atlas-domain groups inside Drawing documents. The active document may load lazily; collapsing a floor doesn't cause full chunk decoding.

**Identity rules:** assign fresh opaque IDs at creation, persist in Atlas registry and document metadata, and never derive ID from display names, filesystem paths, indices, or mutable group order. Reject duplicate `(map,floor,detail)` keys and duplicate document IDs in a campaign. Rename/reorder retains IDs. Duplicating map/floor/content allocates fresh document and layer IDs and remaps internal references; *moving* an individual layer retains its globally unique layer ID, *copying* gives new layer IDs. A group in one internal document is local to that document; layer trees are never shallow-shared. `ObjectAsset` has its own global asset identity and `ObjectInstance` its own placement identity, independent of background layers.

## 4. Coordinate and pixel contracts

1. Atlas defines one map-world frame and a **signed integer origin/anchor** for large offsets; never send a 1e12-world-unit absolute `Vector2` as a rendering transform. Drawing receives a generic, camera-relative local transform and/or already-converted document pixel coordinates. Integer raster pixel coordinates are 64-bit on supported builds. Reject out-of-range conversion instead of overflowing or smearing a huge `Vector2`.
2. Prototype world precision is **1,024 integer ticks/world unit** and each detail density is a positive rational `(num, den)` pixels/world unit. The example D0=1 and D1=2 is a *default progression*, not an automatic fixed sequence for arbitrary D levels. T-061 must validate/freeze tick scale and conversion API before any new-format save; use integer quotient/remainder or checked operations, not `float64` multiplication of huge anchors, to compute `pixel = floor(world_ticks * num / (1024 * den))`. A pixel covers a half-open world interval; negative positions floor toward `-∞`. Guard intermediate overflow and return an explicit `COORD_RANGE` error. Non-axis-aligned asset instance transforms operate in an asset-local frame and get a camera-relative placement transform from Atlas; their rotations must not shift map-world D-level alignment.
3. The logical storage tile has **one versioned positive stride per DrawingDocument**. T-067 benchmarks 256 / 512 / 1024 / 2048; **none is the frozen production size**. For each signed pixel `p`, `tile = floor_div(p, stride)` and `offset = p mod stride` with `0 ≤ offset < stride`. Thus at any stride `p = -1` maps to tile `-1` and offset `stride-1`; `p=-stride` maps to tile `-1`, offset `0`; `p=-stride-1` maps to tile `-2`, offset `stride-1`. This is exact integer arithmetic, never floating `floor(p/stride)`. The implemented, standalone-tested reference is `addons/drawing/signed_tiles.gd`.
4. Density becomes immutable for a document **after its first successful content commit** (engineering safety default). Changing it requires an explicit undoable **resample/reindex** operation with a chosen kernel, immutable old revision and a visible fidelity warning; T-061 owns user interaction and high-precision verification. Rasterization and import preserve source-alpha and hidden RGB of **unchanged** pixels exactly; a genuinely edited pixel may change color/alpha by documented tool semantics.
5. Atlas may change the *presented* D-level during zoom, but a pointer gesture pins `(document_id, revision, pixel transform, target layer)` at begin; never switch halfway through a stroke. Snapping coordinates/candidates are generic Drawing values and carry no `AtlasGrid` type. Grid/entrance/navigation hit testing is Atlas overlay logic, not a raster fill source.

## 5. Proposed typed API and lifetime

These are intended signatures/contracts, expressed as pseudotypes to avoid prematurely creating fake working classes. Asynchronous operations may return a job/result instead of synchronously completing; **all failures must be explicit results** rather than silent blank images.

```text
DrawingDocument.open(DocumentId, ManifestSource, ReadOnlyChunkStore) -> Result<Handle>
DrawingDocument.create(DocumentId, DocumentSpace, Density, TileStride) -> Handle
Handle.list_tree() -> metadata (stable layer/group IDs, names, order, visibility)
Handle.request_chunks(layer_id, tile_coords: Array[SignedTileCoord], priority) -> Result<ChunkLease[]>
Handle.begin_edit(target_layer_id, frozen_space_transform, expected_revision) -> Result<EditSession>
EditSession.apply(edit_region: PixelRect, tool_input) -> Result<DirtyRegions, UndoDelta>
EditSession.commit() -> Result<NewRevision, ChangedTiles, ContextSnapshot>
EditSession.cancel() -> void   # no content or metadata mutation
Handle.snapshot_for_save(revision) -> ImmutableManifest + ImmutableDirtyChunkLeases
Handle.replay_delta(delta, expected_revision) -> Result<NewRevision>
DrawingCodec.encode/decode(snapshot, ChunkStore) -> Result<ManifestBytes>
ChunkStore.fetch_verified(blob_ref) -> Result<CanonicalRGBA8>  # missing/corrupt = ERROR
ChunkStore.put_staged(canonical_bytes) -> Result<BlobRef>        # immutable
```

**Document model:** ordered generic nested groups and raster/text/semantic-object layers; no Floor, Detail, Map, Campaign or Grid subclasses/imports in Drawing. Stable layers hold metadata and optionally sparse signed pixel tile refs; **absent tile** is blank *only when the manifest has no tile reference*. Empty guides, group metadata or text can exist without pixels. No full-canvas backing image. `DrawingDocument` controls its own local history when opened standalone; embedded Atlas commands supply deltas and history metadata to a single Atlas global timeline without creating a competing history order.

**Edit safety:** only touched regions/chunks are detached copy-on-write; `apply()` returns bounded typed changed rectangles and compact before/after deltas. Begin/commit capture source document revision; reject stale revisions and read-only/locked layers. A single brush gesture is one transaction and retains once-per-gesture coverage semantics. Cancel or failed commit leaves the original unchanged. Native rasterization is a pluggable *edit-region* operation (T-068) and cannot silently change canonical RGBA8/undo behavior. Saving is separated from edit commit; it must never deep-copy every unrelated image to update one pixel.

**Lazy lifecycle:** `Unmaterialized` (registered empty ID) → `MetadataLoaded` → `VisibleChunksResident` → `Dirty/Pinned` → `Published/Unloadable`. Loading metadata never eagerly allocates tiles. Dirty chunks, outstanding edit sessions and history-reachable deltas cannot be discarded merely to satisfy a cache budget. Eviction of clean leases is allowed after all holders release them. Background decode results carry document+revision and are dropped if stale. Unloading a dirty document requires completing a durable save or retaining the dirty state in a bounded external journal; never silently unload data. A missing/corrupt *referenced* tile yields a visible error, not a synthesized blank view.

**Initial configurable working budgets, not production measurements:** 256 MiB decoded raster CPU cache, 128 MiB GPU tile cache, 64 MiB transient/encode staging and at most 32 simultaneous file descriptors across visible documents. Admit viewport tiles first, optional one-tile prefetch margin, LRU of *clean, unpinned* tiles; throttle requests/edits when dirty+pinned memory exceeds the limit. Separate storage tile size from edit-region and GPU tile sizes and benchmark all budgets on native desktop (T-067/068). Large campaigns may display metadata for many documents but decode only the active/presented range.

## 6. Transactions: create/edit/save/open/undo

**Create and save:** (1) Atlas creates a map/floor/detail and reserves a new document ID in an in-memory registry; initially no physical tiles. (2) User begins painting in the chosen document; Atlas pins target ID, revision and density, Drawing creates its first layer/tile *on successful content commit*, not merely on tool selection. (3) Drawing returns compact deltas and dirty ranges; Atlas adds one global content-history entry with originating map/floor/detail/document/selection/mode and world-space affected bounds. (4) Saving stages changed canonical chunk payloads, checks roundtrip/hash integrity, stages immutable new document manifests, then creates a new campaign root generation referencing both the updated and unchanged documents. (5) An atomic root promotion makes the entire new generation visible; published revisions become clean. (6) Reopening validates that root and required manifests exist before exposing content, and lazily fetches/chunks on demand. Standalone Drawing does the same generic codec work with its own single-document root; it never needs Atlas IDs.

**Undo/redo content:** replay compact deltas through the Drawing API in Atlas global history order; restore originating `(map,floor,detail,document)` + a valid selection and edit mode. If the affected geometry is already **partly visible**, leave camera translation/zoom; else **pan only** to reveal part, preserving zoom. Missing/deleted targets cause an explicit safe fallback and user notification, never selection of a same-named replacement. Navigation/camera/mode changes alone are not history entries. App-wide selection-only history is OFF by default; when ON, meaningful selection transitions may enter history but must not dirty content. Replay must not push new history entries. An in-memory undo after a save advances *dirty* document/project state until republished; history is not itself a durable write.

**Cross-document move example:** with `layer-01` in `doc-001`, drag Ground/D0 → Upper/D1 (`doc-004`). Atlas (1) resolves and pins both documents, locking them in stable ID order; (2) verifies each expected revision and destination constraints; (3) prepares a detached immutable content snapshot and both post-move layer trees, retaining `layer-01`'s stable ID and its correct world-space geometry (resample or preserve a world-space intermediate if the density differs); (4) commits **both** in memory as one logical global history command or rolls both back; (5) saves touched manifests and blobs under one new root pointer; (6) undo/redo restores both trees in one Atlas entry, including the source/destination UI context. Cross-density data must not be silently reinterpreted as a new pixel density: reject without an explicit resample policy if lossless placement cannot be guaranteed. For **copy**, allocate a fresh layer ID; source unchanged and mutable chunk data never aliases destination. If a document is unloaded, load its manifest and only required tiles before prepare. On insufficient cache/revision conflict, abort without touching either document.

**Object source Save:** the Object Editor owns a *private draft* `DrawingDocument` and local undo; linked instances continue using the last published revision. Save stages verified immutable `Objects/<asset-id>/<revision>` content; one root publication updates the asset registry's published revision, and all linked instances resolve the new source only after publication. Cancel discards private edits. The Atlas global history records published source changes and relevant origin context, not each private brush stroke.

**Object Save As from instance A:** capture immutable `(map_id, instance_id, expected_binding, expected_revision)` on opening the editor; prepare a new independent asset **B** (including draft bytes, new stable asset ID) and a new Atlas root generation with B registered, *only A* rebound B, and all other A-linked instances unchanged. If the originating instance/binding changed or disappeared, **reject the rebind and keep the draft**; do not silently rebind a similarly named instance. Publish both via a **single** root promotion. The editor then shows B. **Undo changes A's binding back to original source while B remains a published, reusable asset even if unreferenced; redo rebinds to the same B ID.** Undo must not report the project clean if B remains newly persisted; if B was explicitly deleted, redo fails safely and visibly rather than recreating it. Independent Save As creates B and changes the editor tab without rebinding an Atlas instance. Nested child asset references are copied by *reference* by default, with optional explicit unique clone later; validate the dependency graph acyclic before publishing (T-064). Deletion offers remove references, retained `NULL` placeholders (preserving instance ID/transform/original target) or cancel; this is unrelated to automatic GC.

## 7. Portable persistence and generation publication

**Logical structure (sample names, NOT frozen format/extension):**

```text
Campaign.scn                      # authoritative native campaign root, replaced atomically
Drawings/
  documents/<document-id>/<revision>.<manifest>  # immutable layer tree + refs
  blobs/<shard>/<digest>.<codec>                  # sparse immutable chunks or packed equivalents
Objects/
  <asset-id>/<revision>.<asset-manifest>         # immutable published object versions
Fonts/
  <licensed-font>                                # explicitly referenced redistributable resources
```

The campaign root contains the authoritative registry, a generation ID, published revision pointers for **all** referenced document/asset manifests, relative resource paths, and map/floor/detail metadata. `Drawings/` manifests contain document ID, schema/codec version, **tile stride**, density/space version, group/layer IDs, sorted signed tile coordinates and per-tile content fingerprints. No absolute paths, machine-specific fonts or external live links. Preserve exact straight-RGBA8 pixel bytes *including unchanged fully transparent RGB*. Hash canonical bytes + dimensions + format identity; verify encoded/decoded bytes and fingerprint before accepting a payload, regardless of chosen codec. Chunk refs are immutable within a generation. Object manifests can reuse the same generic Drawing codec without linking their source IDs to Atlas-specific classes.

**Proposed transaction algorithm for T-066 validation:**

1. Acquire per-campaign write lease; snapshot a consistent set of document and asset revisions and expected current root generation. Reject stale concurrent writers rather than overwriting them.
2. Encode **only changed** nonempty tile data. Stage blobs/manifests in sibling temporary files on the same filesystem; flush and verify size, SHA-256 and canonical decoded bytes. Stage new asset versions and font references first. Existing immutable blobs can be reused by digest; packing/sharding is deliberately deferred to T-067.
3. Stage a new root containing new and unchanged references; resolve/check *every required* referenced file and detect cycles/bad IDs. Flush file data (and required containing directories where supported) before publication. No root may reference a still-ephemeral staging path.
4. Retain last known-good root/generation, then use **one atomic replace of `Campaign.scn`** (same-filesystem rename/replace; choose and test Windows/Linux implementation), including its generation guard. Never try to atomically rename a set of unrelated manifests or directories. On failure, retain previous root and leave staged blobs unreachable for later safe cleanup.
5. Mark in-memory savepoints published only if the root promotion succeeds; otherwise retain dirty edits and report failure. Reopen picks the newest **fully verified** root or explicitly offers the retained verified backup; never auto-promote a partial generation. Backup selection must be visible and must not quietly discard a successfully published newer revision.

**Important limitation:** POSIX rename atomicity does not alone prove power-loss durability (fsync files and directories); Windows replacement can fail if files are held open. Treat a failed replace as an error and preserve the old root. File formats, exact revision naming, delta journals, locking implementation, content store layout and compaction must be frozen and fault-injected by T-066. `AtlasCampaignStore` currently saves a **single native `.scn`** and has *no* multi-file transaction implementation. The sample above is a proposed implementable contract, not a claim of deployed storage.

**GC/savepoints:** retain blobs/manifests reachable from current and backup generations, undo/redo and draft pins, and any intentionally saved unreferenced Object Asset (e.g. B after Save As undo). Never GC from refcount zero alone; safely compact only under explicit optimize/retention policy with a verified root and no live leases. `document.dirty` means revision differs from its published revision; `project.dirty` includes newly registered retained assets even after binding undo; private draft dirtiness is separate. Restoring pixels via undo is **not** equivalent to restoring the old project root if the asset library changed.

### Failure and recovery matrix (required fault-injection cases)

| Failure | Load/save response | Permitted recovery and invariant |
| --- | --- | --- |
| Crash before all blobs staged | Old root remains authoritative | Ignore unreachable staged bytes, never publish a dangling ref |
| Crash after blobs but before manifests/root | Old root remains authoritative | Keep/reap unreachable stage only after reachability scan |
| Crash during one root rename/replace | Either complete old **or** complete new root | Verify generation and every mandatory manifest; use backup if current corrupt; never half-new registry |
| New root references missing/corrupt manifest | Refuse affected generation | Offer verified backup and explicit diagnostic; do not invent an empty document |
| Referenced chunk missing, wrong digest, truncated or incorrect hidden RGB | Report chunk error on lazy read, keep editing disabled for affected region | Re-fetch from valid alternate/backup where available; never render missing content as intentionally blank |
| Old root plus incomplete project copy/missing `Objects/` or `Fonts/` | Show incomplete-project report and missing references | Preserve stable IDs/`NULL` when appropriate; request original sibling folders; do not silently substitute fonts/assets |
| Save out of disk space, permission error, or failed fsync | Do not promote root; keep in-memory dirty state | Retry after repair; do not mutate published asset visibility |
| Two writers/stale document or asset version | Explicit revision conflict, no partial commit | Rebase/retry or preserve draft; do not overwrite concurrent work silently |
| Crash between Save As B staging and root promotion | A still refers to original; B not yet *published* | Unreferenced staged files are not visible as saved assets; keep draft/recovery path |
| Undo retained B, then B explicitly deleted, then redo | Reject invalid B binding and notify | Preserve original instance binding; no automatic recreation or GC resurrection |
| Process killed while decoding/evicting, or memory limit reached | Clean cache can be recreated; dirty/pinned data stays owned | Backpressure or cancel edit safely; no loss of committed unsaved changes |

## 8. Acceptance tests and handoff to implementers

**T-051 tests (included):** Python validates 2×2 fixture registry, unique IDs, sparse blank document and explicit density, package source boundary, staging/path safety, and clean independent consumer layout. The staged Godot project imports and runs the **real** generic signed tile primitive, including negative seam and far-integer roundtrips for all four candidate strides. Existing Atlas baseline tests, ticket validator, and explicit-type checker must still pass. CI runs the isolated consumer test *without* Atlas plugins or project resources.

**T-052 tests (implemented):** real `DrawingDocument`/bounded edit/region API, detached chunk snapshots, stable nested layer/group IDs, cancellation, source isolation, sparse blank allocation, exact alpha/hidden RGB, selection/clipboard, cross-document deep transfer, and revision conflicts. The canonical package runs in a clean consumer with no Atlas source. Stride stays per-document (not production-frozen at 256); no native performance improvement is claimed. This ticket does not imply T-053's standalone app or T-066's physical persistence.

**T-053 tests to add:** build a runnable standalone Drawing editor + third consumer from the *complete* package; create group/layer, paint/erase, select/move, undo/redo, save/reopen pixel/alpha/ID roundtrip. No Atlas root, autoload or plugin dependency. Run real pointer + framebuffer tests on Windows/Linux.

**T-061/T-054/T-060/T-062/T-064 tests to add:** shared world transforms and D0/D1/D32 far signed positions, frozen gesture target, blank higher detail with overlays; global selection/mode/camera recovery; Object Save publish isolation, Save As A→B and retained-B undo/redo, stale-instance rejection and missing-B redo; nested-cycle rejection/NULL placeholders. This ADR does not claim those tests or implementations currently pass.

**T-066/T-067 tests to add:** exact RGBA8 roundtrip and hidden-RGB verification, representative sparse/dense/noisy tile data at all four strides, file count and latency benchmarks, staging/rename power-failure injection, portable relocation, backup recovery, eviction budgets and savepoint/GC reachability. Freeze the first production schema only after evidence; no historical-user-save migration.
