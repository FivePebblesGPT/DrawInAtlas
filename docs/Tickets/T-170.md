# Preflight native source retirement before cross-document raster moves

**Split from T-148.** `DrawingDocument.transfer_subtree(..., move=true)` and
`AtlasDrawingTransfer.apply()` previously imported into the destination
*before* removing the source. If source Rust rejected retirement because an
edit was active, the revision diverged, or the Godot tile bytes had changed,
the standalone helper reported success and Atlas could leave a partial target
mutation. A compensating removal is not a substitute for preflighting the
source, since destination history and native source tokens must not change on
an ordinary rejected move.

## Acceptance

- [x] Add a **read-only**, bounded Rust retirement eligibility method whose
  validation is shared with the actual native retirement operation (revision,
  active transaction, ID count/uniqueness and parked source); no bytes,
  revision or history may change on preflight.
- [x] Before destination import, the source checks tree editability, native
  revision and full resident RGBA8 identity/bytes, including hidden RGB. Both
  standalone and Atlas move callers use this common boundary; copies remain
  independent and do not retire their source.
- [x] Fail closed on rejected source retirement, preserving both documents'
  trees, revisions, native source and history. Keep the existing compensating
  rollback for an unexpected late source failure; do not claim a general
  distributed/two-phase transaction across arbitrary reentrant host code.
- [x] Verify with real Hokusai native source/target strokes, active-source
  rejection, hidden-RGB tampering, Atlas Undo/Redo and successful retry;
  confirm a fail-first control against the previous callers. Preserve
  corrected prior T-168 retirement expectations.
- [x] Run Rust unit tests, rustfmt, strict Clippy, release GDExtension,
  surrounding Drawing/Atlas/Object and X11 witnesses; update CI, ABI, parent
  ticket, `docs/Index.md`, and checksummed raw evidence.

This closes the **ordinary rejected source-retirement move** case, not all
