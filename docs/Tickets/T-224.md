# Group panels by icon proximity while keeping panel and group drags distinct

## Owner design (2026-11-20)

Dragging **one panel icon near another group's icons** groups the panels, **not** merely because two icons are close in the static layout. The user must complete a thresholded drag and valid merge-target drop. Panel icons always move **individual panels**; dragging T-223's triangle marker is the only group-drag gesture.

## Acceptance

- [ ] An explicit hover preview distinguishes group merge, insert/reorder between groups, and detach/split; no accidental merge simply from passing nearby.
- [ ] Existing `DrawingDockDrag` and `DrawingDockLayout` commit/rollback remain authoritative. Esc/invalid drops restore all panel IDs, group membership, active tabs, panel order and floating geometry exactly.
- [ ] Moving an icon out produces a singleton if needed; floating hosts still contain exactly one group, without duplicate controls.
- [ ] Scroll/autoscroll, narrow dock, physical pointer threshold, keyboard alternative, saved layout and native insertion-hint framebuffer checks pass.

Requires T-223 so group drag cannot be confused with individual icon drag. T-083 is still unapproved.

T-224 is **Ready** to add explicit proximity merge/insert previews and transactional individual-panel reorganization.
