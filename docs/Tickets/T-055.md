# Embed Drawing in Atlas using explicit adapters and separate overlays

## Status
**PLANNED / BLOCKED by T-051, T-053 and T-054.**

## Purpose
Keep Atlas responsible for campaigns, map/floor organization, grid settings, links, discovery, navigation and presentation policies without duplicating drawing behavior. Preserve one editable map/floor at a time.

## Implementation plan
1. Add an adapter that exposes the selected `AtlasFloor.layers` as the Drawing surface without changing persisted floor resources; synchronize only explicit selection/view state when switching map/floor.
2. Convert grid selection and snapping to optional Drawing input policies (board-space polygons/points), preserving continuous artwork across cells and the selected-cell edit mask.
3. Keep Atlas link hit-testing/chooser, map navigation, fog/token/projector interactions and grid/reference overlays in Atlas-owned controllers or composition layers; do not make them required by the Drawing renderer.
4. Split the authored-detail **data/rendering** contract from the zoom-selection **policy**. Preserve automatic artwork LOD as default, explicit edit target, and never retarget an in-progress gesture. Final placement of this policy follows T-051.
5. Have `AtlasMapCapture` and sidebar/reference preview flows call the Drawing read-only renderer with bounded requests rather than starting an interactive drawing tool stack. Preserve transparent aligned previews, cache signatures, cancellation and privacy filtering constraints.
6. Move existing Atlas shell wiring incrementally, with adapters/shims removed only after regression coverage proves they are unused.

## Acceptance
- Atlas-only campaign/map/link/floor model tests require no Drawing scene or interactive viewport.
- Atlas opens/edit/saves Drawing surfaces; navigation, grids, masks, floors, linked previews and D-level selection remain correct.
- Two workspaces do not share camera, gesture, selection or clipboard state.
- Empty grid cells do not require linked documents to zoom or paint; link selection remains deterministic.
- Native tests cover preview alpha/alignment, camera zoom, pointer interactions and map/floor changes during cancellation.
- Source dependency check shows Atlas depends on Drawing contracts, never the reverse.

## Non-goals
No new projector/player-output or network features, no destructive placement cleanup, no redesign of `T-018` hierarchy beyond what is required to host the Drawing component.
