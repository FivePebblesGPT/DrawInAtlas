# Atlas composition: map Drawing, reusable object instances, entrance input and previews

**Status: DONE (2026-11-02).** All five hard prerequisites T-053/T-054/T-060/T-061/T-062 are Done; no manual-review gate is inherited. Atlas now mounts the canonical Drawing renderer and input transactions. Native LOD acceleration, unified saves and owner UX validation remain separately tracked.

## Plan
1. Consume the canonical Drawing package from the same monorepo; verify the Drawing project itself builds independently. Atlas may supply document handles, floor-group views, world-to-asset transforms and explicit current-detail edit target.
2. Use T-060/T-062's Object Asset registry and Object Editor: place an instance with its own transform and `source_object_asset_id`; an edited/saved source updates all instances, while Save As creates an independent asset. **Do not** treat the map's background Drawing surface as a reusable placed object by default. Do not silently rebind a placed instance after Save As.
3. Atlas maps **Map → Floor group → Detail group → Layers** exactly (T-061). World coordinates are shared among authored levels, while Drawing receives only asset-local/editor-space render and edit requests. Placed reusable objects are a separate overlay/instance collection with mapped world coordinates; define which detail groups display them. Show no lower-level background artwork when higher-detail content is missing.
4. Keep grid/hex overlay, links, fog, tokens, projector and navigation outside Drawing. Atlas can supply generic snap targets and board-space edit masks; Painting tool wins click arbitration at entrance locations.
5. Only Selection/ObjectSelection/Pan double-click of the **same stable entrance ID** may navigate. Use explicit hit testing and stale target rejection; define overlapping entrance handling and click threshold in T-051. A single click must not navigate.
6. Global undo/redo uses T-054's origin context: navigate to the originating map **and restore valid selection and editor mode**, distinguishing a placed Object instance transform from editing the source Object Asset. Atlas may change map/floor/detail presentation during zoom but must freeze the in-flight Drawing edit target until commit/cancel.
7. Preview capture uses Drawing read-only rendering through explicit viewport bounds/LOD and transformed asset references, not interactive `AtlasCanvas`; no document mutations, correct alpha and cache invalidation.
8. Incrementally remove transitional `AtlasCanvas`/editor facades after tests, rather than one giant rewrite.

## Acceptance
Same Drawing painter in both apps; atlas floor groups and shared/copied art behave correctly; blank D-level stays blank; world transformations align; paint-over-entrance paints; double-click with navigation tool works; undo back to A; previews are read-only; no Atlas dependency in Drawing.

## Round 7 — project-relative assets, navigation overlays and publishing
- Atlas consumes reusable Object Asset files from `Objects/` beside the campaign file. Resolve stable IDs and project-relative paths; instance overrides are restricted initially to **transform and visibility**. Expose a peer **Asset Browser** dock (T-065) to place/open/edit/delete assets.
- Object Editor source changes are private until **Save**. Save publishes/invalidate all linked instance renders. Save As entered through an instance stores new B and rebinds only its origin; undo retains B in the library. Native project save and object files form one portable directory bundle, not one opaque campaign file.
- Missing authored higher detail renders **no lower-level art**; **grid, entrance hit-testing and navigation overlays remain visible and functional**. Do not accidentally apply the “blank artwork” rule to navigation UI.
- Implement source deletion prompt for **remove placements / retain visible `NULL` placeholders / cancel**. NULL placeholders retain transform and reference info; never hit-test as if the missing asset still existed.
- When entering a higher level, its raster pixel density is explicit and independent of other levels (with default progression), but maps share one continuous world coordinate reference (T-061).
- For Object Assets nested within other Objects, rely on T-064's cycle-safe graph and shared renderer rather than implementing Atlas-only recursive placement logic. Do not require advanced nesting before the basic flat-instance vertical slice works.
- Entrance double-click uses a **configurable time/distance tolerance** and **same stable entrance ID**; painting tools still paint instead of navigating.

## Round 8 — one DrawingDocument per Atlas floor/detail
The owner selected **Option B**. For each `(map_id, floor_id, detail_id)` resolve exactly **one internal DrawingDocument** with independent layer tree and sparse chunk content. Atlas projects those documents into **Map → Floor group → Detail group → Layers**; the Drawing editor receives a document handle, not Atlas types. Floor/detail switching activates a different document without prompting the user to open an individual `.drawing` file.

Atlas owns the world-to-document mapping, shared coordinate reference and per-level pixel density. Read-only previews must fetch/compose only visible chunks/document layers rather than instantiate the interactive Atlas canvas. Cross-document layer moves/copies/clipboard use explicit transactions and Atlas global history. Persist via [[T-066]] under `Drawings/`, not as a new huge native image embedded in the campaign resource. Empty authored detail remains blank, with grid/entrance overlays functional.
