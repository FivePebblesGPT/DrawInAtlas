# Atlas integration: Drawing surfaces, floor/layer views, authored LOD and entrance input

**Status: PLANNED; blocked by T-051/T-053/T-054.** Native LOD backend research (T-057) is optional.

## Plan
1. Consume a pinned, independent Drawing package via its public API; do not import Drawing's internal implementation files.
2. Atlas owns mapping map identity/world coordinates to DrawingDocument/surface and selected ordinary layers. Atlas floors organize layer subsets/groups; finalize shared-layer semantics and transforms in T-051.
3. Drawing renders/edits supplied surface and layer context. Atlas organizes authored detail levels (which content appears at world zoom); distinguish authored detail from cached raster image pyramids.
4. Atlas owns link navigation, grid overlay, fog, tokens, projector and discovery. Supply Drawing with optional generic snapping targets and board-space selection masks; no Atlas type enters Drawing.
5. Input precedence: active brush/shapes/eraser paint even above entrances; Selection/ObjectSelection or Pan can hit-test an entrance, with double-click on same entrance navigating. Overlap chooser and timing/identity resolved in T-051.
6. Extract read-only preview capture using Drawing's renderer without instantiating a full interactive tool controller. Preserve transparency, aligned crops, bounded caches and invalidation.
7. Bridge Drawing edits into global Atlas history; preserve currently active editing target throughout gestures and map/floor/LOD changes.
8. Retire old AtlasCanvas facades after acceptance; legacy battlemap cleanup not a save migration.

## Acceptance
Maps and logical floors can share/edit Drawing content by the approved policy; painting over entrance paints; deterministic double-click navigation; unassigned hexes remain editable; no duplicate Drawing renderer; preview does not mutate source; Atlas consumes pinned package, Drawing builds alone.
