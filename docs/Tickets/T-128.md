# Guard History-list jumps against pending Brush revision conflicts

**Done — bounded engineering corrective work (2026-11-15).** T-127 guarded
Undo/Redo commands, keyboard shortcuts and History-panel *buttons*, but the
History panel's selectable list still called `DrawingDocument.undo()` and
`redo()` directly in `_history_item_selected`. Clicking a prior or future row
while an active Brush/Eraser transaction was draining incremented the source
revision; the next Canvas frame cancelled already delivered, unpublished paint
and its T-124 queued successor. Rejected navigation also left the highlighted
History row inconsistent with the actual source cursor.

## Scope and acceptance

- [x] Refuse a History-list cursor change while any Brush/Eraser stroke or
      queued successor remains unpublished, **before** either history loop
      touches the document or changes selection/floating-move context.
- [x] Reuse the existing actionable pending-stroke warning; restore the
      list's actual selected row without firing another navigation callback.
      An unchanged-row selection stays a harmless no-op.
- [x] Once normal bounded publication completes, permit backward and forward
      History-list jumps, preserve chronological transactions, exact RGBA8
      rendering and a portable `.drawing` Save/Open roundtrip.
- [x] Exercise both backward jumps with two pending queued gestures and a
      forward jump into an existing Redo branch. The original T-127 source
      fails **13/37** assertions; the candidate passes **37/37** under pinned
      Godot 4.8 beta3 with strict logs and neighboring regressions.
- [x] Add a fail-closed source/CI contract to the existing T-085 required step;
      preserve its 46-check inventory and existing error/log requirements.
