# Floor layer groups, continuous world coordinates and blank authored detail

**Status: PLANNED. Owner approved floor=layer group, shared coordinates, blank higher detail and Option B: one internal DrawingDocument per floor/detail (2026-11-02).** Transform and persistence contracts remain T-051/T-066 work.

## Invariants
1. Atlas floor identity selects exactly one Drawing **floor layer group**, containing **detail groups**, each containing editable **layers**. Layer-group membership and shared asset references are explicit; Drawing does not know that the group represents a floor.
2. All authored D-levels for a map use **one world-coordinate reference**; no D-specific new origins/canvas sizes or per-hex documents.
3. A D-level can have its own pixel density and independent authored layers. Equal world position means equal map location, not equal raster pixel index.
4. Missing authored high-level artwork renders **blank**, without automatic D0 underlay, ghost image or image pyramid substitution. A blank view is sparse/unallocated until successful authoring.
5. The automatic presented detail can change on zoom; the **edit target** remains frozen for an in-flight gesture. A newly selected target is explicit.
6. A reusable **Object Asset** (T-060) has its own local space; Atlas's **Object Instance** transform maps it into the map's shared world space without redefining D-level coordinates. This object is not the entire map background DrawingDocument.

## Plan
1. Implement the owner-confirmed exact hierarchy **Map → Floor group → Detail group → Layers**. Each Atlas detail-group node resolves **one stable internal DrawingDocument ID**, whose ordinary layers populate that node. Atlas owns map/floor/detail group identity; DrawingDocument does **not** contain those domain types. Define ID stability, group visibility, ordering and lazy lifecycle.
2. Define signed world-coordinate representation, asset-local to map-world transforms and zoom/LOD pixel-density functions. Check precision; Godot default Vector2 has 32-bit components, so consider integer chunk positions + camera-local offsets instead of huge unrebased CanvasItem positions.
3. On automatic detail switch to an uncreated high level, render zero artwork and an **Atlas UI indicator** such as `D1 · empty`, plus explicit navigation/back-to-overview controls. No high-res full image allocated and no implicit lower-art backdrop.
4. Only allocate raster chunks/group content on successful user edit; keep static grid/entrance overlays distinct from artwork, pending T-051 choice on overlay visibility.
5. Test at D0/D1/D32 on overlapping locations, negative and very distant world coordinates, pan/zoom culling, grid snapping, independent detail editing and combined saved project.
6. Validate no scale drift for rotated/resized linked artwork and during global history navigation; add native visual witnesses for blank detail and world alignment.

## Acceptance
One floor = one group; same world positions across all D-levels; blank absent detail is visibly distinguishable from disappeared/lost artwork; no fallback art, no eager blank texture; stable far-world strokes and selection; no Drawing map/LOD imports.

## Round 7 — independent LOD resolution and overlays (approved)
- Each D-level has its own **explicit pixels per world unit** with a sensible **default progression**. Levels share one world coordinate frame. Raster index conversion must be deterministic and documented; density changes must not silently translate existing artwork. Define a deliberate resampling command or lock density after authoring as a separate policy.
- **Missing authored D1 remains blank**, but Atlas **grid lines, entrance markers/hit testing and navigation affordances remain visible**. Separate overlay rendering from artwork data so no lower-detail pixels leak through.
- The logical tree remains **Map → Floor group → Detail group → Layers**. **Option B is APPROVED: exactly one internal DrawingDocument per map/floor/detail.** The DrawingDocument is an Atlas-managed editing/storage unit, not a new user-visible standalone file tab. Its sparse manifest/chunk persistence is tracked under [[T-066]].
- Placed Object Assets may be scoped to specific detail groups; whether a particular instance persists in multiple D-level views is a separate explicit visibility rule. No accidental D0 object artwork fallback into a blank D1.

## Round 8 — materialization and cross-document handling
No per-hex documents: each floor/detail DrawingDocument covers the **entire continuous world surface** in shared map coordinates, allocating raster chunks only where content is authored. An unpainted D1 may exist as a logical ID with no raster files. Atlas can lazy-open the active detail, and should not load every floor's chunks simply to show a collapsed layer tree.

Moving a layer between two detail groups is a **cross-document move** with explicit stable identity policy, both documents updated atomically/transactionally and one Atlas undo entry. Copying a layer may require fresh layer IDs; do not shallow-share its mutable raster chunks. Visible Object Asset instances are separate references; their detail visibility policy remains explicit and independent of the background DrawingDocuments.

## Round 9 — world alignment and larger chunks
Logical DrawingDocument chunk stride will be selected by [[T-067]], not assumed `256`. Larger chunks retain the same continuous signed map-world frame, per-detail pixel density and coordinate transforms. A tile's document-pixel origin must be derived from its versioned stride; negative indices and camera-relative rendering must not shift artwork at tile boundaries. A blank D-level remains sparse with **no allocated tile** until authored. Independently benchmark large tiles for sparse remote marks and lazy viewport memory usage.
