# Asset Browser dock, portable Object folder and NULL placeholders

**Status: IN PROGRESS — browser/discovery engineering checkpoint (2026-11-03).** The owner already required validation of the real keyboard/pointer flows in the original acceptance criteria. The explicit `manual_review: true` gate records that existing acceptance obligation; no approval has been inferred from tests.

## UI behavior
- Provide an **Asset Browser panel** with same docking/tab, resize, show/hide, keyboard focus and workspace-layout behavior as Colors, Layers and History. Do not force a separate top toolbar row.
- List the project's `Objects/` assets with thumbnail, stable asset ID/name/path, saved/unsaved metadata, search/filter, selection, open in Object Editor tab, drag into Atlas as linked instance and explicit import/export actions.
- Show both **in-use** and **unreferenced saved** assets, including a Variant B retained after undo. “Unused” is information, **not** deletion authorization.
- Source Delete must prompt for one of: **Remove all references/placements**, **Keep NULL placeholders**, **Cancel**. Placeholders retain stable object-instance identity, origin source ID and transform while rendering a conspicuous missing-object proxy (GMod-inspired). Support repair/relink manually without guessing same-named assets.
- If an Object Asset contains a child reference to the deleted asset, apply the same policy to nested placements once T-064 is implemented.
- Labels distinguish `Edit Source`, `Save`, `Save As`, and the originating Atlas-instance rebind. The Editor tab stays visually separate from a map instance's transform/selection mode.

## Data/integration
- Scan/resolve `Objects/` relative to campaign root; handle missing directory, changed filenames, broken relative links, duplicate IDs and safe path validation. Lazy thumbnails and bounded cache, with invalidation only when source Save publishes.
- Bundled project fonts should be resolvable by the common Drawing library with stable font IDs; no automatic redistribution of unlicensed system fonts.
- Panel selection is eligible for the app-wide opt-in selection-history behavior (default OFF) if it changes the actual selected Object Asset/instance; pure asset browser focus/hover shouldn't dirty artwork or flood global history.

## Acceptance
Rename/move portable campaign directory and keep asset selection/links intact; open/edit/save variants; inspect retained unused assets; see and deliberately manage NULL placeholders; resize/close/reopen panel like peers; no browser runtime dependency. Owner validates keyboard/pointer flows.

## Round 8 — do not confuse asset tabs with internal map documents
The Asset Browser shows reusable `Objects/` sources, **not** every per-floor/detail DrawingDocument under `Drawings/`. Atlas's map/floor/detail document IDs belong to the Layers/navigation hierarchy and are loaded behind the scene. A user's Object Editor document tab still operates on a reusable Object Asset; Save publishes its source. No new tabs are created just because Atlas activates another D-level.

## 2026-11-03 continuation — bounded thumbnail rendering and save invalidation

The shared `DrawingAssetBrowserThumbnails` resolves each selected/visible
indexed Object source through the canonical `DrawingObjectEditorFile` and
`DrawingRenderer`, without introducing another source registry or Atlas
ownership into Drawing. Thumbnails are transparent, 48×48 RGBA8, retain a
source's actual pixels (including nonopaque regions) and use a bounded
192×192 source sample. For authoring frames larger than that budget the
preview is a **center crop**, not a claim to show the entire infinite canvas.
An absent/empty authoring frame previews a bounded 128×128 neighborhood of
the stored origin; this may be transparent for content drawn elsewhere.

The panel requests only visible rows (maximum 24), resolves at most two new
previews per process frame, drops offscreen `ItemList` textures, and keeps a
24-image, content-SHA-keyed LRU. Refresh preserves unchanged previews and
invalidates changed/deleted sources. Successful **local Object Editor Save**
refreshes a browser pointing at the same `Objects/` root; external file edits
are never silently accepted and require explicit Refresh. Open and thumbnail
reads both revalidate the exact indexed SHA and source identity; neither edits
the Drawing document or publishes asset data.

## 2026-11-03 continuation — explicit portable source copies

The browser's **Import…** and **Export…** actions use filesystem dialogs and
`DrawingAssetBrowserTransfer` for deliberate portable `.drawing` copies.
Import into a standalone `Objects/` root names the new loose source by its
**embedded stable source ID**, never by the incoming filename; after success
the browser refreshes. Export copies only the exact source selected at dialog
open and rechecks its indexed SHA before copying. Both actions reject missing,
non-absolute or unsafe paths, symlinked source files, observed preexisting
destinations, stale bytes, and duplicate/reserved source identities. Neither
action edits the Drawing document, deletes source bytes, or automatically
places an Object in Atlas. File copying uses bounded buffered staging in the
destination directory, hash validation and rename. As with other ordinary
filesystem copies, external concurrent writers require coordination beyond
this UI's pre-rename checks; no cross-process no-clobber guarantee is claimed.

**Critical Atlas boundary:** an `Objects/` root containing an
`*.atlas-object-index.json` registry **rejects standalone Import** instead
of silently creating an unregistered source. Atlas-owned source registration
and instance references require their own campaign transaction and are still
unfinished T-065 integration work. The exported file remains a portable source;
export does not modify the registry. Malformed/ambiguous indexes must be
resolved before import to avoid silently choosing a duplicate stable identity.
The action row wraps at narrow dock widths; buttons remain keyboard focusable.

`drawing/tests/asset_browser_transfer_smoke.gd` now passes **29/29** checks
for lossless copies, duplicate IDs, legacy directories, malformed incoming
files, stale exports, no-overwrite checks, Atlas registry refusal, and actual
panel button callbacks. It is in fast desktop CI. T-065 stays **In Progress**
with `manual_review: true` until the missing Atlas instance/delete/relink UX,
portable campaign handling, and owner acceptance are complete.

## 2026-11-03 continuation — Atlas placement, source deletion and explicit NULL repair

Atlas's own Layers sidebar now exposes **Object Assets and missing links…**
(`Ctrl+Shift+B`), an Atlas-only source manager bound to the active
`AtlasObjectLibrary`. The shared standalone Drawing Asset Browser continues to
own portable folder scanning, dock placement, thumbnails and source file-copy
actions; it does **not** import Atlas instance or campaign types. Atlas's
manager lists each published source with stable ID, revision and actual usage
count, explicitly labels zero-use retained variants, and separately enumerates
NULL instances by original source, map/floor and detail. Edit Source opens the
canonical shared Object Editor; **Place at view center** creates one linked
Atlas instance in the current map/floor/detail, not a copy of the source.

**Source Delete…** presents three real policies: **Remove all references**,
**Keep NULL placeholders**, and **Cancel**. The confirmation captures the
published source's revision, index digest, and all instance generations and
revisions; intervening edits reject the destructive action, requiring a new
confirmation. The NULL choice preserves stable instance identity, generation,
transform, visibility, context and source ID and shows the existing bounded
missing-object proxy. A deliberate **Repair** requires separately selecting
the NULL instance **and** an existing published replacement source ID; it
never guesses by name. Repair is a single atomic registry revision that
preserves geometry and identity and records the first missing source ID as
`metadata.null_origin_source_id` for inspection. The manager rebinds on
campaign load/reset, preventing stale campaign mutations. Source bytes remain
on disk after registry deletion for backup/history and are **not** silently
reimported. This is a flat-reference implementation; nested child placement
policies remain under T-064.

**Evidence:** `tests/object_asset_repair_smoke.gd` passes **48/48** real-disk
checks for stale deletion, NULL recovery, exact placement identity,
publication rollback, paired same-name IDs and fresh portable reopen.
`tests/object_source_manager_smoke.gd` passes **20/20** source/NULL UI action
checks. Both are required by fast push CI. A targeted X11/Mesa native Atlas

**17/17** without screenshot capture (18/18 with capture) for sidebar access, current-location instance creation,

## 2026-11-03 continuation — Atlas-managed portable import and export

Atlas's `AtlasObjectLibrary.import_portable_source()` now registers an explicit
external `.drawing` source into the campaign's **actual**
`Objects/<stable-source-id>/v000001.drawing` revision store and publishes the
corresponding registry index atomically. Unlike the standalone browser's loose
file copy, this path preserves the document's embedded source ID, human-readable
name, local origin and frame. The *campaign revision* starts at 1 even if the
incoming portable file has a later independent revision; that external revision
is not impersonated as a prior campaign publication. No instance is created by
import. Existing registry IDs, reserved revision directories, symlinked
external paths (including ancestors), stale library index hashes, and
malformed sources are rejected. A failed registry publication discards the
unreferenced staged file and empty revision directory, permitting safe retry.
An external writer changing the file during import is detected through
SHA-256 checks before and after source staging; this is **not** a cross-process
exclusive filesystem lease (that wider boundary is T-066).

`export_portable_source()` serializes the selected published revision to a
new standalone Object `.drawing` including the exact source ID, name and
origin/frame metadata. It checks the source/index and an optional expected
revision, does not overwrite existing files, and does not alter placements.
Atlas's **Object Assets and missing instances** manager exposes real
**Import portable…** / **Export portable…** file dialogs, with source ID and
revision frozen before Export opens. The standalone Drawing browser continues
to fail closed for Atlas-managed imports; its file-copy UI is **not** a registry
transaction. These APIs make portable source registration available in Atlas
without mixing Drawing browser ownership with Atlas placement records.

**Evidence:** `tests/object_portable_registry_smoke.gd` passes **33/33**
file-backed import/export, identity/frame, stale-index, reserved-ID, atomic
rollback/retry and portable-reload checks, added to fast desktop CI;
`tests/object_source_manager_smoke.gd` passes **33/33** including actual
manager Import/Export action callbacks and stale export confirmation. The
native Atlas manager witness passes **22/22** with the real X11/Mesa window,
source-list changes and selected-source export. These tests are *engineering*
evidence only; T-065's owner UX approval remains required.

**Still open:** shared Drawing dock-to-Atlas **pointer drag/drop**, unifying the

## 2026-11-03 continuation — shared browser in Atlas and guarded canvas drop

Atlas's Layers sidebar now includes a collapsible **Browse published Object
sources** section using the **same** `DrawingAssetBrowserPanel` and
`DrawingAssetBrowserDragList` as standalone Drawing. The shared `ItemList`
produces a versioned Godot GUI drag token (source ID, published revision,
absolute file path and SHA-256), while Atlas's own `AtlasCanvas` exposes a
native Control drag/drop target. Atlas—not Drawing—checks the token against
the **currently bound** `AtlasObjectLibrary`, its index digest, exact
published path/revision/content hash and source availability. The drop is
placed at the pointer's view-to-document coordinate in the current
map/floor/detail, with a stable linked instance ID and no document-source
copy. The panel offers a keyboard-reachable **Place at view center** action
that passes through the same authorization path. Invalid/forged/stale
sources and drops during an active edit fail closed.

An important authority distinction was discovered and covered by tests:
Atlas's published `asset-*` source ID can differ from the embedded Drawing
file's `drawing-*` document ID. The portable scanner must **not** weaken
its identity rules to accommodate that case. Instead, Atlas builds the
browser's read-only published listing from its authoritative registry,
retaining both identities and checking the embedded file identity when
producing thumbnails and opening the Object Editor. This also displays
registry usage counts (including zero-use retained variants). Standalone
file-copy Import/Export buttons are hidden in this Atlas-hosted panel;
registration, deletion and NULL repair remain the separate Atlas Object
Manager's explicit campaign transactions. The list refreshes on published
source changes; hidden panels defer expensive source work, and the Atlas
listing is bounded to 512 sources for this engineering stage.

## 2026-11-03 continuation — large published-library paging and global search

Atlas no longer truncates its visible source catalog to the first 512 IDs.
`AtlasObjectBrowserPages` filters and sorts **registry metadata** globally,
then requests at most **64 immutable source files per page** for integrity
checks and thumbnail metadata. The shared Asset Browser displays Previous/Next
controls, a page count and the number of matching published sources. Typing in
its existing search box resets to page one and searches names **and stable
Atlas IDs across the entire campaign**, not only the already loaded page.
The page selection clamps safely after a search or campaign change. Hidden
panels still defer source work; the standalone Drawing folder scanner retains
its separate 512-source safety bound. Atlas's registry remains the sole
placement authority: browsing a later page does not relax file SHA, revision,
path, campaign or embedded-document identity checks.

## 2026-11-03 continuation — bounded real-file I/O and revisited-page preview reuse

`DrawingObjectEditorFile.open()` now decodes canonical Drawing pixels and validates
Object-source metadata from the **same, bounded JSON envelope** provided by
`DrawingFileIO.read_payload()`. The former Object-open path parsed the file
twice. Ordinary `DrawingFileIO.open()` uses that same reader, preserving the
existing full canonical tile-digest verification. This does **not** replace
full validation with a metadata-only shortcut: listing, preview, Edit Source,
and Atlas drop still retain the separate hash, registry and identity checks.

The shared 24-image thumbnail LRU distinguishes a complete standalone folder
refresh from an Atlas **partial 64-source page**. It may retain an unmodified
off-page preview across navigation, but discards an older SHA when the same
published source ID returns with changed bytes; switching campaign roots
clears all cached images. The next use still runs `safe_to_open` against disk
before returning a cached preview. The LRU size, visible-only thumbnail work
and frame budget remain unchanged.

## 2026-11-03 continuation — registry-verified metadata-only Atlas listing

Atlas's `scripts/interface/editor.gd::_refresh_asset_browser()` previously fully
decoded the canonical pixels of **every** source in a selected 64-row page to
read only its embedded ID, revision and local bounds. It now calls
`DrawingObjectEditorFile.inspect_metadata()` after the published
`AtlasObjectLibrary.asset_exists()` SHA/path/revision check. The new bounded
JSON inspection verifies the standalone envelope, document ID and Object
source metadata, but intentionally **does not validate canonical pixel blobs**.
It cannot return a `DrawingDocument` and is not a placement authorization.
Actual preview, Edit Source, portable import/export and Atlas drop still use
`DrawingObjectEditorFile.open()` and the existing registry/token checks,
including full canonical tile digest validation. Standalone folder indexing
continues full validation. This reduces the cost of opening a large *page*
without weakening the authoritative pixel-read boundary.

Expanded fast-CI `drawing/tests/asset_browser_real_io_smoke.gd` passes **49/49**
assertions. It verifies matching frame and ID, denial of invalid metadata/
schema, rejection of corrupted pixels by full open (even though untrusted
metadata-only inspection can describe their envelope), and exact tile-seam
rendering. A six-pair alternating diagnostic on one 351,288-byte four-tile
source measured about **163 ms for six full opens vs 27 ms for six metadata
inspections** in this sandbox. This is *not* a release latency or physical
