# Asset Browser dock, portable Object folder and NULL placeholders

**Status: IN PROGRESS — browser/discovery engineering checkpoint (2026-11-03).** The owner already required validation of the real keyboard/pointer flows in the original acceptance criteria. The explicit `manual_review: true` gate records that existing acceptance obligation; no approval has been inferred from tests.

## UI behavior
- Provide an **Asset Browser panel** with same docking/tab, resize, show/hide, keyboard focus and workspace-layout behavior as Colors, Layers and History. Do not force a separate top toolbar row.
- List the project's `Objects/` assets with thumbnail, stable asset ID/name/path, saved/unsaved metadata, search/filter, selection, open in Object Editor tab, drag into Atlas as linked instance and explicit import/export actions.
- Show both **in-use** and **unreferenced saved** assets, including a Variant B retained after undo. “Unused” is information, **not** deletion authorization.
- Source Delete must prompt for one of: **Remove all references/placements**, **Keep NULL placeholders**, **Cancel**. Placeholders retain stable object-instance identity, origin source ID and transform while rendering a conspicuous missing-object proxy (GMod-inspired). Support repair/relink manually without guessing same-named assets.
- If an Object Asset contains a child reference to the deleted asset, apply the same policy to nested placements once T-064 is implemented.
- Labels distinguish `Edit Source`, `Save`, `Save As`, and the originating Atlas-instance rebind. The Editor tab stays visually separate from a map instance's transform/selection mode.

## Data/integration
- Scan/resolve `Objects/` relative to campaign root; handle missing directory, changed filenames, broken relative links, duplicate IDs and safe path validation. Lazy thumbnails and bounded cache, with invalidation only when source Save publishes.
- Bundled project fonts should be resolvable by the common Drawing library with stable font IDs; no automatic redistribution of unlicensed system fonts.
- Panel selection is eligible for the app-wide opt-in selection-history behavior (default OFF) if it changes the actual selected Object Asset/instance; pure asset browser focus/hover shouldn't dirty artwork or flood global history.

## Acceptance
Rename/move portable campaign directory and keep asset selection/links intact; open/edit/save variants; inspect retained unused assets; see and deliberately manage NULL placeholders; resize/close/reopen panel like peers; no browser runtime dependency. Owner validates keyboard/pointer flows.

## Round 8 — do not confuse asset tabs with internal map documents
The Asset Browser shows reusable `Objects/` sources, **not** every per-floor/detail DrawingDocument under `Drawings/`. Atlas's map/floor/detail document IDs belong to the Layers/navigation hierarchy and are loaded behind the scene. A user's Object Editor document tab still operates on a reusable Object Asset; Save publishes its source. No new tabs are created just because Atlas activates another D-level.

## 2026-11-03 partial implementation — portable source listing and dock peer

A **read-only** browser milestone is in the canonical shared Drawing package:
`addons/drawing/asset_browser_index.gd`, `asset_browser_panel.gd`, and the
optional `DrawingWorkspace.show_asset_browser(objects_root)` action. The Window
menu now offers **Asset Browser…** and asks the user to select an existing,
absolute `Objects/` directory; it does **not** infer an Atlas campaign from
`Drawings/` or automatically mutate the project. Atlas hosts may supply
`initial_asset_browser_root` *before* attaching the workspace so the stable
`asset_browser` panel is registered before T-083 layout recovery. Dock
ownership, tab/rail/floating behavior comes entirely from T-078–T-083, not a
second browser registry. When no folder is configured, the original three
workspace panels and document behavior remain unchanged.

- The bounded read-only index scans portable standalone `Objects/*.drawing`
  files and the latest numbered `Objects/<source-id>/vNNNNNN.drawing` files.
  It uses the **document's stable source ID**, metadata name and revision,
  not the filename as a replacement identity. Both linked and unreferenced
  saved files can appear; it does not delete an unused variant. Search is by
  case-insensitive source ID/name, and the source path is visible on hover.
- Invalid/broken metadata, mismatched directory/source IDs, unsafe relative
  roots and symlinked candidate files/directories are skipped or rejected.
  Duplicate published IDs are **suppressed** instead of silently choosing a
  namesake. Selection does not dirty the canvas; **Edit Source** rechecks
  the exact indexed path and SHA-256 content before opening an independent
  Object Editor tab, rejecting stale/overwritten sources with a visible error.
  A failed re-index leaves the last valid listing available for inspection.
- `drawing/tests/asset_browser_smoke.gd` passes **37/37** headless checks,
  including latest-version choice, loose sources, search, stale and same-ID
  replacements, duplicate IDs, portable folder relocation, real dock
  registration and Object Editor tab opening. It is included in fast CI.
  Targeted Godot 4.8 beta 2 native Xvfb/Mesa
  `drawing/tests/asset_browser_native.gd` passes **18/18** checks, including
  scroll-to-panel, real pointer selection and opening, keyboard focus and an
  optional screenshot. It is **not** a substitute for owner UX approval.

## 2026-11-03 continuation — bounded thumbnail rendering and save invalidation

The shared `DrawingAssetBrowserThumbnails` resolves each selected/visible
indexed Object source through the canonical `DrawingObjectEditorFile` and
`DrawingRenderer`, without introducing another source registry or Atlas
ownership into Drawing. Thumbnails are transparent, 48×48 RGBA8, retain a
source's actual pixels (including nonopaque regions) and use a bounded
192×192 source sample. For authoring frames larger than that budget the
preview is a **center crop**, not a claim to show the entire infinite canvas.
An absent/empty authoring frame previews a bounded 128×128 neighborhood of
the stored origin; this may be transparent for content drawn elsewhere.

The panel requests only visible rows (maximum 24), resolves at most two new
previews per process frame, drops offscreen `ItemList` textures, and keeps a
24-image, content-SHA-keyed LRU. Refresh preserves unchanged previews and
invalidates changed/deleted sources. Successful **local Object Editor Save**
refreshes a browser pointing at the same `Objects/` root; external file edits
are never silently accepted and require explicit Refresh. Open and thumbnail
reads both revalidate the exact indexed SHA and source identity; neither edits
the Drawing document or publishes asset data.

**Evidence:** `drawing/tests/asset_browser_thumbnails_smoke.gd` passes
**54/54** with a real RGBA8 source, transparent region, stale replacement,
source-save refresh, and bounded cache eviction. Existing source/dock tests
remain **37/37**; the native X11/Mesa panel, real pointer, floating panel,
thumbnail and screenshot witness now passes **19/19** (20 with screenshot capture).
This headless thumbnail suite is added to the required fast CI; native testing
is targeted. A missing physical hardware/owner UX review is not filled by CI.

**Still open:** linked-instance placement/drop and usage counts, Atlas-registry-aware
source import/export, Source Delete's Remove/NULL/Cancel confirmation and

## 2026-11-03 continuation — explicit portable source copies

The browser's **Import…** and **Export…** actions use filesystem dialogs and
`DrawingAssetBrowserTransfer` for deliberate portable `.drawing` copies.
Import into a standalone `Objects/` root names the new loose source by its
**embedded stable source ID**, never by the incoming filename; after success
the browser refreshes. Export copies only the exact source selected at dialog
open and rechecks its indexed SHA before copying. Both actions reject missing,
non-absolute or unsafe paths, symlinked source files, observed preexisting
destinations, stale bytes, and duplicate/reserved source identities. Neither
action edits the Drawing document, deletes source bytes, or automatically
places an Object in Atlas. File copying uses bounded buffered staging in the
destination directory, hash validation and rename. As with other ordinary
filesystem copies, external concurrent writers require coordination beyond
this UI's pre-rename checks; no cross-process no-clobber guarantee is claimed.

**Critical Atlas boundary:** an `Objects/` root containing an
`*.atlas-object-index.json` registry **rejects standalone Import** instead
of silently creating an unregistered source. Atlas-owned source registration
and instance references require their own campaign transaction and are still
unfinished T-065 integration work. The exported file remains a portable source;
export does not modify the registry. Malformed/ambiguous indexes must be
resolved before import to avoid silently choosing a duplicate stable identity.
The action row wraps at narrow dock widths; buttons remain keyboard focusable.

`drawing/tests/asset_browser_transfer_smoke.gd` now passes **29/29** checks
for lossless copies, duplicate IDs, legacy directories, malformed incoming
files, stale exports, no-overwrite checks, Atlas registry refusal, and actual
panel button callbacks. It is in fast desktop CI. T-065 stays **In Progress**
with `manual_review: true` until the missing Atlas instance/delete/relink UX,
portable campaign handling, and owner acceptance are complete.
