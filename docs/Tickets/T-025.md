# Polygon tool

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 16.

## Acceptance
- Agree vertex placement, closing/editing/cancelling and outline/fill behavior using familiar editor references.
- Distinguish polygon shape/fill interaction from Line and the editable open/closed wall-path tool in [[T-026]].
- Implement accepted interactions with masks, protections, undo and persistence.
- Cover invalid/degenerate polygons without partial document edits.

## Implementation candidate and verification — 2026-10-30

- Implemented the initial point-authored Polygon interaction with click-placed vertices, explicit closure/cancellation, and outline/solid-fill modes. The original prototype stored `AtlasStroke` on Ink; the approved raster-first authoring policy (T-049) supersedes that part of the implementation. See [[POLYGON_WORKFLOW]] for the current contract.
- Added `tests/polygon_smoke.gd` and `tests/polygon_visual.gd` with mandatory CI markers. The present drawing tool commits one raster-layer history command. `AtlasStroke` is transient shape geometry; `filled` metadata remains supported for legacy vector saves and semantic Objects but is not used to persist a drawn Polygon.
- Local verification under Godot `4.8.beta2`: full parser/typing, 37 applicable headless suites, 22 native framebuffer suites, Web release export and four source/exported-pack save checks passed. The final small preview and validation refinements were rechecked with the focused suites. Remote CI and manual usability acceptance remain unverified.
- **Open:** owner must agree to closure rules, solid-fill/no-outline style, raster pixel editing instead of independent whole-shape erasure, and per-pixel scope clipping before checking the ticket complete. No owner acceptance has been inferred from repeated automation prompts.

## Raster-first engineering follow-up — 2026-11-01

- Corrected [[POLYGON_WORKFLOW]] after reviewing the live tool against T-049: Polygon now paints Raster pixels, not a saved Ink object. The old whole-object eraser/selection and all-or-nothing filled-mask descriptions were misleading. Current clipping admits only eligible raster pixel quads; semantic point-editable paths remain T-026.
- Fixed a detached-preview/stored-pixels mismatch: changing Polygon color or width while a pointer remains still previously changed the commit-time stroke without repainting the on-screen draft. The shared shape-style refresh now rebuilds active Polygon previews immediately, while preserving the existing Line live-style behavior and Brush/Eraser press-time capture.
- Added checks for color and width changes without pointer motion, no source mutation before commit, exact detached-preview/painted-pixel agreement for outline and filled modes, and native framebuffer preview/commit consistency. Focused suites now pass **58 headless** and **10 native visual** checks on Godot 4.8 beta2.
- Wider regression results: **45/46 applicable headless** suites passed, with the one previously known `fill_scope_smoke.gd` assertion still expecting an oversized brush candidate to fail rather than be split into bounded segments (T-020). **25/25 native framebuffer** suites passed. Parser/import, main-scene launch, explicit typing, Web release export, all **4/4** source/export-pack save-portability checks, Git LFS integrity, and `git diff --check` passed. Remote CI/browser runtime were not exercised.
- **Status remains open:** engineering evidence cannot substitute for owner approval of the proposed interaction. `docs/Index.md` intentionally stays unchecked.
