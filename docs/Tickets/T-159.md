# Reject signed 64-bit extremes in native publication and history replay

**Split from T-148:** T-158 guards lazy registration/manifest tiles, but
`DrawingDocument._publish_native_tile_edit`, `_replay_native_tile_delta` and
`_replay_pixel_delta_native` still used `abs(signed_coordinate)` for their
Godot projection bounds. On Godot 4.8 beta3 `abs(INT64_MIN)` evaluates to
`INT64_MIN` (an overflowing negative value), so a comparison to the positive
limit can let an impossible signed coordinate through to tile preflight,
source resolution, or native history. This is an input-validation/authority
boundary, not a request to change renderer algorithms or owner UX behavior.

## Acceptance

- [x] Reject out-of-range signed tile IDs before reading sources or constructing
  display dirty rectangles in native Brush publication and native tile replay.
  Both axes, including `INT64_MIN`, `INT64_MAX` and adjacent out-of-range
  coordinates, must use the shared tile projection helper from T-158.
- [x] Reject out-of-range historical per-pixel delta coordinates **before**
  `floor_div` grouping or Rust replay. Use a sign-safe pixel projection check
  with the existing inclusive `±2^52` pixel bound, not `abs()`.
- [x] In a real native Hokusai document, prove all rejected attempts leave
  canonical Rust RGBA8, native Undo token, document revision and surviving
  signed tile pixels intact, followed by exact Undo/Redo; prove a fail-first
  result against the pre-fix Godot sources with the identical fixture.
- [x] Run strict Rust and Godot neighboring native/history/Atlas/Object
  regressions, graphical X11 and 96px witness, validate ticket store and CI;
  document honest software-only evidence without approving T-095.

## Completed 2026-11-16

The two native tile-key boundaries use
`SignedTiles.tile_coordinates_in_projection_range`, while the historical
per-pixel history bridge uses a new
`SignedTiles.pixel_coordinates_in_projection_range`. These helpers compare
positive and negative limits directly and reject `INT64_MIN` / `INT64_MAX`
with no `abs` overflow. The regression was run through the **real Hokusai**
extension, against unchanged source for the fail-first control and again
with the fix. All 39 checks pass after the fix; the same fixture fails four
checks at the two native tile entry points on `INT64_MIN` along both axes
before the fix. Previous Hokusai history and pixels survive every rejection
and continue exact native Undo/Redo.

The final 31-invocation offline Rust/Godot/X11 matrix passed, the ticket
validator reports 159 tickets, and the CI workflow parses. See the raw logs,
summary and SHA-256 manifest under
[`T-159 evidence`](../evidence/T-159-2026-11-16-replay-bounds.md).
This child does not close T-148 or owner-gated T-095.
