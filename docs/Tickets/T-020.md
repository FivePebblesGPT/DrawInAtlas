# Brush tool with familiar editor interactions

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 16; related issues: [[T-010]] and [[T-011]].

## Acceptance
- Agree stroke, width, color/opacity, cursor feedback and gesture grouping against familiar editor references.
- Smooth turns and width-wheel adjustment meet their dedicated tickets.
- Paint crosses board/chunk/hex boundaries normally and obeys a mask when enabled.
- Preserve predictable undo, layer protections and save roundtrips under the representation decision in [[T-028]].

## Implementation and verification — 2026-10-30

The Brush (existing `PEN`) tool now has an explicit Paint.NET-inspired interaction contract documented in [[BRUSH_WORKFLOW]]. The sidebar calls it **Brush (B)**, the inspector permits RGBA alpha editing, and an unsaved high-contrast brush-diameter ring follows the pointer on the active, presented, editable ink/raster layer. T-010 round stroke geometry and T-011 half-unit wheel width remain intact.

New translucent raster paint composites source over destination **once per pixel per completed gesture** instead of blindly replacing RGBA. This retains the previous exact pixels in the undo snapshot, allows separate strokes to accumulate alpha, and respects transformed pixel quads, edit masks, signed chunk ownership and layer protection. Vector strokes retain their own RGBA, width and document-space points. No save schema, migration, alternate brush representation or secondary color was added.

**Verified locally with Godot 4.8 beta2:** 34 headless Brush assertions, 12 native Brush assertions, 33/33 applicable headless suites, 17/17 native suites, Web release export, main-scene launch, parser, explicit typing, and all 4/4 source/exported-pack portability checks. `tests/brush_smoke.gd` and `tests/brush_visual.gd` are CI gates. Remote CI, browser runtime and manual UX acceptance remain unverified; hardness, pressure, spacing and secondary color are not claimed as implemented.
