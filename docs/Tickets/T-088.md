# Selection mask/channel, deselection, clipboard and Move workflow

**Status: In Progress — persistent selected-pixel Move follow-up (2026-11-07), pending owner UX/hardware validation.**

**Owner reference research, not implementation acceptance:** [PhotoCraft 0.20.2 selected-pixel Move and selection combination tests](../PHOTOCRAFT_SELECTION_MOVE_RESEARCH_2026-11-06.md) reports executable-verified 29/29 mask checks, floating selection/multiple moves, empty-selection and command-level drop behavior. The previous implementation committed selected-pixel Move on mouse release; the 2026-11-07 follow-up below replaces it with a persistent detached floating selection and new native pointer/keyboard witnesses. Physical GUI acceptance remains pending. Do not mark these user interactions owner-accepted from command-level evidence.
 Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
The workspace keeps selection as `Rect2i` and displays a rectangle, while `DrawingEditSession.paint_path` accepts an optional mask that the standalone brush does **not pass**. Clicking the canvas creates a one-pixel selection rather than deselecting; Move only works on a prior rectangle and gives little feedback. Owner expects selection to be an independent channel/mask with edit restrictions.

## Engineering tasks
1. Create a Drawing-owned mask/channel selection representation with rectangle marquee as one producer, clear/deselect-on-empty-click and explicit add/subtract/intersect modes (scope Essential vs Later by existing feature inventory).
2. Apply the selection consistently to Brush/Eraser, fill, clear and transforms without leaking Atlas types; preserve transparent pixels and signed sparse tiles.
3. Implement functional Delete, Ctrl+C/X/V, move selected pixels and visible drag preview; define active-layer vs visible-composite copy, paste target and outside-selection semantics.
4. Keep selection-only operations non-dirty by default and optional selection-history recording OFF; content operations produce one undoable document edit.
5. Validate mask boundaries, hidden/locked layers, selection across tile seams and file reopen.

## Acceptance / verification
- [x] Click outside deselects, drag creates intended area; no spurious 1px selection.
- [x] Paint/erase cannot change outside selected mask; Delete/Cut/Copy/Paste/Move produce exact expected pixels and interactive previews.
- [x] Undo/redo restores content plus valid selection/mode context with correct clean/dirty and monotonically increasing revision semantics.
- [x] Native pointer/keyboard roundtrip across zoom, negative tile seams, cancellation and save/open.

## Boundaries
- Preserve the one canonical Drawing package shared with Atlas, byte-exact saved RGBA8, source identity, one undoable content transaction per gesture and signed sparse coordinates.
- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.

## Implementation record — 2026-11-06

**Canonical package (no Atlas forks):** `addons/drawing/selection.gd` now owns a
view-relative boolean selection channel. Rectangle marquee is a producer;
`Replace`, `Add`, `Subtract` and `Intersect` compose islands and holes without
materializing entire rectangle-sized pixel maps. Explicit sparse pixel masks
remain supported. The region `bounds` is an enclosing guide, **not** a
substitute for `allows()`. An **enabled empty selection denies all pixels**,
while a disabled selection permits unrestricted editing; this distinction is
required by Atlas cell masks. The operation tree is capped at 128 and its
small-selection outline is traced at most 4096 source pixels per redraw;
large selections show bounded, color-coded operation guides instead.

**Standalone user actions:** Select tool drag creates the marquee; click
outside an existing channel (or blank without a prior channel) deselects
without manufacturing a 1px selection. Select → Replace/Add/Subtract/Intersect
or its contextual tool option chooses the next drag mode. Select → Deselect
and Ctrl/Cmd+D clear the channel. Brush/Eraser pass the actual channel to
`DrawingEditSession.paint_path`; `fill_rect`, `clear_rect`, `flood_fill` and
`apply_region` already support the same Drawing-owned mask. Delete clears only
selected pixels. Ctrl/Cmd+C copies **the active raster layer only**, not the
visible composite or other layers; Ctrl/Cmd+X cuts those same pixels; Ctrl/Cmd+V
pastes into the active editable raster layer at the copied origin +8,+8 for
each successive paste, then selects the pasted shape. Only pixels allowed by
the captured source mask are eligible; fully zero transparent pixels do not
overwrite destination pixels, but nonzero hidden RGB under alpha zero is
preserved byte-exactly. Paste intentionally is **not clipped by the previous
destination selection** because it positions and selects new content. Locked
or hidden destination layers reject edits; read-only copy of an active raster
layer does not unlock it. The clipboard is in-process Drawing data, not the OS
clipboard or cross-application PNG transfer.

**Move semantics:** Move translates the selected pixels within the *active
layer*, clearing source and pasting selected nonzero source pixels at the
signed target location. A detached `DrawingEditSession` is rebuilt for each
frame's latest pointer displacement and rendered in the true layer order
(including transparent erasure and occlusion) **before mouse-up**. Escape,
tool/layer/document/zoom change, stale revision, or an invalid move cancels
without publication or stranded texture overlays. Content actions commit
one undoable transaction, with detached before/after **full channel** snapshots
in `DrawingHistoryContext`; selection-only changes do not dirty the document,
and optional selection-history capture stays OFF by default. Signed document
identity, RGBA8 hidden RGB, ordinary `.drawing` envelope compatibility and
Atlas map selection are unchanged. A new document never inherits a stale
selection from its predecessor.

## 2026-11-07 correction — persistent selected-pixel floating Move

**Engineering implementation complete in this checkpoint; ticket reopened In Progress
pending physical/owner UX.** The previous *single-drag* implementation committed
on mouse-up. The owner specifically requires repeated repositioning before a
separate Drop/confirm, without undo fragmentation. PhotoCraft's 0.20.2
**command** behavior, not unverified native mouse bindings, motivates this.

- A first nonzero selected-pixel drag now stores the **original source mask,
  revision, and detached preview**. Mouse-up ends that drag but publishes no
  document change. Subsequent drags start from the current floating mask,
  accumulate signed offsets, and rebuild the source-clear/target-paste preview
  from the **original** layer pixels. Distant Add islands and Subtract holes
  travel with the outline; transparent hidden RGB and overlapping signed
  tile-seam moves retain canonical bytes.
- **Drop** is explicit via Enter or Select → Drop moved pixels. Clicking
  outside the floating shape also drops it. Switching tools (including the
  Select mode/selection operation), Deselect, clipboard edits and Save/Close
  first resolve the floating piece, then perform the requested action. One
  publication creates **one Undo step and before/after selection context**
  regardless of how many pointer drags preceded it. A content-identical
  floating selection moves its mask but does not create a dirty pixel edit.
- **Escape** or Select → Cancel floating Move discards the preview and
  restores the original selection and pixels. Ctrl+Z/Ctrl+Y while floating
  cancels rather than undoing a prior unrelated history event. A different
  document/layer, zoom change, direct host selection replacement or stale
  canonical revision also cancels safely, rather than silently publishing a
  stale or wrong-layer delta. Atlas's enabled-empty deny-all mask semantics
  and standalone active-layer-only clipboard boundaries are unchanged.
- The standalone Select menu and status tooltip expose Drop/Cancel, rather
  than relying on an undocumented mouse-release assumption. This is *not*
  evidence that PhotoCraft's GUI uses these exact shortcuts.

## 2026-11-07 engineering checkpoint — sparse transparent clipboard paste

**Canonical status: In Progress; physical/owner acceptance is still pending.**
A large marquee with only a handful of stored pixels previously made each
transparent Ctrl+V scan every position in its entire enclosing rectangle.
`DrawingClipboard.capture()` already retains only nonzero RGBA8 payload pixels,
so `addons/drawing/clipboard.gd::paste()` now iterates those captured keys for
transparent, low-density payloads (less than 25% of the area). It preserves the
source-mask and destination-mask checks, ignores out-of-bounds manually supplied
payload keys and treats fully zero pixels as transparent. Denser payloads and
**all `transparent=false` pastes** keep the previous row-major path, which
must explicitly erase absent/zero cells. A failure on either path restores the
caller's pre-existing edit draft and rebuilds its detached preview. Nothing is
published before the caller commits; Undo/Redo and `.drawing` storage remain
unchanged.

**Independent oracle:** New staged `drawing/tests/selection_sparse_paste_smoke.gd`
compares the optimized path against a separate row-major dense oracle across
16 sparse/dense/opaque/transparent combinations, including destination clipping,
boolean source holes, hidden RGB with alpha zero, signed tile boundaries,
zero values, out-of-range payload keys, partial-failure rollback, source bytes,
preview staging and Undo/Redo. Godot `4.8.beta2.official.cafc17a19` headless
passes **56/56** assertions. The on-demand 51/51 native Xvfb/Mesa T-088
pointer/keyboard/framebuffer witness remains green, alongside the T-096 large
selection, T-085 stroke, T-086 viewport and signed-boundary native suites.
The new oracle is added **inside the existing required T-088 fast-CI step**,
using the strict whole-log checker (no added check IDs). Negative comparison
uses the original pre-change clipboard with the exact same oracle.

**Controlled CPU stage-only comparison:** 512×512 selection, six nonzero
selected RGBA8 pixels, seven transparent-paste trials per run; three paired
runs under Linux headless Godot/Mesa. Pre-change per-run median:
**156,375 / 156,613 / 158,162 µs**; new path:
**43 / 42 / 46 µs**. All six runs passed the same 56 independent checks.
This isolated CPU measurement excludes initial capture, document commit,
texture upload, framebuffer presentation and physical input-to-photon latency;
no general UX speedup or physical acceptance is inferred. Initial capture is
still O(selection area) and requires separate profiling for very large regions.
Owner findings and T-056/T-059 manual-review gates remain unapproved, and
T-088 is **not** marked Done on software evidence alone.

## 2026-11-07 engineering checkpoint — sparse clipboard capture

**Status remains In Progress; physical/owner UX gates unapproved.** The prior
sparse-Paste optimization still paid a full enclosing-area scan on each
Copy/Cut/first floating Move capture. `DrawingClipboard.capture()` now walks
only candidate signed source chunks and their committed nonzero RGBA8 entries,
using existing `raster_may_cover()` metadata to skip absent chunks without
reading their empty pixels. All selected source-mask pixels remain eligible;
boolean holes, enabled-empty masks, hidden RGB under alpha zero, signed tile
boundaries and nonzero Atlas anchors keep their original byte-exact semantics.
Lazy chunks still undergo their canonical SHA-256 validation on access, and
**entirely deselected pending chunks are not loaded**: missing/corrupt selected
sources fail closed rather than becoming transparent. No new clipboard schema,
undo behavior, or public document mutation is introduced. Access to the
canonical sparse tile map is read-only; output retains its own detached copy.

`drawing/tests/selection_sparse_capture_smoke.gd` checks capture against an
independent `read_pixel()`-based dense reference over rectangles, selection
holes/islands, explicit pixel mask, deny-all, signed offsets and >32-bit
Atlas anchors. It also asserts skipped-empty-chunk work, selected corrupt lazy
failures, no-fetch for excluded lazy sources, valid lazy reuse, bounds and
invalid-layer rejections. The new oracle is required in the existing
**T-088** fast-CI check (not a new CI step ID). A controlled negative run with
the previous source traversed **289** chunks and failed the new bounded-work
assertion; restoring the new source passes it.

**Paired CPU-only capture benchmark:** 512×512 rectangle, eight stored pixels,
32px source chunks, seven repetitions on Linux Godot
`4.8.beta2.official.cafc17a19`; previous code median **231,542 µs**, new code
median **611 µs** (~379×). The seven samples measure synchronous capture
only, not native pointer-to-preview, file IO, texture uploads, dense source
performance, GPU/physical Windows/Linux acceptance or hosted CI. Correctness
is independently checked for the same fixture. Owner findings and the
T-056/T-059 review gates remain pending; T-088 is **not** Done.
