# Fail closed on rejected native raster subtree removal

**Split from T-148.** `DrawingDocument.remove_subtree()` could erase Godot
nodes even when Rust rejected a recorded park, an unrecorded retirement or
an unreferenced-layer revision bridge. The document revision would advance
alone, stranding canonical Rust tiles and their history until a destructive
later rebase.

## Acceptance

- [x] Preflight the attached native revision and *full* resident subtree RGBA8,
  including hidden RGB; reject stale/ahead revisions and tampered source before
  changing either tree, dirty map, native tiles or local history.
- [x] Attempt the appropriate reversible park or selective retirement before
  erasure. For never-authorized raster IDs, use a checked unreferenced revision
  before erasure. Any refused bridge, including an active Rust transaction,
  returns a typed failure atomically, rather than silently advancing Godot.
- [x] Preserve valid local structural Undo/Redo, unrelated Rust histories,
  unrecorded retirement, never-authorized layer removal, and native-absent
  alpha-era removal behavior (pending T-150).
- [x] Add a real Hokusai-native regression and pre-fix negative control; run
  Rust formatting/tests/strict Clippy/release build, native history, Atlas,
  Object and graphical witnesses with raw exit logs and checksums.
- [x] Add the regression to required-native CI, update the ABI, T-148 and
  canonical Kanban index. Keep T-149 blocked and T-095 owner-gated.

## Evidence and remaining boundary

See [T-168 evidence](../evidence/T-168-2026-11-16-native-subtree-removal.md)
and its checksummed raw logs. T-168 closes **new native-attached raster subtree
removal**, not the remaining unbridged raster producers, global host-owned
detached history timeline or universal revision authority of T-148. This is
not hardware acceptance or hosted CI evidence.
