# Restore T-068 axis-sweep Geometry2D oracle under native tile history

## Problem

The required fast-desktop `tests/drawing_axis_sweep_smoke.gd` fails
**34/137** checks with Rust-backed Godot 4.8 beta4. Every one of its 34
commits uses a historical `>2^53` signed anchor outside the native tile
projection. When only that anchor is corrected, all 34 commits and geometry
checks succeed, but the fixture still expects the removed per-pixel
`DrawingDelta.after` map on native commits.

## Acceptance — one bounded validation repair

- [x] Reproduce original 34 failures on the actual compiled extension and
      isolate the obsolete history-map assertion at a legal signed anchor.
- [x] Preserve the 320 seeded randomized Geometry2D-to-axis optimization
      parity trials, fractional/reversed endpoints, 4 widths, 34 directed
      and masked sweeps, independent exact pixel predicate, and repeated
      once-covered path checks.
- [x] Change only the fixture's source anchor to a fixed large signed
      native-publishable coordinate with nonzero low bits; assert one
      committed revision and that stage coverage equals the independent
      Geometry2D pixel set.
- [x] Check the entire affected rectangle plus a one-pixel border against
      committed straight RGBA8 after commit, all zeros after Undo, and
      the exact original coverage after Redo, including pixels excluded by
      selection masks.
- [x] Prove that a historical out-of-projection sweep cannot publish any
      pixel or revision; verify the new oracle rejects intentional color
      and selection-mask corruption.
- [x] Run the adjacent native dab, source tile cache, signed publication,
      fill and comparator tests; report unrelated failures rather than
      silently declaring all of T-068 CI green.
- [x] Update index, T-068, and retained evidence. No production raster or
      native-history source changes and no owner-review status changes.
