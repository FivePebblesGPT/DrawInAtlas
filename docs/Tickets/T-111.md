# Line release authorization under mid-gesture target changes

**Parent:** [T-024](T-024.md). **State: Done** for this narrow raster
transaction-safety fix, not for the parent's still-unapproved interaction
choices.

## Problem and scope

T-024's existing Line preview captures map, floor and raster **IDs** plus a
copied selection mask at press. If the original raster becomes hidden, locked,
changes authored detail or is replaced by a new layer resource reusing its ID,
release previously passes `_line_context_matches()` and emits a Line stroke.
That can publish pixels onto an unauthorized target or create an unwanted
history transaction. The Polygon/Wall paths already use the stronger Resource
identity and editability boundary.

## Fix

- Capture map, floor and raster **Resource references**, not merely their IDs.
  On release require the same current layer object to remain editable and at
  the presented detail level; continue comparing the exact copied edit mask.
- Invalidated releases cancel the detached preview, emit the existing
  `line_rejected` guidance, and publish **no** `stroke_requested` event or
  Undo entry. A restored target can immediately start a fresh Line.
- Do not alter endpoint, brush-width, modifier, color, grid-snapping or
  saved-pixel policy. No new persistent schema, native binary or owner-facing
  preference is introduced.
