# Enable automatic artwork-layer LOD by default

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 3, clarified by the user as **artwork-layer LOD**.

## Acceptance
- A fresh session automatically presents the appropriate artwork detail while zooming.
- Provide an understandable disable/inspection control, with its behavior defined by [[T-004]].
- Do not implement this ticket merely by switching the existing automatic linked-document navigation flag on.
- User-facing naming distinguishes detail levels from floors and ordinary editable layers.
- Visibility/detail transitions operate on separately authored content and preserve an explicit editing target, including during strokes and transforms.

## Implementation (2026-10-30)

- `scripts/navigation/artwork_lod.gd` (`AtlasArtworkLOD`) builds an availability
  index of *visible, non-transparent authored artwork pieces* at D1…D32 for the
  active board/floor. It uses canvas-space coverage and separate entry (0.65)
  and exit (0.45) ratios, not the detail numbers as zoom multipliers. Separate
  stroke/tile/raster bounds avoid treating disconnected areas as one filled
  detail region. D0 remains the baseline for unpainted regions.
- `AtlasEditor` starts with `automatic_artwork_lod = true` independently of the
  existing opt-in `automatic_navigation` for linked maps. It reevaluates after
  panning, zooming, resize, undo/redo and artwork changes, and rebuilds when the
  current map/floor changes. `AtlasMapNavigator.MAX_ZOOM` increases to 24 to
  let small hexes become useful local detail without changing board coordinates.
- Layers UI distinguishes *presented artwork detail* from *editing layer
  detail*: default-on "Automatic artwork detail (zoom)" checkbox, disabled
  manual view-detail spinner until auto is switched off, and a conspicuous
  `Viewing D… · Editing … (D…, hidden)` status and "Show editing layer detail"
  action. Choosing that action disables automatic presentation for inspection.
  Selecting a detail for presentation does not retarget edits or alter artwork.
- Canvas emits `interaction_finished` and tracks held terrain-paint gestures;
  automatic transitions are deferred through strokes, selections/transforms,
  drags, shapes and paint gestures. Existing hidden-target edit protection
  remains enforced. No floors, linked-map traversal or document ownership are
  changed, and no save schema migration is required.
