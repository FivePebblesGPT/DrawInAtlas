# Guard Save, Object publication and active-tab closure against pending Brush edits

**Done — bounded engineering scope (2026-11-15).** A released Brush stroke
is still a detached, uncommitted `DrawingEditSession` during its bounded
frame-by-frame drain. The document can report clean throughout that interval.
Before this change, **Save** and the FileDialog callback serialized that stale
clean document; **Close Tab** could immediately remove the tab and cancel its
pending pixels. This is a reproducible data-loss risk, not an owner UX policy
choice. T-124's queued successor makes that window longer, but did not cause
the underlying problem.

## Contract

- [x] Introduce a read-only Canvas predicate for outstanding Brush transactions,
      including the bounded deferred successor; do not auto-commit, reorder,
      discard or synchronously flush expensive raster work on Save.
- [x] **Save**, **Save As…**, FileDialog completion, and Object Editor source
      publication fail closed while pixels remain uncommitted; preserve the
      existing destination bytes and provide an actionable visible error.
- [x] **Close Tab** of the active document cannot treat an uncommitted edit as
      clean and destroy it. Other (nonactive) tabs and the existing clean/
      dirty-close safeguards retain their prior behavior.
- [x] After the normal Brush commit completes, Save, portable file reopen,
      Object publication, dirty-close confirmation and clean close resume
      normally. If a pending Save-and-Close chain is refused, clear its
      stale close intent so a later independent Save cannot unexpectedly
      close the tab.
- [x] Add a real Godot persistence witness, red on the original code and
      green on the fix; check complete RGBA8 roundtrip, queued second stroke,
      active-tab closure and Object publication. Run strict logs, neighboring
      regressions, Python/CI contracts and ticket-store validation.

The same canonical `addons/drawing/` code is used by standalone Drawing and
Atlas/Object Editor. No persistence format, synchronous GUI drain, native
backend default or owner review gate is changed. Users must repeat Save/Close
after the stroke visibly finishes; intentionally deferring the *request* rather
than persisting an incomplete snapshot is left to a future UX decision, not
silently attempted here.
