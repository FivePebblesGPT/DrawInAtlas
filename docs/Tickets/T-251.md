## Acceptance

- [x] When **expanded**, retain the **same screen-edge/dock-relative position**, but allow an overlay *within the dock* because sufficient width prevents icon collision. No canvas overlay or change in the apparent anchor when toggling.
- [x] At both sizes and while animating/toggling, hit boxes never overlap the group marker, panel icons, canvas or flyout; mouse, focus/keyboard navigation, tooltips, 100/150/200% UI scaling and small windows work.
- [x] Test expanded ⇄ minimized toggles with floating and grouped panels, frame captures and real X11 pointer events; persistence, scrolling, drag thresholds, standalone and Atlas embedding continue to pass.

## Engineering completion — 2026-11-22

Replaced the canvas-side, root-owned T-222 overlay with **one stable**
`DockEdgeToggle` control. In the minimized state its parent is the first
`DockToggleSlot` within the `DockIconRail` VBox; a 48×56 flow slot physically
pushes all rail icons downward. In the expanded state the same button is
reparented to `PanelDock` as a top-level overlay at the **same dock-relative
origin**; a 34px left-only horizontal `MarginContainer` gutter and fixed 226px
expanded dock width floor prevents all
scrolling panel buttons, group markers and picker controls from reaching its
30×56 hit rect. Neither state overlaps the canvas. During re-render, the
rail-slot child is preserved rather than destroyed; the button keeps tooltips,
focus and its `pressed` handler. Deferred focus restoration is necessary when
Godot reparents the focused button (caught by the new Enter-key regression).
No secondary toggle, alternate panel view or document mutation was added.

[Local native evidence](../evidence/T-251-2026-11-22-dock-toggle.md) includes
actual X11 events, framebuffer captures, 420px/narrow and 150–200% simulated
UI scaling, group floating, restart persistence, embedded Atlas and neighboring
T-079/T-222/T-223/T-224/T-225/T-083/T-091 acceptance regressions.
**Only T-251 engineering is Done**; T-250 is still Blocked, T-083 and T-059
manual owner UX gates remain open. Software-rendered X11 cannot substitute
