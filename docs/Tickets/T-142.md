# Retain shared selection contour tiles across an in-window focus pan

**Done — 2026-11-15; bounded renderer continuity only.** T-140 correctly
invalidated a full 4096-tile outline cache when the camera focus moved inside
an unchanged selection window. However, it erased *all* cached contours, even
when the old and new focal priority plans shared almost all their tiles.
With a four-new-contours-per-frame budget, this could make a distant, already
visible selection island disappear for hundreds of redraws after a one-tile pan.

## Acceptance

- [x] When the visible selection tile window changes, invalidate the entire
  contour cache as before. A deselection, changed mask, or new document also
  continues to invalidate its cached outlines.
- [x] On a saturated 4096-candidate focus change **within the same tile
  window**, discard only cached contours outside the new eligible plan.
  Preserve existing contours for overlapping tiles; newly prioritized tiles
  still honor the four-new-contours-per-frame budget and 4096 cache ceiling.
- [x] Preserve under-cap selection behavior, exact selection authorization,
  deterministic camera-first candidate order, signed coordinates, raster
  pixels and document Undo/Redo.
- [x] Demonstrate a failing unchanged T-141 negative control and passing
  headless and real X11 framebuffer witnesses. Verify the far selected island
  remains visibly outlined after pan without prepopulating its replacement.
- [x] Run T-139–T-141 model and native regressions, T-088 clipboard/sparse,
  T-096 large-selection/Move, strict log verification, an independent native-
  absent Drawing consumer, explicit typing, Python/CI contracts and ticket
  validation. Integrate in the existing **46-check** required fast-CI step
  and on-demand native selection workflow, without introducing a new check ID.

[Commands, raw negative/positive logs and limitations](../evidence/T-142-2026-11-15-outline-cache-continuity.md).

## Scope and review boundaries

This preserves rendered **selection overlays**, not raster pixels, source
history, or selection-mask semantics. The test deliberately primes a valid
settled over-capacity cache to avoid requiring more than 1,000 preliminary
render frames. The observed retained-contour count is a deterministic test
result, **not** a claimed input-to-photon latency or physical UX benchmark.
T-088 stays **In Progress**, T-096 stays **Manual Review**, and the owner,
reference-hardware and hosted CI gates remain unchanged.

## Subsequent refinement (2026-11-15)

The original acceptance above deliberately cleared every cached contour
when the *visible tile window* changed. T-145 later supersedes that specific
policy: per-tile source-coordinate contours shared with the newly eligible
plan are safe to retain across a window shift. This does not revise T-142's
historical completion evidence or T-088/T-096 review gates.
