# Decide the ink representation

## Source
[[ManualReview_2026-10-30#Code review|Code review]], item 1: why is `AtlasInkLayer` an array of strokes instead of a raster image?

## Acceptance
- Explain actual responsibilities and costs from code, not the previous rationale alone.
- Compare raster, vector and justified hybrid approaches against painting quality, erasing, selection/transforms, fill, memory, undo and native saving.
- Obtain an explicit representation decision; do not switch formats merely because the question was raised.
- Create scoped implementation/migration follow-ups if the decision requires changes, including preservation of existing artwork.

## Investigation and owner decision

- Source-level ownership, costs and representation trade-offs are documented in [[INK_REPRESENTATION_DECISION]]. Includes comparisons for painting quality, erasing, selection/transforms, fill, memory, history and native saving.
- A dedicated read-only semantic regression, `tests/ink_representation_smoke.gd`, records current vector/raster semantics and ownership; it does not benchmark rendering or change source artwork.
- **Original recommendation (superseded by approved priority):** keep typed vector ink alongside chunked RGBA8 raster layers. The owner approved **raster-dominant authoring**, retaining vector primarily for specialized editable semantic objects. This keeps both typed representations but changes the expected default editing workflow. Representative performance and usability acceptance still need evidence.
- **Owner approval — 2026-10-31:** raster is primary for ordinary painting; vector is primarily for editable wall paths, shapes, lines and text. No all-raster flattening or artwork migration is authorized or needed. See [[INK_REPRESENTATION_DECISION]] for the precise policy, current implementation gaps and follow-ups. The separate raster-first UI implementation is [[T-049]], and [[T-018]] still needs owner usability acceptance. **Decision ticket accepted:** mark T-028 checked in [[Index]], but do not claim the editor has switched its defaults yet.
