# Reduce remaining 96px full-gesture latency after native source-lookup hoisting

**Motivation:** T-189 consistently improves native tile application and staging
CPU, with exact real-native pixel/history/Save/Open parity; the pooled unchanged
100-event rapid full-gesture p50/p95 is still **282/390ms cold** and
**273/281ms warm**. Cold tail and 54% frame/release-to-settled results are
mixed, so the **250ms milestone and 200ms stretch** remain unmet. See
[measured T-189 evidence](../evidence/T-189-2026-11-17-native-source-read.md).

## Scope — one independently measurable next change

- Re-evaluate the dominant remaining native costs (roughly **50ms Hokusai
  raster**, **20ms fixed-point RGBA scan**, plus script input draining and
  release/settled display), using the recorded per-phase trace; do not optimize
  a speculative candidate or repeat the measured T-189 source lookup work.
- One bounded fail-first native **and graphical** improvement with repeated
  reversed-order same-source/binary A/B, including rejected runs. Do **not**
  change Hokusai-only rasterizer, 96px/512² 100-event sample geometry, the
  6ms soft input-drain deadline, preview visibility, source/commit/history
  semantics or sample retention to meet the threshold artificially.
- Preserve signed coordinates, selection/masks, partial-alpha/hidden RGB,
  source identity, frozen/queued/cancel/floating gestures, native Brush/Eraser,
  Undo/Redo, real Save/Open and bounded memory. Repeat the exact complete
  `total_to_postdraw_ms` cold/warm p50/p95 and 250/200ms target checks.
- Report stage CPU and native phases, first preview, postdraw frames and
  ≥83.33ms fractions, backlog, release→commit and release→settled, exports,
  requested uploads, peak RSS and source hashes. Physical/owner input-to-photon
  acceptance remains separate under T-095.
