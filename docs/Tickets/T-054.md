# Drawing-local history with Atlas global cross-map navigation

**Status: PLANNED.** Owner confirmed **global history** in Atlas and **navigate to originating map A** on undo.

## Plan
1. Define stable Drawing edit transactions recording asset/layer IDs, before/after data or deltas, immutable expected revision and atomic commit/preview/cancel state. Do not require AtlasCampaign.
2. Give the standalone editor a document-local history and dirty/savepoint; Atlas injects a history coordinator/adapter so embedded Drawing cannot also independently record the same edit.
3. Atlas global history commands store **originating map ID, floor-group ID, authored-detail ID and optional camera/edit focus** as well as target Drawing asset ID. This is essential for a live shared asset visible in more than one map.
4. When Ctrl+Z reverses an edit originally made on map A while user views map B, first reverse canonically and navigate/focus A by the approved T-051 rule. Navigation caused by history playback is **not** a new undoable command; guard against re-entrant edits and stale scene IDs.
5. Resolve redo symmetry, deleted-map origins, map/link deletion ordered around artwork changes, and whether a stored camera can still be safely restored. Do not silently ignore invalid target context.
6. Regression coverage: paint shared asset on A/view B -> undo updates both visible references, lands on A; copy asset -> no mutation of original; undo after floor/detail switching; one gesture/one entry; no dirty on rejected edit.
7. Benchmark layer snapshot copying separately; no mandatory optimization or network protocol as part of refactor.

## Acceptance
Drawing-only history requires no Atlas; Atlas has precisely one ordered history; cross-map undo shows origin; shared asset edits are reversed once for all references; navigation never pushes another history entry; stale target is handled deterministically.
