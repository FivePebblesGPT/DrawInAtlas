# Keep Atlas context handlers stable during reserved history operations

**Bounded T-148 child.** T-245–T-248 reserve Atlas's command timeline,
notifications, and active map. However callers could still assign
`AtlasEditHistory.context_provider` and `context_restorer` (including via
`Object.set`) from synchronous context capture, command apply, `changed`
observers, or Undo/Redo restoration. The same command could therefore capture
before/after UI state through different providers or silently replace the
restorer that handles an already-published command.

## Acceptance

- [x] Reject direct and reflective callback replacement while the host
  timeline is reserved or replaying, without changing the previously installed
  callback or adding a nested command.
- [x] Preserve ordinary idle handler configuration, legitimate failure cleanup,
  chronological Undo/Redo, and synchronous context/warning behavior.
- [x] Cover real Atlas-owned native Drawing publication and transparent hidden
  RGB without changing Rust's raster or history ABI.
- [x] Reproduce the bug against old code, run neighboring standalone/Atlas
  regressions, and pin an exact-count test to required fast CI.

## Completion — 2026-11-22

`tests/t249_atlas_context_handler_reservation.gd` fails **42/84** checks
against the preceding history implementation, and passes **84/84** with
getter/setter guards that leave both handlers configurable between operations.
Ten neighboring history/selection/Atlas suites pass, including T-245–T-248,
real native tile history, and detached recovery. The separate 70-command
