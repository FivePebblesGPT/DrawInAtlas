# Preserve unpublished Brush input against Undo/Redo history mutations

**Done — bounded engineering corrective work (2026-11-15).** Following
T-124–T-126, released or queued Brush/Eraser pixels remain detached until
frame-budgeted staging finishes. Workspace Undo/Redo previously operated on
the last **committed** transaction during this interval, incrementing the
`DrawingDocument` revision. On the next process frame, Canvas rejected its
pending `DrawingEditSession` as stale and cancelled both the unfinished
stroke and any queued successor. This could silently discard delivered
input even though Save and document switching were already protected.

## Contract and verification

- [x] Guard workspace **Undo** and **Redo** against an outstanding Brush
      session *or* T-124 deferred successor, before any committed history
      mutation or floating-selection policy. Preserve the old history cursor,
      exact committed pixels, source revision and detached input when blocked.
- [x] Reuse the existing user-visible pending-stroke refusal; do not
      synchronously flush, auto-commit, or change history semantics. All menu,
      Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z and History-panel actions share these guards.
      Explicit Escape remains available for intentional cancellation.
- [x] Once the pending strokes publish normally, allow chronological Undo and
      Redo again; verify distinct transactions and byte-exact RGBA8 after
      Undo/Redo, portable Save and reopen. A new commit after a prior Undo
      still replaces that older redo branch as usual.
- [x] Reproduce the failure on unmodified T-126 (20 failed assertions out of
      40), then demonstrate **40/40** in Godot 4.8 beta3 with strict logs.
      Run neighboring Brush, navigation, Open and independent Drawing
      consumer regressions; retain the existing 46 required CI IDs.
