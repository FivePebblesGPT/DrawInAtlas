# Restore T-124 queued Brush/Eraser regression under required native Hokusai

## Scope and acceptance

The previously Done T-124 contract was still exercised by required CI, but
its headless test compared four native queued Brush/Eraser source transactions
against the retired GDScript `DrawingEditSession.paint_path` rasterizer. The
baseline failed **12/69** assertions, exclusively in full-image RGBA8 parity
and the first Undo/final Redo comparisons. Such a mixed-engine pixel comparison
cannot validate native queue correctness.

- [x] Replace only the obsolete oracle with a separate sequential **native**
      Hokusai Canvas/document. Replay the **actual delivered** source points
      and receipt timestamps, frozen original Brush width/pigment and queued
      Brush/Eraser settings, and the exact complex selection mask.
- [x] Repair the separate raw-pointer native-X11 fixture: after native
      batching improvements, its 190-point first release no longer held a
      pending session. Route 840 real events to retain a deferred press, then
      capture exact source/time samples (including Godot's extra release
      sample), verify canonical bytes against the same native reference,
      framebuffer pigmentation and two Undo/Redo steps.
- [x] Test both release-before-promotion and held-until-promotion paths for
      Brush and Eraser, without inserting a parallel native transaction into
      the queued production Canvas. Assert two separate atomic history steps,
      byte-exact after publication, both Undo steps, and both Redo steps.
- [x] Require the second stroke to change actual pixels; capture all source
      input and release events with no omissions, and include a changed-width
      Hokusai reference that **must** produce different bytes.
- [x] Preserve bounded sample-overflow, visible error, rejected predecessor,
      selection-hole, navigation-after-release and source-authority checks.
      Do not modify painting production code, native Rust, timing budgets,
      CI marker names or owner-review gates.
- [x] Reproduce baseline fail-first, repeat headless and native-X11 tests,
      preserve exact raw process logs and exits, validate neighboring smokes,
      Rust/Python/lint, and ticket Kanban state.

## Evidence and limits

[Detailed test commands and raw log integrity](../evidence/T-206-2026-11-19-native-queue-oracle.md).
The repaired suites pass **78/78 checks in four headless and 20/20 in three
raw-pointer software-X11 runs** with required native Hokusai. `tests/test_t124_queued_stroke_ci.py`
continues to guard the existing CI marker and now rejects regressions to
`paint_path` as a native pixel oracle. This is a **test-oracle repair**, not a
change in source painting, performance, physical input latency or user-visible
behavior. The reference shares the same native engine; it validates queue
sequencing and parameter freezing, not independent brush artistic accuracy.
