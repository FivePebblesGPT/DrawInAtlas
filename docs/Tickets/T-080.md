# Reorder panel tabs and form, split or move dock groups

**Status:** Done — engineering verification 2026-11-03, following T-079. Only this ticket was implemented. [Agreed docking specification](../DRAWING_DOCKING_SPEC.md).

## Scope

- Pointer drag and keyboard-accessible equivalent to reorder panel tabs **within a group**, move one tab between groups, split a tab into a new dock group, and reorder whole groups in the vertically stacked dock.
- The corresponding right-side rail icons and separators update to mirror the final group/tab order. A group remains a tabbed unit; never interpret adjacent icons as unrelated flyouts.
- Draw alignment/insertion hints while dragging, including before/after member tabs, between groups and merge-into-group targets. Only commit on an accepted drop; invalid drops, Esc and loss of focus roll back without dropping any panel.
- Keep group identity, active tab and collapse state stable or explicitly apply documented transfer semantics. Expose the reusable drag/target model for T-082; do **not** ship floating container UI or cross-host reparenting here.

## Acceptance

1. Native drag tests reorder a multi-tab Colors/Swatches/Gradients group, create a second group and merge it back, verifying tabs/icons/separators are the same ordered structure.
2. Boundary and scrolling cases cover top/bottom insertion, narrow dock, HiDPI, collapsed group, tab-strip overflow, and keyboard focus.
3. Esc/invalid target/cancel after showing an alignment hint returns the **exact** original layout model and visible ordering. No duplicate panel ID, stale signal connection, orphaned group or accidental canvas paint.
4. Existing Drawing/Object Editor operations and the T-079 flyout suite pass.

No owner gate for this engineering stage. The same drag semantics must be reusable by [T-081](T-081.md) and [T-082](T-082.md).

## Implementation and evidence — 2026-11-03

- `addons/drawing/dock_drag.gd` (`DrawingDockDrag`) supplies a reusable transactional drag planner for T-081/T-082: panel/group source, typed tab/group/merge targets, **nonmutating** model preview using a restored trial layout, one atomic commit, explicit cancellation, conflict detection against the originating snapshot, and generated collision-free group IDs. It reuses **the exact T-078 `DrawingDockLayout`** rather than registering a second panel or fabricating view copies. Intra-group tab moves, cross-group tab moves, split-to-new-group, group reorder and merge-group actions use the existing invariant-checked model methods.
- `addons/drawing/workspace.gd` provides a visible, focusable group drag handle; each real panel icon is a draggable tab; flyout tabs and minimized rail icons also expose the same drag input. In-app `DockInsertionHint` shows tab slots, group-before/after markers or merge targets **only while a destination is valid**. A short-window edge hold scrolls the dock during drag, and horizontal `ScrollContainer` tab strips make many members reachable in a narrow dock. No OS window or canvas gesture is created by a drop.
- Expanded group **⋮ Arrange** menu offers tab left/right, transfer to previous/next group, split active tab, move group up/down, and merge adjacent groups. On focused tabs, `Ctrl+Alt+Left/Right` reorders, `Ctrl+Alt+Up/Down` moves to neighbor groups, `Ctrl+Alt+S` splits. On focused group drag handles, `Ctrl+Alt+Shift+Up/Down` changes group order. All commands go through the same transaction planner. Drag previews do not select a tab or mutate the model; Esc, invalid drop, window focus loss and intervening model mutations abort instead of committing. After a valid drop, rendering uses the original panel Controls and current model order to regenerate grouped icons/separators.
- `drawing/tests/dock_drag_smoke.gd` passed **60/60 model checks**: insertion at both extremes, tab reorder, split/remerge, group order/merge and stable member order, separators, exact full-snapshot rollback after cancellation or invalid target, and stale-drag rejection without overwriting external changes.
- `drawing/tests/dock_reorder_native.gd` passed **68/68 native X11/Mesa Godot 4.8 beta 2 checks** including actual pointer press/motion/release, preview line, split/merge and whole-group movement, Esc and window-focus rollback, invalid canvas drop, 420px narrow workspace, 1.5× content scale, collapsed groups, auto-scroll at dock edges, horizontal tab-strip overflow, accessible focus and keyboard actions, preservation of unique view Controls and unchanged Drawing revision/dirty state. A framebuffer image of the noncommitted tab insertion hint was inspected; a screenshot is **not** an owner UX approval.
- The T-079 native flyout suite **40/40** and T-078 model **82/82** pass after changes. Standalone Drawing package, Object Editor, Atlas composition, native T-063 and keyboard regressions are recorded with the task handoff; deferred legacy native/Web suites remain untested, and T-059/T-056/T-083 owner reviews are still open.

**Out of scope:** In-app floating hosts (T-081), cross-container drag/drop and reparenting (T-082), persistent workspace layouts and final owner UX review (T-083). T-081 is the next Ready ticket; do not infer manual approval from these checks.
