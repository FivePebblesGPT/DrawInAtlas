# Reorder panel tabs and form, split or move dock groups

**Status:** Blocked on T-079. [Agreed docking specification](../DRAWING_DOCKING_SPEC.md).

## Scope

- Pointer drag and keyboard-accessible equivalent to reorder panel tabs **within a group**, move one tab between groups, split a tab into a new dock group, and reorder whole groups in the vertically stacked dock.
- The corresponding right-side rail icons and separators update to mirror the final group/tab order. A group remains a tabbed unit; never interpret adjacent icons as unrelated flyouts.
- Draw alignment/insertion hints while dragging, including before/after member tabs, between groups and merge-into-group targets. Only commit on an accepted drop; invalid drops, Esc and loss of focus roll back without dropping any panel.
- Keep group identity, active tab and collapse state stable or explicitly apply documented transfer semantics. Expose the reusable drag/target model for T-082; do **not** ship floating container UI or cross-host reparenting here.

## Acceptance

1. Native drag tests reorder a multi-tab Colors/Swatches/Gradients group, create a second group and merge it back, verifying tabs/icons/separators are the same ordered structure.
2. Boundary and scrolling cases cover top/bottom insertion, narrow dock, HiDPI, collapsed group, tab-strip overflow, and keyboard focus.
3. Esc/invalid target/cancel after showing an alignment hint returns the **exact** original layout model and visible ordering. No duplicate panel ID, stale signal connection, orphaned group or accidental canvas paint.
4. Existing Drawing/Object Editor operations and the T-079 flyout suite pass.

No owner gate for this engineering stage. The same drag semantics must be reusable by [T-081](T-081.md) and [T-082](T-082.md).
