# Zoom-out, cache-budget and large-layer viewport stress

**Parent:** [T-086](T-086.md). **State:** Done (2026-11-12). This ticket has its own independently verifiable outcome; it does not inherit the parent’s remaining manual/device acceptance.

## Problem
T-086 still lacks bounded-memory and real-device results for large dense documents and zoom transitions.

## Bounded implementation / research
Stress sustained zoom/pan with multiple dense/transparent layers, 25–100% view and memory pressure; refine the display-tile LRU/LOD and full-tile texture upload policy based on evidence, not a hypothetical partial `ImageTexture.update()` API.

## Acceptance and evidence requirements
Run repeated real input/viewport captures with p50/p95/max frame delay, cache occupancy, RAM and texture bytes; preserve exact pixels and invalidation after edit, navigation, masks and source Save. Separate Xvfb software evidence from reference Windows/Linux hardware.

## Existing evidence / starting point
[T-086 source-space cache history](History-T086.md).

## Scope boundary
Change only this deliverable; keep canonical straight RGBA8, signed source coordinates, layer/mask semantics and atomic Undo/Redo where relevant. Preserve the existing T-094 fail-closed CI log policy. Record actual commands, exit codes, raw failure controls and source SHA. Do not treat Xvfb/Mesa engine callbacks as physical input-to-photon timing.

## Implemented and bounded outcome (2026-11-12)

- `DrawingCanvas._focal_retention_plan()` derives the nearest **144 occupied source-aligned 128px display tiles** once per oversubscribed committed viewport frame. The stable signed-key tie breaker keeps the working set deterministic across repeated camera positions. Scanning has a hard 4,096-candidate/65,536-window limit and falls back conservatively for unknown occupancy, active previews and unreasonable viewports. The `9 MiB` persistent texture budget and source-space geometry are unchanged.
- On a cache miss, a prepared list of nonpreferred victims replaces per-miss full-cache distance scans. Evicted textures stay referenced for the remaining draw so a still-visible tile can be submitted *without redundant recomposition*, even when displaced before raster traversal reaches it. A transparent tile that retires a victim earlier is skipped safely. Over-budget transient tiles **still render completely in the same frame**, with full-tile `ImageTexture` uploads; no speculative partial-update or lossy LOD is introduced.
- New **13-check** headless planner oracle and **150-check real X11** pointer/viewport witness cover signed center/corners, 192 lazy source tiles plus translucent overlay, 25/50/100% zoom and real wheel/middle-pan events, 18 sampled frame delays, cache/RAM/texture telemetry, exact source SHA, visibility, selected/masked Brush, hidden RGB, Undo/Redo, and standalone Save/reopen. The exact pre-T-103 Canvas fails the added focal-plan controls while preserving original source parity.
- Two earlier comparable 18-frame software trials measured **240.95–243.89ms original vs 202.82–232.82ms candidate draw p50** (baseline controls exclude a new planner check); initial cold draws varied from seconds, and per-frame transient work still costs hundreds of milliseconds. An updated real-wheel fixture produced original **269.88ms** vs candidate **233.04ms** p50 and cold draws **6.20s** vs **3.87s**, but this is not a controlled hardware latency guarantee. Retained cache stays at 144 × 64KiB = **9MiB**, peak OS process memory is ~1.1GiB, and ephemeral in-frame references can reach **12MiB**. Different runs do not show a reliable RAM reduction.
- Complete command, test, red-control and measurement boundaries: [T-103 evidence](../evidence/T-103-2026-11-12-overbudget-retention.md). The existing 46-check fast-CI inventory gains the 13-check oracle **inside** `ci_t086_viewport_cache_model`; the on-demand native workflow requires the strict marker and all 150 graphical assertions while preserving raw logs.

**Not closed:** T-086's reference Linux/Windows hardware, full cold 25%-zoom stall, physical input-to-photon latency and hosted Actions are unverified.
