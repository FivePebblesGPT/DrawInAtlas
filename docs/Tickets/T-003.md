# Align transparent detail previews with the hex overlay

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 1.

## Work
Replace the floating opaque-picture experience with correctly registered detail on the continuous board. Decide which compositing/detail presentation is appropriate after the canvas/LOD contract is established.

## Acceptance
- Detail is aligned to its actual board/hex position and remains registered while panning/zooming.
- Transparent regions do not acquire an unintended opaque rectangle.
- Preview framing/zoom represents the relevant detail rather than a detached arbitrarily scaled picture.
- Verify adjacent hexes, grid rotation/scale, chunk seams and empty detail; do not reintroduce a separate document per hex.

## Implementation and acceptance evidence — 2026-10-30

Completed the **registered preview** treatment without changing document
ownership or introducing one document per hex:

- **Spatial child references** use their actual placement footprint and the
  existing child-to-parent transform. Both inspector preview strengths now draw
  *on the board* with source alpha preserved (faint 35%, overlay 70%). Camera
  pan/zoom applies the ordinary board transform; rotating/resizing a grid does
  not rebase either layer artwork or registered previews. The default is the
  aligned overlay rather than an arbitrary thumbnail floating next to a hex.
- **Spatial parent references** retain the existing rotated/cropped mapping,
  with transparent background capture. Reference opacity is applied once during
  compositing; the source document is not edited. The read-only capture uses
  a private, input-disabled viewport and suppresses grids, link markers, and
  recursive previews. The preview cache has an alpha-specific audience key.
- **Unregistered/symbolic links** keep their discoverable on-board markers and
  map-browser/overview preview panels, but do **not** claim a fabricated
  alignment or display a detached image on the editing board. Their preview
  budget/capture cost is zero.
- **Read-only preview panels** can request an explicit authored `D0…D32`
  level (default `D0`), and now fit the visible artwork **of that level only**.
  Sparse raster chunks are cropped to the alpha-used area, accounting for
  negative chunk coordinates and layer transforms. Empty levels show the
  neutral empty preview instead of framing other detail levels or an arbitrary
  96×64 thumbnail. Cached captures are partitioned by detail level.
- Actual separately authored detail layers are still rendered directly from
  the **same shared board coordinates**, never transformed per-hex. The
  existing presentation selector remains explicit; automatic LOD and zoom
  transitions are T-005, and retiring/migrating old battlemat/linked-document
  workflows is T-012/T-014/T-015. This change does not silently convert a
  legacy independent map into an authored detail group.

### Repeatable checks

- `tests/aligned_detail_previews_smoke.gd` — 20 checks: rotated/translated
  hexes, adjacent cells, D0/D1/D2 bounds, sparse raster alpha and signed
  seam coordinates, registration through pan/zoom/grid edits, transform/UV
  corners, and unchanged edit-target identity.
- `tests/aligned_detail_previews_visual.gd` — 15 native framebuffer checks:
  source alpha at clear and painted pixels; overlays over an intact underlying
  board; panning, zooming, and grid changes; empty detail capture; D1 artwork
  continuity, with PNG witnesses under `user://validation/`.
- The existing native `references_ui_smoke.gd` (46 checks) now enforces
  marker-only symbolic links, spatial faint/strong previews, parent reference
  freeze/opacity/source-floor behavior, cache/cancellation, and edit isolation.
  Existing `preview_ui_smoke.gd` (31 checks) still validates read-only panels
  and asynchronous cancellation/invalidation.
- Godot **4.8.beta2**: resource import/parser and explicit typing check passed;
  20 headless suites and seven native framebuffer suites passed; Web release
  export passed; all four source/exported-pack portable-save checks passed.
  Added both new suites to `.github/workflows/godot-check.yml`.

**Limits:** Remote CI and human usability acceptance are not claimed. The
non-spatial legacy previews remain available in the search/map preview area,
not on the editing canvas. The LOD driver, navigation zoom ceiling, and
battlemat migration have separate open tickets.
