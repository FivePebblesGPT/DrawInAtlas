# Reject Text Apply after detachment from the registered campaign/map/floor

**Parent:** [T-027](T-027.md). **State:** Done for this narrow source-ownership
boundary only. T-027's separate modal control, font, readability and owner
interaction acceptance remains unapproved.

## Problem

The Text modal already freezes the original map/floor/Objects-layer Resource
pointers and exact cell edit scope. However, a host can replace or remove the
map from `AtlasCampaign.maps`, replace/remove its floor, or change campaign
ownership while Canvas retains the original pointers. A text draft may then
publish against a Resource no longer authorized by the live campaign,
possibly creating an Undo command and changing hidden/stale text.

## Bounded implementation

- Capture the exact `AtlasCampaign` Resource when the modal opens and clear it
  on dismissal, along with the existing map/floor/layer/scope snapshots.
- Before Apply, require the Editor and Canvas to still share the captured
  campaign, and require that campaign's registered map and that map's
  registered floor be the exact originally captured Resource instances.
- Continue checking layer identity and the selected-cell mask exactly as
  before. Rejecting an invalid Apply leaves the dialog visible with the typed
  draft and an explicit error, without adding history or writing content.
- A legitimate edit and unrelated map changes still work with single-step
  Undo/Redo. No text schema, persistence format, shortcut policy, text style,
  screen-space culling threshold or manual-review status is changed.
