# Frame-safe Brush input draining and held-preview scheduling

**Parent:** [T-095](T-095.md). **State:** Done (narrow scheduler change; **not** T-095 owner/device acceptance).

## Delivered

- Keep **all** source-space input samples, the original 24px interpolation cap, the 8,192-pixel estimated atomic batch cap and the unchanged **6ms soft drain deadline**. This avoids the long raster-stage spikes of the rejected 30ms drain-budget and larger-staging-batch trials.
- Under an active backlog only, aggregate at most **two separate drain calls** into one dirty-preview display submission, with a **20ms monotonic deadline** and immediate submission whenever the queue empties. Isolated dabs and held-pointer pauses render immediately. Drawing and input stage measurement still use the earliest pixel-changing stage/receipt. Commit and cancellation clear the scheduler.
- The 100-event 96px full-red native pointer witness now reports draw/callback p50/p95/max, depth/age and retains its independent 512×512 source/framebuffer/Undo checks. Its opt-in **110 changed preview frame** oracle fails on the old scheduler (160 frames), passes on the new scheduler (79–81). Native on-demand workflow runs this oracle plus a new **46-check** real-pointer held-preview/signed-mask Brush/Eraser/Undo/navigation/cancellation witness, fail-closed and with both raw logs retained.

## Acceptance evidence

[Paired baseline, red control, source hashes, exact commands, strict exits, and limitations](../evidence/T-099-2026-11-12-held-preview-scheduling.md).

Four same-host software trials (two cold processes, two strokes per process) produced **158–160 → 79–81** dirty-preview draws while retaining all **100 pointer receipts and 296 raster segments**. Whole-gesture wall time ranged **5.03–5.84s → 4.16–5.29s**, and cumulative compositor CPU **1.36–1.50s → 0.76–0.89s**. Receipt→preview frame p95 ranged **3.54–4.09s → 2.85–3.55s**. These are Xvfb/Mesa engine-CPU observations, not a physical pointer-to-photon measurement or proof that the aspirational 100ms target is met. A single candidate trial hit a **76.6ms** raster drain outlier even with unchanged atomic batching; do not represent the 6ms **soft** budget as a hard maximum or infer reference-device frame safety from local sample counts.
