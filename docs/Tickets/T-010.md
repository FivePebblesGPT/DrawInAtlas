# Remove sharp artifacts at pen turns

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 8.

## Acceptance
- Reproduce the reported turn/join artifact with native pointer input.
- Determine whether sampling, stroke geometry, joins/caps or rasterization causes it.
- Correct it without changing intended stroke width, color/opacity or selection-mask behavior.
- Verify slow/fast strokes, tight turns and undo/save roundtrips; align the final behavior with [[T-020]].

## Implementation and verification — 2026-10-30

**Root cause (reproduced):** `AtlasCanvas._draw_stroke()` drew one
antialiased polyline *and* another translucent circle at every pointer
sample. Each overlap applied the source alpha again; a quick right-angle
turn was substantially brighter than its straight leg, while densely
sampled slow strokes were dark throughout. This is a rendering overlap,
not a flaw in document-space input sampling, stored stroke points, or
native save serialization. The native-pointer reproduction was run before
fixing the renderer and failed at the fast corner.

**Fix:** Render open pen paths as a single constant-width filled silhouette
with round caps and joins (`AtlasStrokeGeometry`). Consecutive duplicate
and sub-0.01-unit samples are discarded **only for rendering**. Single
taps render as a single antialiased circle. Source stroke points, width,
color, transparency, undo grouping, clipping and native-save schema are
unchanged. For closed/looped paths where the geometry library returns
multiple contours (potential holes), keep the previous polyline renderer:
CanvasItem's polygon fill cannot cut interior holes and must not silently
fill a rectangle or loop. This fallback is a known presentation limitation
for such paths, not a change to their artwork or persistence. The broader
Brush tool review remains [[T-020]].

**New regression gates:** `tests/pen_turns_smoke.gd` checks round geometry,
slow/fast/tight turns, duplicate samples, width/cap bounds, mask inset and
preserved alpha, one-gesture undo/redo, and native scene save/reload.
`tests/pen_turns_visual.gd` uses native X11 pointer events for slow, fast,
hairpin and single-tap strokes. It samples the real framebuffer for
uniform turn opacity, verifies undo/redo and proves a closed rectangle
retains its hollow center. Both are wired into the GitHub Actions workflow.

**Local evidence (Godot 4.8.beta2.official.cafc17a19):** parser/import and
explicit-type audit passed; **25/25** headless suites and **12/12** native
framebuffer suites passed, including **49** new headless checks and **12**
new native checks. The Web release export, clean main-scene launch and all
**4/4** source/exported-pack native-save compatibility checks passed.
Remote CI and manual usability acceptance have not been performed.
