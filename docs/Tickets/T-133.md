# Guard standalone window close against pending strokes and unsaved tabs

**Done — 2026-11-15, bounded application-lifecycle safety.** T-125 protected
File → Close Tab against unpublished Brush input; T-132 protected asynchronous
Save As against another tab. Neither handled the standalone operating-system
window-close notification. The default `SceneTree.auto_accept_quit` could still
terminate Drawing with an uncommitted Brush/Eraser transaction or dirty tabs,
bypassing the existing Save/Discard/Cancel workflow altogether.

## Engineering acceptance

- [x] Only the **standalone top-level Drawing workspace** disables automatic
      OS quit; restore the original SceneTree setting on teardown. Embedded
      Atlas workspaces must never assume ownership of the host quit policy.
- [x] A window-close notification during a detached or queued Brush stroke
      must refuse quitting, preserve its input and source revision, and display
      the existing actionable pending-stroke error. The same request can be
      retried after the ordinary frame-budgeted commit.
- [x] Process every saved/dirty standalone tab through the existing Close Tab
      semantics: clean tabs close, dirty Drawing/Object tabs get explicit
      Save/Discard/Cancel, cancelled Save As aborts quitting, and a later
      retry resumes without stale closing authority. A successful Save As is
      completed against its original tab before advancing.
- [x] Open FileDialog only **after** hiding the close confirmation; neither
      dialog may try to become an exclusive child while another remains open.
- [x] Add a focused headless lifecycle witness, an equivalent native-X11
      scripted notification witness, Python source/CI contracts and strict
      log checks under the existing required T-085 check (46 IDs unchanged).
- [x] Verify pending Brush and Save As regressions, Object Editor, standalone
      and explicit types; validate the entire canonical ticket store.
