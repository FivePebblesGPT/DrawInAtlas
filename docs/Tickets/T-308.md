# Restore Object Editor background and standalone asset drag/drop

## Owner finding — 2026-11-25
Asset Browser lists contents, but Object Editor lacks a background and objects cannot be dragged onto the canvas.

Source: [PR #23 hands-on review](../DRAWING_UX_REVIEW_2026-11-25.md). This is a standalone Drawing correction; no dependency on the T-250 Atlas acceptance gate. Historical completed tickets remain valid for their narrower scope.

## Scope
Reproduce on actual standalone Drawing/Object Editor; restore the visible transparency/canvas background consistent with ordinary documents, not an opaque paint mutation. Support Asset Browser drag/drop into an eligible Drawing canvas with valid source identity, placement coordinates, visible preview and canonical reusable-object semantics. Reuse existing safe source authorization, cycle checks and link/copy rules; never invent implicit copy or bypass Atlas registry. Keep Atlas-specific acceptance under T-065/T-064/T-108.

## Acceptance
- [x] Native pointer drag from browser into ordinary Drawing and eligible Object Editor canvas; verify visual placement, stable source identity, history, Save/Open and cancellation/invalid targets.
- [x] Reject self/cyclic nesting, unsafe paths, stale source and locked/hidden targets without partial state changes; if a standalone placement policy is not defined, resolve with existing documented contracts before implementation.
- [x] Inspect actual background, drag feedback and drop result; verify shared Atlas surface without requiring T-250 approval for foundational Drawing fix.
- [x] Record fail-first functional evidence where applicable, neighboring regression results, and actual visual inspection for UI changes in accordance with AGENTS.md. Update the ticket and Index; no owner signoff is inferred from engineering completion.

## Implementation and evidence — 2026-11-25

- Restored display-only transparency checker for unbounded Object tabs and finite Object frames, shared by standalone and hosted Drawing. Ordinary Drawing frame behavior is unchanged.
- Native Asset Browser row drag offers an authenticated source token, with thumbnail offset from the pointer and cyan destination frame/coverage outline. On release, a checked model transaction reauthorizes the source graph and inserts one named semantic Object layer with a stable source ID and signed integer anchor; no copied pixels or embedded paths. Escape/focus loss and invalid targets cancel. Reopening resolves against the explicitly chosen catalog; Undo/Redo preserves records and source identity. Browser Refresh and successful local Save update dependent views and invalidate nested thumbnails.
- Standalone policy: only a flat explicit `Objects/` root, not an Atlas registry or immutable revision directory. Hidden/locked destinations, stale tokens, unsafe paths, self/cyclic nesting, and ambiguous indexes reject before mutation. The graph is bounded to 64 links/document, depth 8, 128 expanded visits and 128 MiB source bytes; resolution is synchronous and point-in-time, not a filesystem lease. Unresolved graphs display NULL and refuse raster export. Save linked local Objects directly in the authorized catalog; nested Save As, single-source transfer, generic linked subtree transfer and Atlas import fail closed pending explicit graph-aware link/copy policy. Atlas registry placement/child-editing contracts and acceptance remain separate. See [workflow](../OBJECT_ASSETS_WORKFLOW.md) and [standalone usage](../../drawing/README.md).
- Fail-first counterfactual with pre-T-308 workspace/canvas: native drag starts but does not publish the expected link (exit 1). Initial full test exposed Escape not cancelling and sparse tile-size feedback; fixed and re-rendered. The final `make test-object-drop` target with Godot 4.8 beta4 + mandatory native Rust extension, X11/llvmpipe, passed 40/40 standalone and 12/12 hosted, with strict log checks. Standalone covers native pointer placement/cancellation in ordinary and local Object tabs, RGBA8 render and signed origin, atomic history, Save/Open, locked/hidden and stale sources, nested resolution/thumbnail invalidation, NULL/export rejection, cycle/forged path/registry rejection. Hosted covers actual checker pixels, source digest and Atlas history, and rejection of implicit standalone registry adoption.
- Adjacent smoke checks: asset browser 79, transfers 43, thumbnails 62, T-109 32, discovery 56, Object UI 26, pending metadata 21, semantic import/removal fences, Atlas assets 95, Object Editor 45, child graph 56, child render 36, portable registry 33, Atlas browser model 32, native Atlas browser 12, raster export model 55; clean assertions/exit, thumbnail fixture rerun after import cache rebuild. Python documentation/identity 16/16 and explicit typing passed. New target wired into on-demand T-090 CI.
- Real screenshots captured and opened: `object-background.png`, `object-drag.png`, `object-placed.png`, `object-nested.png`, `object-atlas.png` (separate from commit bundle). Cyan outline and offset thumbnail are visible during drag, then exact blue artwork appears at the signed destination. Checkerboard is visible in empty and hosted Object tabs. Physical GPU/Windows, large graph latency, hosted CI and owner acceptance remain unverified. T-059/T-250 retain independent gates.
