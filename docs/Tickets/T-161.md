# Reject signed 64-bit extremes at public gesture, viewport and image anchors

**Split from T-148.** T-159/T-160 made the native publication and replay
boundaries sign-safe, but three public entry points still compared
`abs(signed_anchor)` against the older inclusive `±2^60` document limit:
`DrawingDocument.begin_edit`, `DrawingRenderer.render` and
`DrawingRasterImport.import_image`. Godot 4.8 beta3 evaluates
`abs(INT64_MIN)` as the negative overflowing value, so the old guard
admitted the invalid negative extreme. The viewport also added a caller
supplied origin and a signed Rect2i offset *before* validating the origin:
`INT64_MAX + 1` wrapped to the same undetected `INT64_MIN`.

## Acceptance

- [x] Compare both signed axes against the existing inclusive `±2^60`
  document anchor range using one dependency-free helper; reject signed
  64-bit minima/maxima and the adjacent out-of-range values without `abs()`.
- [x] Validate the renderer's signed 64-bit origin before adding its 32-bit
  viewport offset; verify the translated origin again. Never allow an
  overflowing addition to wrap into a permitted coordinate.
- [x] Reject invalid image-import and gesture anchors before allocating
  transactions or changing document/native tile source. Preserve valid
  historical non-native inclusive endpoints and ordinary image Undo/Redo.
- [x] Prove the old behavior fails against the same real-native regression,
  with unchanged Rust history tokens, committed RGBA8 and dirty state.
- [x] Run pinned Rust checks, neighboring native/detached/Atlas/Object and
  signed-coordinate Godot suites, software-X11 Canvas and 96px Hokusai
  witnesses; integrate the regression into required-native CI. Synchronize
  ABI docs, Kanban and ticket validator. Do not approve T-095's owner gate.
