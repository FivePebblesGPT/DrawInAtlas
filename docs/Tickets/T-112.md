# Verify Atlas Line and Polygon Save/Open against the portable campaign format

**State: Done** for this narrow regression repair. The parent Line and Polygon
user-interaction approvals are separate and unchanged.

## Defect and scope

`tests/line_smoke.gd` and `tests/polygon_smoke.gd` call the live Atlas Editor's
`_on_save()`, which publishes the generation-indexed portable project from
T-066. But both tests then called the retired one-file
`AtlasCampaignStore.load_campaign(path)` and assumed the Editor had written
`campaign.scn`. Thus both failed on Godot 4.8 beta3 even though the current
portable Save/Open is supported. These failures cannot be ignored as passing
save regressions, and reverting the production writer would break T-066.

## Fix and evidence

- Check the real Editor's successful-generation status and load the saved
  project with `AtlasCampaignStore.load_portable_result(path)`.
- Compare exact campaign metadata and raster RGBA chunk dictionaries before and
  after Save; require a real portable root and **no** legacy one-file head.
- Verify an Undo after Save does not change the independently loaded published
  generation. Existing preview, masks, density/detail and history checks stay.
- Run both authoring suites with exact success markers, 120-second watchdogs,
  raw logs and T-094 strict log policy in the existing Atlas composition CI
  step, retaining 46 required check IDs.

[Reproduction, red/green logs and validation](../evidence/T-112-2026-11-12-atlas-portable-authoring-roundtrip.md).

This updates the **tests and CI only**. No Save format, persisted data, input
policy or application runtime behavior changes. It is neither hosted CI evidence
nor the owner approval required by T-024/T-025 and related UX gates.
