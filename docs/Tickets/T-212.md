# Preserve the required-native Linux distribution on packaging failure

## Scope and acceptance

T-201's package helper validated the *final* export only after publishing
`addons/drawing/native/bin/libdrawing_brush.so`. A missing/invalid PCK or an
unexpected extra binary rejected the distribution but left the newly installed
library and directories behind. The failure was not atomic.

- [x] Reproduce both original tests failing with the unmodified package code:
      invalid content leaves a native library and injected post-install
      validation failure leaves a second native artifact.
- [x] Reject malformed ELF/PCK, extra artifacts and symlinks **before**
      writing anything into an invalid distribution. Inspect a disposable
      complete export projection with the exact staged native ELF, keeping
      the authoritative `inspect_distribution` strict.
- [x] Roll back only a newly installed native library and directories if
      final inspection fails unexpectedly. Never replace a different existing
      library or remove any existing successful exported artifact.
- [x] Preserve performance for large PCKs via same-filesystem hardlinks for
      the candidate ELF/PCK, with a cross-device native-source copy fallback.
- [x] Verify source and published native SHA-256, clean exported ABI launch,
      Python release/portability tests, Rust native tests, Ruff, ty and
      ticket-store gates. Retain fail-first and positive raw logs.

## Evidence and boundaries

[Commands, zero-exit real beta3 PCK/native launch, fail-first controls,
source hashes and test matrix](../evidence/T-212-2026-11-19-native-export-atomic.md).
The repair changes only release packaging and its test fixture. No painting,
history, pixels, Godot integration ABI, LFS payload, or persisted save schema
was modified. No official release-template binary, Windows DLL/export,
GitHub-hosted CI success or physical-device acceptance was established. Those
remain separate T-180/T-105/T-106/T-150 gates.

## Subsequent exact-tree hardening — T-213 Done

[T-213](T-213.md) closes a separate path-enumeration gap: empty unexpected
directories and special filesystem nodes were not counted as files by the
T-212 preflight/final inventories. They are now rejected before native ELF
publication, with both Linux and structural Windows checks. The official
export and owner acceptance gates remain unchanged.

## Subsequent owned-temporary cleanup hardening — T-214 Done

[T-214](T-214.md) prevents the T-212 `finally` handler from deleting a
pre-existing file or symlink named after its historical `.so.tmp` staging
path when strict preflight rejects the export. New exclusive staging files
are the only ones cleaned up; aborted copies leave no residue. This does not
close the broader release, hosted-CI, or manual review gates.
