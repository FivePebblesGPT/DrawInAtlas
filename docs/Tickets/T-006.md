# Put drawing tools in a categorized sidebar icon palette

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 4.

## Acceptance
- Add a drawing-tools sidebar tab using the existing sidebar's categorization model.
- Replace the large text selector with a compact grid of tool icons and descriptive tooltips.
- Keep active-tool state, shortcuts and relevant settings discoverable and synchronized.
- Demonstrate native pointer/keyboard use and compact-window layout; preserve space for the drawing board.
- Use Paint.net as the primary tool-interaction reference while retaining the requested categorized sidebar layout.

Coordinate tool semantics with [[E-TOOLS]] and general icon treatment with [[T-007]].

## Implementation (2026-10-30)

- Added a **Tools** activity in the existing resizable/collapsible sidebar, with
  compact 42 × 42 icon buttons in four named categories: Draw & Erase, Shapes,
  Select, and Map & Terrain. The ten existing canvas tools remain available,
  including legacy map authoring tools pending their separately tracked removal.
  Individual vector icons, tool descriptions and shortcut hints are present in
  hover tooltips and accessible button names.
- `AtlasToolPalette` emits tool choices to `AtlasEditor`; the canvas remains the
  tool-state authority. Pointer selection, `B/E/V/F/L/R/O` shortcuts, and
  programmatic tool requests all converge through `_on_tool_changed`, which
  refreshes the highlighted icon, inspector active-tool label, and the
  applicable ink, terrain, selection, or placement controls. Selection does
  not unexpectedly switch sidebar tabs. The old visible text `ToolPicker` has
  been removed from the right inspector rather than duplicating state there.
- This ticket deliberately **does not** revise pen/selection/fill behavior or
  introduce the general compact-icon changes of [[T-007]]. Tool semantics remain
  owned by their individual [[E-TOOLS]] tickets; the legacy battlemap control
  remains until [[T-014]].

- `tests/tool_palette_smoke.gd`: **53/53** checks passed, including a single

  synchronization and keyboard/programmatic changes.
- `tests/tool_palette_visual.gd`: **21/21** Xvfb/Mesa framebuffer checks
  passed. Native pointer clicks and a real keyboard shortcut changed tools;

**Acceptance boundary:** Native input and layout checks are automated, not a
manual usability sign-off. Remote CI has not run here; tool-specific Paint.net
interaction refinements are still separately ticketed.
