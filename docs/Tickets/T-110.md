# Byte-exact UTF-8 authorization for portable Object sources

**Parent:** [T-065](T-065.md). **State: Done** for the independent,
source-validation boundary; the parent still requires owner-device UX review.

## Problem and scope

Godot's `PackedByteArray.get_string_from_utf8()` replaces malformed byte
sequences with U+FFFD and continues parsing otherwise valid JSON. T-109
indexed the SHA-256 of the *raw bytes* but decoded a potentially different
Unicode value into the source ID/name. An invalid early file could suppress a
valid duplicate ID, and a standalone Import could copy malformed source bytes
into `Objects/` even though a later hardened index should reject them.

## Implemented

- After bounded byte capture, require UTF-8 decode→encode equality **before**
  accepting any source for the portable browser index. Keep the existing
  `HashingContext` hash of that exact captured buffer and full canonical
  `DrawingObjectEditorFile.decode_payload()` validation. Invalid sources
  remain warnings, not partial authorized entries.
- On Import/Export's captured copy path, apply the same byte condition **before**
  creating the `.pending` file. Reject invalid incoming sources with
  `SOURCE_UTF8` without modifying the destination or the selected snapshot.
  Keep the existing digest, path, capacity, and atomic-staging checks.
- Existing valid multibyte Unicode names and exact SHA-256 source bytes remain
  supported. No change to file schema, native binary, owner-visible policy,
  upload size cap or the `46` required fast-CI check IDs.

## Verification

[Evidence, paired diagnostic scans and red/green raw logs](../evidence/T-110-2026-11-12-lossless-portable-utf8.md).
The exact T-109 files fail **7 of 20** new real-filesystem assertions (process
exit 1), including index admission, duplicate suppression and malformed Import.
The candidate passes **20/20**, with process exit 0 and strict success-marker
checking; neighboring T-065/T-109 tests and ticket-store validation are
recorded separately. The 512-source scan comparison shows **no demonstrated
speedup**; additional UTF-8 validation may increase CPU and transient memory.
