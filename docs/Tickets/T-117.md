# Reject Wall Path operations detached from the registered campaign/map/floor

**Parent:** [T-026](T-026.md). **State:** Done for the independently testable
source-identity authorization fix. T-026 remains Ready pending the separate
owner decision about vertex insertion/movement/deletion, styling, whole-path
edit-mask behavior and additive persistence of editable paths.

## Defect and bounded fix

Wall Path construction and vertex movement already froze a layer Resource and
exact edit mask at first vertex or drag start. Release checked Canvas map/floor
pointers, but not whether those Resources remained registered in the original
campaign. A same-ID/byte map or floor replacement, removal or campaign switch
could therefore publish a path command under a stale authorization.

Capture the campaign Resource along with the existing map/floor/layer and mask.
All held preview, vertex-drag and commit pathways now require the same
campaign owner **and** registered map/floor Resource identities. Invalid
operations clear the detached preview and context, emit `wall_rejected` once,
and leave artwork and history unchanged. New immediate insert/delete/restyle
operations require their *current* map/floor to be registered; they do not
inherit an obsolete captured gesture. A newly registered campaign is allowed
to authorize a fresh direct edit independently of an old, rejected draft.

No path geometry, Save/Open schema, mask coverage algorithm, renderer,
shortcut, styling model or owner-facing UI decision changes. The pre-existing
T-026 manual acceptance remains an independent gate, expressed here as a
`related` ticket rather than falsely blocking this narrow correction.

pass), including same-ID map/floor replacements, registry removal, old-campaign
loss, draft and drag rollback, direct mutations, unrelated-map changes, valid
Wall commands and byte-exact Undo/Redo.

The existing 20-check graphical Wall Path test and scoped Line, Bucket,
Polygon and Atlas composition suites pass with strict logs. The historical

old and new code; those are **not** counted as passing. The new test is added
to the existing T-055 CI check without increasing the 46-check required
inventory. Local beta3/Xvfb tests do not prove hosted CI or physical-device
usability and do not approve T-026's remaining decisions.
