# Document what non-obvious fields encode

## Source
[[ManualReview_2026-10-30#Code review|Code review]], item 6.

## Acceptance
- Document non-obvious units/coordinate spaces, packed layouts, ownership, mutability and invariants at their declarations.
- Distinguish canonical fields from caches, viewer state and derived values.
- Prefer clear names and concise field-level explanations over comments restating obvious types.
- Review high-risk artwork/editing/model fields, including the modules named in [[T-033]], [[T-034]], [[T-035]] and [[T-036]].

## Implementation and verification — 2026-10-30

Completed this as a **field-encoding documentation pass**, not a behavior or
readability refactor. Declarations now state non-obvious units, ownership,
mutability and invariants where future editors will encounter the fields:

| Area | Clarified field contract |
| --- | --- |
| `scripts/artwork/` | Board-unit stroke vertices/width and text-size reuse; layer ID and authored D-level identity; signed 256-pixel chunk coordinates, sparse `"cx,cy"` keys, RGBA8 ownership and encoded-vs-decoded storage; raster local-to-board transform and density; indexed terrain palette. |
| `scripts/campaign/` | Cell-index versus board-unit grid geometry, radians and native distance metadata; display grid versus historical terrain grid; ordered floor/layer ownership; legacy placement conversion and source/target link coordinates; canonical map registry. |
| `scripts/editing/` | Transient selection indices and stale-source checks, board-space edit-mask polygons, relative clipboard positions, detached fill results, history state identities and dirty checkpoints. `fill.gd`, `raster_brush.gd`, `selection_geometry.gd` and `stroke_eraser.gd` explicitly identify pixel/board conversions and geometry inputs without preempting T-033–T-036. |
| `scripts/interface/`, `scripts/navigation/` and `scripts/persistence/` | Camera and gesture units; derived GPU render nodes, authored-detail bounds, preview caches and ephemeral view sessions; pending-fill isolation; native root integrity digest versus canonical map Resources. |
