# Prioritize occupied outline tiles for bounded, over-capacity explicit masks

**Done — 2026-11-15, bounded rendering correctness only.** T-140 prioritizes the
camera for irregular/oversized contours but traverses *empty* tiles when a
positive explicit mask contains more than 4096 occupied 64px tiles. A selected
island farther than the first 4096 empty camera-centered candidates can remain
unoutlined even though the mask itself authorizes its pixels.

## Acceptance

- [x] For positive, operation-free explicit masks containing **at most 8192
  pixel dictionary entries**, enumerate exact visible `true` occupied tiles
  (deduplicated, source bounds/viewport clipped) even if there are more than
  4096 distinct tiles. Keep at most 4096 candidates, prioritized by distance
  from camera focus; integer ring buckets and stable within-ring order avoid
  a global GDScript comparator sort each frame.
- [x] Preserve the historical exact small-mask row order. Retain the T-140
  camera-first conservative fallback for >8192 raw pixel entries, inverted,
  compound, or unknown selection forms; preserve the four-new-contours-per-
  draw and 4096 retained contour limits. Do not alter mask truth or RGBA8 data.
- [x] Reproduce the original omission against unmodified T-140 in headless
  and real X11 framebuffer tests, including a 16px selected island, signed
  coordinates, camera changes, duplicates, false entries and fallbacks.
- [x] Run neighboring T-139/T-140 models and native witnesses, T-088
  clipboard/sparse and T-096 large-mask/Move tests, strict logs, independent
  Drawing package consumer, explicit typing, Python/CI and canonical ticket

[Commands, failing controls, actual software framebuffer and limitations](../evidence/T-141-2026-11-15-occupied-overflow-outlines.md).

## Limitations and review

Exact occupied-tile priority is intentionally capped at 8192 input mask keys,
not a complete renderer for arbitrary giant inverted/compound selections.
At most 4096 occupied contour tiles can remain visible simultaneously, and
this is software-GPU correctness, not an input-to-photon latency result or
physical owner approval. T-088 remains **In Progress**, T-096 remains
**Manual Review**, and hosted CI/owner gates stay unchanged.
