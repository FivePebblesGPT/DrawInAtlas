# Editable text with screen-space culling

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 16.

## Acceptance
- Text remains editable after placement and after save/load; editability is confirmed rather than a pending alternative.
- Agree placement and font/size/style controls, using Paint.net as the primary interaction reference except where persistent editability requires an explicit extension.
- Cull text when its on-screen font size becomes unreadably small. Choose the screen-space threshold through a focused visual check; do not tie readability to a fixed world-space size.
- Culling changes rendering only: retain the text content, style, position and editability, and show it again at a readable zoom.
- Keep text editing distinct from global drawing shortcuts.
- Accepted text respects the layer/object model, selection and transforms.
- Verify undo, saving and readable display across relevant detail levels.

## Implementation candidate — 2026-10-30

- Implemented a dedicated Text (T) tool, in-editor multiline editing dialog, color/font/size/style controls, and persistent editable text objects using additive validated ink metadata. The complete interaction and storage proposal is in [[TEXT_WORKFLOW]].
- Rendering culls below **9 on-screen font pixels**, based on an initial native framebuffer comparison of 8 px (hidden) versus 10 px (visible). This is a presentation-only rule; text survives zoom, detail switching, undo, clipboard, and native saves. Final device usability tuning remains for acceptance.
- Added `tests/text_smoke.gd` and `tests/text_visual.gd` to CI. Locally confirmed pointer placement, editor keyboard isolation, selection, masked edits, whole-object erasure, rotation/movement, persistence, D0/D1, and compact-window display.
- This is a **review candidate**. The ticket remains unchecked until the owner agrees to the proposed controls, font-style/fallback policy and 9 px visibility threshold. Remote CI and hands-on usability acceptance remain unverified.
- Final local Godot `4.8.beta2` gates: **39 applicable headless suites**, **24 native framebuffer suites** (including re-runs after text/eraser changes), `text_smoke.gd` **47 assertions**, `text_visual.gd` **15 assertions**, explicit-type audit, parser/import, main-scene launch, Web release export, and all four source/exported-pack save interoperability checks pass. Browser-runtime and physical-display readability checks remain deferred.

## Modal target-integrity follow-up — 2026-11-01

- Fixed a loss-of-draft and wrong-destination hazard: a Text dialog now captures the **map, floor and Objects layer IDs** at opening, and Apply refuses to commit if the active target no longer matches. The previous content snapshot still protects revisions against interleaved history edits. Without the identity guard, a new-text placement (which has no original object snapshot) could land on another selected layer or board.
- Apply now closes the modal **only after a successful history operation**. Empty text, a locked or hidden layer, an invalid edit mask, or an obsolete source keeps the draft visible and displays a readable inline rejection message. A recovered target can retry without retyping; a no-op edit closes without adding a history command. Cancellation still discards the draft explicitly. The native save schema and text culling threshold are unchanged.
- Godot `4.8.beta2` local verification: T-027 **60/60 headless** and **17/17 native framebuffer** checks pass, including stale revisions, cross-layer and cross-map placement, locked-layer retry, and a screenshot of the rejected native dialog. Overall, **46/47 applicable headless suites** and **26/26 native suites** pass; the sole headless failure is the pre-existing T-020 `fill_scope_smoke.gd` assertion expecting oversized brush windows to be rejected rather than split. Explicit typing, resource import/parser, scene launch, Web release export, **4/4 source/export-pack save portability** checks and Git LFS validation passed. Remote CI, browser runtime, and physical display usability were not verified.
- **The ticket remains open** until the owner approves the placement/editor controls, font/fallback policy, and screen-space 9 px readability cutoff.

## Modal edit-mask authorization follow-up — 2026-11-01

- Closed the remaining modal authorization gap: a Text placement/revision now captures the exact map, floor, Objects-layer instances and **effective selected-cell edit-mask polygon** when opened. Apply rejects changed cell selection, mask mode, grid orientation/geometry, or a replaced same-ID layer instead of applying under a newly selected authorization. Edits made under a disabled mask remain unaffected by cell focus changes. Rejected submissions retain their draft, leave objects and undo history untouched, and can be submitted when the original scope is restored. Closing the modal releases the captured resource references.
- Expanded `text_smoke.gd` from 60 to **70 assertions** covering stale placement, grid rotation during revisions, safe retries, unrestricted cells, same-ID layer replacement and context cleanup. Expanded `text_visual.gd` from 17 to **22 assertions**, including an 800×600 native error-state screenshot and a verified retry. This is an engineering safety follow-up only: the saved text schema and proposed 9 px screen-space culling policy did not change.
- **Still open:** the owner must approve placement and editor controls, fallback font/style policy and real-display readability threshold before T-027 can be marked accepted. Browser-runtime and physical-display validation remain separate from automated Godot checks.
- Final local Godot `4.8.beta2` verification: **58/58 headless** and **34/34 native-rendering suites** passed, including 70/70 focused Text headless and 22/22 native assertions. Editor import/parser, main-scene launch, Web release export, **4/4 fresh-process source/export-pack portability** checks, explicit-type audit and Git LFS integrity passed. Browser runtime, physical-display readability and owner acceptance were not verified.
