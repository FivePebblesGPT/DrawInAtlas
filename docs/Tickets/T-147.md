# Unify NativeHard and Hokusai behind one native stroke engine

**Scope:** NativeHard and Hokusai **already share** the optional Rust `DrawingNativeBrush` GDExtension; consolidate their divergent stroke-state/API paths rather than pretending they are separate packages or forcing identical painting results. This is an alpha refactor: breaking old script-facing APIs is permitted, with no migration shims.

## Deliverable

- Define one versioned Rust-facing stroke contract: `begin_stroke(layer, brush_mode/preset, options, source_revision)` → opaque transaction handle; `append_samples(handle, packed positional/pressure/time samples)`; `preview_changes(handle)`; `commit/abort(handle)`. Names are illustrative; document actual types and ownership. Explicitly freeze transforms, clipping, selection and source context at gesture start.
- Keep two **strategies within one native engine**: deterministic hard coverage and MyPaint/Hokusai preset pigment. Share sample ingestion, bounded batch scheduling, cancellation, error reporting, resource lifetimes and rollback. Preserve each strategy's own overlap/opacity behavior; exact cross-backend pixel equivalence is **not** a requirement.
- Remove per-mode transaction and fallback branching from the `DrawingCanvas` hot path where the common interface replaces it. Bridge commands and native handles at stroke/sample-batch granularity, not one FFI call per dab/pixel.
- Establish a concrete **native tile patch/buffer** contract for the next ticket: signed tile ID, pixel format/stride, base revision, dirty bounds, generation, ownership/lifetime and atomic error state. Keep the present document working for this ticket through a temporary adapter if needed; do not prematurely claim native raster ownership.

## Acceptance

- [x] Unit and native integration tests cover hard/preset modes, pressure, signed transforms, masking, cancellation/retry, invalid handles, stale revision, errors, Undo/Redo through the transitional bridge and actual displayed strokes.
- [x] One GDExtension interface with stable documented batch semantics and no duplicated per-mode transaction lifecycle; 96px Hokusai and NativeHard regression witnesses remain executable and separately labelled.
- [x] A native/FFI call-count and stage-volume profile confirms no accidental per-pixel boundary calls. No speedup or physical p95 pass assumed.

## Boundaries

Blocked by the T-146 benchmark, not T-095's manual approval. Tile ownership and document history migration belong to T-148; display/persistence seams to T-149; Legacy deletion to T-150.

## Implementation and evidence — 2026-11-15

**Done:** The existing `DrawingNativeBrush` GDExtension now exposes a single handle/revision-bound **ABI v1** with two internal raster strategies, unified sample ingestion and one rejectable batch/commit/abort lifecycle. The Canvas routes both modes through the same `DrawingEditSession` adapter; native boundary calls are per sample batch, not per pixel. No old native hard/preset transaction entry points survive in production code; historical native fixtures use dedicated test-only adapters. Source staging, blending and masks **remain GDScript-owned only temporarily**, explicitly delegated to T-148; Legacy deletion is T-150.
