# Freeze Drawing / Atlas contracts after owner Round 3

**Status: PARTIALLY RESOLVED.** See [[DECISIONS_DRAWING_ATLAS_2026-11-01]]. Do not ask again whether the repos must be separate, whether floors are layer groups, whether missing detail is blank, or whether global undo navigates; those are answered.

## Confirmed
- One **monorepo**, two independently runnable Godot projects; Drawing is a reusable package with a single implementation.
- Drawings can live outside Atlas; Atlas supports shared **linked** and independent **copied** artwork.
- One Atlas floor maps to a Drawing layer group; Drawing has no floor domain concept.
- Atlas controls world surfaces and authored LOD. All map detail levels use continuous shared world coordinates; absent high-detail artwork is **blank**, with no implicit lower-detail underlay.
- Drawing owns snap functionality; text is one editable element per layer created on first successful edit and later rasterized.
- Atlas global undo navigates to the origin map. Paint clicks paint; Selection/ObjectSelection/Pan double-click same entrance to navigate.
- No old user-save migrations. Web **may** be dropped, not confirmed dropped.

## Remaining owner/API decisions — narrow scope
1. Is live linking initially **within Atlas's asset registry only**, or does it also track external standalone Drawing file changes? What happens on external edits, asset removal and duplicate references?
2. Map/document topology: does each authored detail hold its own DrawingDocument or can one DrawingDocument contain floor groups with detail subgroups? Can different Atlas floors show the same Drawing layer without moving it?
3. What canonical world-unit and resolution policy applies at each detail level? Specify asset-local -> Atlas-world transform, rotation/scale allowed, and layer transforms. Prove integer/chunk/local precision at distant signed positions (see T-061).
4. When undo navigates back to A, restore the stored camera/selection as of the edit or just enter the target map and focus the changed artwork? What if the recorded map was deleted? Is redo symmetric?
5. Empty-detail UI: are grid/entrance overlays visible when raster artwork is blank, and which control returns to D0? Do not render D0 artwork as backdrop.
6. Is Web an actual product/release target? If dropped, record explicit scope change in E-007/T-044/export checks; otherwise native fallback may be required.
7. File format choice for standalone Drawing and Atlas project, including refs to shared assets and safe recovery. No migration constraints.
8. Text font bundling/fallback, entrance double-click threshold/overlap choice and first minimal feature inventory (T-059).
9. Monorepo **physical layout** compatible with the existing Atlas-root `project.godot`: one canonical Drawing source tree, packaging/version contract, independent clean builds without accidental nested Godot import/global `class_name` collisions.

## Required design deliverable
Write an ADR or append an approved interface contract including:
- public `DrawingDocument`, layer group, source asset handle, editable transaction and render request contracts;
- link vs copy semantics and asset identity/mapping table;
- world/chunk/local transform and pixel-density table for at least two detail levels;
- floor-group hierarchy example and empty-detail screen UX;
- global undo/redo navigation sequence for a **linked asset**;
- repo tree/import/build diagram and minimum acceptance tests.

## Exit criterion
Owner approves the remaining blocking contracts; approved T-052–T-061 can then proceed incrementally. An unanswered minor UX preference need not hold an unrelated source-extraction spike hostage if it is explicitly deferred.
