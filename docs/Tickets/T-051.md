# Finalize physically independent Drawing / Atlas contracts

**Status: PARTIALLY ANSWERED — DECISION GATE OPEN.** Confirmed owner decisions are recorded in [[DECISIONS_DRAWING_ATLAS_2026-11-01]]; do not reopen them without a concrete conflicting requirement.

## Confirmed boundaries
- Standalone Paint.NET/PhotoCraft-style Drawing product; physically independent build and reusable package.
- Drawing assets can exist without maps.
- Floors are layers/groups organized by Atlas. Drawing provides snapping.
- Atlas manages world surfaces and authored-detail/LOD presentation, Drawing paints into selected content.
- Text makes editable text layer at first successful edit, with explicit later rasterization.
- Painting clicks paint; double-click same entrance with Selection/ObjectSelection or Pan navigates.
- Atlas global chronological history; no old user saves to migrate.

## Remaining blocking questions
1. One repository with an independent Godot subproject/versioned addon, or separate repository and pinned dependency? Which standalone platforms and Web responsibilities?
2. Can an Atlas map share one live DrawingDocument with another, or only copy/link as separate instances? What is Drawing's file format?
3. Is an Atlas floor a view of layer groups in one surface or a separate DrawingDocument? Can layers be intentionally shared between floors?
4. Exact map/world-to-drawing coordinate transform, pixel density, signed chunks and transforms; does authored detail share common board coordinates?
5. Authored LOD fallback for empty regions and whether lower details remain underneath; how to freeze editing targets through zoom.
6. Is one text object one layer or can a text layer hold multiple objects? What font embedding and rasterization rules?
7. Exact double-click gesture and overlapping entrance chooser; does Pan also select, or just hit-test?
8. When global undo targets another map, should the camera follow that map or stay where it is?
9. Standalone Drawing Web required, or only Atlas's embedded Drawing runtime? Native/WASM optimization policy.
10. Owner's minimum Drawing feature list, requested separately under T-059.

## Deliverables
Approved package topology, dependency check, public document/render/edit/gesture/snapping/asset interfaces, one paint and one cross-map undo sequence diagram, layer/floor mapping, coordinate contract, initial UX vertical slice and decision on open questions. Update docs/ARCHITECTURE.md when accepted.

## Gate
T-052–T-056 and T-058 require these relevant choices before implementation. No migration of old saves.
