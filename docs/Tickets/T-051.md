# Decide Drawing / Atlas boundaries before extraction

## Status
**DECISION GATE — OPEN.** This ticket records questions, not approved implementation choices.

## Source and observed coupling
- `scripts/interface/canvas.gd` mixes strokes, artwork rendering, links, cell selection, tokens, fog and projector framing.
- `scripts/interface/artwork_editor.gd` reads the canvas's active map/floor/layer and applies edits through campaign-wide history.
- `scripts/editing/commands/edit_command.gd` accepts `AtlasCampaign`, including for artwork-only mutations.
- `scripts/interface/map_capture.gd` instantiates an interactive `AtlasCanvas` for read-only captures.
- `docs/Epics/E-006.md`, `docs/RASTER_OBJECTS_WORKFLOW.md` and `docs/Epics/E-SAVE.md` already constrain continuous board-space artwork, typed raster/Objects layers, authored LOD and native saves.

## Questions requiring owner decisions
1. Is standalone Drawing a user-facing editor/mode, a separate deployable application, or only a testable engine embedded in Atlas? What workflow demonstrates success?
2. Is Drawing's persisted document an independent artwork file, or does a Drawing surface live only within an Atlas floor? May standalone sketches later be linked/imported?
3. Does Drawing own its own canvas coordinate system, infinite-board policy and resolution? Which grid/snap/mask facilities must exist in standalone Drawing?
4. Is authored D0/D1/... detail a Drawing concept, while the *automatic selection policy* is Atlas-specific? What happens if there is no high-detail artwork at the current location?
5. Are undo/redo one ordered workspace history across map and artwork changes, or separate per-document histories? What should undo after switching maps do?
6. Are tools permitted to auto-create or auto-switch layers, or should the current explicit authoring target never change without a confirmation?
7. Do walls, text and image props remain Drawing semantic objects? Where exactly do GM tokens, fog, projector frames and map-link click targets belong?
8. Must native v2 `.scn` saves load byte/semantic-equivalently without a migration? Are script/resource-path changes prohibited in the first extraction?
9. Should Drawing and Atlas have distinct UIs or one shared shell with different modes? Which painting workflow is the minimum acceptable UX?
10. What performance and Web-export constraints define a viable first milestone (large signed chunks, long strokes, viewport size, input device)?

## Deliverables
- Record owner answers and explicit unresolved items as an ADR in `docs/`; link it here and update `docs/ARCHITECTURE.md` to distinguish current implementation, accepted future design and superseded historical material.
- An ownership/dependency matrix for data, services, rendering, history, session state, UI, overlays and persistence.
- Define stable public Drawing API contracts (surface, edit context, gesture, optional mask/snapping policy, render request, edit transaction) and one end-to-end sequence diagram.
- State save/migration and rollback policy, including `T-015` approval boundaries, and specify measurable Drawing-only and Atlas-integration acceptance.

## Exit conditions
The owner explicitly approves the core boundaries and answers the blocking decisions. No implementation under T-052–T-056 begins until this gate is resolved. Do not mark the ticket complete merely because a design document was written.
