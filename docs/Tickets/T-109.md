# Production-scale Asset Browser and filesystem hardening

**Parent:** [T-065](T-065.md). **State: Done** for this scoped on-disk
bounded-scan and source authorization deliverable; this is not T-065's
owner-device browser acceptance.

## Implemented

- Index `Objects/` entries from **one bounded byte buffer per source**,
  validating canonical pixel/metadata payload and computing the advertised
  SHA-256 from exactly those bytes. Later Open, preview, drag and Export still
  revalidate the selected snapshot. Neither a symlinked ancestor nor a
  changed selected file can gain authority from a filename alone.
- Recheck the entire bounded, warning-free source snapshot before a new
  standalone Import, rejecting stale listings, late duplicates and over-limit
  directories without publishing an unindexed source. The Atlas-managed
  source registry remains separate from standalone `Objects/*.drawing`.
- Pin Export's staged source bytes to the selected SHA-256 through the final
  source check; reject mismatches **before** destination publication. Validate
  the captured copy bytes as well as the path. No overwrite or source removal
  behavior was added. The existing Remove/NULL/Cancel policy is unchanged.
- Bound Atlas-registry discovery during Import (no unbounded `get_files()`).
  Keep the existing 512-source, 2,048-candidate and 24-thumbnail limits.
- Fix test-only native pointer Dummy audio selection and a modal-dialog
  sequencing mismatch in the source-manager witness, so strict logs can
  distinguish application failures from test setup errors.

## Acceptance evidence

[Reproducible T-109 evidence and raw logs](../evidence/T-109-2026-11-12-asset-scale-and-path-hardening.md)
include the negative control from T-108, 32/32 real-directory checks, exact
512/513 capacity and late duplicate rollback, selected path/link replacement,
511-slot stale Import, digest-pinned Export, rename/move and 26-to-24 thumbnail
LRU. Existing standalone, Atlas, NULL repair, source manager and **19-check
real XTEST pointer** regressions pass, with strict log verification.

Nine warm/cold sampled scans of the same on-disk 512-source fixture report
p50/p95/peak process RSS for both source revisions. The protected one-read
hash path is **slower than** T-108 in this software sample; no scan-speedup,
Windows, GPU, network/filesystem-race atomicity or owner-device acceptance is
claimed. GDScript lacks a cross-process no-replace transaction primitive;
path and digest checks are point-in-time safeguards, not a filesystem lease.
