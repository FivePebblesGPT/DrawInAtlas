# Bounded occupied-tile outlines for sparse explicit selection masks

**Done — 2026-11-15, narrowly scoped engineering correction.** The existing
64px irregular-mask outline cache holds at most 4096 tiles and traces four
new tiles per frame, but its row-major traversal still inspected every tile
inside a potentially huge selection *bounding rectangle*. At 25% zoom on a
1680×960 Canvas, this can miss real selected islands late in the window and
spend its budget on transparent tiles. This is independent of the existing
source mask truth (`DrawingSelection.allows()`).

## Acceptance

- [x] For a positive, operation-free explicit pixel mask, enumerate only tiles
  containing `true` selected pixels within the selection's base bounds and
  viewport footprint, including negative signed coordinates and far-right
  or far-bottom islands; ignore `false` and offscreen entries. Preserve exact
  contour generation, screen drawing and selection semantics.
- [x] Keep the existing progressive four-new-tile draw budget and bounded
  4096-entry cache. Do not allocate a full viewport-sized list for irregular
  masks; overflow, inversion and compound boolean operations keep a bounded
  conservative row-major fallback.
- [x] Reproduce a failing T-138 baseline on the *same* native X11 test and
  pass both a headless candidate-index model and actual two-island framebuffer
  readback at 25% zoom. Verify no document revision/content publication,
  cancellation and re-entry remain independent.
- [x] Run T-088 selection/clipboard/sparse capture regressions, native
  selection/clipboard witness, strict logs, Python/typing/CI contracts and
  T-096 large selection/Move oracle, native-absent Drawing consumer and
  canonical ticket validation. Add the model within the existing T-088 CI
  check and native witness to its on-demand X11 workflow, without expanding
  the 46 required CI check IDs.
