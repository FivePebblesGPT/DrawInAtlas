# Require effective Drawing project identity and startup scene in native export stages

## Problem

The source-stage release gate previously checked only whether the text
`config/name="Drawing"` appeared *anywhere* in `project.godot`. A comment or
unrelated section could spoof that substring even when the active application
identity was Atlas, and an unrelated startup scene was never checked. Such a
stage could pass preflight before native Linux packaging. This is a release
source-identity issue, not a Brush or Canvas change.

## Acceptance

- [x] Reproduce six false accepts: comment-spoofed identity, unrelated-section
      identity, duplicate/conflicting identity, repeated application section,
      wrong launch scene, and comment-spoofed launch scene.
- [x] Check effective keys in exactly one `[application]` section, rejecting
      duplicate `config/name` or `run/main_scene`, and require the canonical
      `Drawing` name and `res://main.tscn` startup scene.
- [x] Reject a stage *before* native packaging modifies ELF/PCK, publishes an
      `.so`, or leaves preflight artifacts; retain the normal staged project.
- [x] Verify the actual 522-file native stage, real isolated PCK/ABI launch,
      configured Python suites, native Rust tests, Ruff/ty and Kanban gate.

## Evidence and limitations

[Fail-first, final commands, source hashes, and raw process results](../evidence/T-216-2026-11-19-project-identity.md).

The previously established T-215 allowed-directory and binary contracts remain
unchanged; no runtime Drawing or History code was modified. The Linux launch
uses the supplied Godot 4.8 beta3 executable with the real PCK/native library,
not an official release template. Hosted GitHub CI, Windows-native runtime,
physical responsiveness and all manual-owner gates remain open in T-105,
T-106, T-180 and the applicable UX/performance tickets.
