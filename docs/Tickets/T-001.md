# Enforce explicit GDScript types and correct skill guidance

## Source
[[ManualReview_2026-10-30#Code review|Code review]], item 5. The user explicitly identifies this as the current **top priority**.

## Work
Audit applicable project/global Godot skills and their examples for guidance permitting `:=` or inferred declarations. Require explicit type annotations, including locals, and align project GDScript with that convention. Identify active skill copies so an uncorrected copy cannot reintroduce the guidance.

## Acceptance
- Applicable instructions/examples consistently use explicit declarations and return types.
- Project-owned scripts are audited for `:=`; replacements preserve behavior and use meaningful concrete types.
- Third-party addon changes are separately scoped rather than silently mixed into application cleanup.
- Record the locations audited and run appropriate parser/regression checks.

## Implementation and audit — 2026-10-30

- Audited all 90 project-owned `.gd` files under `scripts/`, `prefab/` and
  `tests/`. Replaced 110 inferred declarations with explicit, concrete types,
  including local variables and the two canvas constants. Retained return-type
  annotations on existing functions; the audit found no untyped function
  declarations in those project-owned scripts.
- Audited all 33 Markdown files under `.agents/skills/`, including their
  fenced GDScript examples. Replaced 87 inferred declarations, corrected the
  `godot-gdscript-patterns` instruction that previously allowed `:=`, and
  fixed two untyped default parameters and the multiplayer callback signature.
  Resource API call illustrations now use positional arguments, not the
  misleading `:=` notation for API defaults.
- Checked for other active copies in `$HOME/.agents/skills/`,
  `$HOME/.config/agents/skills/`, `$HOME/.config/opencode/skills/`,
  `$HOME/.local/share/opencode/skills/` and `$HOME/.codex/skills/`, and searched
  the home directory for another `godot-gdscript-patterns` installation. In
  this workspace, the only found copy is the project-owned skill; no global
  copy or symlink was present to update. External agent installs on other
  machines were not available to inspect.
- Four test-only `const Name = preload("res://...gd")` script handles remain
  intentionally unannotated. Experimentally annotating them as `GDScript`
  changed static method lookup and caused runtime type errors in the selection
  suite (which otherwise passes 198 checks). This is a distinct script-type
  binding from variable inference and is preserved for behavior compatibility.
- `addons/` is third-party code and was deliberately excluded: 8,298 `:=`
  occurrences across 464 addon `.gd` files remain out of this ticket's scope.
- Added `tests/check_explicit_types.py` as a CI guard against inferred or
  untyped variables and missing function return annotations in project GDScript
  and the bundled skills' fenced GDScript examples.
