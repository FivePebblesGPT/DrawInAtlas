# Reject a Polygon draft detached from its registered campaign/map/floor

**Parent:** [T-025](T-025.md). **State:** Done for this narrow source-identity
authorization fix; T-025 remains Ready for owner approval of its separate
vertex/closure/style/raster-pixel interaction decisions.

## Problem

The existing Polygon context pins map, floor, raster layer and exact edit mask
as Resource references at the first vertex. Its later validation checks only
Canvas's map/floor pointers and the selected layer; it does **not** require
the campaign to still register those Resources. A same-ID map/floor replacement,
removal from the registry, or changed campaign owner can therefore authorize
an old draft, emitting a stroke and sometimes a history entry onto a replaced
source even when its IDs and serialized bytes appear unchanged.

## Bounded fix

Capture the campaign Resource along with the first Polygon vertex. During
subsequent vertex input, preview refresh and commit, require the same campaign,
map and floor Resources to remain active **and** require the campaign to
register that map and the map to register that floor. Retain the existing
layer identity, lock/visibility, detail level and exact edit-mask checks.
Stale drafts emit `polygon_rejected`, clear transient state and produce no
`stroke_requested` emission or Undo entry. Valid drafts and unrelated map
registration changes continue to work unchanged.

No new serialized field, drawing style, geometry rule, line/fill policy,
native dependency or user-facing option is introduced.
