# Compact color controls, History panel and selection-history preference

**Status: Done — engineering scope (2026-11-06); physical owner UX re-review remains pending.** Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
The default Godot color popup is oversized for the intended compact dock. The floating History panel wastes space on 'Undo / Redo' and a persistent 'Log selections' toggle; the latter is an app-wide preference, not history content. The status bar exposes a monotonic internal revision that users may mistake for undo position.

## Engineering tasks
1. Provide a compact Colors panel with current/previous foreground/background, hex/RGB entry, a concise swatch/recent-color section and an optional expanded advanced color picker; avoid copying PhotoCraft artwork.
2. Show meaningful history events and current cursor, with actionable Undo/Redo; do not duplicate a redundant panel heading.
3. Move selection-history preference into Edit > Preferences (default OFF), persist as workspace/app preference without dirtying artwork, retain setting semantics across tabs.
4. Keep internal revision checks monotonic through Undo/Redo but display an understandable history state/dirty marker; do not reset revision when undoing.

## Acceptance / verification
- [x] Colors stays compact at narrow dock; swatches/recent colors functional, advanced picker accessible (model and native Xvfb).
- [x] History shows content operations, current position, one-gesture grouping, correct Undo/Redo, no intrusive in-panel preference toggle.
- [x] Preference persists independently from document content; Undo increments internal revision safely without suggesting the undo cursor advanced.
- [x] Native narrow/floating tests cover focus/resize and stable layout (software Xvfb; physical Windows/Linux owner UX still PENDING).

## Boundaries

- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.

## T-092 implementation and evidence — 2026-11-06

**Engineering Done; physical/owner usability acceptance is not implied.** One
canonical shared `addons/drawing/` workspace now supplies an immediately usable
compact Colors panel: current/previous FG and BG color swatches, swap, strict
`#RRGGBB`/`#RRGGBBAA` input, three 0–255 RGB controls, and six clickable
recent-color swatches. The complete Godot `ColorPicker` is an explicitly
collapsed **Advanced picker** section, not an oversized default popup.
Changes to pigments and panel preferences never edit document bytes or dirty
history. Background is a secondary stored UI pigment, not an automatic fill
or new blend mode; foreground remains the paint color with exact RGBA8 packing.

History has accessible Undo and Redo buttons, a bounded 64-event list showing
selection, raster, text and structure events by human-readable name, and a
`cursor / total` indicator. Item selection permits jumping to an earlier or
later retained step using the existing atomic Undo/Redo paths. The
`DrawingDocument.history_summaries()` public API returns **labels only**, never
mutable pixel deltas or history snapshots. The status bar displays
`history n/m` and Saved/Unsaved instead of conflating the monotonically
increasing internal `revision` with the undo cursor. The revision remains
unchanged by selection-only undo and **increments** on content undo/replay,
protecting stale-revision checks. Atlas can still own its external timeline.

The selection-history preference (default OFF) lives under
**Edit → Preferences…**, in a separate, schema-checked, size-bounded, atomic
`user://drawing-workspace-preferences-v1.json`; it can recover an intact
backup after an interrupted replacement. It is shared across workspace tabs,
restored before opening the first tab, and never serialized into `.drawing`.
This preference is separate from the T-083 dock layout settings; embedded
host applications can opt out or choose a private `preferences_settings_path`.
