# Bound cold detached-preview texture population to retainable indexed tiles

**Done — 2026-11-15, narrow scheduling improvement, not physical latency acceptance.**
The T-102 cold-population frame budget initially applied to committed content
only. Even after T-136 had validated a complete bounded detached Brush/Move
preview index, a cold preview could synchronously composite every visible tile
in one `_draw()` callback. This caused avoidable software frame stalls when the
committed and preview footprints were small enough to retain entirely.

## Acceptance and evidence

- [x] Reuse the **validated** T-136 committed/preview signed tile union to
  schedule at most four missing cold tiles per draw under T-102's existing
  10 ms *soft* compositor budget. Revalidate preview stamp, owner identity,
  dirty bit, source revision and viewport each draw; preserve focal priority.
- [x] **Fail closed:** no throttling for unknown occupancy, incomplete or
  invalid preview indexes, over-144-tile footprints or dense views lacking a
  trustworthy union. Existing committed-only scheduling remains unchanged.
- [x] A 15-check headless model proves focus, cached generations, changed
  owners, invalid keys and unbounded fallback. The 18-check native X11 test
  proves first-frame capping, subsequent settlement, actual preview/source
  framebuffer pixels, cancellation, immutable source and Undo/Redo.
- [x] Compare against unchanged T-136 source using the **identical** native
  test and pinned software renderer. The baseline fails 3/18 new scheduling
  assertions; the candidate passes 18/18. Headless, neighboring native
  viewport, independent consumer, strict log, typing and ticket contracts
  are retained under the same 46 required fast-CI IDs.

**Scope boundary:** This is progressive rendering of an artificially cold,
partly occupied **50% zoom software viewport**. A 10 ms soft budget cannot
interrupt an in-progress individual tile composite and does not measure real
input-to-photon latency. Intermediate frames intentionally show an incomplete
cold viewport, then settle without dropping preview pixels. Over-budget/dense
views remain unthrottled. T-086 stays In Progress for reference Windows/Linux
large dense views; T-095 stays In Progress with `manual_review: true` pending
actual hardware and owner acceptance. Hosted CI and other review gates are
not claimed or changed.
