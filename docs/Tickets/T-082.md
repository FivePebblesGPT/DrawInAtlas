# Transactional cross-container docking with alignment previews

**Status:** Done (engineering; 2026-11-03). See [agreed docking behavior](../DRAWING_DOCKING_SPEC.md).

## Scope

- Drag an individual panel tab **or a whole tabbed group** between the expanded right dock, its minimized icon rail and one or more floating in-app containers.
- Show unambiguous target previews for insert before/after a particular group, before/after a tab within a group, and group merge/split. Preview reflects actual cursor position and final order, including relevant separators and tabs.
- **Whole-group redock:** dragging a floating tabbed group into the dock reinserts **every member in its current order at the indicated insertion position**. The full icon sequence returns to the dock rail, with separators reflecting group boundaries. A single-tab drag transfers only that tab.
- Dragging a group out of the dock removes **all** its icon buttons and separator boundaries from that dock; floating host retains its own tabs and supports subsequent reordering.
- Transfers must be transactional across both source and destination. A cancelled drag (Esc, invalid target, focus change) restores exact prior ownership, active tabs and ordering; no duplicated live UI, orphaned tabs or document edits.
- Handle resize/scroll while previewing, input event routing and keyboard-accessible target choice wherever feasible. Native OS windows remain out of scope.

## Acceptance

1. Native end-to-end evidence: group Colors + Layers, detach the group, reorder it to Layers + Colors while floating, and redock **between two existing groups**. Assert rail icon order and group separators match the precise indicated insertion target; no original icons remain stranded.
2. Test single-panel moves separately, group merges, split targets, scroll-edge positions, repeated dock/undock, multiple floating hosts, narrow window and high DPI.
3. Esc/invalid destination/target destruction returns exact source/destination models and original focus, without duplicate controls or dropped input into the canvas.
4. Cross-container tests run alongside T-079–T-081 regression suites. No persistence or owner signoff is implied; those are [T-083](T-083.md).

Engineering ticket; manual UX acceptance remains T-083.

## Implementation and verification — 2026-11-03

- `addons/drawing/workspace.gd` now coordinates dock- and floating-host-origin pointer gestures through **one shared `DrawingDockDrag`** planner and `DrawingDockLayout` ownership registry. Topmost visible in-app floating host wins hit-testing, including overlap with the right dock; the expanded dock, minimized grouped rail and in-app flyout retain exact tab and group slot markers. A canvas drop deliberately detaches into a new in-app `DrawingFloatingHost`; invalid regions clear stale valid previews instead of releasing onto the last hovered target. The model is unchanged during hover, and a new destination is created only at successful canvas release.
- `addons/drawing/floating_host.gd` routes tab/group drags across container boundaries without duplicating panel views. Whole-group transfers preserve the group's tab sequence, active selection and collapse state; the receiving dock regenerates panel-level rail icons with separators strictly between groups. Single-panel transfers merge into target tabs or split into a new group at the cursor. An emptied source floating host is removed from the model and UI only after successful transfer, never during preview. Hidden hosts cannot intercept target hit tests, and scroll-edge preview movement updates the indicator.
- Esc, invalid target, OS focus loss, stale concurrent model mutation and a disappearing/relocated target cancel without overwriting the committed source/destination state. Focus-loss also suppresses a subsequent click release so the original active tab cannot flip accidentally. Float host and dock **Arrange** menus provide keyboard-reachable transfers; `Ctrl+Alt+D` redocks a focused floating tab, and `Ctrl+Alt+Shift+D` redocks a focused floating group. All floating hosts remain Godot Controls inside the app; persistence remains T-083.
- `drawing/tests/dock_cross_smoke.gd` passed **62/62** standalone Godot 4.8 beta 2 headless checks: ordered group redock between existing groups, precise separator sequence, a single-tab cross-host transfer, split and merge, multiple floating hosts, repeat detach/redock, exact cancellation, stale mutation handling and uniqueness. Added to required fast desktop CI without expanding native push gates.
- `drawing/tests/dock_cross_native.gd` passed **56/56** pinned native X11/Mesa checks without screenshot capture, exercising actual press/motion/release transfers: Colors + Layers detached, reordered as Layers + Colors, redocked between History and Swatches from the minimized rail; receiving group insertion hints; dock-to-host tab merge and host-to-host whole-group move; source cleanup; invalid and Esc drop; OS focus-loss suppression; concurrent target relocation; keyboard-menu transfer; hidden-host exclusion; narrow viewport/1.5× content scale; unchanged Drawing document revision and dirty state.
