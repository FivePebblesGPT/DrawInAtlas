### Concrete readability findings and changes

1. `scripts/editing/clipboard.gd::_decode_raster()` previously mixed closed
   metadata validation, content-address/dimension consistency, strict base64
   checks, WebP/hash verification and per-chunk mutable ownership in one long
   sequence. Extracted `_raster_asset_dimensions()` and
   `_decode_raster_assets()` with explicit failure boundaries. All references
   are still checked before decoding any binary data; each chunk receives its
   own mutable `Image`, even when content hashes repeat. No wire-format,
   size-limit or public API changes.
2. `scripts/editing/cell_scope.gd::clip_strokes()` did not say why text is
   preserved whole, why a half-width inset is used, or why one line can yield
   several detached fragments. Added comments for these contracts; no geometry
   operations or conditional order changed.
3. `scripts/interface/artwork_editor.gd::_paste_tiles()` did not show the
   transaction boundary clearly. Marked compatibility validation, whole-paste
   destination/scope preflight, and the single undo command. No paste logic
   changed.
4. **Deferred behavior/design question (not a readability patch):**
   `cell_scope.gd::clip_strokes()` handles text atomically but constructs plain
   `AtlasStroke` instances for clipped *non-text* inputs. When `_paste_ink()`
   sends a filled polygon or editable wall path through this function with a
   selected-cell scope, its semantic flags can be lost. An unfamiliar reviewer
   should trace this exact path and the intended semantics of masked paste;
   changing it would require a tool-behavior decision under T-025/T-026, not a
   silent refactor here.

## Source-only follow-up — 2026-11-01 (still pending independent review)

### Finding: candidate-budget contract contradicted by an old test

Reading `scripts/editing/raster_brush.gd` alongside its direct callers in
`interface/canvas.gd` and `interface/artwork_editor.gd` exposed an outdated
expectation in `tests/fill_scope_smoke.gd::_test_raster_brush()`: the test
asserted that a long stroke must be rejected when its **whole-leg** candidate
area exceeded two raster pixels. Since the earlier raster-first disappearing-
stroke fix, `_stage_segment()` instead splits an oversized segment into smaller
candidate **scan windows** while preserving the shared per-gesture coverage
set. The previous assertion therefore failed even though the documented
painting behavior was intentional.

- Clarified the budget's units and granularity, subdivision/recovery phases and
  stationary-dot failure condition directly in `raster_brush.gd`. The editing
  algorithm and its public API were **not changed** in this follow-up.
- Replaced the stale assertion with a byte-exact raster comparison between a
  two-pixel scan-window limit and a large limit, using a translucent,
  doubled-back stroke spanning negative and positive chunk coordinates.
  Also checks coverage at both ends, non-accumulating alpha, preservation of
  source data and failure of a genuinely oversized stationary dot.
- The test remains in the existing CI workflow; no CI job was removed or
  weakened. This specifically repairs a repeatedly observed broad-suite
  failure, rather than reclassifying it as an accepted failing test.
