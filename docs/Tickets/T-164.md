# Guard inclusive signed image-import extents before editing

**Split from T-148.** T-161 made image-import *anchors* sign-safe, but
`DrawingRasterImport.import_image` still only checked the first image pixel.
A multi-pixel image starting exactly at the accepted positive `+2^60` edge
could publish pixels *past* the document's supported public range. Invalid
imports could reach source resolution, edit-session staging, or history
publication before discovering any failure. The contract is a complete
bounded image rectangle, not merely a bounded top-left pixel.

## Acceptance

- [x] Validate the inclusive opposite corner of the decoded image's
  dimension rectangle against the same existing `±2^60` signed bounds,
  **after** validating the starting anchor and pixel budget, and **before**
  decoding pixels or opening the edit session. Reject with `COORD_RANGE`.
- [x] Preserve exact inclusive positive/negative endpoint imports, historical
  signed-64-bit non-native editing and Undo/Redo. Do not silently replace the
  public bound with the stricter `±2^52` native publication limit.
- [x] Invalid images never resolve lazy tiles or alter revision, dirty state,
  native token/bytes, display epoch or history. A real Hokusai source must
  remain Undo/Redo-capable after rejections.
- [x] Prove the old behavior fails against the same fixture. Run Godot
  standalone and Atlas/Object regression neighbors, pinned offline Rust,
  strict Clippy, release build, and both software-X11 native witnesses.
- [x] Update the required-native CI loop, T-148, native ABI documentation,
  and Kanban Index. Preserve T-095 owner/hardware and T-149 dependency gates.

## Evidence and disposition

[Execution evidence](../evidence/T-164-2026-11-16-image-extents.md)
contains the pre-fix and positive fixture, the execution matrix and checksummed
raw logs. This closes image-import *extent* preflight only. It does not
