# Conventional File/Object menus and unified Open for raster images

**Status: Ready — owner UX requirements recorded on 2026-11-12; not implemented or tested.** This is a new corrective scope after the 11-11 sprint. T-090's older menu arrangement and T-093's bounded Object discovery/image import implementation remain historical engineering evidence, not approval of the new behavior. No additional manual gate is created for routine implementation; final owner-facing usability acceptance remains in T-059/T-056.

## Owner decision

- Keep the File menu conventional and concise: **New** (Ctrl+N), **Open…** (Ctrl+O), **Save** (Ctrl+S), **Save As…** (Ctrl+Shift+S), **Close Tab** (Ctrl+W). Do not say "New Drawing" in a Drawing application, or "Open Drawing" where Open handles more than one file type.
- **Open… is the only ordinary document-opening command.** For `.drawing`, open the saved editable Drawing document. For a supported raster image (`.png`, `.webp`, `.jpg`, `.jpeg`), create and open a *new Drawing document* initialized from that image, with image bounds/frame and a raster layer. The new project is unsaved until the first Save/Save As chooses a `.drawing` destination; the input image must never be overwritten.
- Remove the **Import Image as Drawing…** command from File rather than relabeling it. The old separate import path should be reused behind Open's format dispatch, not run in addition to a duplicate command.
- Move Object-source management into its own top-level **Object** menu: New Source, Open Source…, Rename Source…, Save Source As…, Browse Sources…. Do not render literal **Object ›** prefixes as flat File entries; this is a real menu category, not a simulated submenu.
- Preserve the independently scoped **Object Editor/source identity** and **Asset Browser** workflows. Opening an ordinary raster image does *not* automatically create/publish an Object source or place/rebind any Atlas instance. Keep Window for workspace-level controls, including the existing Asset Browser command if useful.

## Implementation tasks

1. Update the shared canonical `addons/drawing/workspace.gd` menu specs and opening dispatcher, with no standalone-only fork. Route ordinary image files into the existing bounded `DrawingRasterImport` + new-document path and keep native `.drawing` loading unchanged.
2. Expose both .drawing and PNG/WebP/JPEG in Open's file chooser; enforce file type/size/geometry validation, preserve error handling without partial tabs and display an unsaved imported-image tab with a usable title and frame. Save produces a normal `.drawing` and must never mutate the original image.
3. Add an independent Object top-level menu using `DrawingEditorTopBar` and preserve responsive overflow. If the menu does not fit, move Object commands under the existing **More** overflow as `Object › …` entries while preserving command identity, toggles, accessibility and working shortcuts; only the top-level File menu must not include Object-prefixed commands.
4. Preserve existing dirty-close prompts, multi-tab behavior, keyboard shortcuts, Save/Save As roundtrip and portable Object-source open/rename/save/browse behavior. Do not add an unrequested "Import Image as Layer" command.

## Acceptance and verification (open)

- [ ] File has exactly the five approved visible commands and labels; a separate Object menu works at normal width and its actions remain reachable when the bar overflows. No obsolete import command or literal Object-prefixed File entry.
- [ ] Ctrl+N creates a blank document; Ctrl+O chooses either an existing .drawing or supported raster image; Save/Save As/Close preserve their original shortcuts and dirty-document safeguards.
- [ ] Open raster PNG/WebP/JPEG yields a new editable, **unsaved** Drawing document with exact canonical pixels, appropriate image frame and a single raster layer. Opening transparent images preserves the empty frame; no Object source/Atlas placement is silently created.
- [ ] First Save of an image-backed document writes a fresh `.drawing`; subsequent reopen roundtrips image pixels/frame, while the original image's bytes/path remain unchanged. Open of malformed/oversized/unsupported input leaves the document list unchanged with a clear error.
- [ ] Add focused headless Godot/file-dialog dispatch and portable source regression tests plus real native pointer/menu/overflow and image-open/save roundtrip tests; keep the independent Drawing consumer/Atlas shared-package staging intact. Report results rather than treating this ticket as already done.
