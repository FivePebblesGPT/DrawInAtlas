# Create editable point-by-point wall paths

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 16.

## Confirmed refinement — 2026-10-30
“Contour” originally referred to Aseprite-style closed freehand/lasso drawing. The user replaced that request with an **editable point-by-point tool** for walls and similar structures, supporting both open paths and closed enclosures. Paint.net remains the primary general editor reference; this is an explicit tool-specific requirement.

## Acceptance
- Place points incrementally, finish an open path or close an enclosure, and cancel an unfinished path predictably.
- Points remain editable after creation; agree adding, moving and deleting points and styling/width behavior before implementation.
- Keep the editable path distinct from polygon shape/fill interaction and selection-lasso behavior.
- Integrate masks, protections, undo and saving without losing editability.
- Decide the persistence representation/schema impact explicitly; do not rasterize the editable structure merely to reuse brush storage.

## Implementation candidate and verification — 2026-10-30

- Added a **Wall path (W)** tool, independent from the Polygon shape tool. New paths are typed editable ink resources, with open/closed control vertices and explicit styling. Point operations and the proposed interaction rules are documented in [[WALL_PATHS_WORKFLOW]].
- Added strict path invariants and additive `editable_path` / `closed_path` metadata, keeping existing save and clipboard formats compatible. History, selection, native save, move/transform, eraser, and edit-mask workflows preserve whole-path editability rather than flattening geometry.
- Added `tests/wall_paths_smoke.gd` and `tests/wall_paths_visual.gd` to CI. The implementation is a **review candidate**: approval of vertex insertion/movement/deletion, styling, full-path mask handling, and the additive persistence policy is still required before checking this ticket complete.
- Local Godot `4.8.beta2` verification: 39 applicable headless suites pass (the two framebuffer-only suites were run natively), all 23 native framebuffer suites pass, `tests/wall_paths_smoke.gd` passes 59 assertions, and `tests/wall_paths_visual.gd` passes 14 assertions. Parser/import, main-scene launch, explicit-type audit, Web release export and all four source/exported-pack save interoperability gates passed. Remote CI and manual usability acceptance remain unverified.

## Wall draft rendering follow-up — 2026-11-01

- Fixed a draft/final mismatch: previously, unfinished wall segments were a fixed translucent gold polyline, regardless of chosen RGBA and width. Fixed vertices now render as a detached, typed open `AtlasStroke` through the same vector renderer as committed paths. The gold guide is only the **uncommitted next leg**, not part of the saved geometry. No path schema, masks, history, or interaction mapping changed.
- The cached draft is refreshed on vertex placement/removal and on brush color/width changes, including when the pointer remains stationary. Finishing or cancelling a path drops the transient draft; selecting and restyling existing walls remains an explicit inspector action. Added headless checks for preview independence, style fidelity, Backspace invalidation and exact draft-to-command equivalence, plus a native framebuffer test for changed color and preview/final color agreement.
- Godot `4.8.beta2` local checks: T-026 **65/65 headless** and **16/16 native framebuffer** assertions passed. Wider sweeps: **45/46 applicable headless suites** and **26/26 native suites** passed. The one headless failure is the previously identified, pre-existing `fill_scope_smoke.gd` assertion that expects an oversized brush candidate to be rejected instead of split into bounded segments (T-020). Import/parser, main-scene launch, explicit types, Web release export, **4/4** fresh-process source/export-pack save interoperability checks and Git LFS validation passed. Remote CI/browser testing not performed.
- **Status remains open** for owner approval of wall editing interactions, masks, and additive persistence, independent of engineering test results.

## Wall gesture authorization follow-up — 2026-11-01

- Fixed a mid-gesture edit-mask/target race in the Objects wall tool. Authoring freezes the effective cell mask and target from the first vertex; vertex dragging freezes them at press. Every finish path (Enter, click-to-close, double-click, right-click and drag release) rejects changes to that context and clears the session-only preview instead of trying to commit under newer permissions. A locked original Objects layer or different layer instance also invalidates a draft.
- Added 13 headless checks (65 → 78) for stale open/closed paths, scope and layer changes, vertex release, undo-history invariants, fresh retry, and unrestricted cell-focus changes. Added 4 native framebuffer checks (16 → 20) including a pixel witness for rejected draft removal. The existing whole-path bounds policy and additive save schema are unchanged.
- **Still open:** owner approval of control-vertex interactions, whole-path edit-mask behavior, style controls and the persisted editable-path representation is required before marking this ticket accepted.
