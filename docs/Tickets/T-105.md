# Portable native candidate builds and process-memory evidence

**Parent:** [T-068](T-068.md). **State:** In Progress. This ticket has its own independently verifiable outcome; it does not inherit the parent’s remaining manual/device acceptance.

## Problem
The existing native candidate measurements do not establish Windows/MSVC reproduction, exported-app portability or physical RAM/VRAM residency.

## Bounded implementation / research
Reproduce pinned candidate ABI and strict-float oracles on Linux and Windows, build and launch a portable standalone Drawing export where supported, and measure full-process/RAM/native residency alongside canonical RGBA8 publication.

## Acceptance and evidence requirements
Report compiler/toolchain, platform and build SHA, signed/masked pixel parity, full release launch, p50/p95 CPU/end-to-end results and memory limits; explicitly distinguish proxy Linux worker HWM from real editor RAM/VRAM. Do not silently downgrade required correctness tests.

## Existing evidence / starting point
[Prior native worker and release-gate evidence](History-T068.md).

## Scope boundary
Change only this deliverable; keep canonical straight RGBA8, signed source coordinates, layer/mask semantics and atomic Undo/Redo where relevant. Preserve the existing T-094 fail-closed CI log policy. Record actual commands, exit codes, raw failure controls and source SHA. Do not treat Xvfb/Mesa engine callbacks as physical input-to-photon timing.

## 2026-11-12 Linux portability checkpoint (In Progress)

A **real Godot 4.8 beta3 Linux x86-64 release** was built and isolated-launch
verified from a native-absent, allowlisted Drawing consumer. The release's
ELF/PCK hashes, strict launch exit/status, CPU and full-process `/proc`
VmRSS/VmHWM samples are captured in
[`T105_2026-11-12_linux_export_residency.json`](../benchmarks/T105_2026-11-12_linux_export_residency.json),
with commands and limitations in
[the evidence](../evidence/T-105-2026-11-12-portable-native.md).

For the detached C++ candidates, Linux strict-float oracles remain mandatory;
the Windows-only, deterministic test-source adapter rejects MSVC `/fp:fast`
and explicitly exports the scope-mask ABI from Windows DLLs. The original
T-068 C++ sources and their SHA-pinned historical oracles stay untouched. A **new on-demand two-OS workflow**
compiles and tests the Windows MSVC signed-mask/straight-RGBA8 parity, then
exports and isolates a native-absent Windows Drawing release and records its
OS process working set. None of those Windows tests has run in this Linux
session; it is **not** a Windows pass, and a syntactically valid workflow is
not a hosted green run.

**Remaining T-105 acceptance:** verify Windows/MSVC and Windows export
artifacts on an actual Windows runner; obtain matched real-editor Brush
latency/memory including signed/masked release publication on both platforms,
and measure/label actual physical RAM/VRAM residency where the owner/device
can provide it. No proxy worker HWM, Godot static allocator count, headless
startup or frame callback is promoted to physical input-to-photon evidence.
Keep this ticket **In Progress** until those required gates are evidenced;
T-068 remains In Progress, T-095 retains its independent manual gate, and
T-096 stays Manual Review. The portable default remains GDScript; no new
third-party native dependency is shipped.
