# Adjust pen width with the mouse wheel

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 9.

## Acceptance
- Hovering/focusing the width parameter permits predictable wheel adjustment.
- Agree step/clamping and focus behavior; avoid accidental board zoom while adjusting the control.
- Keep displayed width and subsequent brush behavior synchronized.
- Verify native input dispatch and compatibility with the compact tool-settings layout.

## Implementation (2026-10-30)

- Reused the compact inspector's existing `BrushWidthSpinner` instead of adding
  another control. Mouse-wheel events over either the inner text field **or**
  the spinner's arrow region now adjust width in **0.5 board-unit increments**,
  clamped to the existing **0.5–256** range. Wheel release events are ignored.
- **Focus/hover rule:** the mouse pointer must be over the width control;
  keyboard focus is **not** required. Keyboard focus on the numeric text field
  continues to permit exact values via Enter. Focus left in the field does not
  intercept wheel events elsewhere, including board zoom. The width field is
  read-only in the Fill tool and does not change there.
- Width changes still flow through the existing `brush_width_changed` signal to
  `AtlasCanvas.brush_width`; the next pen gesture uses that displayed value.
  The handled wheel event is consumed so the inspector's containing scroll
  area cannot move while width is being adjusted. A tooltip describes the
  step, bounds, and exact-value alternative. No persistence schema, drawing
  geometry, canvas zoom behavior or inspector minimum width changed.
- This is the chosen initial step/focus policy for usability review. Physical
  trackpad tuning and user acceptance can refine it without altering the
  interaction contract.
