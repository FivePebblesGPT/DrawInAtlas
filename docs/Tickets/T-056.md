# Verify physical independence, asset semantics, huge-world LOD and new files

**Status: PLANNED.** There are **no historical user saves to migrate**. Web support is a release decision, not a presently mandatory feature gate.

## Plan
1. Clean-build/run independent Drawing Godot project from the same monorepo using **only its package and app assets**, without Atlas. Build Atlas and a third minimal consumer against the same package revision. Check no duplicated source or class-name/import conflicts.
2. Roundtrip fresh Drawing documents and Atlas projects: exact raster/alpha, sparse signed chunks, group/tree IDs, one-text-per-layer editability and rasterization, asset links/copies, transformations, save recovery and failed-write atomicity.
3. Assert linked art edits update all references, copies do not; deletion/relink, undo after shared edit, map-unique placement transforms and multi-floor grouping remain intact after save/open.
4. Validate one continuous map-world coordinate reference for D0/D1 despite distinct pixel densities and asset-local placements. Test extreme signed positions/panning, chunk origin rebasing, pen alignment, double clicks and low/high zoom. A missing high-detail group is visibly empty and no full-sized blank texture is allocated.
5. Test Atlas's global cross-map history with camera navigation to original map A, redo and invalid origin cases; ensure navigation itself creates no undo entry. Check pre-commit cancellation and frozen edit target.
6. Run Godot parser/typing, headless, real pointer/framebuffer, clean fresh-package consumer, desktop release export and representative memory/frame-time tests. Run Web export and browser regression **only if Web remains a supported release target**. Record scope decision before claiming final release completion.
7. Owner reviews independent Drawing UX and Atlas floor/LOD/share/copy/entrance flows before declaring the epic complete.

## Acceptance
All supported platforms validated, clean physical isolation, link/copy identity, floor-group mapping, blank LOD, world precision and undo navigation tested, new save formats recoverable. Do not require historical save migration or claim that a legacy Web test proves current browser usability.

## Round 4 acceptance extensions
- Build the Object Editor with the same Drawing engine as standalone/map drawing. Source `Save` updates all linked instances. **Save As entered through instance A creates Variant B and automatically rebinds only A to B**; other instances and the original source remain unchanged. Standalone Save As rebinds none. Require atomic result, stale-instance rejection and one undo/redo binding transaction.
- Place a reused object with two independent world transforms, edit its source, change one instance's transform, and undo both operations separately with the appropriate **object-source vs instance-placement selection and editing mode** restored.
- Verify **Map → Floor group → Detail group → Layers** tree exactly, including persistence, layer/group visibility and authored blank detail. Do not treat the object instance registry as a substitute for map background layers.
- UI shell: test proposed [[DRAW_MODULE_UI_SPEC]] through T-063 at typical/narrow/high-DPI window sizes, menu/tool option overflow and keyboard focus, tabs/unsaved prompts. Owner UX approval remains required.

## Round 5 history and Save As acceptance
- History selection toggle is **OFF by default**; selection-only gestures are absent from history when off and can be stepped backward/forward when on. Regardless of toggle, content undo always restores valid relevant selection and editing mode.
- Selection-only entries are grouped per gesture, do not dirty project/artwork, do not generate duplicate steps during playback, and survive a toggle-off as previously recorded entries until ordinary history reset/truncation.
- Save As from instance A: new asset B + only A's rebind, one atomic content history step; source and other instances unchanged. Undo returns A to old asset and context; redo returns A to B. Stale/deleted instance cannot be rebound.
- Independent Object Editor Save As creates B with no map/instance side effect. Document whether persisted orphan asset B remains after undo without destroying user-created files.
