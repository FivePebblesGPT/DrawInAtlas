# Validate module boundaries, native saves and usability before cleanup

## Status
**PLANNED / BLOCKED by T-051 and T-055.**

## Implementation and verification plan
1. Establish a pre-extraction fixture set from supported native v2 `.scn` checkpoints and representative campaigns: signed/transparent raster chunks, editable text/walls/image props, D0/D1 layers, multiple floors, independent maps, links, tokens/fog and backup recovery.
2. Compare old/new load semantic digests, artwork byte-exact RGBA content, object identity/geometry, save/load isolation and recovery paths. Existing older prototype/terrain formats remain under their documented rejection policy; do not imply newly supported migration.
3. Test both Drawing-only and integrated Atlas: parser/import, explicit-type audit, headless suites, native Xvfb/Mesa interaction and framebuffer checks, Web release export, fresh-process source/export-pack compatibility and memory/large-stroke budgets.
4. Run dependency/static checks: no Atlas classes in Drawing modules, no hidden data mutation in previews, no persistent `AtlasCanvas` dependency in the final Drawing API, and no unintended Drawing-specific duplication in Atlas.
5. Review actual keyboard/pointer UX with the owner using two demonstrations: Drawing-only paint/erase/select/layer/undo and Atlas grid/mask/LOD/links/navigation without artwork distortion.
6. After regression and owner acceptance, remove only proven-unused shims and update `docs/ARCHITECTURE.md`, `docs/CODE_READIBILITY.md` and the run/test instructions. Record any remaining compatibility dependencies and follow-up tickets.

## Compatibility and rollback
- Default policy: **no serialized Resource path, field or native schema changes** as part of extraction. If a change is unavoidable, stop and obtain explicit migration/compatibility approval under a separately scoped ticket.
- `T-015` remains the authority for any legacy placement/artwork conversion. No silent destructive migration.
- Keep changes individually revertible; do not delete original storage/capture paths before their replacement is verified.

## Acceptance
- Automated checks, source/export-pack save portability and Web build are recorded with exact versions/log references.
- Old supported checkpoint loads in the new implementation with semantically identical content; recovery is exercised.
- Owner signs off on usability and module boundaries. Test passes alone cannot close this ticket or E-009.
