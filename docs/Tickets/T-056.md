# Verify physical independence, asset semantics, huge-world LOD and new files

**Status: PLANNED.** There are **no historical user saves to migrate**. Web support is a release decision, not a presently mandatory feature gate.

## Plan
1. Clean-build/run independent Drawing Godot project from the same monorepo using **only its package and app assets**, without Atlas. Build Atlas and a third minimal consumer against the same package revision. Check no duplicated source or class-name/import conflicts.
2. Roundtrip fresh Drawing documents and Atlas projects: exact raster/alpha, sparse signed chunks, group/tree IDs, one-text-per-layer editability and rasterization, asset links/copies, transformations, save recovery and failed-write atomicity.
3. Assert linked art edits update all references, copies do not; deletion/relink, undo after shared edit, map-unique placement transforms and multi-floor grouping remain intact after save/open.
4. Validate one continuous map-world coordinate reference for D0/D1 despite distinct pixel densities and asset-local placements. Test extreme signed positions/panning, chunk origin rebasing, pen alignment, double clicks and low/high zoom. A missing high-detail group is visibly empty and no full-sized blank texture is allocated.
5. Test Atlas's global cross-map history with camera navigation to original map A, redo and invalid origin cases; ensure navigation itself creates no undo entry. Check pre-commit cancellation and frozen edit target.
6. Run Godot parser/typing, headless, real pointer/framebuffer, clean fresh-package consumer, desktop release export and representative memory/frame-time tests. Run Web export and browser regression **only if Web remains a supported release target**. Record scope decision before claiming final release completion.
7. Owner reviews independent Drawing UX and Atlas floor/LOD/share/copy/entrance flows before declaring the epic complete.

## Acceptance
All supported platforms validated, clean physical isolation, link/copy identity, floor-group mapping, blank LOD, world precision and undo navigation tested, new save formats recoverable. Do not require historical save migration or claim that a legacy Web test proves current browser usability.

## Round 4 acceptance extensions
- Build the Object Editor with the same Drawing engine as standalone/map drawing. Source `Save` updates all linked instances. **Save As entered through instance A creates Variant B and automatically rebinds only A to B**; other instances and the original source remain unchanged. Standalone Save As rebinds none. Require atomic result, stale-instance rejection and one undo/redo binding transaction.
- Place a reused object with two independent world transforms, edit its source, change one instance's transform, and undo both operations separately with the appropriate **object-source vs instance-placement selection and editing mode** restored.
- Verify **Map → Floor group → Detail group → Layers** tree exactly, including persistence, layer/group visibility and authored blank detail. Do not treat the object instance registry as a substitute for map background layers.
- UI shell: test proposed [[DRAW_MODULE_UI_SPEC]] through T-063 at typical/narrow/high-DPI window sizes, menu/tool option overflow and keyboard focus, tabs/unsaved prompts. Owner UX approval remains required.

## Round 5 history and Save As acceptance
- History selection toggle is **OFF by default**; selection-only gestures are absent from history when off and can be stepped backward/forward when on. Regardless of toggle, content undo always restores valid relevant selection and editing mode.
- Selection-only entries are grouped per gesture, do not dirty project/artwork, do not generate duplicate steps during playback, and survive a toggle-off as previously recorded entries until ordinary history reset/truncation.
- Save As from instance A: new asset B + only A's rebind, one atomic content history step; source and other instances unchanged. Undo returns A to old asset and context; redo returns A to B. Stale/deleted instance cannot be rebound.
- Independent Object Editor Save As creates B with no map/instance side effect. Document whether persisted orphan asset B remains after undo without destroying user-created files.

## Round 6 verification — retained Variant B after undo
- Save As from instance A creates one B; undo rebinds A to the original while **B still exists and is reopenable/reusable from the asset library**. Other linked instances never change. Repeating undo/redo reuses the same B ID without growing the library or changing pixel content.
- Save/reopen the project or asset library after undo and verify that an unreferenced B persists. If storage is project-owned, assert project dirty/savepoint accurately represents B's surviving addition; if library-owned, test independent library and project savepoint bookkeeping.
- Explicitly delete B while the binding is undone, then exercise redo and assert predictable safe rejection, no accidental asset resurrection and no corrupt instance links. Missing/invalid instance origin must not leave a half-created/half-bound Save As.

## Round 7 validation changes — desktop, portable assets and safe UI
1. Test moving/renaming a project directory with `Campaign file + Objects/` (and bundled font resources): stable IDs and relative references survive. Deleting an Object Asset offers remove placements / `NULL` placeholders / cancel; placeholders preserve transforms/IDs and remain inspectable after restart.
2. Edit a source with several linked placements: while the Object Editor tab has an unsaved red roof, existing instances display the saved roof; **only Save** updates them. Cancel, stale-save rejection and failed writes must never publish a partial source. Check asset library/file state and dirty markers.
3. Nested asset composition (T-064): A→B→C renders with transforms, shared child Save updates all parents, cycles are rejected, corrupted cycles don't crash, missing children yield NULL proxies. This can be a later acceptance milestone than the first flat-Object demo.
4. D1 blank artwork: ensure **grid/entrance navigation overlays stay operational**. Allow explicit pixels-per-world-unit per level and verify alignment at distant signed positions across D0/D1.
5. Global undo camera: if affected object is partly visible leave camera *and zoom* alone; if invisible pan into view without zoom changes; deleted target safely notifies. Selection-history option is app-level and off by default.
6. Verify dedicated Object Editor tab and the Asset Browser dock (T-065) integrate with Colors/Layers/History, including small windows and keyboard focus. Validate bundled licensed fonts and text references in portable save.
7. **Windows/Linux desktop** build and real native pointer/framebuffer testing are the release gates. **Web exports/browser runtime are out of scope for now**, and the original T-044 Web fallback is archived at [[Archive/Web/T-044]]. A later owner decision may reopen Web separately.
8. Do not claim full single-file portability: native campaign plus `Objects/` and bundled resources form the portable project. Document incomplete-copy failure behavior and safe multi-file recovery.

## Round 8 — per-detail sparse multi-file acceptance
- A two-floor/two-detail map has **four stable internal DrawingDocument IDs**. Atlas renders a single logical Map/Floor/Detail/Layers hierarchy without requiring the user to open four drawing files; standalone Drawing still opens its own independent documents.
- On first paint in a blank detail, only the edited document/chunks and necessary manifest/index metadata are materialized. No giant empty texture and no unrelated floor/detail raster rewrite.
- Edit one tiny chunk in a distant sparse region and verify only that region's payload and referenced manifest/generation change; untouched chunk hashes and bytes remain intact. Negative signed chunk coords, partial edge chunks, alpha, hidden RGB and per-detail density roundtrip exactly.
- Delete a required document manifest or chunk file, corrupt a blob, interrupt after staging payload but before root publication, interrupt after root publication, and verify deterministic recovery or explicit failure; never silently load the wrong/blank detail as “success.”
- Move/copy the **entire campaign directory** containing campaign metadata, `Drawings/`, `Objects/` and fonts; all links and identities survive. Copy only the campaign file and verify descriptive missing-resource errors.
- Validate large sparse maps with thousands of available chunks: performance of directory listing, chunk lookup, lazy loading, save-time file updates, opened file count, cleanup of unreachable chunks and bounded memory. No accidental garbage collection of undo-referenced chunks or retained Variant B.
- Cross-document move/undo/redo must leave both document manifests and global context coherent after save/restart. User-facing Atlas tab count must not grow merely because four detail documents exist.
