# Define viewport-appropriate zoom and artwork LOD

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 2; confirmed artwork-layer meaning in [[E-006]].

## Work
Study Leaflet's relevant zoom/LOD/preview principles and compare them with the current experience: small on-screen hexes and disproportionately large Greyhaven tile detail. Translate useful principles into the shared-board model rather than copying a map-document switching hierarchy.

## Acceptance
- Separately authored detail groups and an explicit editing target are confirmed constraints, not alternatives to reopen.
- Explain the current scale mismatch with a reproducible example.
- Agree coordinate/resolution relationships, viewport-coverage criteria and transition behavior before implementation.
- Demonstrate coherent world overview/local detail through zoom in both directions.
- Record unresolved thresholds explicitly; the old fixed camera limits/three-extra-step document gate are not inherited requirements for artwork LOD.
- Define what is shown and how the target is indicated when automatic LOD hides the active editing group; never switch a gesture's editing target silently.

## Investigation result — 2026-10-30

**Design contract:** [[ZOOM_AND_ARTWORK_LOD]] specifies the measured scale
mismatch, Leaflet-derived viewport/zoom principles, continuous board-space
coordinates, bounds/fit calculations, presentation hysteresis, no-blank-map
fallback, and explicit hidden editing target. This confirms and retains the
already-decided separately authored groups and explicit editing target from
[[E-002]], [[E-006]] and [[T-002]]; it does not propose a per-hex document.

**Reproducible sample:** `examples/northern_marches.tres` has a world hex of
45 units radius (90-unit diameter) while Greyhaven's 13×9 city tiles occupy
624×432 board units. At zoom 1 that is a 6.93× apparent width difference. On
an 800×600 drawing viewport, the 90-unit world hex only occupies 45% of the
height even at the current 3× camera ceiling; an 80%-height fit needs zoom
5.33 for the unrotated hex. Neither ratio is a valid geographic-scale
conversion: the old documents use unrelated board coordinates. The old
three-extra-step navigation gate is not an authored-artwork LOD rule.

**Geometry and transition agreement for follow-on implementation:** use
camera-anchored continuous zoom and fit-to-board-bounds, not document
switching; compare rendered detail-region/cell size against the actual canvas
viewport rather than fixed camera numbers; choose only available authored
levels, retain navigability in empty cells; use entry/exit hysteresis and an
atomic presentation switch; defer switches mid-gesture; preserve the selected
editing target and explicitly show/refuse a hidden target. Never rescale saved
artwork, impose an implicit `2^D` zoom mapping or merge floors with LOD.
Manual override/automatic default belong to T-005, transparent registered
previews to T-003, and legacy-map cleanup to later tickets.

**Verification:** Added `tests/zoom_lod_contract_smoke.gd` (28 passing
assertions) and `tests/zoom_lod_contract_visual.gd` (12 passing actual-pixel
and screenshot checks). They reproduce source sample dimensions and demonstrate
D0 → fitted D1 → D0 at an unchanged document position on a rotated grid,
including a fit *above* the existing camera limit, pointer-anchored zoom in
and out, and retention of the hidden D0 editing target. Both tests are wired
into CI. Godot 4.8 beta2 parser/import, explicit-type guard, **19 headless
suites**, **6 native framebuffer suites**, five-frame launch, non-threaded Web
release export, and **4** source/pack save portability steps passed locally.
Remote CI has not been run.

**Left open for T-005 tuning:** numeric entry/exit thresholds, content
footprint selection, safe camera limits, trackpad behavior, sampling quality,
and precise hidden-target control placement. A 0.65/0.45 coverage pair is
only an illustrative usability trial, **not** a shipped or user-accepted
threshold. The automated witness does not establish manual UX acceptance;
future work must still verify the behavior in the editor and browser.
