# Simplify fill implementation for source-only readability

## Source
[[ManualReview_2026-10-30#Code review|Code review]], items 7–9; target: `scripts/editing/fill.gd`.

## Acceptance
- Make fill bounds, traversal, eligibility, limits and result/mutation phases explicit.
- Use explicit types, meaningful names, concise field encodings and commented function steps.
- Preserve behavior during the readability pass, including masks, transparency, limits and failure atomicity; handle any discovered behavior fix separately.
- Verify meaningful existing cases and obtain code-only review beyond previously selected milestone-6 hotspots.

## Implementation — 2026-10-30

- Reorganized `AtlasFill.tiles()` into validation, seed/background bounds,
  four-/six-neighbor traversal with polygon-scope eligibility and a detached
  terrain-copy write phase. Renamed locals for grid cells and palette IDs.
- Reorganized `AtlasFill.raster()` into validated document-to-pixel seed
  mapping, bounded pixel collection, explicit no-op detection and detached
  result creation. Extracted two **cohesive** traversal helpers:
  `_connected_raster_pixels()` compares neighbors to the initial seed color;
  `_matching_stored_raster_pixels()` scans sorted chunk keys and their actual
  image extents. Each returns no more than `limit + 1` matching points so the
  caller can reject an overflow before cloning or writing.
- Named premultiplied RGBA channel differences in `_matches()` without changing
  the maximum-channel comparison; explained finite coordinate bounds, sparse
  chunk coordinate keys, whole-pixel-quad scopes and the shared brush/fill
  snapshot writer. Public signatures, result/error text, traversed cells and
  pixels, data representation and persisted schema are unchanged.
