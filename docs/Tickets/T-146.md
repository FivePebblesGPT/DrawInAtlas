# 96px Hokusai hard-round full-canvas pointer benchmark

**Owner direction (2026-11-15):** First test the existing Hokusai `hard_round.myb` path on the actual **96px full-canvas fill-by-Brush** workload. Brush appearance need not be pixel-identical to Legacy or NativeHard. This is a benchmark and correctness witness, not a native-architecture rewrite or a claim that Hokusai is faster.

## Deliverable

- Extend `drawing/tests/t095_full_canvas_brush_native.gd` (currently rejects `Hokusai`) or add an equivalent actual graphical pointer harness. Use a new 512×512 raster document, one continuous 96px hard-round stroke and the established 100 chronological mouse events/nine-pass serpentine path; **do not substitute `fill_rect`, bucket fill or direct pixel writes**. Exercise the actual Rust preset GDExtension, not a mock.
- Keep identical input trajectory, viewport, zoom, sample clock and cold/warm process setup for Legacy/NativeHard *reference* and Hokusai runs. Log backend/preset and source SHA; use a separate non-parity oracle for Hokusai's accumulating pigment semantics. Quantify total filled area, holes, opacity distribution, final framebuffer coverage and any visual mismatch; do not relax the benchmark to hide unfilled regions. If the current hard-round preset cannot fill the intended area, record the failure and a reproducible tuned-preset experiment separately.
- Capture per-phase native compute, marshalled changed-pixel volume, GDScript stage/blend/preflight, source publication, preview compositor, texture create/upload, input queue, release→commit, input→first visible change, input→settled frame, frame stalls and process memory. Repeat cold and warm runs; report sample counts, p50/p95 and anomalous/process-timeout runs without treating a printed marker as successful exit.
- Verify actual frame/readback coverage, one atomic history transaction, Undo/Redo, cancellation/retry, selection/mask and hidden-RGB persistence as appropriate to the preset. Test extension presence and report any fallback; a Hokusai comparison may not silently run Legacy or NativeHard instead.

## Acceptance

- [x] Reproducible Linux native X11 + software framebuffer test and strict exit/log checks with all 100 pointer events, an explicit filled-area assessment, and source/history/readback assertions; no false Legacy equality requirement.
- [x] Matched baseline/candidate tables with raw logs and exact test commands, timing boundaries, build hash, cold/warm p50/p95 and explicit limitations. Physical hardware/input-to-photon results are distinct and remain with T-095.
- [x] Clear result: viable hard-round preset and measured editor latency, or explicit failure/blocker with source evidence. Do not claim a latency win without comparable end-to-end evidence.

## Boundaries

This first slice changes instrumentation/fixtures or a clearly isolated preset experiment, **not** canonical raster ownership. Existing Legacy and NativeHard remain available strictly for benchmark comparison until T-150. T-095 stays In Progress and owner-gated. T-147 starts only after this benchmark is documented.
