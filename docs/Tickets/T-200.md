# Restore T-095 profiling smoke parity against the actual Hokusai engine

## Bounded acceptance (2026-11-19)

- [x] Diagnose four historical graphical T-095 profiling smokes without
  weakening frame-phase, callback attribution, atomic commit or Undo/Redo
  checks. All four expected `DrawingEditSession.paint_path` to produce the
  same RGBA8 as a native Hokusai gesture. That API is **not the native
  Hokusai algorithm** and is not a valid byte-for-byte Brush oracle after T-153.
  T-199 exposed two failures; broader verification exposed two more.
- [x] Replace those historical references with a separately committed native
  Hokusai control transaction using the same explicit source points, brush
  preset, width, color and input receipt timestamps as the visible Canvas.
  Disable rendering and frame-post-draw callbacks **only on the reference**;
  require exact nonempty rendered source RGBA8 equality to the measured stroke.
- [x] Demonstrate the comparison detects real output drift: changing native
  pigment in the callback smoke and width in the frame-phase smoke must
  produce different bytes, with successful native history commits.
- [x] Retain checked live callback correlation, bounded chronology,
  input-backlog accounting, per-frame CPU accounting, complete native commit
  and exact Undo/Redo. For the changed-preview stage smoke, wait for an
  actual matched Canvas frame/render callback instead of manually invoking
  `_on_frame_post_draw` after one unproven frame. Do not modify application
  painting, native engine, scheduling or profiling.
- [x] Rerun all four graphical tests three times each (86 checks per run),
  adjacent native preview/performance regressions, native and Python tests,
  and ticket-store validation; retain output, exits and limitations.

## Evidence and follow-up

See [T-200 oracle and regression report](../evidence/T-200-2026-11-19-native-profiler-oracle.md)
