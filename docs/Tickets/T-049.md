# Make raster the primary authoring target while retaining semantic vector objects

## Source
Owner-approved raster-dominant representation policy, 2026-10-31: [[INK_REPRESENTATION_DECISION]] and [[T-028]]. Coordinate the compact layer hierarchy with [[T-018]], but do not bundle its outstanding owner acceptance into this implementation.

## Acceptance
- New board/floor authoring starts with an editable raster layer available and selected as the normal freehand target, with a clear way to create/select a semantic vector layer. The obsolete palette-cell terrain artwork has been removed by prerequisite [[T-050]]. A new blank raster must accept first brush strokes, including signed coordinates, without allocation of an unbounded canvas.
- Pen/brush and Eraser have discoverable pixel workflows by default. Raster Bucket and its finite existing-pixel fill semantics are explained accurately. Explicit selection of an ink layer remains possible, and Pen/Eraser never silently rasterize existing vectors or retarget an explicit layer on a zoom/LOD change.
- Wall paths, text, polygon/shape and line tools keep editable vector objects and their metadata. Type-required tool changes use clear layer affordances and do not overwrite or convert previously authored data. A vector freehand stroke in an intentionally selected ink layer remains readable/editable; restricting legacy capability requires a separate decision.
- A suitable raster layer at the presented authored detail level can be selected or created without reinterpreting a different D-level as the edit target. UI labels and keyboard shortcuts are consistent with raster-first authoring.
- Current supported raster/vector native saves and test fixtures round-trip without content conversion; no migration framework or eager flattening is added. Any terrain-bearing prototype save incompatibility is handled/documented by prerequisite [[T-050]]. Undo/redo, cancellation, preview/commit boundaries, clipboard and layer protections remain correct.
- Add headless and native-renderer regression coverage for new-document defaults, brush/eraser/bucket, explicit layer switching, semantic object editing, multiple detail levels, and save/load. Re-run the typing audit, import, export and relevant existing suites. Obtain owner usability acceptance for changed defaults before marking the **interaction** accepted.

## Owner-approved scope refinement (2026-10-31)

The later clarification in [[INK_REPRESENTATION_DECISION]] and
[[RASTER_OBJECTS_WORKFLOW]] supersedes the earlier wording above about
vector-authored lines and polygons. **Brush, eraser, bucket, line, rectangle,
ellipse, and polygon paint raster pixels.** **Wall paths, text, selection,
movement, and placed image props use an Objects layer** with editable semantic
records. The former `AtlasInkLayer` is retained only to load prototype saves,
not as a new authoring target. Tool choice automatically routes to an eligible
layer in the presented detail group, creating one through history if needed;
explicit layer selection remains available.

## Engineering status and verification (2026-11-01)

The raster-first feature implementation arrived with commit `ccd68ff`:

- New board/floor defaults contain a **4 px/board-unit sparse raster** and an
  Objects layer. The default freehand tool is Brush on raster; no unbounded
  backing image is allocated on floor creation. The layer hierarchy exposes
  separate add/select actions and tool-specific labels.
- Brush, eraser, bucket and raster shapes use pixel transactions. Wall paths,
  editable text and placed image props retain independently editable object
  records, with native saving/clipboard/history support. Authored D-levels are
  still independent presentation and editing targets.
- Updated the Bucket inspector's persisted scene hint and runtime help text to
  say explicitly that a **completely blank raster has no fillable stored
  pixels**. This distinguishes transparent pixels in allocated chunks from
  unbounded, unallocated background.
- Expanded `tests/raster_objects_smoke.gd` from **36 to 52 checks** for new
  floor creation when the prior floor had selected Objects, first translucent
  paint at signed chunk coordinates, empty-bucket rejection without history
  mutation, exact undo/redo, D0/D1 isolation, explicit tool-driven creation
  of a D1 raster, and restoration of per-floor layer preferences.
- **20/20 related headless suites**, **6/6 native X11/Mesa framebuffer suites**,
  editor import/parser, explicit typing audit, `git diff --check`, Web release
  export (non-threaded), and **4/4 cross-source/export-pack native save
  portability checks** passed locally using Godot 4.8 beta2. Export was
  generated outside the repository. Remote CI and a real-browser runtime were
  not run; these passing checks are not a substitute for a human interaction
  review. The native performance suite passed but its timing is environment-
  dependent and not a representative device benchmark.

**Still awaiting owner usability acceptance:** verify the auto-routing
experience, the discoverability of Raster versus Objects in the compact layer
hierarchy, Bucket's finite-area explanation, and Brush/Eraser/shape feel in the
running editor. Keep this ticket unchecked in [[Index]] until that acceptance
is explicit; do not equate engineering test success with signed-off UX.
