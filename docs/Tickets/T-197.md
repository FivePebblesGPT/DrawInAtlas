# Remaining 200ms tail and first-preview / physical pacing work

T-196's single idle-deferred drain helps a deep 100-event queue in some
software-X11 observations, without extending the mouse-up callback. The final
four-observation cold p95 regresses (215.2→227.4ms), warm p95 remains 205.4ms,
and first-preview p95 also increases in the paired samples. The 200ms stretch
and full-workspace paced frame acceptance are **not achieved**.

## 2026-11-18: renderer-callback integrity checkpoint (in progress)

The first-preview metric previously accepted the next global
`RenderingServer.frame_post_draw` callback once `first_preview_submit_us`
was nonzero, even without a Canvas frame/active edit-session match. T-197
now stamps `first_frame_post_draw_us` **only** in the existing matched
frame-phase callback, after a Canvas frame submitted after first preview.
No Brush input, native staging, source or release scheduling was changed.

A fail-first Godot regression observed **3 failures/6 checks** in the
unstaged pre-fix Canvas; after restaging it passes **9/9**, including
real Hokusai first preview and one atomic native history commit on X11.
Two confirmed full Drawing workspace processes (16 scenarios total) capture
54%/100% cold/warm/held Brush and Eraser; source RGBA digests match in all
corresponding scenarios. The repeatable remaining hotspot is **Eraser
composition, 79–92ms cumulative**, versus **3–5ms for Brush**;
its transparent/hidden-RGB single-layer preview falls back to per-pixel
GDScript compositing. The benchmark evidence is observational, not a
same-binary performance A/B. No performance win or 200ms p95 has been
claimed; actual optimization and physical acceptance are still open.

See [T-197 checkpoint evidence](../evidence/T-197-2026-11-18-preview-callback.md)
and [raw workspace logs and process exits](../evidence/T-197-2026-11-18-preview-callback-raw/).

## 2026-11-18: source-exact native Eraser display checkpoint (in progress)

Eraser preview's hidden RGB previously rejected the single-raster native crop,
forcing a per-pixel GDScript compositor over the display buffer. Rust now
exports a **separate display-only RGBA8 crop**, clearing RGB only where
alpha is exactly zero. Canonical source, draft, history, Save/Open, and the
normal `read_tile_region` API still carry unchanged hidden RGBA bytes.
Source and display crops use distinct bounded session-cache keys. Multilayer,
text, and cross-storage-tile views remain on the existing renderer.

A four-process same-binary **reference → optimized → optimized → reference**
full-workspace A/B at 54% and 100% zoom replays the *historical hidden-RGB
fallback only*, rather than forcing Brush off its already-fast path.
All four processes exited 0, all 32 native Hokusai gesture cases validated,
and the canonical after-source SHA-256 matched for each corresponding case.
Eraser cumulative composition CPU fell from **76.7–81.9ms to 3.0–3.5ms**;
first-preview callbacks also became earlier in these Eraser observations.
These are four virtual-X11 observations, **not** a population p95. Slow
postdraw intervals of at least 83.33ms still occurred in every process,
and the 200ms p95 and owner hardware targets remain **open**.

The previous T-187 exact-image oracle has been extended to 183/183 checks,
covering real Brush/Eraser, hidden RGB source/display isolation, signed
coordinates, native history and both historical/full fallback references.
Native Rust 35/35, Python 24/24, focused graphical regression suites,
Atlas native history 43/43, offline Ruff/ty, and ticket-store validation
pass. No Windows/export or physical review is claimed.

See [source-exact display A/B report](../evidence/T-197-2026-11-18-native-display.md)
and [raw logs including an unconfirmed-exit attempt](../evidence/T-197-2026-11-18-native-display-raw/).
