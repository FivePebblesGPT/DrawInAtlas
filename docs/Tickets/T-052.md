# Extract independent Drawing document, generic layer groups and snapping

**Status: PLANNED.** Only implement after the relevant T-051 package/API contract is agreed.

## Plan
1. Create the shared Drawing library in the agreed monorepo layout. One canonical source tree must serve the standalone Drawing project and Atlas; no duplicate modified copies and no imports of Atlas assets/classes/autoloads.
2. Define DrawingDocument, generic layer-group tree, stable layer IDs, raster/semantic-object/text layers, sparse signed chunks and optional rendering subranges. **No Drawing Floor class or authored Atlas LOD class.**
3. Extract current raster brush, eraser, shapes, fill, selection, object handling and clipboard from `scripts/artwork/`, `scripts/editing/` and `AtlasArtworkEditor`, maintaining current semantics where applicable.
4. Define Drawing-owned pixel/grid/guide/object snapping with optional candidate/constraint inputs, expressed without `AtlasGrid` or campaign types.
5. Separate source artwork data, generic per-document layer grouping, viewport cache and edit transactions. Tool selection must not mutate the document; successful content edits may create appropriate layers. One-text-per-layer comes from T-058.
6. Expose asset-local coordinate positions and a render/gesture API capable of receiving a camera-relative transformed view from Atlas without embedding world-map rules. Keep stable chunk indexing for negative positions and distant board coordinates.
7. Build/test in an isolated Drawing-only project for brush, alpha, sparse allocation, hidden/locked groups, snapping, cancellation, layer operations and font-independent object behavior.

## Acceptance
Clean Drawing package builds and tests with Atlas removed; generic layer groups can contain many layers; source has zero Atlas references; no complete blank backing images allocated; stable IDs allow later reference/copy handling. No historical-save migration.

## Round 8 — generic per-detail document and sparse persistence boundary
Atlas will own **one generic DrawingDocument per map/floor/detail**; Drawing must **not** receive Atlas map/floor/LOD classes to accommodate this. A DrawingDocument retains its own layers, subgroups, sparse signed raster chunks, text and edit transactions; Atlas resolves which document is active. Reuse **signed coordinates, chunk codec invariants and SHA-256 identity**, but treat the current `AtlasRasterChunk.SIZE = 256` as a **baseline to replace**, not the final Geometry. Owner requests larger chunks; select production size using [[T-067]], and use a versioned per-document tile-size contract under [[T-066]]. Extract into independent Drawing types without copying/importing Atlas internals.

Expose a generic `DrawingDocument` codec and lazily requested chunk interface so [[T-066]] can save/reload document metadata and sparse chunk payloads as separate files. Avoid assuming that a generic document is one giant `.scn`, or that every sparse chunk lives in memory. Cross-document transfer requires explicit copy/move transactions, not shallow-layer aliases. Standalone Drawing can still open ordinary independent artwork even though Atlas's internal D-level documents are not separate user-facing tabs.

## Round 9 — don't hard-code new Drawing tiles to 256
Current source uses `const SIZE: int = 256` and several raster indexing/import paths implicitly depend on that stride. The new Drawing chunk abstraction must centralize its geometry, validate signed addressing, and support a **selected larger production tile size**. Avoid baking a 1024 choice into source without T-067's measured result. Test negative chunk indices, fill/brush/selections at boundaries, image imports, partial chunks, exact lossless serialization and cross-LOD densities.

## Native rasterizer seam to preserve (2026-11-02)
The Drawing core should expose a bounded, typed **edit-region/changed-region** interface so optimized pure Godot or a future GDExtension rasterizer can operate without per-pixel Godot/native calls. Source snapshots are detached; minimize copying of unaffected chunk images, preserve existing once-per-gesture coverage and selection-mask semantics, report changed rectangles, and retain exact canonical pixel/undo semantics. [[T-068]] benchmarks custom C++ versus Blend2D/Skia before any dependency selection. Native raster code must never import Atlas floor/map types.
