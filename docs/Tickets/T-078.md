# Shared dock panel, group and container state model

**Status:** Implemented (2026-11-03). **Scope agreed by owner (2026-11-02)** for the six-stage PhotoCraft-like docking follow-up; this is not implementation approval of a future UX result. See [docking specification](../DRAWING_DOCKING_SPEC.md).

## Objective and boundary

Refactor the T-063 right-dock panel bookkeeping behind a reusable, UI-independent model so **dock and floating hosts share the same panel/group representation**. Do not yet add draggable controls, floating windows, grouped flyout UX or persisted application settings. Existing Drawing and Object Editor layouts/commands must remain functional. No Atlas/pixel/layer data changes.

## Model contract

- Stable unique panel identifiers and registered view factories or equivalent references; one live owner per panel, independent from visibility.
- Ordered **groups** with ordered panel IDs, one selected tab per nonempty group, stable group identity, group collapsed state and independent group ordering within a container.
- A container has an identity and kind (e.g. right dock, future floating in-app host); multiple groups can belong to the same dock. An icon rail derives ordered **panel-level icons with separators at group boundaries**, not one icon per group.
- Distinct state for dock minimize, currently visible shared group flyout, active tab, panel visibility, attachment and group-body collapse.
- Atomic/transactional operations to select, reorder, group, ungroup, transfer and insert a panel or a whole ordered group at an explicit target; invalid or cancelled operations leave the prior state untouched. Group transfer preserves current member order and identity; no ghost/duplicate members or empty ghost groups.
- A versionable plain-data layout snapshot format/codec (or equivalent pure model export) to allow later T-083 persistence without actually writing settings in this ticket.

## Acceptance and evidence

1. Deterministic unit/headless tests construct three singleton groups, merge Colors + Layers, select Layers from its rail icon and verify a **single group owner with ordered tab IDs**. A separator appears only between the merged group and History.
2. Tests reorder tabs, split groups, move an ordered group to another container, and roll back invalid/aborted operations. All IDs remain unique and selection semantics remain valid.
3. Round-trip layout snapshots without losing group membership/order, selected tab, collapse or minimize state. Version mismatch/unknown panel IDs fail predictably or use explicitly tested fallback semantics.
4. Plug the model into the current T-063 shell incrementally without changing visible working behavior. Standalone Drawing and Object Editor existing suites still pass.
5. Document APIs, ownership invariants, data migration plan and test commands. Don't mark Done on documentation-only evidence.

**Next:** [T-079](T-079.md) supplies chevrons, icon rail and flyouts using this model. No owner review gate for this engineering foundation.

## Implementation and verification — 2026-11-03

- `addons/drawing/dock_layout.gd` provides a pure, typed, Atlas-independent `DrawingDockLayout` model. Stable panel and container identities, ordered groups/selected tab, minimized state, one active shared flyout and group collapse are independent. `rail_icons()` emits **one panel icon per attached, visible panel**, with separator flags at group boundaries.
- `attach_panel`, `move_panel`, `split_panel`, `merge_groups` and `move_group` use deep-copy validation before publication; unsupported ownership, unknown IDs, duplicate panel/group/host identifiers, invalid target indices and invalid snapshot versions reject without mutating live state. Whole groups preserve tab order on transfers. Visibility does not implicitly change ownership; factories/references are runtime-only.
- `snapshot()`/`restore()` provide `version: 1` plain-data layout roundtripping, including visibility and active/collapsed/minimized/flyout state. **No settings file is written** (T-083) and there is no drag/drop/floating UI yet (T-079–082).
- `addons/drawing/workspace.gd` registers the existing Colors/Layers/History controls once, keeps their view references in `dock_views`, and installs the model behind the unchanged T-063 stacked interface. The standalone app, Object Editor and third-party consumer still use the same canonical package.
- `drawing/tests/dock_layout_smoke.gd`: **82 headless assertions** in both root and isolated staged Drawing projects, covering ownership, group separators, shared flyout selection, reorder/merge/split, floating host transfer, transactional rejection, snapshot validation and actual workspace binding. Standalone Drawing smoke **38 checks**; T-055 Atlas composition **89 checks**; targeted Xvfb native T-063 layout **75 checks** and keyboard **8 checks**, all passed with Godot `4.8.beta2.official.cafc17a19`. Parser/import and 83-ticket validator passed. No owner manual gate was closed.
