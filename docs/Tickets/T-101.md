# Optional NativeHard and Hokusai end-to-end throughput

**Parent:** [T-095](T-095.md). **State:** Ready. This ticket has its own independently verifiable outcome; it does not inherit the parent’s remaining manual/device acceptance.

## Problem
NativeHard still took ~8.01s and 154 drain frames on the 96px software witness. The native rasterizer alone is not a solution; Hokusai presets have separate stroke behavior.

## Bounded implementation / research
After measuring remaining native-vs-GDScript overhead, optimize the optional ABI/delta handoff and preset path only when profiling justifies it. Keep missing/old GDExtension fallbacks, Hokusai pigment semantics and portable build constraints.

## Acceptance and evidence requirements
Record matched 96px and textured-preset gesture latency, preview frame cost and release latency with/without native code; retain real Rust/Godot transaction rollback, RGBA8, masks, signed coordinates, no-native import and one Undo. Do not make native adoption mandatory for T-095 Legacy acceptance.

## Existing evidence / starting point
[NativeHard-vs-Legacy profile](../evidence/T-095-2026-11-11-96px-godot-profiler.md).

## Scope boundary
Change only this deliverable; keep canonical straight RGBA8, signed source coordinates, layer/mask semantics and atomic Undo/Redo where relevant. Preserve the existing T-094 fail-closed CI log policy. Record actual commands, exit codes, raw failure controls and source SHA. Do not treat Xvfb/Mesa engine callbacks as physical input-to-photon timing.
