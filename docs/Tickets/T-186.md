# Reduce the measured Drawing critical path toward 250ms / 200ms

**Owner target (2026-11-17):** fresh profiling should lead to approximately
halving the discussed ~0.53s workload to **250ms**, with **200ms** preferred.
The app seems usable, but apparent ~12 FPS during strokes still warrants work.
This is a practical current-sprint milestone, not measured comfort or a blanket
physical input-to-photon threshold.

**Dependency satisfied:** T-185 is Done with [fresh full-workspace and rapid
benchmark profiling](../evidence/T-185-2026-11-17-current-workspace-profile.md).
Start with exact-changed native tile generations and warm display refreshes;
retain the T-181 correctness gate. This is a falsifiable *first candidate*,
not an established optimization. T-152 still owns the later post-consolidation checkpoint.

## Deliverable

- Implement one bounded, profile-led improvement. Candidates include localized
  native batch/tile generations, avoiding unrelated warm-tile recomposites,
  fewer RGBA/FFI copies or texture updates, or native staging work **only if
  T-185 identifies them as dominant**. Split further independent hotspots into
  follow-up tickets instead of combining speculative rewrites.
- Compare before/after under identical native/preset hashes, input, zoom,
  rendering environment and cache state. Keep visual stroke semantics fixed;
  account for T-183 brush corrections separately from performance gains.
- Reduce frame stalls as well as total work. Report median/p95 frame times,
  long frames/FPS, first preview, input backlog, release→commit/settled display,
  complete benchmark latency, transfer/upload bytes and memory.
- Target **≤250ms** for T-185's explicitly declared comparable 96px/512²
  benchmark metric; attempt **≤200ms** as the stretch target. Report both
  median and p95, cold and warm results, and any target not reached.
