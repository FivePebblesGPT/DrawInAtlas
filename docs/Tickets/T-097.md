# 96px full-canvas Brush correctness and profiling baseline

**Parent:** [T-095](T-095.md). **State:** Done. This ticket has its own independently verifiable outcome; it does not inherit the parent’s remaining manual/device acceptance.

## Problem
The original large-brush complaint was not represented by a full-canvas pointer-driven correctness and timing witness.

## Bounded implementation / research
Maintain `drawing/tests/t095_full_canvas_brush_native.gd`: 100 chronological actual Godot mouse events in one 96px opaque-red stroke on a new 512×512 image, including framebuffer samples, 262,144 byte-exact RGBA8 pixels, a single history revision and Undo/Redo. Keep per-phase profiler counters and a reproducible cold-process baseline.

## Acceptance and evidence requirements
The test passes source, preview/framebuffer, input accounting and Undo/Redo oracles with the strict `T095_FULL_CANVAS_PASSED` marker. `T095_FULL_CANVAS_P95_BUDGET_MS=100` remains an **opt-in reference-device gate** and is currently **not passed**. The Xvfb/Mesa software runs, native comparison and Godot profiler capture are recorded; no device-to-photon or owner signoff is implied.

## Existing evidence / starting point
[96px pointer benchmark](../evidence/T-095-2026-11-11-full-canvas-96px-red-brush.md) and [Godot profiler attribution](../evidence/T-095-2026-11-11-96px-godot-profiler.md). Delivered in PR #17 before this ticket split; this Done status is for the regression harness, **not** for Brush performance.

## Scope boundary
Change only this deliverable; keep canonical straight RGBA8, signed source coordinates, layer/mask semantics and atomic Undo/Redo where relevant. Preserve the existing T-094 fail-closed CI log policy. Record actual commands, exit codes, raw failure controls and source SHA. Do not treat Xvfb/Mesa engine callbacks as physical input-to-photon timing.
