# Preserve the next Brush/Eraser gesture across an unfinished release backlog

**Done (bounded engineering scope, 2026-11-15).** T-095's input drain can
span several software frames after mouse-up. `DrawingCanvas.start_gesture`
previously rejected every subsequent Brush/Eraser pointer-down while the
old session was draining, so rapid users lost the entire next gesture, even
when its press, motion and release had been delivered by Godot. This was a
real event-ordering gap, distinct from physical latency acceptance.

## Bounded implementation

- Capture **at most one** subsequent Brush/Eraser gesture while a released
  predecessor drains, storing exact source-coordinate press/motion/release
  and arrival times in capped append-only arrays (4096 samples maximum).
  Exceeding the cap emits a user-visible error and discards only the pending
  gesture. Do not build an overlapping `DrawingEditSession` or create history
  from deferred input before the previous session commits.
- Freeze its captured tool, backend/preset, brush color/width, selected pixel
  mask and frame clipping. Source authorization is rechecked when it is
  promoted. The previously released stroke retains priority: pan/zoom and
  tool changes **after** the queued release cannot alter either stroke;
  changing the mapping/tool **during** queued capture cancels only the queue.
  Explicit Escape cancels only the queued gesture while the predecessor is
  draining. Document/layer/edit-policy changes continue to cancel unsafe
  transactions under their preexisting rules.
- Once the previous edit commits successfully, begin a new edit at the
  recorded source position, replay all delivered waypoints with original
  arrival timestamps, and preserve a second atomic Undo/Redo transaction.
  A queued still-held pointer promotes into normal capture; a completed
  queued release can drain over subsequent frames without blocking the GUI.
- Keep the original T-095 6 ms soft atomic-batch drain cap, preview and
  layer revision guards, source-space snapping semantics, direct Godot
  renderer, T-094 fail-late CI and native-absent Legacy default.

## Engineering acceptance and evidence

- [x] Original implementation fails **19/33** independent, signed-mask,
      two-transaction controls; no source runtime error is required for the
      negative control. Candidate passes **69/69** Brush/Eraser, held/released
      queue, navigation, rollback, exact RGBA8 and Undo/Redo assertions.
- [x] Real X11 pointer injection/framebuffer readback passes **19/19**;
      post-release second stroke is visible, and both independent source
      transactions compare byte-exactly to an unsliced reference.
- [x] Existing 60px source-navigation witness updated to exercise buffering
      and Escape without losing the first released transaction. Other
      nearby Brush/preview/standalone and CI checks pass per evidence.
- [x] Both oracles wired under existing **46 required** fast-CI IDs or
      the on-demand native workflow; strict log checking retains known
      Godot post-exit resource leak diagnostics. Ticket store validates.

[Full reproduction commands, results and limitations](../evidence/T-124-2026-11-15-queued-brush-backlog.md).

**Scope boundary:** This change prevents an already delivered second stroke
from being rejected, but does not establish a physical GPU input-to-photon
p95 or a target recovery duration. Two strokes are sequential, not
simultaneously rasterized. A third press while the single bounded queue is
occupied still receives a clear error. T-095 remains **In Progress**, with
`manual_review: true` and owner hardware acceptance explicitly unresolved.
T-085/T-086 display/physical UX and T-106 hosted CI stay open.

## 2026-11-23 — T-284 deterministic queued-input regression

The old 210-sample headless predecessor could finish within the current
256-segment synchronous mouse-up budget, so the test's next press sometimes
ran against an idle canvas instead of the queued-gesture path. [T-284](T-284.md)
uses 840 distinct source samples and guards stale-revision fault injection
against an absent predecessor. The beta4 Rust-backed headless witness passes
four 78-check runs and the real X11 pointer/framebuffer witness passes 20/20;
shortening the predecessor to 12 samples fails as intended without a script
crash. This is regression-fixture hardening, not owner/device approval.
