# Bootstrap native authority on first direct tile-local edit

**Split from T-148.** A non-Brush tile-local edit on a document that had
never used Hokusai previously published a Godot-only per-pixel history map.
The next native gesture had to attach its tile store later, despite an
already committed tile-local transaction. T-230 fixed detached history
replay; this ticket addresses **edit production** for the tile-local path.

## Acceptance

- [x] With `DrawingNativeTiles` available, preflight signed tile bounds, the
  128-tile limit and the stride-aware three-span/256 MiB budget before lazy
  source resolution, even when no Rust store has been attached.
- [x] After full source preflight, create a provisional Rust store at the
  document revision, import the exact original RGBA8 tile images, and adopt
  recorded or untracked edits. Publish the owner only after successful
  adoption; failed source, import or commit may not attach partial authority
  or mutate document pixels, revision or history.
- [x] Preserve full-tile native history tokens for local and host-owned
  commands, hidden RGB, signed tiles, Undo/Redo, new pixel edits after the
  tile-local bootstrap, and portable Save/Open recovery.
- [x] Demonstrate fail-first, run T-100's independent pixel oracle, nearby
  native/history suites, Atlas integration and native X11 Canvas. Wire a
  strict assertion count into the required-native fast CI job and update docs.

## Completion — 2026-11-22

The first `_publish_tile_edit` now completes one bounded, failure-atomic
`DrawingNativeTiles` adoption even when no native gesture has yet occurred.
Untouched resident/lazy-loaded sources are imported into the provisional
store before changing them. Failed source verification and transfer preflight
leave the store absent. The attached owner and its tile snapshots continue
through the document's shared native Undo/Redo and host history bridges.

[Fail-first and local validation evidence](../evidence/T-232-2026-11-22-tile-bootstrap.md).

**Scope boundary:** The ordinary `_publish_edit` global pixel-map producer
remains native-absent until later T-148 work (or the first native replay).
This is not yet general host-owned command lifetime migration, Rust-side
production of all raster tools, physical owner approval, or hosted CI proof.
T-148 remains In Progress and T-149 remains Blocked.

**Later scope update (T-233, 2026-11-22):** The previously open ordinary
pixel-map publication producer has since acquired native ownership; see
[T-233](T-233.md). T-148 still has other open producer and host-lifetime work.
