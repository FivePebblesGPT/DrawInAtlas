# Cold dense viewport first-population performance

**Parent:** [T-086](T-086.md). **State: Done (2026-11-12)** for this independent software cold-frame scheduling deliverable, **not** for T-086's remaining owner hardware, memory-pressure or zoom-out gates.

## Implemented

- A committed-only, occupancy-indexed scheduler selects up to four missing **128px display tiles nearest the viewport/pointer focus**, then composes at least one per draw up to a **10ms soft CPU budget**. Subsequent draw requests are queued from the next `_process` tick, never recursively from `_draw`, and revalidate document/revision, source epoch, visibility, pan, zoom and cache dirtiness.
- A 16-tile 512² source now settles over successive frames instead of freezing a single cold draw. Pixel/alpha content is never changed; all previously cached textures are drawn immediately and the remaining images arrive incrementally.
- Tiny footprints, unsupported/unknown occupancy, active detached previews and views exceeding the **144 retained-texture limit** use the old complete-frame path. Large sparse viewport lookup iterates the smaller occupancy map, avoiding thousands of empty display cells on warm redraws. No new global source scan or retained texture allocation is added.

## Evidence and closure

- **Red control:** exact prior T-101 Canvas at `d892ac1d548156fc4bf066711df4f552a507de78` fails **20/110** dedicated native cold scheduling checks (exit 1); unrelated source/framebuffer/Undo checks remain intact. The candidate passes **110/110** with a real GL-compat Xvfb framebuffer, 25/50/100%, two full signed 512² raster layers, hidden RGB, pan, visibility, signed edits and full-source byte-identical Undo/Redo hashes.
- New deterministic **13/13 headless** scheduler oracle validates focus, dirty/stale-preview invalidation and safe fallback. Neighbors pass: 45/45 cold composite, 82/82 visible plan and 153/153 native viewport; other required viewport models pass.
- On Godot **4.8.beta3 / Mesa llvmpipe**, cold 50% first-frame p50 fell from **350–357ms** (two previous-source three-trial sets) to **51.3ms** (candidate three trials); worst per-draw CPU p95 fell from **356–397ms** to **25.5ms**. Full settling worsened from **350–357ms to 437.9ms**: this is responsiveness by incremental presentation, **not** a whole-render throughput win. The 10ms budget is soft; a second candidate control observed a 95ms draw outlier. Warm 50% p50 stayed **0.26–0.30ms → 0.26ms** after sparse index iteration. Memory and texture counts remain bounded as documented, not proven across stressed owner GPUs.
