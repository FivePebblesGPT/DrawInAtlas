# Cold dense viewport first-population performance

**Parent:** [T-086](T-086.md). **State:** Ready. This ticket has its own independently verifiable outcome; it does not inherit the parent’s remaining manual/device acceptance.

## Problem
T-086 reports a regression in first 50% viewport population despite improvements to cached redraws.

## Bounded implementation / research
Profile cold tile index, render, upload and eviction against dense multi-layer 512² through large sparse documents. Bound incremental first-population work and avoid repeated full source scans without changing stored pixels.

## Acceptance and evidence requirements
Record cold and warm first-frame/settling p50/p95, max per-frame CPU, texture bytes and process memory. Compare old/new source bytes and native framebuffer at 25/50/100% and signed seams; verify no dropped or wrong tiles after pan, visibility and Undo.

## Existing evidence / starting point
[Existing viewport history](History-T086.md) retains the earlier software/cold-cache observations.

## Scope boundary
Change only this deliverable; keep canonical straight RGBA8, signed source coordinates, layer/mask semantics and atomic Undo/Redo where relevant. Preserve the existing T-094 fail-closed CI log policy. Record actual commands, exit codes, raw failure controls and source SHA. Do not treat Xvfb/Mesa engine callbacks as physical input-to-photon timing.
