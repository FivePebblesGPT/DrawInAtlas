# Bound signed lazy raster tile IDs before persistence

**Split from T-148:** Live native tile history and publication reject unsafe
signed source coordinates, but `DrawingDocument.register_lazy_chunk()`
previously registered arbitrarily large integer tile IDs. `export_manifest()`
also accepted out-of-range resident IDs if an external producer injected them.
The resulting lazy/save projection could hold tile IDs the Godot native-tile
publication path could never accept. This is a source-authority and overflow
boundary, not a change in Hokusai painting or a request for owner approval.

## Acceptance

- [x] Use the Godot consumer's existing `2^52 / storage_stride` inclusive
  signed tile-origin limit for lazy registration and manifest export. Compare
  with positive/negative limits rather than `abs()` (unsafe for `INT64_MIN`).
  Reject before changing pending refs, persistence identities, epochs or pixels.
- [x] Logical manifest open and portable `.drawing` decode reject an out-of-
  bounds signed tile before allowing the source into the document. Valid large
  positive/negative signed tile IDs still serialize/resolve and preserve exact
  straight RGBA8, including hidden RGB under zero alpha.
- [x] Retain the persistent Rust tile store, existing Brush history token,
  document revision and unrelated Ink pixels on every rejection. Confirm
  native Undo/Redo and successful retry; add the regression to the native CI
  loop, without claiming hosted CI or hardware T-095 acceptance.
- [x] Real native Godot regression, fail-first control with the same fixture,
  neighboring lazy-source/Atlas/Object/native-history suites, strict Rust
  checks and software-X11 graphical witnesses pass; update the ABI and Index.

## Completed 2026-11-16

`SignedTiles.tile_coordinates_in_projection_range` shares the conservative
Godot projection bound between lazy registration and manifest export. It
compares both `int64` tile coordinates without `abs()` overflow. `open_manifest`
uses checked registration, and `.drawing` decode uses `open_manifest`; neither
can admit an invalid source through the public persistence route. Rust's
separate input-coordinate bound is unchanged, and no source algorithm or
history ABI was modified.

The new real-native fixture passes **24/24 checks**, including valid distant
signed RGBA8 `.drawing` roundtrip and intact native Undo/Redo. With the **same
fixture** against pre-fix `document.gd` and `signed_tiles.gd`, **9/24 failed**
as expected. All **30 final suite invocations** passed locally, including the
native tile/history, root lazy-cache and Atlas/Object regressions and both X11
witnesses; see [T-158 evidence](../evidence/T-158-2026-11-16-tile-bounds.md).

**Still open:** T-148's universal raster producers and host-owned history
authority, T-149's downstream bulk display/save conversion, and T-095's
reference-device/manual acceptance. This child does not close them.
