# Reuse bounded selection-outline candidate plans across deferred frames

**Done — 2026-11-15; local planning throughput only.** T-141 indexes up to 8192
explicit selected pixels and prioritizes 4096 occupied outline tiles; T-143
reconciles a saturated cache when source clipping changes. The overlay traces
just four new tiles per frame, but until this ticket every redraw also rebuilt
and sorted the same 4300-input eligibility plan. A stationary selection could
therefore repeat millisecond-scale planning for hundreds of successive frames.

## Acceptance

- [x] Cache only the existing **bounded** candidate list (at most 4096 tiles)
  for an unchanged selection, mask generation, exact clipped source footprint,
  and camera focal tile. Return detached arrays so callers cannot poison the
  plan. Preserve bounded 8192-input indexing, focal bucket priority and the
  original full-scan fallback for inverted, compound, or oversized masks.
- [x] Invalidate after `set_selection_mask`, legacy rectangle assignment,
  in-place `DrawingSelection.set_mask`/boolean combination, direct inversion,
  altered pixel/operation count, focal camera move or sub-tile clipped view
  change. In-place mask mutation also invalidates previously traced contours.
  Do not change mask truth, RGBA8 pixels, selection/Move authorization or
  Undo/Redo. The existing 4096 contour cache and four-new-contours-per-frame
  budget are unchanged.
- [x] Reproduce repeated candidate work against the unchanged T-143 Git tree,
  compare median/p95 CPU planning on the same pinned Godot beta3 runner, and
  verify real framebuffer outlines while the progressive contour backlog
  drains. Test context changes and malformed/oversized fallback behavior.
- [x] Run neighboring T-139–T-143 headless/native selection tests, T-088
  clipboard and sparse Paste/Capture, T-096 large-mask oracle, strict logs,
  independent native-absent Drawing consumer, typing, CI/source contracts and
  canonical ticket validator. Attach to the existing 46-check T-088 CI step;
  keep native X11 tests on demand.

## Boundaries

The candidate-plan cache is keyed to the DrawingSelection mutation API,
including an explicit generation for supported public mutation methods;
callers must use `set_selection_mask` or the selection's public mutators,
not write private `_pixel_mask` entries directly. This reduces the isolated
stationary candidate-planning cost, **not** the total contour generation,
full-canvas draw time, or physical input-to-photon latency. T-088 remains
**In Progress**, T-096 remains **Manual Review**, and the original owner,
physical-hardware, hosted-CI and other ticket gates remain unchanged.
