# Move tool for selected artwork and editable objects

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], items 10 and 16.

## Acceptance
- Follow Paint.net for ordinary artwork movement and active-layer selection by default; clearly identify selected editable path/text objects.
- Live feedback, cancellation, snapping options and completed transforms are consistent.
- Do not introduce battlemat containers or their content-following transform policy. Projection framing uses a distinct presentation object in [[T-013]].
- Operations respect masks/protections and remain undoable without unintended resampling.

## Implemented interaction contract and evidence (2026-10-30)

See [[MOVE_WORKFLOW]] for the full contract. The **Move artwork (M)** tool is
separate from Select artwork (V) and Select grid cell, and operates on only
the current authored layer. It preserves V's multi-object selection through
tool switches, supports pick-and-drag movement with live previews and Escape
cancellation, and never moves a document, map link, grid or hidden detail.

- Ink stroke points move in board space without changing RGBA or width. A
  raster asset moves by composing its existing affine transform; all chunks
  and pixel content remain unchanged. A movement is one atomic undoable edit,
  and no-op, locked, masked, stale, and invalid movements don't commit.
- Optional T-016 snapping uses cell-center displacement even on rotated hex
  grids, with no jump for existing off-grid art. The source and destination
  must both satisfy selection/edit masks. The UI identifies ink-stroke versus
  whole-raster selection; new editable path and text types must integrate with
  this in their own [[T-026]] and [[T-027]] tickets.
- `tests/move_smoke.gd`: **37/37** checks for selection, group moves,
  cancellation, invalid and hidden targets, rotated-hex snapping, raster
  transform preservation, undo/redo and native-save round trip.
- `tests/move_visual.gd`: **10/10** native pointer/keyboard/framebuffer checks
  for the M shortcut, icon, drag preview, exact undo, inspector feedback and
  960×660 / 800×600 layout. Captures under `user://validation/move-*.png`.
- Godot 4.8 beta2: **35/35** headless suites, **19/19** native framebuffer
  suites, parser/import, explicit types, main-scene launch, Web release
  export, and **4/4** source/exported-pack save-interoperability checks all
  passed locally. New headless and native suites are wired into CI.
- Remote CI, physical-device usability review, and browser-runtime tests
  remain unverified. No saved-data schema, LOD coordinate ownership or
  battlemat placement policy was changed.
