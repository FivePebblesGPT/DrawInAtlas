# Single text element per editable layer, created on first edit

**Status: IMPLEMENTED (2026-11-02). Owner-approved one-text-per-layer semantics are enforced in the canonical Drawing package.**

## Plan
1. Introduce generic Drawing text layer with **exactly one editable text object**, stable layer ID, text/style/font/fallback/layout, transform and visible flag. Grouping is generic; floor assignment is Atlas's layer-group mapping.
2. Selecting Text, opening an empty edit or cancelling is non-mutating. First **successful text content commit** creates the text layer and content atomically, with one history entry; editing existing text modifies its current layer rather than creating a second.
3. Handle many small text labels without giant sidebars: compact rows, layer grouping, virtualization/search and scroll-to-selection. Cross-floor sharing follows T-060 asset semantics, not implicit text duplication.
4. Define explicit undoable `Rasterize Layer` converting one text element into raster layer contents at recorded pixel density/transform. Preserve layer order, appearance and alpha within a documented font-rendering tolerance; no silent destructive conversion on tool switch.
5. Test edits/rename/copy, empty text, cancellation, selection, locked layers, negative coordinates, zoom/culling, font fallback, save/open, undo/redo and rasterization rollback in Drawing standalone and Atlas.

## Acceptance
One successful new text => one text layer => one text element. No layer on tool switch or failed edit. Rasterized pixels are ordinary editable raster; undo recovers text editability. Text/layer UI scales to map labels. No historical-save migration.

## Object Editor coordination — 2026-11-01
An Object Asset may contain Drawing text layers with exactly one text element each; editing the text in an object source and saving the Object Asset updates linked Atlas instances. Do not create Atlas-specific text rendering or rasterization paths; one Drawing implementation serves standalone, map painting and Object Editor ([[T-062]]).

## Round 7 — bundled project fonts
The owner approved **bundling required known fonts into the portable project save** and storing explicit font references. Define a stable font identity and loading fallback; choose embedded native resource versus project-relative font resource file under T-051/E-SAVE. Verify redistribution rights before embedding user-system fonts; report missing fonts rather than silently corrupting text layout. Font assets must survive campaign-directory relocation, object-source Save/Save As and text rasterization.

## Completion evidence — 2026-11-02

**Implemented in one canonical package:** `addons/drawing/text_element.gd`,
`text_raster.gd`, `document.gd`, `renderer.gd`, `file_io.gd` and licensed
`fonts/Lato-{Regular,Bold,Italic}.ttf` with OFL license. A text layer has exactly
one `DrawingTextElement` (content, stable font identity/style, size, RGBA color,
world-pixel position, rotation, scaling and left/center/right alignment).
`commit_text("", draft, expected_revision, parent)` atomically creates the first
layer *only for a validated nonempty commit*. Editing the same layer never adds
a second element. New/edit/conversion each produce one local history event;
undo/redo preserve layer IDs and source editability. `rasterize_text()` writes
ordinary sparse editable RGBA8 tiles at the document's recorded pixel density,
using exactly the same Godot FontFile/OpenType glyph atlas CPU compositing path
as the live Drawing viewport: **zero differing RGBA bytes in the core screenshot
witness**. Unchanged transparency is preserved; over-budget rasterization aborts
without publishing. Atlas can reuse the same package; T-055 still owns *actual*
Atlas canvas/tool input integration.

**Standalone user experience:** Text-tool canvas click opens a text editor
without a layer; cancellation/tool switch is non-mutating. Dialog exposes
bundled Regular/Bold/Italic, point size, alignment, color and rotation. Layer
menu offers explicit `Rasterize text layer`. Existing text is re-edited in its
current layer. The layer list is searchable by label/name and **paged at 200
rows**, with indentation for group nesting and selection scroll-to-reveal.
Actual application-level tree expansion and owner UX validation remain T-063/T-059.

**Font portability:** Only verified SIL OFL Lato fonts are bundled; no random
OS font is embedded. `.drawing` saves carry the required exact font bytes,
explicit font version identity, SHA-256 and full redistribution license.
Reopening verifies the font against the canonical licensed binary. Missing,
unknown, modified or unlicensed font assets are reported as errors; unsupported
glyphs in an otherwise valid bundled font render a visible `?` replacement and
attach a `GLYPH_FALLBACK` warning to `DrawingResult` without altering saved
Unicode source text. In an exported desktop project the codec reads exact bytes from imported
`FontFile` resources, rather than missing original `.ttf` paths, and the OFL
license is explicitly included in the PCK. Known font is available after
standalone project relocation; in campaign folders, T-066 is responsible
for generation-wide `Fonts/` publication and recovery. Object Asset source
`.drawing` files use this same codec, so T-060 draft/Save/Save As inherits these
verified references. No historical save migration.
