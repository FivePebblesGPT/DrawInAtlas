# Visible image frame, screen-space transparency checkerboard, grid and snap

**Status: In Progress — corrective engineering checkpoint (2026-11-07).** The 2026-11-06 implementation was recorded as engineering Done, but the PR #13 handoff identifies two regressions: Brush painted outside the finite standalone image and checker phase shifted at the image's top/left edge. The corrections and local tests below are complete; physical Linux/Windows owner UX findings #02 and #16 remain **PENDING** in the separate T-059 gate. No owner acceptance has been inferred. Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
Standalone artwork currently paints on an opaque infinite-looking dark surface with no visible image edge or checkerboard. The only `Snap (8 px)` toggle rounds cursor positions; **it does not display a grid**. Sparse unlimited storage remains important for Atlas, so the UI image extent must be separated from the underlying storage model.

## Engineering tasks
1. Introduce explicit standalone image bounds (dimensions/origin, visible image edge) while preserving sparse unbounded internal documents and Object Asset origin/bounds; document resize/crop behavior before implementing it.
2. Render a screen-space, non-zoomable checkerboard **inside transparent image bounds** and a distinguishable workspace outside. Reconcile clipping, panning, zoom, negative coords and exported transparent pixels.
3. Provide independent `Show grid` and `Snap to grid` settings, configurable spacing and visible origin/spacing. No accidental change to Atlas-owned grids or world snapping.
4. Add cursor/image size/status behavior and separate model from presentation; do not silently crop artwork or change existing `.drawing` content.

## Acceptance / verification
- [x] New/open ordinary `.drawing` shows usable image edge and checkerboard at different zooms (checker size stays in screen pixels).
- [x] Infinite/legacy document compatibility and Object Asset framing remain defined and safe; no data loss on reopen.
- [x] Grid visibility independent of snap; snapping only affects intended tools, and visible grid aligns with edits under pan/zoom.
- [x] Test small/large/negative origins, zoom, alpha roundtrip and Atlas independent-detail surfaces.

## Boundaries
- Preserve the one canonical Drawing package shared with Atlas, byte-exact saved RGBA8, source identity, one undoable content transaction per gesture and signed sparse coordinates.
- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.

## Implementation record — 2026-11-06

**Canonical code:** `addons/drawing/image_frame.gd` (frame validation,
legacy sparse-extent inference); `file_io.gd` (optional envelope metadata and
single-read validated `open_with_frame`, backward-compatible ordinary `open`);
`canvas.gd` (clipped screen-pixel checker tiles, source-grid overlay and
separate snap flag); `workspace.gd` (per-tab frame, fit/reset, metadata dirty,
Image/View menus and signed spacing/origin controls). No generated
`drawing/addons/` copies are tracked. Atlas `DrawingDocument`, Object Asset
frame semantics, world-grid transforms, native pixel format and history were
**not** changed. Default standalone image guide is signed
`Rect2i(-256,-256,512,512)`; a legacy `.drawing` without `image_frame`
inherits a minimum 512px non-cropping guide enclosing known raster tiles/text.
Extreme sparse coordinates may exceed the safe 1,000,000px image guide; in
that case the UI uses the default view **without deleting or hiding the data**.

**Non-destructive image-frame contract:** `image_frame.origin` is two signed
canonical decimal strings (avoids JSON float truncation), `size` is two
positive integral dimensions (1..1,000,000), and both edges remain within
±1,000,000,000 coordinates. Invalid metadata fails before file publication
and fails closed on open. Changing the frame only updates the standalone
view/dirty marker; Save stores metadata alongside untouched RGBA8 chunks.
There is deliberately **no crop/resample/resize of pixels** in this ticket.
A future destructive operation needs explicit outside-pixel, undo, signed
origin and export rules. The 16-screen-pixel checker is not serialized into
alpha; art outside the guide continues to render and roundtrip.

**Grid contract:** View → Show grid and the tool Snap switch are independent;
View → Grid spacing and origin… sets a signed source origin and 2..4096px
spacing. Only Drawing input positions are snapped; panning and viewport
transform remain raw, and Atlas's grid remains owned by Atlas. Grid lines are
painted only within the image frame, source-aligned after pan/zoom. At low zoom,
the overlay skips subpixel lines by whole spacing multiples; the snap model
still uses every spacing intersection. Preferences persist across tabs in the
running workspace, not across app launches nor into `.drawing` content.

## Corrective checkpoint — 2026-11-07 (PR #13)

**Defects:** A bounded *standalone* image was previously only a visual guide;
Brush and Eraser could create new pixels in the surrounding workspace. Also,
`draw_texture_rect(checker, visible_intersection, tiled=true)` reset its UV
phase each time the intersection moved during panning, producing an apparent
checker shift at the left/top edge (with inconsistent phase at other edges).
These were distinct from the earlier legacy-sparse-file preservation contract.

**Correction:** `workspace.gd` explicitly enables
`canvas.clip_strokes_to_image_frame` for standalone tabs. Its default remains
**false** for Atlas/embedded hosts, including those displaying a frame guide.
An out-of-frame Brush/Eraser mousedown does not start a session; strokes
started inside may cross the edge, but the *whole swept brush footprint* is
intersected with a frozen `Rect2i` during `DrawingEditSession.paint_path`
(candidate-window clipping before the pixel cap). This avoids altering the
user selection expression, including saturated/inverted masks, and does not
change `DrawingSelection`'s enabled-empty deny-all semantics in Atlas. Frame
changes during a held stroke cancel its detached session without publication.
The path stays continuous and publishes one Undo step; the eraser cannot
remove preserved off-frame pixels. Other editing commands (including Move,
clipboard, import and direct document APIs) are **not** silently clipped by
this Brush/Eraser-specific correction.

The checker now uses a viewport-origin-anchored repeated texture source region
with wrap enabled. The checker is still exactly **16 screen pixels** per
square, clipped to the visible frame and never written to RGBA8. The same
texture remains in use; no new per-frame checker texture is allocated.

**Save/export and old off-frame data:** Existing off-frame sparse pixels
remain visible, editable through the direct shared API and serializable in
`.drawing`; frame resize is non-destructive. Neither Save nor Open crops the
canonical chunks or their hidden RGB. There is **no** automatic PNG export
or destructive crop operation in this standalone workflow; future flattened
export/crop commands must specify their extent and treatment of off-frame art
rather than silently discard it. A native unbounded Atlas authoring host
retains paint access beyond any optional guide.
