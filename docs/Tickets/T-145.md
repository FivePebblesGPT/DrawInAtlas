# Retain eligible selection contours across visible tile-window pans

**Done — 2026-11-15; bounded overlay continuity only.** T-142 retained
saturated contour tiles when the focal plan changed *inside* a stable visible
64px window; T-143 reconciled sub-tile clipped footprints. Both still allowed
`_sync_mask_outline_cache()` to clear every traced tile when the camera moved
far enough to shift the visible tile window, even when over 4,000 tiles
remained in the new eligible candidate plan. Since only four new contour tiles
are generated per frame, a previously visible island could disappear after
a normal one-tile pan until the progressive backlog caught up.

## Acceptance

- [x] For a changed visible tile window, preserve cached **source-coordinate**
  contours only when their tiles remain in the newly eligible candidate list.
  Evict old off-plan tiles and record the new window and clipped footprint;
  do not retain stale contours after selection replacement or mutation.
- [x] Preserve the 4,096-cached-contour hard cap, four-new-contours-per-frame
  scheduling, focal candidate order, signed source coordinates, exact mask
  authorization and document/Undo/Redo state. Keep the existing conservative
  fallback for compound, inverted and oversized masks.
- [x] Reproduce the window-shift loss on the exact unmodified T-144 Canvas;
  use a source-space 64px camera pan that genuinely changes the visible
  tile window, not only its focal priority. Prove a distant selected island
  stays outlined on a real native X11 framebuffer before the cache drains.
- [x] Run T-139–T-144 headless/native outlines, T-088 selection/clipboard,
  sparse Paste/Capture, T-096 large mask and native Move, independent

## Boundaries

The cached line segments are generated for individual 64px source tiles,
independently of the viewport clip. Changing the camera does not mutate those
segments, but a changed selection **does**, so selection mutation continues
to fully invalidate its cache. The changed-window `clear()` branch from
T-142 is superseded only for *overlapping eligible contours*; a wholly
unrelated window retains no old tile. T-088 stays **In Progress**, T-096
stays **Manual Review**, and hardware, hosted CI, physical user acceptance
and other manual gates remain unchanged.
