# Bounded sparse atomic Brush publication and Undo

**Parent:** [T-095](T-095.md). **State:** Ready. This ticket has its own independently verifiable outcome; it does not inherit the parent’s remaining manual/device acceptance.

## Problem
Canonical publication alone consumed ~1.578s CPU for the 96px full-canvas Legacy stroke in the software-rendered baseline.

## Bounded implementation / research
Profile `DrawingDocument._publish_edit()` and batch/tile changed-pixel publication, cloning and history deltas. Implement a tile-local/copy-on-write commit path if measured as faster, keeping source-revision conflict rejection, immutable prior state and one atomic Undo transaction.

## Acceptance and evidence requirements
Paired cold/warm 96px pointer runs report commit CPU p50/p95/max, bytes copied, peak memory and full gesture time; independent RGBA8 oracles cover all 262,144 pixels, hidden RGB, signed anchors, mask/layers, cancelled/failed commits, retry, mixed edits and Undo/Redo. Never publish partial state on failure.

## Existing evidence / starting point
[Commit cost attribution](../evidence/T-095-2026-11-11-96px-godot-profiler.md).

## Scope boundary
Change only this deliverable; keep canonical straight RGBA8, signed source coordinates, layer/mask semantics and atomic Undo/Redo where relevant. Preserve the existing T-094 fail-closed CI log policy. Record actual commands, exit codes, raw failure controls and source SHA. Do not treat Xvfb/Mesa engine callbacks as physical input-to-photon timing.
