# Reject noncanonical Godot PCK directory resource names

## Problem

T-218 checks complete payload integrity and non-overlap, but the PCK v4
inspector still accepted ambiguous directory names: an embedded NUL, surplus
whole blocks of NUL padding and ASCII control/DEL characters. Those entries
can carry valid payload checksums while not being valid canonical resource
names. The verifier should reject them before approving or publishing the
required-native standalone export.

## Acceptance

- [x] Reproduce six fail-first assertions covering embedded NUL, four extra
      NUL padding bytes, newline, carriage return, control and DEL characters;
      retain a valid non-ASCII UTF-8 resource as a positive control.
- [x] Require UTF-8 resource names followed by exactly the zero bytes needed
      for 4-byte alignment, with no embedded NUL or control characters.
      Preserve existing path traversal, duplicate, size and checksum guards.
- [x] Prove Linux native packaging rejects a PCK with an invalid optional
      resource name **before** `.so` installation, preserving the entire
      exported file inventory and preflight cleanup.
- [x] Wire five new unit tests into Make and both relevant CI workflows;
      verify the full configured Python suite, pinned Ruff/ty, native Rust,
      and a real 528-resource Godot beta3 PCK plus isolated native ABI launch.
- [x] Preserve fail-first and passing raw logs, SHA-256 source hashes,
      process outcomes and unchanged owner/manual-review gates.

## Evidence and remaining gates

[Fail-first comparison, tests, real-pack compatibility and source hashes](../evidence/T-219-2026-11-19-pck-names.md).

This is a canonical **directory-name encoding** check, not publisher
authentication, a full PCK interpreter or physical-device acceptance.
The runtime smoke uses the supplied Godot beta3 binary with a real exported
PCK, not an official Linux release-template ELF. Hosted CI, Windows native
runtime, owner hardware approval and T-197 performance acceptance remain
separate. T-105, T-106 and T-180 remain In Progress.
