# Reject undeclared directories and special nodes in standalone Drawing source stages

## Problem

After T-213, the *exported distribution* inventory rejected extra directories,
FIFOs and Unix sockets, but `inspect_stage()` still built its source inventory
from `is_file()` results. An undeclared empty sibling directory or special
filesystem node was silently ignored and could accompany a stage approved for
native Linux packaging. This was a stage-vs-export validation inconsistency;
no Brush or raster engine code was involved.

## Acceptance

- [x] Reproduce rejection failures for an extra root directory, an extra
      `addons/` sibling, FIFOs in tests and generated cache paths, and a Unix
      socket in the cache. Retain the fail-first output.
- [x] Reject every symlink, undeclared directory, and non-regular staged entry
      before reading required files or publishing a native library.
- [x] Preserve permitted script, test, canonical `addons/drawing` and generated
      `.godot` subtrees; retain source-file and manifest/ELF checks.
- [x] Rejected stages do not change ELF/PCK bytes, publish the `.so`, or leave
      temporary preflight artifacts.
- [x] Validate the actual 522-file Drawing stage, the real PCK/native ABI
      isolated launch, unit suites, Rust, configured lint and ticket index.

## Evidence and remaining gates

[Fail-first, final process exits, SHA-256 manifest and launch results](../evidence/T-215-2026-11-19-stage-inventory.md).

T-215 changes only the Python source-stage release inspector and its fixture
coverage. The original `T-201` native package behavior is preserved. The
isolated launch uses the supplied Godot beta3 executable and an existing real
PCK; it does not validate official release templates, Windows-native runtime,
hosted CI, device FPS, pointer latency, or owner acceptance. T-105/T-106/T-180
and manual-review dependencies retain their existing statuses.
