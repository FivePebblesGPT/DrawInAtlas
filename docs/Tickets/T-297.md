# Reject Brush candidate-bound integer overflow without dropping clipped strokes

## Defect

`DrawingEditSession._paint_segment()` converted the unbounded floating Brush
footprint to 64-bit integer coordinates **before** clipping or checking the
candidate budget. A finite but huge width (e.g. `1e30`) overflows/saturates
`floori`/`ceili`, then `right - left` wraps negative: an otherwise invalid
unclipped Brush batch returned success, mutated the remembered pointer state,
and painted nothing. The same bad conversion could silently discard a valid
Brush clipped to a 2×2 region. The dab, horizontal/vertical and oblique
scanline helpers repeated the conversion-before-clamp mistake.

## Completed acceptance

- [x] Fail-first against the untouched base: **48/113 failed** real
      Godot 4.8 beta4/Rust checks for huge finite widths and clipped paths.
- [x] Clip floating candidate bounds before integer conversion, validate the
      safe view-relative pixel domain and reject genuinely unbounded work with
      `BRUSH_LIMIT` **before** preview, coverage or pointer state changes.
- [x] Clamp per-row dab, axis and oblique candidate windows in floating point
      before `floori`/`ceili`; bounded 2×2 strokes paint all four pixels, not
      an empty wrapped scanline. Preserve the existing final geometry predicate.
- [x] Verify same-session normal Brush retry, exact opaque RGBA8 and prior
      transparent hidden RGB, Commit, Undo and Redo.
- [x] Corrected **113/113** real-native checks; existing dab geometry,
      axis sweeps, bulk projection, native Delete, Atlas Brush and Drawing
      Brush scanline/coverage suites pass. Required T-068 fast-desktop CI
      includes a strict 113-check witness without adding a workflow step.
