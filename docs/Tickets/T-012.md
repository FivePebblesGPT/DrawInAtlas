# Replace battlemats with separately authored local detail

## Source and confirmed constraints
[[ManualReview_2026-10-30#Usability testing|Usability testing]], items 10–12, followed by the user's revision in [[E-006]]. Battlemaps are simply more detailed local-map views; the battlemat concept is retired entirely. This supersedes the earlier within-map-container proposal.

## Acceptance
- Define how separately authored local detail is represented and selected within the shared-board/LOD model.
- Preserve explicit editing targets, continuous coordinates and independent artwork authoring across detail groups.
- Remove reliance on battlemat documents, containers or nesting as the way to access local detail.
- Identify migration/cleanup responsibilities for existing data, coordinated with [[T-015]].
- Keep projection framing in [[T-013]] separate from artwork ownership and transforms.

## Delivered design and acceptance evidence (2026-10-30)

- [[AUTHORED_LOCAL_DETAIL]] defines the authoritative local-detail ownership, authoring, presentation/edit-target, coordinate and save contract. A local view is a set of `AtlasLayer` instances tagged with D0–D32 on one `AtlasMapDocument` / `AtlasFloor`; it has no `AtlasPlacement`, child document, inherited canvas or automatic per-hex ownership. The existing Layers controls let the DM choose an empty level manually, add independent content there and explicitly select it. Zoom-based LOD remains a presentation decision and may never silently choose the editing target.
- `tests/local_detail_workflow_smoke.gd` exercises **24 assertions** through the real editor: empty-hex/manual D1 creation, independently authored D2 at near and distant points, unchanged D0/D1 when D2 is edited, same-board/zero-new-link/zero-new-placement identity, hidden-edit rejection, explicit layer selection, automatic LOD isolation, grid/measurement independence, undo/redo and native save round-trip. The suite is included in `.github/workflows/godot-check.yml`.
- Legacy migration is explicitly **not** implied by a green test. The contract inventories existing `AtlasPlacement`, `AtlasMapLink`, navigation/preview consumers and preservation decisions for vector/raster/terrain geometry, symbolic vs spatial placement, native units, layers/floors, references and save/rollback. [[T-015]] owns approved conversion and removal of obsolete persistence/ownership paths; [[T-014]] owns removing legacy creation tools; [[T-013]] owns projection framing. Old saved independent documents remain readable until an approved conversion exists.

**Boundary:** This is a `kind: design` ticket. The documented, executable no-battlemat authoring workflow is accepted here. Neither the obsolete “Drag battlemap” UI nor legacy placement persistence has been removed in this ticket; both have separately ticketed cleanup/approval requirements. Remote CI and human usability acceptance have not been observed.
