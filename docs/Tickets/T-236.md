# Preflight direct pixel-map publication before lazy source callbacks

**Bounded T-148 child.** `_publish_edit` previously validated one pixel-map
entry at a time while resolving lazy tiles, permitting a malformed later
original or replacement to run an earlier callback. It also compared source
**identity**, not in-place source bytes, before native adoption. A callback
could change caller-owned before/after maps or an already-resolved resident
tile without advancing document revision.

## Acceptance

- [x] Preflight every changed coordinate and required original, native signed
  projection, native transfer budget and straight RGBA8 channel range before
  the first lazy source callback; retain synthetic out-of-native-ABI strides.
- [x] Freeze original and replacement maps for staging, fingerprint each
  resolved canonical source tile, and reject reentrant map/source-byte changes
  before native adoption, revision, history or raster publication.
- [x] Retain exact hidden RGB, signed tile source identity, recorded and
  untracked Undo/Redo, portable Save/Open and Atlas-owned detached history.
- [x] Demonstrate unchanged-source fail-first reproduction, final native
  regression and neighboring publication/Atlas checks in required-native CI.

## Completion — 2026-11-22

The unchanged `HEAD` implementation fails **16/35** checks; this fix passes
**35/35** with the same compiled Godot-native extension. T-068's old smoke
test was updated for the T-233 native tile-delta output and now runs its
full-int64 legacy-coordinate oracle with a deliberate out-of-native-ABI
synthetic stride; all **30/30** checks pass. Other publication/Atlas suites
pass; see [T-236 evidence](../evidence/T-236-2026-11-22-pixel-map-preflight.md).

**Scope boundary:** This is direct pixel-map transport hardening, not native
production of all non-Brush raster work or ownership of general host history
commands. A malicious lazy provider's **own** in-place mutations are not
rolled back by the guard; rejection prevents publication of the requested
edit. T-148 remains **In Progress**, T-149 **Blocked**, and owner/hosted
CI gates retain their prior statuses.
