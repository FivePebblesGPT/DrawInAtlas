# Guard document switching while Brush input is unpublished

**Done — bounded engineering hardening (2026-11-15).** T-125 prevented Save,
Save As, Object publication and *active*-tab closure during a released Brush
backlog. Other workspace transitions still called `_activate()` while a
`DrawingEditSession` was draining: replacing the Canvas document implicitly
cancelled that work even though its source document was still clean. Opening a
new tab, clicking/cycling to another tab, attaching an Atlas Object draft, or
closing a *different* tab could drop already delivered pixels without any
save/discard decision. This is a reproducible data-loss boundary, not a choice
of preferred editor interaction semantics.

## Bounded contract

- [x] Deny **New**, **New Object**, `.drawing`/raster **Open**, Object-source
      **Open** and Atlas-host `attach_object_session()` while the Canvas has an
      unpublished Brush transaction or T-124's deferred successor. No orphan
      tabs, source replacement, counter changes or mismatched active tab.
- [x] Deny direct/TabBar/keyboard document switching until pending strokes
      finish; restore the visible selected tab on a rejected TabBar change.
      Preserve existing idle same-tab refresh behavior, but never reset an
      active Brush session through a reentrant same-tab signal.
- [x] Deny active and inactive **Close Tab**, including the internal removal
      path, while the current Canvas is draining. A stale Save-and-Close intent
      for another tab must fail without saving the wrong document or leaving
      a latent close request.
- [x] Continue normal background drain, ordered queued stroke promotion,
      exact RGBA8 publication, independent Undo/Redo, Save/reopen and tab
      switching **after** commit, without synchronous raster flushing.
- [x] Demonstrate failure on the unmodified T-125 code and success on the
      fix with actual Godot documents, pointer-like source gestures, TabBar
      selection, portable files and Object sessions; run strict logs, native
      GUI regressions, clean consumer, source/CI contracts and ticket validator.

## Verification and limits

[Reproduction, commands, raw-log digests and neighboring results](../evidence/T-126-2026-11-15-pending-document-switch.md).
The original T-125 code fails **26 assertions** in the final 33-check negative
control. The corrected source passes **34/34**, including a queued second
stroke, two Undo/Redo transactions and exact portable-image bytes. Existing
T-124/T-125, File/Open, Object, standalone and Xvfb pointer suites remain
passing; the new oracle executes under the existing T-085 fast-desktop CI step
without changing the 46 required check IDs.

This intentionally requires the user to retry a document switch after Brush
work finishes; it does not adopt deferred UI actions, increase throughput or
promise a maximum release latency. The parent T-095 remains **In Progress**
with `manual_review: true` until real-device results and explicit owner
acceptance. T-085/T-086 and hosted T-106/T-107 gates remain separate.
