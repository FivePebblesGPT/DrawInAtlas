# Retire battlemat creation controls

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 10.

The user's later decision in [[E-006]] retires the concept, superseding the earlier plan to restrict creation to local maps.

## Acceptance
- Remove “Drag battlemap” and other battlemat creation affordances from tools, menus, shortcuts and pointer paths at every detail level.
- Local detail is accessed through the authored-detail/LOD workflow, not through creation of another canvas/container.
- Do not replace the removed tool with an equivalent under another name.
- Preserve ordinary artwork editing; projection framing is separately scheduled in [[T-013]].

## Implemented — 2026-10-30

- The tool palette no longer offers **Drag battlemap**; `AtlasCanvas.Tool` no longer has a `BATTLEMAP` choice. Removed the drag/draft signal, overlay, mouse press/motion/release branches, editor dispatch, Q/E rotation interception, inspector placement section and obsolete tool SVG. None of those paths changes or creates a document at any authored level.
- **Linked maps** no longer offers “Create independent document,” a BATTLEMAP kind, or creation of spatial/symbolic footprints. A new link can now point only to an **existing independent map** through a marker. The creation form selects an existing destination by default and explains that File → New Board creates independent documents. `AtlasLinkedMaps.submit()` also rejects newly supplied placement objects and bundled new documents, so removed UI cannot be bypassed through that editor facade.
- **Compatibility boundary:** Existing saved spatial/symbolic links, placements and independent artwork remain readable, editable and navigable. The legacy form exposes their geometry only when editing a link that already owns a placement; ordinary map creation, D0–D32 authoring, pointer gestures, undo and native saves continue to work. No stored schema or existing data is migrated. [[T-015]] still owns removal/conversion of the legacy model after approval; [[T-013]] owns projection framing.
- `tests/retired_battlemap_controls_smoke.gd` runs **29 assertions** covering the missing tool/signal/facade/UI creation paths, normal pen gestures and undo in **D0, D1 and D2**, forced invalid draft modes, and protection against forged facade creation without any campaign mutation. Added it to CI. Existing `linked_maps_ui_smoke.gd` now covers legacy footprint editing using a historical-data fixture rather than obsolete end-user creation, while `smoke.gd` exercises navigation and artwork on a historically created battlemat fixture.
