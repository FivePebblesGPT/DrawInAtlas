# Restore floating panel geometry when a move or resize is canceled

## Defect (2026-11-22)

A floating panel preview immediately updates `DrawingFloatingHost.position/size` during a grip move or an edge/corner resize. Pressing Escape stopped processing the gesture, but `_clear_gesture()` only canceled tab-drag state; the host retained its interim position/size. Releasing the mouse afterward did not roll back either value. This contradicts the established cancel/rollback contract in T-091 and causes accidental persistent panel displacement.

## Acceptance — engineering Done

- [x] Escape during a grip move restores the exact pre-gesture floating rectangle; a delayed mouse release cannot reapply it.
- [x] Escape during bottom-right or top-left corner resize restores **both size and position**. Keep all existing edge/corner clamps and normal committed resizing.
- [x] Check real mouse input at 100/150/200% simulated UI scaling; after repeated cancellations, a normal drag still works and no dock group/tab is transferred.
- [x] Reproduce in Atlas embedding using the same canonical Drawing workspace; keep document source, revision and history unaffected.
- [x] Run fail-first negative controls, neighboring floating/dock regressions and ticket-store validation; preserve T-091 physical hardware and T-250 owner gates.

**Change:** In [`DrawingFloatingHost`](../../addons/drawing/floating_host.gd), restore `_frame_start` via the existing clamped `set_host_rect()` **before** clearing a canceled `move`/`resize` gesture. Do not restore geometry for a canceled tab drag or emit a committed `state_changed` event.
