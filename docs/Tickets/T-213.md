# Reject non-regular and undeclared entries in standalone exports

## Bounded scope and acceptance

T-212 made failed native export packaging atomic for invalid *regular files*,
but T-068 and its preflight enumerated `is_file()` entries only. Extra empty
folders or FIFO nodes therefore evaded both inventories and were accepted as
valid release content. An invalid Linux package could even receive the native
ELF before being accepted with these undeclared entries still present.

- [x] Demonstrate fail-first release inspection for extra empty directories
      and FIFOs in **both** structural Windows and required-native Linux exports,
      plus fail-first Linux packaging that leaves those nodes accepted.
- [x] Share one exact-tree inspector for regular files, expected native
      ancestor directories, symlinks, and special filesystem nodes. Permit
      an absent native ELF only in the un-packaged Linux preflight projection.
- [x] Verify rejected Linux candidates do not install the native `.so`,
      produce temporary residue or delete the unexpected entry.
- [x] Preserve successful Windows structural inspection, native Linux
      packaging, cross-device fallback, rollback, real isolated ABI launch,
      portability unit tests, Rust/Python/toolchain and ticket-store checks.

## Evidence and limits

[Commands, six fail-first subtests, final source hashes and raw logs](../evidence/T-213-2026-11-19-export-entries.md).
The change affects only Python release artifact inventory and unit tests;
no native painting, GDScript, persisted format, canonical pixels or runtime
asset was changed. Isolated launch reuses the previously exported beta3 PCK
and Godot executable surrogate. Official release templates, Windows runtime,
hosted CI, T-150 native authority and manual owner acceptance remain open in
T-105/T-106/T-180 and related integration tickets.
