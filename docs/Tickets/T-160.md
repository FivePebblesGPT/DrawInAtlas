# Guard native-attached direct pixel/tile publication bounds

**Split from T-148.** T-158 and T-159 protect lazy registration,
manifest export, native publication and native/detached history replay, but
`DrawingDocument._publish_edit` and `_publish_tile_edit` were still able to
publish out-of-projection coordinates through their older direct staging
paths. With an attached Rust tile owner, especially with `record_history=false`,
such an edit advanced the Godot document/dirty source without advancing
Rust's canonical revision/history. It also exposed tile multiplication and
per-pixel source resolution to signed values beyond the supported Godot
projection range.

## Acceptance

- [x] In native-attached documents reject canonical out-of-bound signed tile
  IDs and pixel coordinates on both axes, including ±(limit+1), `INT64_MIN`,
  and `INT64_MAX`, **before** source resolution or any revision/dirty change.
  Reject malformed or noncanonical pixel keys prior to parsing.
- [x] Preserve native Rust history token/revision, unchanged Brush pixels,
  local Undo stack and dirty/save records on every rejected direct edit.
- [x] Exercise the valid inclusive positive pixel and negative tile endpoints
  with opaque native Hokusai source, alpha-zero hidden RGB, common Rust
  Undo/Redo timeline, and actual `.drawing` Save/Open.
- [x] Preserve historical non-native signed-64-bit direct-session behavior;
  T-150 still owns deleting Legacy. Do not turn this bounded child into a
  premature universal T-148 or T-095 acceptance claim.
- [x] Prove fail-first against previous code; run native Rust checks, Godot
  integration, root lazy-cache/Atlas/Object/history and graphical 96px tests;
  add a required-native CI marker, record checksummed evidence, and validate
  ticket state and manual review gates.
