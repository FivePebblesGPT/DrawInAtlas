# Recover docked panel/group drags after a lost mouse-up

## Defect

[T-259](T-259.md) fences mouse-up loss inside a floating host, but the
**expanded right dock**, **group markers**, **minimized icon rail** and **flyout
tabs** use the independent `DrawingWorkspace._input` dock-drag candidate.
A motion event with `button_mask=0` after a real left-button drag left that
candidate and its cross-container transaction alive when the OS dropped
mouse-up without focus loss. A later release over the canvas could detach a
panel/group that the user had already stopped dragging.

## Engineering acceptance — Done

- [x] Motion without the left button cancels only an active right-dock pointer
      candidate/owned drag, clears merge/detach hints, and leaves the validated
      dock model untouched. An unrelated floating-host gesture is not canceled.
- [x] The possible delayed mouse-up is suppressed so it cannot commit a stale
      tab transfer or invoke the source icon's normal collapse/flyout click.
- [x] A new genuine press resets the old suppression state even if the missing
      release never arrives. Legitimate held-button icon/group drag and click
      behavior remain available.
- [x] Standalone X11 pointer tests cover expanded icons and group handles at
      100/150/200% simulated scaling, minimized rail/flyout, late releases,
      a fresh press without a preceding release, saved panel ownership, and
      document revision/dirty/history invariants. Atlas embeds the same
      canonical workspace and confirms the cancellation path.
- [x] Re-run neighboring docking/floating regressions and the ticket-store
      validator; provide a separate on-demand clean-build workflow and Make
      target. No owner signoff is inferred from synthetic lost-release input.

**Implementation:** [`DrawingWorkspace._input`](../../addons/drawing/workspace.gd)
now abandons a right-dock pointer candidate or owned drag when an unpressed
motion arrives, using the same `_cancel_cross_drop` transaction rollback as
Escape/focus-out. `_dock_drag_press` establishes a fresh suppression lifetime
on each real LMB down. No raster, document or Rust source code changes.

**Tests:** [Standalone native X11](../../drawing/tests/t264_dock_lost_release_native.gd),
[Atlas native X11](../../tests/t264_atlas_dock_lost_release_native.gd),
[on-demand workflow](../../.github/workflows/godot-native-t264-dock-release.yml),
`make test-dock-release`.

**Evidence:** [T-264 engineering report](../evidence/T-264-2026-11-22-dock-release.md).

**Gates:** T-091 remains In Progress for physical Windows/Linux tests; T-083
remains unapproved and T-250 stays at Manual Review. A synthetic X11 pointer
sequence does not prove physical window-manager behavior.
