# Stop clipped floating tabs from stealing grip and close clicks

## Scope and reproduction (2026-11-22)

In a narrow (236px) floating Drawing host with five icon tabs, scrolling the
TabStripScroll horizontally moves the child Buttons under the clip viewport.
Godot still reports the Buttons' **full global rectangles**. The T-225
viewport-level tab hit-test used those uncut rectangles, allowing an invisible
tab to steal a pointer event over the move grip or close control. A real X11
pointer test demonstrated the bug: after scrolling right, clicking the grip
changed the active tab from `future` to the invisible `colors`, and dragging
that point began a tab drag rather than moving the floating host.

## Acceptance — completed engineering scope

- [x] Tab hit-tests only apply within the **visible** floating tab scroll
  viewport; partially visible icons remain clickable inside their visible
  section and a fully clipped icon cannot capture the grip/close header.
- [x] Narrow host still supports real pointer grip movement, active-tab
  switching, close/hide/reopen and one-group tab ownership. The existing 8px
  outer resize-edge hit region stays intact.
- [x] Same shared Drawing package behaves in an Atlas-owned workspace without
  taking over Atlas lifecycle, source bytes or history.
- [x] Add fail-first real X11 regression, software framebuffer screenshots,
  exact success markers and an on-demand clean-native-build workflow.
