# Establish explicit, commented steps inside complex functions

## Source
[[ManualReview_2026-10-30#Code review|Code review]], item 8, with item 6's field-documentation requirement.

## Acceptance
- Agree a concise convention that separates meaningful phases with comments and/or cohesive named helpers.
- Use a representative paint/fill function to demonstrate the convention before broad application.
- Preserve readable local context; avoid both dense variable/if sequences and excessive fragmentation.
- Record the convention in applicable project/agent guidance and apply it through the dedicated module tickets.

## Implementation — 2026-10-30

- Established intent-named function phases in [[CODE_READIBILITY]]: guard and
  normalize, establish working space/bounds, traverse/compute, stage edits, and
  construct a result. These are a guide, not a rigid template for small helpers.
  Comments explain ordering, units, limits and ownership, rather than syntax;
  blank lines and local variables keep each phase self-contained. Named helpers
  are for meaningful subalgorithms, not one-line wrappers.
- Recorded a short version in the project-owned
  `.agents/skills/godot-gdscript-patterns/SKILL.md` so subsequent GDScript work
  encounters it alongside the explicit-typing rule.
- Demonstrated the convention in `AtlasRasterBrush.paint()` with comments and
  phase spacing for validation, board-to-pixel bounds, candidate-work limits,
  per-pixel masking/blending, and detached snapshot construction. Deliberately
  avoided algorithm extraction or a functional refactor: that belongs to
  [[T-034]]. The dedicated module passes [[T-033]], [[T-035]] and [[T-036]]
  remain open.
