## Acceptance

## Candidate boundary and technical verification — 2026-11-01

See [[PLAYER_PROJECTION_CONTRACT]] for the proposed audiences, whole-layer
publication rules, denied metadata, projector framing/follow/freeze, cache
revocation, fog/token/LOD privacy matrix, and **specific owner decisions**.

This turn adds an **isolated proof** in `scripts/presentation/player_projection.gd`:
from an explicitly granted layer set, make a detached, sanitized one-map
`AtlasCampaign` suitable as capture input. No grants means blank artwork;
invalid or ambiguous grants fail closed. The proof does *not* wire a player
window, authorize publication of editor layers, persist privacy settings, or
implement object-granular permissions, fog or tokens. It deliberately exposes
why the existing preview cache's `audience` field is not an access-control
boundary. Rendering through the sanitized campaign is exercised natively.

**Acceptance remains blocked**: the owner must agree publication granularity,
object/text privacy, fog intermediate-image policy, metadata, follow/freeze,
policy persistence and co-GM scope. Dependencies on approved core usability
and the actual T-013/T-040–T-044 privacy integration remain open. Thus T-039
is **not checked** in [[Index]]. CI checks are technical evidence only.

**Local validation (Godot 4.8 beta 2, Xvfb/Mesa):** new contract test
30/30 checks; new native player-capture test 5/5 checks. Full repository
headless sweep 47/47 suites and native framebuffer sweep 27/27 suites passed.
Main-scene launch, Web release export, all four source/export-pack save
portability checks, explicit-typing guard, `git diff --check`, and Git LFS
integrity passed. Remote CI and an actual second-monitor/browser projector
session were **not** run; no claim of end-to-end privacy is made.
