# Restore required-native T-093 Object-source CI and Atlas identity witness

## Problem

The standalone T-093 Object-source discovery on-demand workflow staged the
Drawing copy and began software-X11 tests **without compiling the required
Rust Hokusai extension**. Since the `.so` is not in Git, a clean runner cannot
reliably load the editor. That workflow also omitted Atlas, which uses the
same published-source browser but owns separate campaign identity, placement
and global history.

This is a **bounded engineering validation** of an existing Done feature,
not new Atlas functionality or implicit owner Asset Browser approval.

## Acceptance — Done

- [x] Pin Godot 4.8 beta 3 and Rust 1.99.1 in the on-demand workflow; build
      the mandatory native extension and import both Drawing and Atlas before
      running the T-093/T-120/Atlas witnesses.
- [x] Require the current 56-check source-root model, 27-check real-X11
      standalone Object discovery and 20-check T-120 File/Object UI tests.
      Preserve the original strict log verifiers, error rejection and logs.
- [x] Add a real-X11 Atlas browser test proving campaign-scoped source
      publication has a distinct stable ID, native row/Open actions open the
      dedicated Object Editor rather than placing an instance, and browsing
      cannot change map/global history or published bytes. Changed on-disk
      source content must invalidate its previously authorized browser token
      without opening an extra tab or instance.
- [x] Add `make test-object-sources` with required-native build/import, Bash
      `pipefail`, explicit check counts and log-error gates; test its CI
      contract fail-first.
- [x] Update old T-093 workflow contract for delegated Make imports; document
      actual native tests and preserve owner/hosted acceptance boundaries.
