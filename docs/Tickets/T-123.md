# Bound PNG/WebP/JPEG decoded dimensions before allocating the image

**Done (engineering scope, 2026-11-15).** The T-121 single-snapshot reader
bounded encoded source bytes to 64 MiB, but called `Image.load_*_from_buffer`
before checking the decoder's output dimensions. A very compressible oversized
raster could therefore request excessive decoder allocations/CPU despite an
encoded-byte cap. This is a distinct follow-up to T-121; it does not reopen
its completed file-identity/TOCTOU work or change the approved unified Open UI.

## Bounded implementation

- Parse the PNG first IHDR, WebP VP8/VP8L/VP8X canvas/frame fields, and JPEG
  segment-walk SOF from **the same** captured bounded buffer. Validate offsets,
  markers, chunk/segment lengths, positive dimensions and the existing
  4096px-per-side / 16,777,216-pixel limits **before invoking Godot's decoder**.
- Keep the exact `load_file_image` snapshot reader, extension dispatch,
  original format decoders, canonical straight RGBA8, failure rollback,
  frame selection and .drawing Save identity. Recheck dimensions after decode
  rather than trusting potentially inconsistent header metadata.
- Keep corrupt/truncated input fail-closed; do not create a workspace tab or
  Object source for any rejected image. Bound direct `decode_image_bytes`
  callers by the same encoded-byte cap.
- Add a fail-first Godot model oracle for oversized synthetic headers that
  contain *no decodable pixel payload*, plus valid real PNG, lossy/lossless
  WebP and JPEG controls, underspecified chunks and transactional Open.
  Include a Python source/CI contract. Run under existing T-093 fast CI step;
  do not introduce another required CI check ID.

## Engineering acceptance

- [x] Pre-change T-121 source fails 14/42 initial negative-control assertions;
      it either decodes before rejecting or returns DECODE rather than
      IMAGE_LIMIT/HEADER for oversized/malformed headers.
- [x] New guard rejects every declared oversized PNG, WebP variant and JPEG
      before codec allocation, and malformed marker/length inputs fail safely.
- [x] Real valid images including boundary dimensions still decode accurately,
      independent of extension case; failed Open leaves tabs/history unchanged.
- [x] Existing snapshot, unified Open, neighboring regressions, strict logs,
      CI inventory/typing and independent Drawing consumer remain intact.
- [x] Ticket store validates; owner UX, hardware and hosted CI gates are
      neither silently satisfied nor changed.

## Evidence and limitations

[Commands, regression outcomes, negative controls and known Godot teardown
leaks](../evidence/T-123-2026-11-15-raster-predecode-bounds.md).

This preflight provides an early decoded *dimension* bound, not a bound on all
codec CPU/transient allocations, and it does not make ordinary filesystem
reads atomic when bytes are overwritten in place. Runtime tests are headless
software Godot 4.8 beta3 and are not real Windows or physical input-to-photon
acceptance. T-056/T-059/T-095 and hosted CI remain independent.
