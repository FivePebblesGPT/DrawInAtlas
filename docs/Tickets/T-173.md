# Fail closed on rejected native-attached public layer metadata revisions

**Split from T-148.** `create_layer`, `rename_layer`, `set_visibility`,
`set_locked` and `reorder` wrote Godot metadata/tree state *before* attempting
`DrawingNativeTiles.advance_metadata_revision`. During an active native edit
or attached-native-ahead revision, Rust rejected that metadata bridge but the
caller still returned success, advanced Godot and detached Rust's canonical
source/history. A later Brush stroke could clear unrelated native Undo tokens.

## Acceptance

- [x] For actual changes in the five public layer APIs, acquire the checked
  native metadata revision before modifying the Godot layer tree. A busy or
  divergent attached native store must reject with an explicit error without
  changing nodes, sibling order, revisions, Undo/Redo, RGBA8 or attachment.
- [x] Preserve no-op behavior, native-absent layer metadata operations until
  T-150, and successful metadata edits with preserved native history and
  exact source bytes. Verify retry after discarding the held transaction,
  metadata Undo/Redo and a later Hokusai stroke on the same store.
- [x] Run identical 31-check real-native regression against the old document
  implementation as a fail-first control (22 failures) and the new one
  (31/31 pass); verify active transaction and native-ahead boundaries.
- [x] Run offline Rust tests, rustfmt, strict Clippy, release build, root and
  Drawing/Atlas/Object native-history tests, graphical Canvas and the
  96px/512×512 full-canvas Hokusai witness. Correct historical fixture
  expectations to match T-168 atomic subtree rejection and this metadata gate.
- [x] Add required-native CI coverage, ABI note, parent/index updates, raw
  checksummed execution logs and ticket-store validation.

## Scope boundary

This ticket protects these **five public layer metadata/tree commands**.
Other semantic, host-owned detached-history and cross-document transaction
paths retain T-148's broader integration gate; it does not complete universal
native ownership or T-149. No owner/manual review is required for this narrow
engineering fix. T-095 hardware acceptance is independent.
