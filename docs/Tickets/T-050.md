# Retire palette-cell TerrainLayer artwork

## Source and approved direction

Owner decision, 2026-10-31: a digital traditional map uses raster as the main painting medium, semantic vector objects when needed, and independent grids/region metadata. The palette-cell `AtlasTerrainLayer` is unnecessary as a **visual artwork type**. Future 5-foot tilemap PCG and raster-brush type masks are separate potential systems; see [[TERRAIN_LAYER_DECISION]]. **No real user data needs migration.**

The old palette-cell content and prototype save fixture have **no production migration requirement**. The grid retains all spatial roles; only the distinct palette-cell artwork store and its clipboard/command/UI/serialization authority are being retired.

## Acceptance

- Inventory `AtlasTerrainLayer`, `TILES` wire-kind, palette/cell structures and all floor, editor, tool, UI, selection, clipboard, commands/history, persistence, fixtures and export references **before removing them**. Remove their runtime and UI authority rather than leaving misleading compatibility shims.
- New and loaded supported boards use raster artwork and editable semantic ink without terrain artwork; world-grid geometry, independent per-region properties, gridless boards, cell-scoped edit masks, snapping and authored LOD remain operational.
- Update relevant defaults, tool dispatch, layer-selection safeguards, fill/brush/eraser and clipboard routing so no operation silently falls back to or manufactures a terrain layer. Preserve raster edit atomics, detached snapshots, undo/redo, preview/cancel, explicit target choice and lossless raster/native-save fidelity.
- Explicitly revise native-save schema/payload validation and native save fixtures if terrain types are removed from the wire format. The owner does **not** require a migration reader for old prototype terrain saves. Preserve raster/vector content in the supported current schema; clearly document any incompatibility instead of promising migration.
- Remove or replace terrain-specific tests/CI entries with focused coverage of new documents, raster+ink round-trip, editing, scope masks, existing document metadata and historical layer-type rejection (if applicable). Verify Godot import, explicit typing, representative headless/native UI suites, Web export and a clean working tree.
- Update README, technical architecture, data model, and affected ticket wording once code reflects the new model. Historical test/decision documents may remain labeled as archival; do not represent old tests as passing new behavior.
- No pixel-to-biome inference, new type-mask schema, PCG framework or graphical tilemap editor in this ticket.

## Implementation and verification (2026-10-31)

**Implemented:** Retired `AtlasTerrainLayer`, its naming compatibility shim,
`AtlasTileEdit`, palette-paint tool and UI, tile fill and clipboard dispatch,
terrain previews and renderer, terrain floor/grid serialization, and obsolete
prototype native-save fixtures. Current floors use raster + ink resources.
The independent board grid, cell-based edit masks, navigation and authored
detail levels remain. Sample artwork previously represented by solid terrain
cells is intentionally absent, not silently converted into painted pixels.

**Wire contract:** Native scenes require `AtlasCampaignSaveRoot` version 2;
current dictionary validation requires campaign schema 7, containing only
`RASTER` and `INK` layer kinds. Prototype versions and `TILES` payloads
are deliberately unsupported. No user-data migration tool was added.

**Verification:** Explicit typing audit; clean Godot 4.8-beta2 import;
all applicable headless and native framebuffer smoke suites; raster/ink
ownership, grid-mask, detached snapshot, undo/redo and native roundtrip
regressions; and Web release export. Tests now exercise current data rather
than the deleted terrain palette format. Remote CI, manual usability acceptance
and browser-runtime smoke were not performed in this environment.

**Scope:** This ticket is complete. Raster-first default authoring selection
remains an implementation task under [[T-049]]; region classification masks,
5-foot PCG/tilemaps, and migration are explicitly outside T-050.
