# Profile post-consolidation native Brush critical path

**Goal:** After native consolidation and Legacy removal, measure which architectural layer/functions dominate **the new** hard-round 96px full-canvas Brush path. Existing T-095/T-104 profiles reflect older GDScript staging/publication and cannot by themselves rank the new architecture.

**2026-11-17 owner request:** [T-185](T-185.md) separately profiles the current
post-PR-20 app now, including apparent ~12 FPS during motion. That ready snapshot
task is not blocked on this later consolidation milestone. Its result and the
250/200ms current-sprint optimization in T-186 do not close this ticket or T-095.

## Deliverable

- Re-run the T-146 96px/100-event 512² full-canvas native hard-round/preset workload, plus held/short and repeated overlap/erase cases, on pinned Godot and exact native build hashes. Record input paths, preset configuration, coverage, correctness, startup/hot cache and incomplete/timed-out runs.
- Instrument monotonic timestamps and CPU durations at **each seam**: Godot pointer receipt/queue, GDExtension call count/copy, Rust stroke resampling/raster/mask/blend, native tile allocation/copy-on-write/preview, transaction preflight/commit/undo, bulk RGBA8 conversion, Godot image/texture creation/upload, compositor/frame submission and `frame_post_draw`. Include allocation and bytes moved per tile and total process RSS. Do not add nested inclusive CPU durations as if disjoint wall time.
- Capture full Godot/GDScript function-profiler hotspots and native Rust sampling/profile flamegraph where supported. Clearly distinguish wall latency, cumulative CPU, missed/late input, per-frame max/p95, native thread time and physical input-to-photon (not measured by Xvfb).
- Compare new results to source-pinned historical Legacy/NativeHard/Hokusai measurements as context **only**, never attribute improvements to an uncontrolled hardware/build change. Produce a ranked critical-path bottleneck and reproducible proposed target for T-152.

## Acceptance

- [ ] Repeatable cold/warm source-hashed runs with p50/p95 and error bars or sample limitations, strict process exits, raw logs and meaningful time-segment attribution across all three seams.
- [ ] Rank top CPU and frame-stall functions/layers with evidence; identify first optimization and counterfactual measurement that could falsify it.
- [ ] Clearly report whether the original 100ms owner reference-device p95 gate is met, unmeasured or failed; no premature T-095 closure.

## Boundaries

Diagnostics and decision only. Do not assume the answer must be Rust or Godot rendering until measured. Optimize in T-152 as a separate, verifiable slice.
