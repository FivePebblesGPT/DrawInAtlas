# Compact repeated text controls with recognizable icons

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 5.

## Work
Audit high-space-cost controls and choose recognizable, skeuomorphic-style visual affordances where they improve compactness and comprehension. Evaluate them alongside [[T-006]], grid settings and the layer hierarchy.

## Acceptance
- Record the controls compacted and compare usable canvas space before/after.
- Icons have useful tooltips, accessible names and clear selected/disabled states.
- Retain short text where an icon would obscure meaning; demonstrate the resulting native UI to the user.

## Implementation (2026-10-30)

- Audited the persistent, high-space-cost buttons in the **Layers** sidebar and
  **FLOORS** inspector. Converted six layer actions (raise, lower, new ink,
  new terrain, new raster, import image) from two reorder buttons plus four
  full-width text rows into **one icon toolbar**. Converted the add, rename,
  raise, lower floor controls from two text rows into **one icon toolbar**.
  The tools tab from [[T-006]] remains the exclusive drawing-tool selector.
- Added eight local vector icons distinguishing move direction, pen/ink,
  terrain/hex, raster pixels, image import, creation and renaming. Every
  icon-only action has an accessible name, a descriptive tooltip and normal
  keyboard focus. No change to command routing, shortcuts, layer IDs, detail
  selection, persistence or undo semantics. Boundary-aware disabled states
  remain driven by the existing layer/floor refresh logic. Actual layer
  selection and visibility/lock checkboxes remain visible and stateful.
- Retained text for **Delete floor**, **Make default** and **Show editing layer
  detail** because those actions would be ambiguous, potentially destructive,
  or easy to overlook with icons alone. Numeric/grid editing controls were
  not replaced by ambiguous symbols; the settings-popup relocation belongs
  to [[T-008]]. The layer hierarchy retains clear layer names and kinds.
- Reduced inspector nominal width from 252 to 232 pixels; existing form
  content makes the actual native minimum 234 pixels. Icon-toolbar spacing
  was tuned to avoid widening the sidebar and undoing the canvas gain.

### Measured native layout (960×660 and 800×660, X11/Mesa)

| Measurement | Before | After | Change |
| --- | ---: | ---: | ---: |
| Canvas width at 960×660 | 368 px | 394 px | **+26 px** |
| Canvas width at 800×660 | 208 px | 234 px | **+26 px** |
| Inspector width | 252 px | 234 px | −18 px |
| Layers sidebar panel height | 644 px | 558 px | **−86 px** |
| Floor action rows combined height | 60 px | 36 px | −24 px |

The canvas height remains 607 px at 960×660. Canvas gains represent actual
visible board width, not a claim that vertical controls directly enlarge the
board. Measurements are made with the sidebar expanded, Layers active, the
sample board, and unchanged viewport sizing. The two native screenshots are
reproducible as `user://validation/compact-controls-960.png` and
`user://validation/compact-controls-800.png` via the native test.
