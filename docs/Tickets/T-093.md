# Discoverable Object sources, Asset Browser and import/open distinction

**Status: Done — bounded engineering implementation (2026-11-06).** Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
Owner cannot discover how to load reusable Objects. The standalone Window > Asset Browser prompts for an `Objects/` directory, File > Open Object source requires specialized source metadata, and File > Open handles ordinary `.drawing`; this is correct internally but opaque as a user workflow.

## Engineering tasks
1. Clarify and organize Open Drawing / Open Object Source / Import Image / Show Asset Browser in the correct File/Object menus and context; label which commands need an Atlas project `Objects/` root.
2. Provide empty-state explanations, visible source root and choose/recent root behavior without guessing an Atlas campaign or silently rebinding saved Object IDs.
3. Connect Asset Browser search/open/edit to dedicated Object Editor tabs and distinguish 'place linked instance in Atlas' from 'open source in standalone'; preserve T-065's NULL/remove/cancel and saved variants.
4. Show actionable errors for wrong file type, missing folder, corrupt asset and unreferenced source; no false success.
5. Validate standalone/embedded drawing and portable relocation with keyboard/pointer walkthrough.

## Acceptance / verification
- [x] A first-time user can find/open a saved Object source via File → Object › Browse saved sources… and the dock's **Choose Objects/ folder…** action; no automatic campaign guessing.
- [x] Ordinary `.drawing` Open/Save still roundtrips; Open Object source, New Object source, Import Image and browser open are distinct commands.
- [x] Missing/corrupt/unreferenced source listings and Atlas NULL responsibilities are explained; invalid switches, stale files and imports never silently mutate source IDs or map links.
- [x] T-065 remains separately manual-review gated for full Asset Browser workflows; no approval inferred.

## Boundaries
- Preserve the one canonical Drawing package shared with Atlas, byte-exact saved RGBA8, source identity, one undoable content transaction per gesture and signed sparse coordinates.
- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.
- Do not mark complete merely because earlier T-053/T-063/Docking smoke tests pass. Report hardware, Godot version, viewport, zoom, timing and limitations for applicable evidence.

## 2026-11-06 engineering evidence and limitations

**Authoritative implementation:** `addons/drawing/workspace.gd`, `asset_browser_panel.gd` and new app-only `object_root_history.gd`, all copied unchanged by `tools/build_drawing_app.py` into the independent standalone app and third consumer. The File menu labels **New Drawing**, **Open Drawing**, **Object › New source**, **Object › Open source**, **Import Image as Drawing**, and **Object › Browse saved sources**. The existing Window → Asset Browser entry opens the same dock peer. The source browser now has an initial explanation, explicit **Choose Objects/ folder…** button, compact project/Objects root label, exact absolute path tooltip and Copy root path action, an opt-in **Use last folder** control, and actionable no-results, invalid-file, missing-folder, corrupt/duplicate and stale-source errors. The standalone browser does not offer Atlas instance placement; Atlas's separate **Place at view center**, linked-instance drop, NULL remove/keep/cancel and repair pathways remain unchanged under T-065.

The most recently **explicitly** selected valid absolute `Objects/` path is written to a small versioned `user://drawing-recent-objects-root-v1.json` preference with atomic write, backup fallback and format limits. Merely loading that preference never scans, registers, opens, places, or rebinds an Object. Users must invoke **Use last folder** after each launch; an Atlas host may independently provide `initial_asset_browser_root`. Invalid/missing folders fail without changing the active valid listing or the last-good path. Source IDs are always taken from validated file payloads, **not names or the folder label**; previews/open keep exact SHA verification. Browser refresh and Save are separate operations; duplicate IDs are not guessed. An unreferenced source remains a saved source, not automatic deletion authorization.

**Import Image as Drawing** creates a separate ordinary Drawing tab only after a bounded, valid PNG/WebP/JPEG load (64 MiB file, 4096px per side, 16.8M pixels total); existing `DrawingRasterImport` stages canonical RGBA8 transactionally. Completely transparent images create their frame without inventing pixels. This never creates an Object source, Atlas placement or implicit `.drawing` save. The byte-exact Drawing save/open path is unchanged.

**Local verification:** Godot 4.8.0-beta2, Linux X11/Xvfb/Mesa llvmpipe, 1280×900 and 960×640 viewports. `drawing/tests/object_discovery_smoke.gd` **56/56** headless checks cover explicit root switching, malformed/backup preference, invalid or corrupt source, standalone-vs-source tabs, no false-success errors, portable relocation, RGBA8 PNG import and `.drawing` roundtrip. `drawing/tests/object_discovery_native.gd` **27/27** native checks exercise the actual dock chooser click, visible root, lazy thumbnail/framebuffer, source-list pointer, dedicated Object Editor opening, missing-root errors, narrow layout and explicit recent-root click. The FileDialog subwindow's **directory confirmation** is tested through its signal handler, **not** claimed as a native OS-dialog pointer click. The separate on-demand Xvfb workflow optionally captures two PNGs and uses `check_native_t093_log.py` to reject any pre-success errors while retaining known Godot/Mesa post-success GL/RID leaks. Existing T-065 headless source listing, thumbnail, portable transfer, real I/O, Atlas browser listing and registry tests are the non-regression baseline. A full Windows/Linux physical pointer walkthrough and owner acceptance **remain PENDING** under T-065/T-056/T-059 (finding #21). This ticket has `manual_review: false` and its own engineering acceptance does not close those separate manual gates.
