# Discoverable Object sources, Asset Browser and import/open distinction

**Status: Ready (2026-11-05).** Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
Owner cannot discover how to load reusable Objects. The standalone Window > Asset Browser prompts for an `Objects/` directory, File > Open Object source requires specialized source metadata, and File > Open handles ordinary `.drawing`; this is correct internally but opaque as a user workflow.

## Engineering tasks
1. Clarify and organize Open Drawing / Open Object Source / Import Image / Show Asset Browser in the correct File/Object menus and context; label which commands need an Atlas project `Objects/` root.
2. Provide empty-state explanations, visible source root and choose/recent root behavior without guessing an Atlas campaign or silently rebinding saved Object IDs.
3. Connect Asset Browser search/open/edit to dedicated Object Editor tabs and distinguish 'place linked instance in Atlas' from 'open source in standalone'; preserve T-065's NULL/remove/cancel and saved variants.
4. Show actionable errors for wrong file type, missing folder, corrupt asset and unreferenced source; no false success.
5. Validate standalone/embedded drawing and portable relocation with keyboard/pointer walkthrough.

## Acceptance / verification
- [ ] A first-time user can find/open an existing Object Asset without reading source code or choosing an arbitrary wrong directory.
- [ ] Ordinary `.drawing` Open/Save still roundtrips (owner-confirmed); Object source open and new source are distinct and visible.
- [ ] Missing/corrupt/NULL/unreferenced files provide correct explanations; no silent links, mutations or loss of source identity.
- [ ] T-065 remains separately manual-review gated for full Asset Browser workflows.

## Boundaries
- Preserve the one canonical Drawing package shared with Atlas, byte-exact saved RGBA8, source identity, one undoable content transaction per gesture and signed sparse coordinates.
- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.
- Do not mark complete merely because earlier T-053/T-063/Docking smoke tests pass. Report hardware, Godot version, viewport, zoom, timing and limitations for applicable evidence.
