# Layer/group selection, insertion order, row eye/lock and structural undo

**Status: Done (2026-11-06; bounded engineering acceptance only).** Corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
The layer Tree currently selects only raster/text rows as active target; `_add_group` always appends to root, and `_add_layer` appends to a remembered layer's parent. Per-item visibility is a glyph plus menu command, not an eye checkbox; hierarchy/editing and history can silently diverge.

## Engineering tasks
1. Distinguish selected Tree row/group from current paintable layer; make group selection available without accidentally painting into a group.
2. Insert new layer/group at a predictable position relative to selected row/group and select the newly created item. Add reorder/reparent with cycle and locked/hidden guards.
3. Use row-level eye visibility and lock controls with clear affordances, keyboard access and group propagation; no per-item menu hunt.
4. Ensure structural mutations (create/remove/rename/reorder/visibility/lock) follow explicit undo/redo/save semantics rather than untracked edits; maintain stable IDs and lazy navigation on high layer counts.
5. Preserve layer order and exact pixel composition through persist/reopen and embedded Atlas projections.

## Acceptance / verification
- [x] Choosing a group and pressing +Layer/+Group inserts in the intended hierarchy and order; a selected layer positions the insertion consistently.
- [x] Eye/lock acts on the clicked row; navigation and painting respect group state; reorder/move cannot create cycles.
- [x] Structural undo/redo and save/reopen produce identical tree, IDs, visibility, history and pixels.
- [x] Keyboard and pointer native tests cover short dock, filtered/paged tree and Object Editor.

## Boundaries
- Preserve the one canonical Drawing package shared with Atlas, byte-exact saved RGBA8, source identity, one undoable content transaction per gesture and signed sparse coordinates.
- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.
- Do not mark complete merely because earlier T-053/T-063/Docking smoke tests pass. Report hardware, Godot version, viewport, zoom, timing and limitations for applicable evidence.

## Implementation and evidence — 2026-11-06

- `addons/drawing/document.gd`: opt-in structural history for create, remove,
  rename, reorder/reparent, visibility and lock. Old direct/Atlas callers default
  to untracked structural changes and retain external history ownership. Local
  transactions capture subtree IDs, nested nodes, lazy tile references and exact
  canonical RGBA8; undo/redo are failure-atomic, retain stable identities and
  increment the document revision monotonically. Same-value edits are no-ops.
  Editable parent deletion cannot bypass a locked/hidden descendant in the
  locally recorded path. Invalid reparent/cycles and locked targets fail before
  changing the graph.
- `addons/drawing/history_context.gd`, `workspace.gd`: selected Tree **row**
  is independent of the current raster/text paint target; group selection
  disables painting. +Layer/+Group append inside a group or insert immediately
  above a selected sibling. Eye and lock SVG buttons act on the clicked row;
  keyboard operations on a focused Layers Tree use **Ctrl+Alt+Up/Down** to
  reorder, **Ctrl+Alt+Right/Left** to indent/outdent, **Ctrl+Alt+V/L** for
  visibility/lock and **Ctrl+Alt+R** for rename. Structural history restores
  selection context; moved/created rows are revealed despite filters/pages.
  The Tree GUI handler defers redraw until native input dispatch is complete;
  secondary layer-action buttons wrap rather than forcing the compact dock
  wider than a 420px application window. Text creation also updates the Tree
  selection in the Object Editor, preserving the previous document contract.
  Structural edits cancel detached active strokes rather than showing stale
  uncommitted pixels. Rows are rendered in pages of at most 200.
- `drawing/tests/layer_structure_smoke.gd`: **62 passing model checks** for
  signed exact bytes, hierarchy, group propagation, atomic guards and cycles,
  undo/redo/save/reopen, Atlas external history, filter and 205-row paging,
  no-op history, locked descendant deletion, active stroke cancellation and
  standalone workspace selection.
- `drawing/tests/layer_structure_native.gd`: **32 passing X11 pointer/keyboard
  and framebuffer checks** for actual eye/lock clicks, three-layer composite
  changes, group selection, keyboard reorder/undo/redo, short dock and Object
  Editor, file reopen and RGBA8 preservation. Godot
  `4.8.beta2.official.cafc17a19`, Linux X11 `gl_compatibility`, Xvfb/Mesa
  software renderer, 1120×800 and 880×550 viewports, 400% zoom; no physical
  mouse-to-photon timing was measured. Additional regression evidence:
  `drawing/tests/object_editor_ui_smoke.gd` **25/25** and
  `drawing/tests/compact_workspace_smoke.gd` passed on X11/Xvfb at the 420px
  narrow window with 150% UI scaling; `workspace_keyboard_smoke.gd` passed.
  The Object Editor test now invokes the explicit row-selection API instead
  of changing the private paint-target field alone. Source commands:
