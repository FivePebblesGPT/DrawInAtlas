# Layer/group selection, insertion order, row eye/lock and structural undo

**Status: Ready (2026-11-05).** Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
The layer Tree currently selects only raster/text rows as active target; `_add_group` always appends to root, and `_add_layer` appends to a remembered layer's parent. Per-item visibility is a glyph plus menu command, not an eye checkbox; hierarchy/editing and history can silently diverge.

## Engineering tasks
1. Distinguish selected Tree row/group from current paintable layer; make group selection available without accidentally painting into a group.
2. Insert new layer/group at a predictable position relative to selected row/group and select the newly created item. Add reorder/reparent with cycle and locked/hidden guards.
3. Use row-level eye visibility and lock controls with clear affordances, keyboard access and group propagation; no per-item menu hunt.
4. Ensure structural mutations (create/remove/rename/reorder/visibility/lock) follow explicit undo/redo/save semantics rather than untracked edits; maintain stable IDs and lazy navigation on high layer counts.
5. Preserve layer order and exact pixel composition through persist/reopen and embedded Atlas projections.

## Acceptance / verification
- [ ] Choosing a group and pressing +Layer/+Group inserts in the intended hierarchy and order; a selected layer positions the insertion consistently.
- [ ] Eye/lock acts on the clicked row; navigation and painting respect group state; reorder/move cannot create cycles.
- [ ] Structural undo/redo and save/reopen produce identical tree, IDs, visibility, history and pixels.
- [ ] Keyboard and pointer native tests cover short dock, filtered/paged tree and Object Editor.

## Boundaries
- Preserve the one canonical Drawing package shared with Atlas, byte-exact saved RGBA8, source identity, one undoable content transaction per gesture and signed sparse coordinates.
- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.
- Do not mark complete merely because earlier T-053/T-063/Docking smoke tests pass. Report hardware, Godot version, viewport, zoom, timing and limitations for applicable evidence.
