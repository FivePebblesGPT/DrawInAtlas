# Move grid configuration to a toolbar-opened settings popup

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 6.

## Acceptance
- Grid shape and other infrequently edited grid configuration live in a dedicated settings popup.
- A recognizable toolbar action opens it; current settings are visible when opened.
- Preserve intentional settings/undo behavior and artwork coordinates.
- Keep edit-mask controls distinct from grid configuration and remove the duplicated always-visible inspector clutter.

## Implementation (2026-10-30)

- Moved the existing `AtlasGridControls` form from the always-visible
  right-inspector **MAP** block into a bounded, scrollable **Grid settings**
  popover opened by a grid-icon **Grid** action in the top toolbar. The form
  still shows and edits shape, overlay visibility, cell/hex size, origin,
  rotation, native distance per cell and native units. The same form scene is
  reused for new-board creation; no separate grid model or staging state was
  introduced.
- The inspector now presents **EDIT MASK** independently, with its compact
  **Lock to selected cell** checkbox. This label intentionally retains its
  original width so the 26-pixel canvas gain from [[T-007]] is not lost.
- `AtlasEditor.apply_grid()` remains the sole grid-edit command path, including
  history-backed undo/redo, geometry-sensitive scope reset and preservation of
  artwork coordinates. Opening/reopening synchronizes the controls against the
  current board; command/undo/redo and board switching still use the existing
  `_refresh_grid_controls` path. Gridless grids continue disabling irrelevant
  inputs and edit masks.
- The popover is an in-editor `CanvasLayer` with a fixed-size `Panel`, not an
  OS-owned popup window. This is deliberate: the native beta2 build expanded
  the window-backed `PopupPanel` beyond the screen during verification. The
  in-editor panel renders at the correct stacking level, is bounded at 960×660
  and 800×600, scrolls when needed and closes via **Done**, **Escape**, or an
  outside pointer click. Tool/floor/sidebar content remains unchanged.

## Verification

- Godot `4.8.beta2.official.cafc17a19` parser/import, main-scene launch and
  explicit-typing guard passed.
- `tests/grid_settings_smoke.gd`: **23/23** checks for toolbar wiring,
  initial/current grid values, inspector cleanup, mask separation, undo/redo,
  board coordinates, gridless handling and popup reopening.
- `tests/grid_settings_visual.gd`: **22/22** native X11/Mesa checks for actual
  toolbar pointer interaction, rendered overlay, usable dimensions at 960×660
  and 800×600, Done, Escape, outside-click dismissal and retained canvas width.
  Reproducible screenshots are `user://validation/grid-settings-960.png` and
  `user://validation/grid-settings-800.png`.
- Full local sweep: **24/24** headless suites, **11/11** native framebuffer
  suites after retaining the compact mask label, Web release export and **4/4**
  source/pack save-interoperability checks passed. Both new test suites run in
  CI. The original native sweep caught the accidental inspector width growth;
  it was corrected and the affected T-007 and T-008 visual tests reran green.

**Acceptance boundary:** Automated and screenshot-based native verification
is not human usability acceptance or a remote CI run. The popover does not
change grid ownership, mask semantics, or the existing undo-command granularity.
