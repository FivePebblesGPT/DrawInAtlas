# Make the native held-stroke test portable across POSIX shells

## Defect and scope

T-262 introduced the `make test-live-stroke` target with `set -euo pipefail`
inside its **Make recipes**, not just an explicitly Bash-invoked script. GNU
Make defaults to `/bin/sh`; versions of Dash and other POSIX shells without
`pipefail` reject the command before any Godot test runs. Other versions of
Dash do support it, so a successful run on one machine is not a sufficient
portability guarantee. The same target must also propagate failures from
both Godot commands through `tee`, even when their output verifiers succeed.

This is **one bounded Linux Make/test-reproducibility correction**. No Brush,
rendering, document, native Rust, Atlas or UI production code is changed.

## Engineering acceptance — Done

- [x] Explicitly run GNU Make recipes with Bash rather than relying on the
      distribution's `/bin/sh` implementation.
- [x] Fail-first regression injects a POSIX shell without `pipefail` before the
      real Makefile; old Makefile fails, corrected Makefile overrides it and
      executes model + native commands in the required order.
- [x] Real Make recipe tests distinguish a successful run, Godot model failure,
      Godot X11 failure and verifier failure, including attempts to hide
      Godot failures behind successful `tee` and checker processes.
- [x] Run the actual `make test-live-stroke` pipeline, rebuilding native and
      reimporting both Drawing and Atlas with the offline Rust vendor, and
      require 81/81 headless and 144/144 X11 with nine long replay traces.
- [x] Update run instructions and link current evidence without changing any
      manual-review or hosted-CI gate.

[Commands, fail-first output, actual native run and limits](../evidence/T-263-2026-11-22-make-bash-shell.md).
