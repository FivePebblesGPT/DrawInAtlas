# Preserve retained native history during chronological detached replay

## Scope
The bounded native history retains at most 64 entries, while the local or
Atlas chronological timeline retains older checked raster deltas. Traversing
an evicted event must not invalidate the other native tokens that are still
in that timeline. An arbitrary detached recovery request cannot assert this
ordering implicitly.

## Acceptance
- [x] Reproduce loss of 64 newer Redo tokens with real eviction in both local
  and Atlas timelines, without rewriting an opaque history token.
- [x] Keep both native stacks and the persistent source store on ordered
  detached replay; do not fabricate a native event for the evicted delta.
- [x] Reject retained-token bypass, stale revision, malformed source and busy
  native store atomically; preserve signed hidden RGB and exact projection.
- [x] Traverse the boundary repeatedly and reclaim genuinely abandoned tokens
  on a new command. Keep unordered recovery's conservative invalidation.
- [x] Complete pinned Make/native, adjacent history and CI checks, and ticket
  validation with recorded evidence.

This fixes chronological replay across the bounded native history window.
The command owner still retains the older detached byte snapshots; T-148's
universal lifetime, revision and integration acceptance remains independent.
