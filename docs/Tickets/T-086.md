# Incremental viewport compositing, cached textures and zoom scaling

**Status: In Progress (2026-11-06).** Source-space cached display tiles and software tests implemented; owner physical-hardware acceptance and first-population/large dense viewport optimizations remain. Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
Standalone `DrawingCanvas._draw()` currently re-renders the visible document in 192px CPU rectangles and calls `ImageTexture.create_from_image()` on each redraw. Zooming out exposes many more source pixels and makes the app lag even for small edits. T-068's small CPU benchmark does not prove full-viewport responsiveness.

## Engineering tasks
1. Profile `DrawingRenderer.render`, memory allocations, texture creation/upload, frame submission and visible-tile count by zoom/layer count.
2. Maintain persistent display texture tiles keyed by document/layer/composite revision and view transform; schedule only dirty tiles/rectangles, with bounded cache and eviction.
3. Separate storage stride, edit dirty area and GPU display tile geometry. Use Godot native textured quads and GPU scaling; investigate derived LOD/mipmaps on zoom-out without changing canonical pixels.
4. Update textures when necessary rather than creating images/textures on every pointer redraw. Do not assume `ImageTexture.update()` is partial-rectangle upload.
5. Ensure pan/zoom/visibility/selection/asset publication/undo trigger correct invalidations; preserve transparent pixels and signed seam geometry.

## Acceptance / verification
- [x] Small raster edits invalidate nearby display content rather than the full view (headless dirty-journal and software framebuffer witnesses, one existing 128px tile per 1px edit/Undo/Redo).
- [ ] Pan/zoom and 25%/50%/100% with multiple layers do not stall UI input or exceed documented bounded cache memory **on reference Windows/Linux hardware and large dense documents**; software cached redraws are fast but first 50% population regressed in one run.
- [x] Byte/pixel parity across signed tile seams, layered alpha, text, visibility, cancellation and history (Godot native Xvfb/Mesa readback; physical display still pending).
- [x] Reproducible before/after CPU-composite, texture-call and software-frame median/p95, process HWM, exact workload, Godot version and llvmpipe context; physical GPU/display measurements still pending.

## Boundaries
- Preserve the one canonical Drawing package shared with Atlas, byte-exact saved RGBA8, source identity, one undoable content transaction per gesture and signed sparse coordinates.
- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.
- Do not mark complete merely because earlier T-053/T-063/Docking smoke tests pass. Report hardware, Godot version, viewport, zoom, timing and limitations for applicable evidence.
