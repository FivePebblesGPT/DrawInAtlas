# Separate GM and player views with projector calibration

## Source
[[E-007]] and the archived local-table/projector deliverables.

## Acceptance
- Provide independent GM editing and fullscreen player output through the agreed privacy boundary.
- Support explicit camera follow/freeze behavior without changing canonical artwork.
- Connect the player's camera to the projection framing object from [[T-013]], with the same aspect ratio as the output.
- Calibrate displayed grid/board geometry for physical tabletop use.
- Keep framing zoom/pan, output-window size and physical grid calibration distinct in the UI and data contract.
- Verify native multi-view behavior and supported display scaling; make unsupported platform behavior explicit.

## Engineering checkpoint — 2026-11-01 (partial; owner approval pending)

- Added isolated `AtlasPlayerOutputSession`: native *separate* player `Window`, blank by default, capture exclusively from `AtlasPlayerProjection.build_capture_input`'s sanitized independent campaign. No GM canvas, canonical campaign, private references or editor caches are attached to player output. Denied/stale grants and missing capture results blank the window; `invalidate()` cancels in-flight captures and removes the last texture. No user-facing publishing controls yet.
- Added explicit follow/freeze camera state linked to T-013's frame, matching aspect guard, resize reauthorization and bounded output dimensions. **Freeze is a local camera/image hold, not a permission freeze:** policy changes must invalidate even while frozen. Live editor policy tracking and grants are still unapproved.
- Added `AtlasProjectorCalibration`: measured physical output width and tabletop target cell size, with suggested board-frame width and actual cell-mm computation; physical measurement, board framing and render pixels stay distinct. No guessed DPI, automatic artwork mutation or save schema changes.
- Documented the proof, manual measurement, native-platform limits and pending decisions in [[PLAYER_OUTPUT_WORKFLOW]]. CI includes independent headless and X11 framebuffer tests. **Not closed:** privacy/publishing policy, trusted editor wiring, user-facing monitor/fullscreen/calibration UI, real display scaling/calibration and owner acceptance all remain.
