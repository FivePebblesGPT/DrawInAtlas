# Prevent flood-fill frontier from loading unpublishable signed neighbors

## Reproduced defect

`DrawingEditSession.flood_fill()` validated its seed, but enqueued adjacent
pixels without checking the same ±2³⁰ view-relative pixel limit used by
`_stage()`. A fill beginning at the final valid signed X/Y pixel could follow
a matching source into an invalid neighbor, load its lazy tile, and then abort
the otherwise valid transaction with `COORD_RANGE`. At the negative edge the
invalid neighbor may share a tile with the valid seed, still causing an
unnecessary publication rejection.

## Acceptance — verified

- [x] Reproduce failure in native-backed Godot beta4 with four legal seeds at
      positive/negative X and Y bounds and matching out-of-bounds source pixels.
      Baseline: **10 failures / 22 executed checks**.
- [x] Exclude out-of-range neighbors before queueing them or invoking a lazy
      source callback; preserve exact four-connectivity inside the permitted
      range and the existing fill candidate budget.
- [x] Check that positive-boundary lazy neighbors are not fetched, and all
      four valid edge seeds stage exactly one pixel without premature publish.
- [x] Verify exact RGBA8 commit, native Undo to transparent hidden RGB, and
      Redo for each boundary. Corrected witness: **38/38**.
- [x] Include the real native test in the existing mandatory T-068 fast CI

- [x] Run eight neighboring native flood-fill, tile, source staging and bulk
