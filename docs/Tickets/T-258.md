# Cancel floating-panel pointer gestures on window/application focus loss

## Defect and scope (2026-11-22)

T-257 repaired Escape rollback of a floating host's temporary move/resize rectangle. The same host had **no focus-out handler**: Alt+Tab/window deactivation or application focus loss could consume the OS mouse-up while `_gesture` or `_candidate_id` remained set, leaving a transient frame displaced or a tab drag alive. Subsequent input could then commit an unintended geometry/ownership change. The parent [T-091](T-091.md) remains In Progress for physical Windows/Linux acceptance.

## Acceptance — engineering Done

- [x] On `NOTIFICATION_WM_WINDOW_FOCUS_OUT` or `NOTIFICATION_APPLICATION_FOCUS_OUT`, restore the exact pre-gesture move/resize frame, cancel the host-owned tab/group drag and preview, and suppress any late mouse-up.
- [x] A subsequent **fresh** press starts a legitimate gesture even if the original mouse-up never arrived. Focus loss while idle is a no-op; an unrelated host's drag is never canceled just because this host loses focus.
- [x] Validate 100%, 150%, and 200% simulated UI scaling with actual native X11 pointer input, native notification injection, stale-release and new-press cases. Reproduce the canonical Drawing workspace embedded in Atlas and preserve dock owner, document bytes and history.
- [x] Fail first on prior code, run neighboring floating/dock suites, add an on-demand native CI workflow and record the owner/hardware limitation.

## Implementation

`DrawingFloatingHost._notification()` now uses the existing T-257 rollback and transaction-cancel mechanisms on either focus-loss signal. Its guard scopes cancellation to this host's active move/resize, pending tab candidate or owned cross-drag. `_suppress_release` protects against the former mouse-up; a new left press in a host header/tab resets suppression, preventing the next real drag from being discarded. No geometry-change or history event is emitted for canceled work.

**Evidence:** [T-258 implementation and tests](../evidence/T-258-2026-11-22-focus-loss.md). Tests: `drawing/tests/t258_floating_focus_cancel_native.gd`, `tests/t258_atlas_floating_focus_cancel_native.gd`, on-demand `.github/workflows/godot-native-t258-floating-focus.yml`, and `make test-floating-focus`.

**Gate:** Linux X11 tests inject Godot's OS notification into an actual rendered host; they do not replace testing physical Alt+Tab/window-manager behavior on Windows and Linux. **T-091, T-083 and T-250 owner gates remain unapproved**; T-258 is a narrowly scoped engineering correction only.
