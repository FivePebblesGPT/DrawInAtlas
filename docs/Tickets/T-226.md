# Redesign Colors with focused FG/BG, recent-color bars and inline scrollable native picker

## Owner design (2026-11-20)

The uploaded `DrawInAtlasColorPanel(3).png` shows an editor with FG/BG color blocks beside **vertical recent-color bars** and a native color picker directly underneath. Treat it as a design reference; screenshot is user-provided in conversation and not committed by this planning PR.

- The top section shows **FG and BG** in approximately half the width, with a distinct highlight around the **currently edited** role; choosing BG does not swap or repaint using BG.
- The other half is a compact sequence of **vertical recent-color bars**, **excluding both current FG and BG** from the displayed choices. This is a **display filter only**: keep the underlying bounded history intact, and restore entries when no longer equal to FG/BG. Use canonical packed RGBA8 equality (not approximate floating-point equality) for exclusion/deduplication. Selecting a bar applies it only to the active role.
- Use Godot's **native `ColorPicker` embedded into the scrollable panel body**, not an overflowing popup; do not create a new color engine or recreate native controls manually. The picker always reflects the active FG/BG value.
- Retain compact discoverable Swap/Default, previous FG/BG restore, canonical hex input, independent BG semantics and exact RGBA8/hidden RGB.

## Acceptance

- [ ] FG/BG selection, highlight, picker/hex sync and independent background editing are tested bidirectionally.
- [ ] Recent bars deduplicate and exclude current FG/BG using exact RGBA8 (alpha/hidden RGB included); bounded predictable history and correct selected-role application.
- [ ] Inline picker remains fully reachable by **panel scroll** at narrow/short/150–200% sizes, in minimized flyouts and floating hosts, with no popup overlay/overflow or swallowed wheel/focus.
- [ ] No accidental document dirty/history entry on UI color changes; native screenshot/pointer, persistence and Atlas/standalone tests pass.

This extends T-092 presentation without invalidating earlier functionality; owner approval under T-059/T-083 remains open.
