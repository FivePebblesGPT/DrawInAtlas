# Profile and fix slow selection Delete

## Owner finding (2026-11-20)

Deleting a selection reportedly takes a long time although painting now seems usable. This is **untimed owner feedback**, not measured latency. Distinguish **Delete selected pixels** (Del/Edit) from **Deselect** (Ctrl+D). The current workspace calls `_delete_selection() → DrawingEditSession.clear_rect(canvas.selected, canvas.selection_mask) → _commit_clipboard_edit()`; the selection bounds need not equal the allowed mask pixels.

## Scope

- Reproduce the real command with 512×512 and sparse/large selections, rectangles, mask islands/holes, empty selections, transparency and signed tile boundaries. Record OS/GPU/Godot/build SHA, zoom, touched tiles, input and time.
- Attribute command-to-visible completion, mask evaluation, tile work, GDExtension/Rust updates (if reached), commit/Undo journal, preview/texture upload, long frames and bytes. Report repeated cold/warm p50/p95 before/after.
- Apply **one profile-led improvement** without blindly clearing huge bounding rectangles or bypassing Rust-owned authority. Record counterfactuals and any regressions.
- Distinguish ordinary content deletion from selection-only non-dirty deselection. Preserve safe cancellation and pending edit restrictions.

## Acceptance

- [ ] The slow path is independently reproduced and measured, and Delete vs Deselect reported separately.
- [ ] Matched before/after input, pixel and native hashes demonstrate improvement without deferring stalls.
- [ ] Exact straight RGBA8 including hidden RGB, mask holes, locked/hidden layers, signed sparse tiles, one atomic undoable edit, Undo/Redo and Save/Open parity remain intact.
- [ ] Headless/native pointer and framebuffer regression in Drawing and embedded Atlas; memory and time are bounded for huge sparse selection bounds.
- [ ] Hardware owner recheck is requested separately; virtual-X11 is not physical acceptance.

T-088 and T-148/T-149 remain integration/ownership gates, not hard prerequisites for diagnosing this bug. No measured diagnosis or performance claim yet.
