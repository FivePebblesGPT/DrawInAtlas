# Fail closed on rejected native semantic text Undo/Redo

**Split from T-148.** Public `commit_text` was fenced in T-174, while
`DrawingDocument._replay_text_tree()` still changed semantic TEXT nodes and
parent membership before calling the post-mutation native metadata bridge.
A busy or native-ahead Rust store could therefore be detached and Godot's
local Undo/Redo cursor advanced without native approval. This ticket covers
semantic TEXT↔TEXT edits and TEXT creation/deletion history only.

## Acceptance

- [x] Validate the text history target and acquire the exact Rust metadata
  revision **before** modifying Godot nodes; return typed `NATIVE_METADATA` or
  `STALE_REVISION` on failure, without detaching native source/history.
- [x] Preserve local history cursor, text content, parent membership, dirty
  state, full native RGBA8 (including hidden RGB), and Rust Undo/Redo tokens on
  rejection. Accepted replay increments both revisions once and uses
  `discard_redo=false` to keep the replayable Redo branch.
- [x] Exercise busy-native Undo and Redo for both text creation and editing,
  native-ahead rejection, successful retries, subsequent real Hokusai
  Undo/Redo, `.drawing` Save/Open, and native-absent compatibility.
- [x] Run identical pre-fix negative control, offline Rust tests/rustfmt/strict
  Clippy/release build, text/native/Atlas/Object neighboring regressions,
  software-X11 graphical witnesses; record real logs and SHA-256 checksums.
- [x] Wire required-native CI and update T-148, the native ABI and Kanban
  index; validate ticket dependencies and unchanged manual gates.

## Boundaries

This is a **local semantic text-history** revision fence. TEXT↔RASTER
conversion still uses the T-154 parked-source contract. Host-owned detached
history, other raster producers, and universal Rust history authority remain
T-148 work; T-149 stays Blocked. No physical-device/T-095 owner approval or
hosted CI result is inferred from software-X11 testing.
