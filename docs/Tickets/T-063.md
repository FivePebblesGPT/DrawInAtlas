# Compact Draw workspace top bar, BarDivider and overflow UX

**Status: PROPOSED UI — based on owner-uploaded [[DRAW_MODULE_UI_SPEC]] (2026-11-01).** User provided the design as **Status: Proposed design**; do not imply final usability approval. This is a concrete workspace ticket, not the complete tool feature list (T-059).

## Proposed layout
- One compact top row: **fixed File/Edit/View/Image/Layers/Select/Window/Help menus** on left; `BarDivider` boundary; **contextual tool controls** to the right in a horizontally scrollable flexible region.
- **No separate quick-access toolbar** for New/Open/Save/Undo/Redo. Menu commands and shortcuts remain discoverable. New Ctrl+N, Open Ctrl+O, Save Ctrl+S, Save As Ctrl+Shift+S, Undo Ctrl+Z; one redo shortcut default must be chosen.
- Separate document tabs with modified `*` and unsaved-change prompts, left vertical tool rail, central Drawing canvas, right dock (Colors, Layers, History tab), bottom status bar (cursor, canvas size, zoom).
- Tool-specific controls for supported tools only. Do not show inert Brush/Selection/Text/Transform options merely because the spec illustrates them. The Drawing app and Object Editor should reuse layout components where helpful.

## Implementation phases (preserve uploaded specification order)
1. **Compact functional workspace:** fixed menus + contextual options row and `BarDivider`; no redundant toolbar; rail/canvas/dock/tabs/status; keyboard shortcuts and dirty state.
2. **Overflow/input polish:** tool options scroll horizontally only on overflow, no row wrapping; edge cues/chevrons, Shift-wheel/touchpad scroll, focus-in-view, scroll reset on tool switch, scrollbar input rules preventing accidental slider changes, narrow-menu More overflow, high DPI and narrow-window tests.
3. **Optional customization:** dock resize/show-hide/layout persistence/reset; arbitrary floating docks and draggable divider only if usage justifies them.

## Code responsibility
`WorkspaceUI` owns shell, `EditorTopBar` composes fixed `MenuRegion`, visual `BarDivider` and flexible `ToolOptionsRegion`; the **options region** owns scrolling/width/focus/overflow, not `BarDivider`. UI invokes shared Drawing commands, never directly edits layer pixels. See [[DRAW_MODULE_UI_SPEC]] section 6.

## Acceptance
At normal desktop widths menus + important contextual controls occupy one row; at narrow widths settings scroll but canvas height remains unchanged; focus reachable by keyboard; hidden controls discoverable; tool switching resets option scroll; pointer wheel cannot accidentally adjust slider while intending bar-scroll. Document changes survive tab/module switching and closing prompts. Owner validates native UX screenshots and actual pointer interactions.

## Coordination
T-053 provides an independently running Drawing editor; T-059 will add remaining feature inventory; T-062 provides Object Editor-specific context. Do not change Atlas mode selection or undo semantics inside layout code.

## Round 5 — history-option UI (confirmed behavior, placement proposed)
Expose an obvious user-facing toggle **Record selection changes in Undo History** (default **OFF**), for example in Edit/History settings or the History dock. The exact control placement may be assessed alongside [[DRAW_MODULE_UI_SPEC]]; toggling must not consume a top-bar tool-options slot, because it is a workspace/history preference, not a brush setting. When ON, meaningful selection commits are eligible for separate undo/redo steps (T-054); when OFF, content-undo selection/mode restoration still works. The preference itself must not mark a document dirty. Decide persistence scope (per-workspace vs app preference) in T-051.

## Round 7 — Asset Browser dock parity (owner approved)
The new **Asset Browser** must behave like the existing Colors/Layers/History panel dock: dock/tab selection, show/hide, resizing and keyboard accessibility. The Object Editor is a **dedicated document tab** hosted by Drawing; opening a selected asset must not add a separate toolbar row. See [[T-065]] for file indexing, thumbnails, Search, drag/drop, Save As, nested assets and NULL placeholders. This is an accepted panel requirement, even though the source [[DRAW_MODULE_UI_SPEC]] remains a proposed full workspace layout.

## T-063 implementation and verification — 2026-11-02

**Engineering state: Done.** The shared Drawing/Object Editor shell now uses
`addons/drawing/editor_top_bar.gd`, which owns `MenuRegion`, `BarDivider`,
`ToolOptionsRegion`, fixed eight menus and a keyboard-accessible **More** command
fallback. Brush/Eraser show their real width and snap settings, Select/Move/Text
show their generic snap control, and Pan has no inert options. The options region
provides chevrons, Shift/horizontal wheel support, focus-to-view, non-wrapping
layout and scroll reset on tool change. The selection-history preference moved to
the History dock (OFF by default, no content dirtying). The right-side
`HSplitContainer` dock supports resizing, show/hide, and reset; the dock's existing
Colors/Layers/History tabs serve as the peer contract for T-065's later Asset Browser.

File/Edit commands display their accelerators; **Ctrl/Cmd+Shift+S opens Save As**,
**Ctrl/Cmd+Y** is the primary redo shortcut (Shift+Z remains a compatibility
alias), and existing close-with-unsaved-changes protection remains intact.
The status bar reports cursor world pixel, bounded canvas dimensions and zoom.
No toolbar row was added. The fixed menu names are
File/Edit/View/Image/Layers/Select/Window/Help. Object source commands remain
accessible in File/Image/Window without a ninth menu.

**Native evidence:** `drawing/tests/compact_workspace_smoke.gd` exercises 52
assertions under X11/Mesa, including 1280×800, 560×600 and 1.5x content
scale, pointer-wheel safety, hidden-command dispatch, dock toggling and the
Save As dialog. The existing standalone and Object Editor suites confirm no
core/publishing regression; `drawing/tests/workspace_keyboard_smoke.gd`
continues testing document/undo/unsaved-close routing. The Python
`tests/test_t063_workspace_docs.py` checks source and ticket boundaries.
The same native witness runs in CI.

**Not claimed:** The complete 47-Essential feature UI, an Asset Browser (T-065),
arbitrary floating docks, persisted personalized layouts, and native Windows
hardware usability. This ticket implements a reversible engineering prototype
of the proposed workspace; **owner hands-on final UX acceptance remains in
T-059** and integration signoff in T-056. No review approval is inferred.

## Owner-requested workspace refinements — 2026-11-02

**Scope: T-063 refinement, not a second ticket.** Based on the owner’s feedback
following the first 682673f prototype:

- The six left-rail tool names are replaced by Drawing-owned, packaged **SVG
  icons** (Brush, Eraser, Select, Move, Text, Pan). Keyboard-focusable buttons
  retain explicit tooltips and a visible pressed state. The fixed eight textual
  application menus remain discoverable, as required by the original spec.
- **Window → Show document tabs** is a checked, reversible **session-only** toggle
  for the `Untitled`/Object Editor tab strip. The current document name and
  dirty `*` remain in the status bar while hidden; Ctrl/Cmd+Tab and
  Ctrl/Cmd+Shift+Tab cycle documents, and New/Save/Close retain their safety
  prompts. This changes chrome visibility, not document/session ownership.
- The right resizable dock now stacks **Colors → Layers → History** in a single
  vertical `ScrollContainer`, rather than choosing mutually exclusive tabs.
  The layer tree keeps its own bounded row viewport; short windows can scroll
  to History, including via keyboard focus. Dock hide/show/reset is preserved.
  T-065 may add Asset Browser as an equivalent *stacked panel* without changing
  the source-editing tab architecture.

**Verification:** `drawing/tests/compact_workspace_smoke.gd` now checks **75 required**
real native X11/Mesa assertions (up from 52), including icon loading and
pressed state, hidden-tab keyboard navigation and close guard, scroll overflow,
History focus visibility, narrow windows, 150% scaling, Save As, undo/redo and
zero-alpha pixel integrity. An optional screenshot environment adds four image
capture checks (79 total). `tests/test_t063_workspace_docs.py` verifies source,
asset staging and review boundaries; `tests/test_drawing_app.py` checks clean
standalone packaging. CI continues to run the native witness after SVG import.

**Review boundary unchanged:** T-063 has no manual gate and remains Done for

[T-078–T-083](../DRAWING_DOCKING_SPEC.md), rather than silently expanding this

follow-ups is implemented by T-063**, and its Done status does not approve
