# Separate visual Brushes panel with native-backed parameters

**Owner request (2026-11-17):** "The brush selector should be a separate panel
with visual selector and parameters." The T-182 text dropdown is an interim
accessibility fix, not the requested final brush-selection interface.

## Deliverable

- Add a dedicated **Brushes** panel to the shared Drawing workspace using its
  existing grouped dock/floating-panel model and stable panel IDs.
- Present selectable visual stroke/dab previews with preset names, a clear
  active selection, keyboard focus and accessible labels. Generate previews
  from representative native preset output rather than generic circle icons.
- Provide meaningful parameter editing: size/width, opacity and the selected
  preset's supported shaping controls (for example hardness, spacing or flow
  where a defined native mapping exists). State units/ranges and actual native
  effects; document which parameters each preset exposes.
- Keep one active settings authority shared with Brush/Eraser and any compact
  toolbar shortcuts. Freeze in-flight and queued gesture settings. Reuse
  workspace persistence conventions and define preset/default/reset behavior.
- Keep the panel usable at narrow sizes, when scrolled, docked and floating.
  Scope the work to Drawing-owned UI shared by standalone/Object consumers.

## Acceptance

- [x] The real app has a separate visual brush panel, not just another text
      dropdown; all four existing presets can be selected and identified.
- [x] Parameter controls change the settings actually consumed by native
      strokes, without creating document history until a gesture is committed.
- [x] Brush/Eraser, 96px selection, tool/tab switches, queued gestures and
      per-gesture frozen settings remain coherent.
- [x] Visual examples reflect T-183's preset behavior once corrected; retain
      representative screenshots and native parameter-effect tests.
- [x] Test narrow-window focus/wheel access, layout restore, hidden/floating
      ownership and teardown with no orphaned option/popup resources.

T-183 is related rather than a hard dependency: panel composition can proceed
independently, with final native examples/settings refreshed after preset fixes.
This feature does not close the existing owner workspace acceptance gates.

## Completion evidence — 2026-11-17

[Native visual panel, deterministic preset examples, versioned preference and
real Hokusai pixel/frozen-gesture tests](../evidence/T-184-2026-11-17-brush-panel.md).
The canonical shared workspace has one `brushes` dock view with generated
preview buttons, compact-toolbar synchronization, width (1–96 Drawing px),
opacity (0–100% of preset), native hardness (0–100%), per-preset overrides and
reset; native painting, floating/persistence and narrow focus are covered.
T-183's corrected preset behaviors were used for the generated thumbnails.
This closes the engineering feature, **not** the separate owner-hardware,
workspace acceptance, native-transition, or responsiveness review gates.
