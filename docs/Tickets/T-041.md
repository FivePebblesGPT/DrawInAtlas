# Author and move tabletop tokens

## Source
[[Archive/2026-10-30/IMPLEMENTATION_PLAN#Current execution milestones (1–8)|Execution milestone 7]]: tokens.

## Acceptance
- Agree token identity, position, layer/context association and permitted visibility.
- Implement placement/movement with appropriate selection, protections, undo and saving.
- Keep GM/private tokens out of player output and honor the projection contract.
- Avoid introducing a rules-engine/combat-system scope beyond tabletop token use.

## Engineering checkpoint — 2026-11-01 (partial; approval pending)

- Added typed `AtlasToken` and `AtlasTokenLayer` Resources. Stable validated IDs, finite signed board positions, bounded radius, printable label and RGBA tint persist in native `.scn` without introducing separate sidecars or rules-engine state. A floor/LOD-specific `TOKENS` layer is created lazily by the GM Token tool and has the same order, lock, visibility and opacity rules as other layers.
- Added Token (K) in the palette with native drawing, hit selection, stationary placement, detached drag preview, deletion, styling via the inspector, optional snapping and one guarded history transaction per edit. Stale edits and locked/hidden/mismatched contexts do not mutate the campaign. Cell masks require the full token bounds inside the edit region. See [[TOKEN_WORKFLOW]].
- Tokens are **GM-only**. The T-039 sanitizer never accepts them, even if a caller explicitly tries to grant a token layer. Native save roundtrip and the source/export-pack portability fixture now include a token layer. This is not a working player-token publication or role-permissions system.
- **Still open:** agreement on token privacy/visibility, per-token versus per-layer publication, labels and sizing UX, token selection hierarchy/ownership, in-person usability, and T-043 end-to-end privacy acceptance. T-039's policy dependency remains unresolved; do not check this ticket off in [[Index]].

## Gesture safety follow-up — 2026-11-01 (engineering evidence, not acceptance)

Token drags now freeze the press-time map, floor, `AtlasTokenLayer` resource,
source token contents, edit-mask polygon/enabled state, and snap toggle.
Pointer updates and release reject changed authorization or stale source
**before** emitting `token_edit_requested`; the preview and selection clear,
with a visible explanation and no movement history command. A fresh drag
succeeds under the current scope; cell focus while the mask is off is harmless.

`tests/token_smoke.gd` covers stale masks, a successful retry, locked and
replaced layers (including reused IDs), concurrent token changes, and
unrestricted cell focus. `tests/token_visual.gd` verifies that rejection
