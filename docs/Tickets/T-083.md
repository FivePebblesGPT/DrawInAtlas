# Dock layout persistence, recovery and owner UX validation

**Status:** Ready for persistence/recovery engineering after T-082 was completed (2026-11-03). **Owner approval required** only after engineering work is complete and a reviewable native build is available. Owner agreement to the staged ticket plan on 2026-11-02 is **not** approval of the delivered interaction. See [design contract](../DRAWING_DOCKING_SPEC.md) and [review workflow](../TICKET_WORKFLOW.md).

## Scope

- Persist/restore per-workspace docking state with versioned schema: panel/group IDs, tab order, group ordering and membership, current active tab, expanded/collapsed group sections, whole dock minimized/expanded state, open flyout group, floating-host visibility, size/position/z-order where safe.
- Recover from missing/renamed/unsupported panels, stale data, malformed layout settings and display-resolution/DPI changes. Never lose document/layer content or strand a panel off-screen. Provide **Reset workspace layout** and predictable migration from T-063's three vertically stacked groups.
- Validate shared Drawing/Object Editor use; Asset Browser is a future peer under T-065 if shipped, and must register without hardcoding its presence. Do not extend this ticket into T-065 asset logic or into T-059's whole-drawing inventory.
- Conduct accessibility, focus, tooltip, resize, visual consistency and native/manual interactions across compact and normal desktops. Collect a reviewer walkthrough/video or screenshots with the actual grouping/dragging flows before requesting owner UX signoff.

## Acceptance — engineering

1. Save/relaunch/load a mixed layout with two dock groups, one floating multi-tab group and a minimized dock; all tabs, icons, separators, group order, selection and collapsed state round-trip exactly.
2. Exercise migration from T-063, corrupted data, absent future panel plugin, changed display scaling, offscreen placements, reset defaults and clean shutdown; failures are safe and deterministic.
3. Native integration tests cover group flyout, reorder, float, redock (preserving group tab order and insertion at preview position), keyboard focus, 420px and desktop widths, and no unwanted OS windows.
4. Final documentation reflects real features and known limits. Existing standalone Drawing/Object Editor and relevant Atlas smoke tests pass.

## Manual review gate — do not auto-close

After the engineering evidence is complete, set **Manual Review** and ask the owner to use the build to verify: shared flyouts from separator-delimited rail groups; independent group collapse; icon affordances; tab reorder/merge/split; in-app floating tabbed hosts; group re-dock preserving order at the insertion hint; layout persistence and recovery. Record **explicit owner response** as `manual_review_approved` plus `review_evidence` before marking Done. Keep [T-059](T-059.md) and [T-056](T-056.md) separate, unapproved gates unless the owner independently approves their scope.
