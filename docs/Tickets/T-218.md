# Verify all Godot PCK payload checksums and reject overlapping resource extents

## Problem

T-217 checked the PCK v4 index and essential Drawing resource checksums, but
other indexed resources were not checked against their stored Godot MD5. A
corrupted non-startup asset or two overlapping file extents could pass Linux
native export preflight despite an intact startup scene and manifest.

## Acceptance

- [x] Reproduce five failed/erroring fail-first assertions: non-essential
      payload tampering, index checksum tampering, and overlapping records
      (plus the positive count contract). Previous inspection accepted all
      three malformed cases.
- [x] Check every indexed resource checksum in bounded streaming chunks,
      including zero-length legitimate resources; preserve the required
      startup/ABI witnesses and their nonempty constraints.
- [x] Reject overlapping nonempty file extents, even with equal content and
      equal checksums, before accepting an exported PCK.
- [x] Show packaging rejects a corrupt optional asset without installing the
      native `.so`, touching other export bytes, or leaving preflight files.
- [x] Run all existing release/packaging regressions, configured Python and
      lint targets, 35 native Rust tests and an isolated ABI/application launch
      using the 528-resource real Godot 4.8 beta3 PCK.
- [x] Wire the regression suite into Make and the desktop/portability workflows;
      record raw evidence, source hashes and process outcomes.

## Evidence and remaining gates

[Fail-first, source hashes, final validation and raw logs](../evidence/T-218-2026-11-19-pck-payload.md).

This verifies stored **Godot MD5 integrity fields**, not cryptographic
publisher authenticity (MD5 is not a signature). Nor does it certify
script behavior or a continuously healthy running renderer. The real app
uses the supplied beta3 Godot binary with exported PCK/native `.so`, not an
official release-template ELF. Hosted CI, Windows native runtime, owner
physical UX, and T-197 performance acceptance remain open. T-105, T-106,
and T-180 remain In Progress; no manual gate has been approved.
