# Restore T-085 native live-stroke input, queue and cancellation regressions

## Bounded scope and acceptance

After native Hokusai became the only Brush/Eraser engine, the historical
T-085 model's `paint_path` Brush comparison reported 8/77 failures. Its
X11 native test still demanded changed pixels on a stationary press, and a
layer-switch fixture attempted to create a layer inside an active native
transaction. The latter silently returned an error result whose null ID
caused a GDScript runtime failure before the suite could finish. T-203 did
not change these tests.

- [x] Preserve delivered pointer sample counts, 1.0/0.5/0.25 zoom mapping,
      bounded native queue drains, first held-frame preview, source
      nonpublication until release, and one-step history/Undo. Compare long
      Brush paths to an independently committed **native Hokusai** control
      with identical actual routed source samples and receipt timestamps;
      not the superseded Legacy `paint_path` renderer.
- [x] Require real nonempty native Brush changes for enabled/hole/inverted
      mask, stable-mask history, selection-change cancellation and Eraser
      draft checks instead of assuming 1px stationary Hokusai dabs changed
      source. Include a changed-width reference negative control.
- [x] Ensure raw X11 release and motion paths remain exercised. Capture the
      actual native input values *after* Godot routes events: synthetic
      pixel-to-screen-to-source reconstruction differed in many samples,
      especially at fractional zoom. A missing or duplicated routed event
      fails explicitly; do not relax the nine 840-point long-loop trials.
- [x] Create a valid replacement layer before the layer-change cancellation
      witness rather than during an active native stroke, then verify
      outside-control sparse release/Undo and other cancellation gates.
- [x] Repeat headless and software-X11 fixtures, run adjacent regression
      suites, Rust/Python tooling, index validator and record raw process
      exits. Do not change production Brush, raster authority, compositor,
      scheduling or physical-device acceptance.

## Delivery and limits

`drawing/tests/live_stroke_smoke.gd` passes **81/81 checks in four fresh
headless runs**. `drawing/tests/live_stroke_native.gd` passes **144/144
checks in four native software-X11 runs**; each includes nine 840-point
loop/crossing bursts, real framebuffer preview/commit/Undo and tool,
selection, zoom, layer and outside-control cancellation. The T-200
native reference has no Canvas callback and uses identical per-sample
receipts; the model's changed-width control differs in pixels.

See the [fail-first logs, test commands, source hashes and explicit
limitations](../evidence/T-204-2026-11-19-native-live-stroke.md).
This is a **test-oracle / invalid-fixture repair**, not a new Brush speed,
frame cadence or hardware result. Parent T-085 still depends on T-149 and
needs Linux/Windows physical presentation and latency acceptance;
T-106/T-180 hosted CI gates remain open. No manual owner gate is approved.
