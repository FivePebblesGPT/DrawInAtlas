# Make snapping coherent for detail editing

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 12: placement appears to snap and not snap at the same time.

Battlemat-specific snapping is retired with [[T-014]]/[[T-015]]. This ticket carries forward the usability concern for the accepted artwork and editable-object tools.

## Acceptance
- Agree which artwork/object operations snap to the editing grid, which coordinates are used, and how snapping is enabled/disabled; use Paint.net conventions where applicable.
- Draft feedback matches the committed object for both free and snapped operations.
- Cover rotated grids/objects, all drag quadrants, zoom levels and masks.
- Preserve artwork positions unless the user explicitly chooses a content transform.
- Keep projector framing/calibration policy separate; it is defined through [[T-013]].

## Implementation and verification — 2026-10-30

- Policy and explicit snap targets: [[GRID_SNAPPING]]. Opt-in for shape endpoints
  and selection moves; free pen, numeric transforms, marquee and resizing.
- `AtlasGridSnap` uses board-space nearest square/axial centers, accounting for
  rotated/translated grids. Move displacement uses two cell centers, so a
  selected off-grid object does not jump at the start of a drag.
- Inspector toggle drives both draft and commit through the same canvas path.
  Gridless boards disable snapping. No native-save schema change or implicit
  artwork transform.
- Regressions: `tests/snapping_smoke.gd`, `tests/snapping_visual.gd`, added
  to the strict CI workflow.
- Godot `4.8.beta2.official.cafc17a19`: import/parser, explicit type check,
  30 applicable headless suites, 15 Xvfb/Mesa native suites, main scene,
  Web release export, and four source/export-pack save interoperability
  checks passed locally. T-016 focused coverage: 90 headless and 10 native
  checks; native screenshot inspected at 960×660 and layout at 800×600.
  Remote CI and manual ergonomic acceptance remain unverified.
