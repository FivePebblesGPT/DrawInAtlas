# Close only the visible document tab under a clipped close glyph

## Defect

The native Godot `TabBar` has `clip_tabs = true` and scrolls to the selected
last document as more tabs are opened. In Godot 4.8 beta 3,
`get_tab_rect(index)` returns a shared zero-origin fallback rectangle for
**multiple hidden tabs**. The `DrawingWorkspace._tab_close_hit` override
iterated all rectangles in ascending index order, so clicking the close glyph
of visible tab 11 on a 13-tab strip returned **index 0**. Closing a clean,
scrolled-away document could therefore **silently delete the wrong tab**,
while a dirty tab could prompt for the wrong document.

## Engineering acceptance — Done

- [x] Resolve the native `get_tab_idx_at_point` for the actual pointer before
      evaluating the close-glyph subrectangle. Ignore points outside the
      visible TabBar strip and native hits with no rendered tab.
- [x] Keep the 28px close target behavior for visible tabs, including
      inactive dirty documents, without changing tab selection on prompt.
      The close target never aliases an offscreen document.
- [x] Confirm a clean hidden tab is not silently removed when closing a
      *different* visible dirty tab. Cancel retains all documents; returning
      to the first tab permits its ordinary clean close.
- [x] Cover 100/150/200% simulated UI scaling, title/body versus close
      regions, outside-strip clicks, back-to-first scrolling, and actual
      X11 pointer presses in standalone Drawing. Cover the canonical workspace
      inside Atlas and document/history integrity.
- [x] Add a clean-build Make target, on-demand native CI workflow, strict
      success-marker verification, neighboring UI tests, and engineering evidence.

**Implementation:** [`DrawingWorkspace._tab_close_hit`](../../addons/drawing/workspace.gd)
checks native tab ownership before the close rectangle. No raster, native
