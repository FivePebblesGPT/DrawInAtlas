# Accurate large selection contours and low-latency floating Move

**State: Ready for the next sprint (2026-11-07).** The owner's selection usability complaint is unresolved despite passing model/native correctness tests.

## User reproduction

Create a painted region spanning multiple storage/display chunks. Select a meaningful rectangle or a mask with Add/Subtract islands and holes. The initial marquee disappears and a larger, less precise outline appears; moving the selected pixels is **visibly laggy**. Selection and Move should not look like a box around all nonempty pixels, and the user must be able to distinguish the selection boundary from a conservative bounding rectangle.

## Confirmed code behavior / hypotheses

In `addons/drawing/canvas.gd`, `_draw_selection_outline()` traces the actual mask only when `selected.size.x * selected.size.y <= 4096` and zoom >= 0.5. Larger masks deliberately draw the enclosing rectangle and operation guides. This explains why an initially precise outline can become a larger box; it is not evidence that the actual selection *data* became rectangular.

A floating Move currently calls `_stage_move_preview()` as the pointer displacement changes. It starts a new edit session and calls `DrawingClipboard.move_selection()`, which captures source pixels, clears the selected area and pastes at each new displacement. That repeated work is a likely latency contributor; quantify it before changing the algorithm.

## Engineering tasks

1. Separate the transient drag marquee, persistent mask boundary, enclosing bounds and floating-content footprint visually and semantically. Avoid claiming that a bounding rectangle represents the exact selection.
2. Render visible selection contours with bounded work at large sizes: cache mask boundaries/tile spans or recompute only viewport-visible edges; preserve disjoint islands, holes and subtract/intersect semantics.
3. Profile Move pointer-event latency, source capture, clear/paste, session construction and compositor invalidation. Avoid recapturing the identical original source on each drag update; reuse immutable source/mask data and update only affected preview regions.
4. Preserve cumulative floating Move, repeated drags before explicit drop, Escape cancellation, click-outside behavior, correct layer depth, signed chunk boundaries and one Undo/Redo content transaction.
5. Add native pointer/framebuffer tests for selections exceeding 4096 pixels, complex masks, rapid drags at multiple zooms, and cold/warm viewport performance.

## Acceptance

- [ ] Initial marquee and the resulting persistent outline describe the same **actual mask**, without an unexplained jump to a larger bounding rectangle.
- [ ] Large selections display visible islands/holes correctly and render without unbounded CPU work during panning, resizing and moving.
- [ ] Repeated floating moves remain responsive through physical pointer interactions; record median/p95 motion-to-preview and release/drop timings with a hardware baseline.
- [ ] Byte-exact content and mask semantics, overlapping source/destination, multi-layer compositing, cancellation, one-step Undo/Redo, and clipboard paths keep existing T-088 regressions passing.
- [ ] Owner performs a real move on a representative large selection and confirms the visual/latency behavior.

## Boundaries

Do not change selection mask truth to match its drawing shortcut. Maintain the bounded sparse document model and keep the physical owner UX gate separate from automated software-rendered tests.
