# Preserve history ownership while a native tile transaction is active

**Bounded T-148 child.** `set_external_history()` previously checked only
committed document revision and local events. Between Rust `begin_edit` and
commit/cancel, neither had advanced, so a caller could transfer an already
in-flight command from the local history to Atlas or vice versa. The eventual
publisher would then record under a different owner than the one at gesture
begin.

## Acceptance

- [x] Expose a side-effect-free native active-edit query, without advancing the
  Rust FFI counters, revision or token stacks.
- [x] Refuse changing `external_history` in either direction while the attached
  native store has an active edit; retain idempotent same-owner calls.
- [x] After cancellation, unchanged documents may still explicitly select an
  owner. A subsequent real direct edit must retain its native authority and
  exact hidden-RGB Undo/Redo semantics for both local and host owners.
- [x] Reproduce failures against the previous native library, record native,
  standalone and Atlas regression evidence and pin the test in required CI.

## Completion — 2026-11-22

The 40-check fail-first Godot fixture rejects **10/40** checks with the old
native binary and old history-mode handoff. After the Rust query and checked
handoff, it passes **40/40**. Both ownership directions reject without
altering document revision, native counters or active transaction. Cancelling
restores legitimate pre-edit owner selection. Rust's **36/36** tests and the
existing native/Atlas history suites pass locally. See
[execution evidence](../evidence/T-243-2026-11-22-active-history-handoff.md).

**Scope:** This closes the active *attached Rust tile edit* handoff window.
It does not track every standalone GDScript-only pending session, integrate
arbitrary external commands, complete T-148, unblock T-149, or imply hosted
CI or physical owner approval.
