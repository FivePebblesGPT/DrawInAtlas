# Reduce residual 96px gesture latency after run-aware native grouping

**Motivation:** T-188 removes repeated storage-tile hashing during native
pixel-grouping/authorization, with exact source and history parity; its matched
100-event rapid full-gesture p50/p95 is still **266/422ms cold, 286/297ms
warm** in the last same-binary A/B round, missing the **250ms milestone / 200ms
stretch**. The prior matched round showed cold p50 **352ms**, underlining
run-to-run variation. Do not replace this metric with native stage CPU,
frame p50, or software-rendered apparent FPS.

## Scope (one next measurable engineering change)

- Start from T-188's per-phase native traces. Hokusai stroke rasterization
  remains ~50ms, changed-pixel quantization ~20ms; other fixed costs include
  preview updates, 100-event input drain, release/commit and postdraw.
- Choose and implement **one** measured causal optimization with fail-first
  Rust + graphical regression and same-source/native-binary A/B. Avoid changing
  sample geometry, dropping intermediate tiles, weakening the 6ms soft drain
  deadline, or hiding input queue/post-release latency.
- Preserve native Rust/Hokusai-only Brush/Eraser, masks, signed tiles, alpha
  and hidden RGB, floating/source history, queued/frozen/cancel paths,
  Save/Open, warm preview retention and bounded memory.
- Repeat the exact 96px/512² 100-event benchmark; report cold/warm complete
  `total_to_postdraw_ms` p50/p95 and the 250/200ms gates, release→commit and
  settled display, per-phase CPU, first preview, frame/postdraw p95 and long
  frame fraction, input backlog, byte transfers, source hashes, RSS, and raw
  failed runs. Re-profile physical/owner acceptance separately under T-095.

## Acceptance

- [ ] Matched improvement survives repeated processes and native graphical
      parity/Undo/Redo/Save/Open tests; no source or queue regression.
- [ ] The 250/200ms milestones are explicitly reported against the unchanged
      full gesture, with any unmet target left open under a follow-up.
- [ ] Do not self-approve T-095, T-151 or T-152 review/hardware gates.
