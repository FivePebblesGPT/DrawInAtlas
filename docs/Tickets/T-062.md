# Object Editor for reusable Atlas Object Assets

**Status: PLANNED — UI placement remains open; Save As instance rebinding is owner-approved (2026-11-02).**

## Why
The owner envisions authoring an **object**, placing instances that link to its asset in Atlas, and editing/saving the original or saving it as a new copy. A generic whole-map document link is not the target. This editor must reuse the Drawing paint/shape/text/layer engine.

## Plan
1. Create an Object Asset authoring workflow hosted in the independent Drawing runtime, possibly exposed as a distinct Object Editor mode or document tab; exactly where the UI lives is a T-051 decision. No Atlas import in the Drawing engine.
2. An editable Object Asset owns asset-local origin/bounds, optional transparent pixels, generic layers/groups, one-text-per-layer records and semantic objects. It is independently savable/openable as a reusable source asset.
3. Provide explicit `Save` (update existing source ID/content) and `Save As` (new ID/deep copy) with modified marker, unsaved-change prompt, target name/path and undo/savepoint semantics.
4. In Atlas, an instance offers `Edit Source` to open the Object Editor with a captured stable instance/map/source editing context. **Save As through that instance automatically creates Variant B and rebinds only the captured instance to B**, leaving others on the original. An independently opened Object Editor's Save As creates a new asset without any Atlas instance binding change. Always display source/instance identities.
5. After ordinary source Save, every instance still linked to that source displays new artwork. Save As routes asset duplication through Drawing but Atlas owns instance rebinding, combined as **one logical atomic history operation**. Changing an instance transform never modifies source. Support cancellation, stale/deleted/replaced captured instance, broken links, concurrent source edits and safe mode transitions without partial saved/rebound state.
6. Add tests for Save, Save As through selected instance A versus standalone editor, pixel-perfect transparent art, one-to-many refresh, asset cloning, failed/stale atomic rebind, undo/redo restoring A's previous/new source link and appropriate source/instance editing mode. Check that instance B and old source do not change on A's Save As.

## Acceptance
One editable object source can be used at multiple Atlas placements with independent transforms. `Save` updates the shared source; **`Save As` entered through instance A creates a new source and automatically retargets A only**; standalone Save As cannot rebind any instance. Undo restores the original binding and relevant selection/mode; redo returns to Variant B. Independent Drawing and Atlas use the same painting engine; owner reviews the UX.

## Non-goals
No procedural prefabs, nested objects, per-instance override system or network asset synchronization without explicit later approval.

## Round 6 — Save As copy survives Undo (approved 2026-11-02)
When editing through instance A and saving as Variant B, Undo rebinds A to its original asset **without removing B from the asset library**. The Object Editor must allow later opening or placing B independently, including after reloading the library. Redo reconnects A to B using its original ID, not a new deep copy. Avoid misleading labels such as “Undo create variant” if undo only reverts the binding; the history UI should communicate the effective action accurately. Deleting Variant B is a separate explicit operation.

## Round 7 — dedicated tab and Save-to-publish (owner approved)
- The Object Editor is a **dedicated document tab** built on the Drawing engine, not a separate painting engine. Atlas launches the tab with a captured source/instance edit context; standalone Drawing may open asset tabs without Atlas context.
- All source changes while the tab is open are **private draft edits**, including unsaved renderer previews and text changes. Other placed instances continue to display their **last saved source state**. Publish/refresh all linked instances **only after explicit Save**; unsaved-close prompts and local undo work on draft data.
- Save As from instance A writes new B under the portable campaign-side `Objects/` and rebinds A only. Existing B created by Save As survives an Atlas undo, even when unreferenced. Failed saves/failed rebind cannot silently publish partial results.
- Provide access to the **Asset Browser** dock (T-065) with object thumbnails, identifiers, tree/navigation, import/open/edit, and drag/drop placement. Its dock behavior should match other Drawing panels (T-063).
- Child Object Asset references in the source are supported as planned under T-064 with cycle checking and dependency handling. Nested child edits/selection use the same engine, with clear asset-boundary navigation.
- Changes to the *published source* after Save versus Atlas global history across file boundaries remain a T-051 transaction contract; do not falsely claim this is solved by ordinary in-memory GDScript undo.
