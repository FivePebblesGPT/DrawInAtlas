# Validate signed clipboard capture rectangles before source traversal

**Split from T-148.** `DrawingClipboard.capture()` accepts arbitrary signed
64-bit `origin_x` / `origin_y` and a signed 32-bit `Rect2i`. Previously it
added them before checking the source range. `INT64_MAX + 1` wraps to
`INT64_MIN` in Godot, silently returning a clipboard from an unrelated
coordinate. Even a legitimate `±2^60` origin could become out of range when
the requested rectangle extends beyond it. Rectangles could also cross the
local `Vector2i` boundary, corrupting stored selection coordinates.

## Acceptance

- [x] Validate each supplied 64-bit origin with the shared inclusive `±2^60`
  document-anchor range **before** adding any 32-bit rectangle offset.
- [x] Check both first and last included source pixels against that bound;
  reject 32-bit clipboard-local rectangle overflow. Keep valid signed
  endpoints, far-off Atlas source origins and sparse selections working.
- [x] Invalid captures must return `COORD_RANGE` without materializing lazy
  chunks, changing document revision/display epoch or touching existing
  Rust tile/history authority. Preserve alpha-zero hidden RGB for valid
  lazy capture.
- [x] Prove the pre-fix bug with an identical fail-first regression, then
  run a real Hokusai-native witness, neighboring clipboard/selection,
  Rust build/lint, Atlas/Object/history and software-X11 regressions.
- [x] Update required-native CI, ABI documentation, parent T-148, and
  `docs/Index.md`; retain T-095's owner/hardware gate and T-149 block.
