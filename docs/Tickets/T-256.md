# Add panel/group context menus to floating icon tabs

## Finding and bounded scope (2026-11-22)

T-222/T-254 introduced RMB and Shift+F10 panel menus for docked and minimized
flyout icons, but T-225/T-255 floating tabs still exposed only LMB selection and
Ctrl+Alt reordering. The floating host's private `_arrange()` helpers were never
wired to a context menu. A fully clipped tab also retained a Godot global hit
rectangle overlapping the floating move grip; pointer context must use the
**visible** horizontal strip, just like T-255's left-click correction.

## Acceptance — engineering complete

- [x] RMB over a visible floating tab opens an icon-scoped menu without
  selecting the tab or changing the model. Reorder, split into another
  one-group host, dock one panel and dock the whole group use checked existing
  `DrawingDockDrag` transactions; inactive tabs remain valid targets.
- [x] Shift+F10 / Menu opens the menu for the **focused** floating tab. RMB or
  Menu on the move grip opens a separate whole-group menu. No permanent text
  buttons appear in the compact floating header.
- [x] Invisible horizontally clipped tab rectangles cannot intercept RMB on
  the grip; partial tab targets remain confined to the visible strip.
  Verify at 100/150/200% simulated UI scale with actual pointer events.
- [x] Context commands fail closed if the target leaves the host before a
  deferred popup action; preserve one-group-per-host, view identity, source,
  history and workspace ownership, including Atlas embedding.
- [x] Fail-first real X11 regression, native screenshots, standalone and Atlas
  tests plus the existing T-081/T-083/T-091/T-225/T-254/T-255 dock regression
  suite pass. Add an on-demand clean-native-build workflow.
