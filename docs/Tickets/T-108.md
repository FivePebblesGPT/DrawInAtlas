# Nested Object Save As link-vs-copy policy and safe export

**Parent:** [T-064](T-064.md). **State:** Ready. This ticket has its own independently verifiable outcome; it does not inherit the parent’s remaining manual/device acceptance.

## Problem
The nested-asset graph works in local tests, but the product decision for a single nested parent Save As/export (preserve child references versus deep-copy) is unresolved.

## Bounded implementation / research
Prototype explicit link-preserving and deep-copy effects on identity, portable paths and dependent previews, and offer one documented user-visible policy with no implicit graph duplication. Guard cycles, NULL references, stale generations, project component copies and atomic rollback.

## Acceptance and evidence requirements
Compare Save As/reload, nested selection, source update propagation and portable project copy with exact object IDs and Undo/Redo. Obtain explicit owner approval of the link-vs-copy behavior before Done; original T-064 history is not proof of that decision.

## Existing evidence / starting point
[Existing nested graph and portable-copy history](History-T064.md).

**Manual decision:** the owner must explicitly approve the policy with dated evidence; do not self-approve.

## Scope boundary
Change only this deliverable; keep canonical straight RGBA8, signed source coordinates, layer/mask semantics and atomic Undo/Redo where relevant. Preserve the existing T-094 fail-closed CI log policy. Record actual commands, exit codes, raw failure controls and source SHA. Do not treat Xvfb/Mesa engine callbacks as physical input-to-photon timing.
