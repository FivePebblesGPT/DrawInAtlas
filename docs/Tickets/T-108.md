## T-108 opt-in engineering prototype — 2026-11-12

**Not owner-approved.** `AtlasObjectLibrary.save_as(..., nested_policy="links" | "deep_copy")`
now exposes two explicit **internal** prototypes. The normal Object Editor
continues to pass no policy and still receives `NESTED_SAVE_AS`; no default
has been chosen or displayed to users. `nested_save_as_impact(draft)` reports
source and child counts before either experiment. A stale pixel revision,
child graph revision or registry hash fails closed.

- `links`: one new parent Drawing source, fresh child placement IDs/generations,
  same published child *source* IDs. Future Save of a shared child propagates
  into both parents; unsaved drafts stay private.
- `deep_copy`: new parent and one new source per reachable published child
  (sharing preserved within the cloned DAG), fresh nested placement identities,
  the same signed transforms, metadata and painter order. Future edits to
  original descendants do **not** affect cloned descendants.
- Both retain explicit NULL tombstones and refuse broken non-NULL children,
  revalidate acyclicity and availability, and stage all immutable revisions
  before a single atomic index publication. Late failures discard staged
  versions; Atlas-origin Save As rebind/Undo/Redo uses the existing global
  history and retains copied sources after undo.
- A single nested `.drawing` export **still fails** with `NESTED_EXPORT`.
  The existing complete `Campaign.scn + Objects/` component copy is the
  tested portable path. No implicit graph cloning or single-file export
  occurs through ordinary UI controls.

The 42-check real-filesystem regression and seven neighboring suites pass
with pinned Godot 4.8 beta3 and strict T-094 log verification. The original
T-107 source fails the new test on unsupported explicit policy arguments.
