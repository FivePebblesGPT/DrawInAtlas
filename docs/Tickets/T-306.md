# Verify end-to-end sRGB artwork color pipeline

## Owner finding — 2026-11-25
Ensure the application uses sRGB color space.

Source: [PR #23 hands-on review](../DRAWING_UX_REVIEW_2026-11-25.md). This is a standalone Drawing correction; no dependency on the T-250 Atlas acceptance gate. Historical completed tickets remain valid for their narrower scope.

## Scope
Define and verify sRGB RGBA8 at user-facing artwork boundaries, including ColorPicker, native storage/compositing, Godot preview/display, import and image export when available. Distinguish encoded sRGB from any internal linear-light arithmetic; prevent missing/double transfer conversion. Keep alpha linear and hidden RGB/lossless byte contract intact. No CMYK/HDR or full ICC workflow is implied; document actual embedded-profile behavior.

## Acceptance
- [ ] Use known sRGB swatches, gradients, semitransparent compositing and roundtrip fixtures with independent expected values, not only LUT parity.
- [ ] Check actual framebuffer/display boundary and native/document bytes; distinguish software framebuffer from physical monitor color management.
- [ ] Coordinate export checks with T-305 and document platform/profile limits; no unsupported claim of display calibration.
- [ ] Record fail-first functional evidence where applicable, neighboring regression results, and actual visual inspection for UI changes in accordance with AGENTS.md. Update the ticket and Index; no owner signoff is inferred from engineering completion.
