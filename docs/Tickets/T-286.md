# Reject non-replayable step metadata in local fast-CI audits

## Defect and bounded scope

`tools/replay_godot_ci.py` executes the checked-in GitHub Actions Bash steps
locally. Its `extract_checks` parser previously accepted new step-level YAML
settings which the local runner **did not apply** (such as
`working-directory` or `timeout-minutes`). Duplicate `if` and
`continue-on-error` keys could also pass a string-presence assertion even
though GitHub uses a different effective YAML value. The resulting local
record could misrepresent the workflow it claimed to replay. This is an
**audit integrity** issue, not a native raster or UI defect.

## Acceptance

- [x] Reproduce accepting unsupported step-level execution metadata and
      duplicate keys on the pre-fix parser.
- [x] Fail closed on unknown step keys, duplicate recognized keys, and
      nonstandard condition/shell values rather than silently ignoring them.
- [x] Retain the existing narrow contract: `id`, `if`,
      `continue-on-error`, optional Bash `shell`, and one `run` command;
      preserve ordinary comments, script indentation, and inline/block runs.
- [x] Parse all 46 current fast CI checks in the original order unchanged;
      keep partial replay/timeout/checksum/commit-attestation tests passing.
- [x] Run neighboring reporting, workflow-order and owner-evidence Python
      tests, static Python compilation, and ticket-store validator.
- [x] Record limits without claiming hosted CI or manual review approval.

## Result — 2026-11-23

The new fail-first suite detected **eight accepted metadata violations** on
current code; after the guard all four T-286 tests and **43 neighboring
Python tests** pass. The original workflow still exposes 46 replayable
checks, and the parser still rejects unresolved GitHub expressions, changed
conditions and alternate shells. [Evidence and command log](../evidence/T-286-2026-11-23-ci-replay-metadata.md).

**Limits:** This hardens the check-level parser only; it neither executes a
fresh full local/hosted Godot CI replay nor attests job-level workflow
configuration changes or owner-facing UX. The test environment lacks
`git-lfs`, so local Git status reads used a **process-local disabled LFS
filter**; no tracked LFS bytes or acceptance policy was changed. T-094,
T-106, T-107 and T-250 retain their separate release/review gates.
