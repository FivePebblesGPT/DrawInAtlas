# Collapsible vertical dock, grouped icon rail and flyouts

**Status:** Implemented (2026-11-03), following T-078. [Agreed design and test scenarios](../DRAWING_DOCKING_SPEC.md). Engineering-only completion; T-083 owner UX acceptance remains pending.

## Scope

- Convert the T-063 stacked Colors/Layers/History display to separately collapsible, keyboard-reachable dock **groups** using a chevron/header. Preserve each group's active tab when collapsing, scrolling or minimizing.
- The expanded right dock retains vertically stacked groups in a scroll container; compact/short windows must not clip inaccessible group controls.
- Minimize the **whole dock** into a narrow vertical rail with a recognizable icon **per attached panel**, accessible tooltips/labels and **visible separators between groups**. No one-letter substitutes or unconditional fixed set of icons.
- Clicking an icon opens a single **in-app group flyout** anchored to the rail and activates that particular member's tab; clicking a different icon of the **same group** switches its tab in the same flyout. Selecting another group's icon switches to that group's shared flyout; clicking the active icon toggles it closed. Canvas clicks alone do not auto-dismiss the flyout.
- Flyouts overlay rather than resizing the canvas, and restore to the expanded dock without losing group collapse, active tab, selection or scroll/focus context. Icon placement on expanded group right edges should remain consistent with the minimized rail.
- Treat active group membership as provided by T-078. Interactive drag/reordering is **T-080**, floating containers are **T-081**, cross-container drop is **T-082**; layout saving remains T-083.

## Acceptance

1. Native pointer/keyboard witnesses show independent chevrons, an intact 420px and desktop layout, vertical dock scrolling and stable canvas size.
2. A test fixture with Color/Swatches in one group demonstrates adjacent icons **without a separator**, one tabbed flyout, correct active tab on each icon, and a separator before History. Default singleton groups also work.
3. Tooltips and keyboard focus identify each icon; screen reader/accessibility labeling is checked where the platform allows it. Small-size hit targets and focus ring are usable.
4. Repeated minimize/restore, flyout switch/hide, and canvas click do not mutate model ownership or document content; T-063/T-062 UI regressions pass.

No owner gate on normal engineering delivery; later [T-083](T-083.md) records hands-on UX approval.

## Implementation and verification — 2026-11-03

- `addons/drawing/workspace.gd` renders ordered, independent model-driven dock groups in the original `PanelDock` vertical scroll viewport. Group header chevrons and per-panel right-edge SVG icons are 40–42px keyboard-focusable buttons with meaningful tooltips; headings and active tabs come from the T-078 `DrawingDockLayout` group/panel IDs, not a second ownership store. Existing Colors/Layers/History controls are **reparented, never duplicated**.
- Window → Minimize/expand panel dock shrinks the visible right split pane to a narrow rail. The rail is generated from `rail_icons("right")`: one icon per attached visible panel, no separator between members of the same group, and a separator at group boundaries. Both the rail and expanded groups can scroll with focused controls. Dock width, group collapse and selected tab survive minimize/restore.
- The single `DockGroupFlyout` is a **Godot `PanelContainer` child of the Drawing canvas** (not an OS `Window` or another split pane). Clicking a rail icon opens the owning group's flyout and activates that panel; same-group icons and flyout tabs reuse the same host; active-icon click closes; other-group click switches; canvas clicks do not auto-dismiss. A flyout never forces canvas resizing.
- `addons/drawing/icons/dock_*.svg` packages meaningful Colors/Layers/History/Swatches/fallback icon artwork in the standalone app and third consumer. The fallback supplies a generic panel pictogram for future model registrations; rail membership still comes only from the T-078 model.
- `drawing/tests/dock_ui_native.gd` is a **40-check native X11/Mesa pointer, Enter-key, narrow-width, short-window scrolling and model-integrity witness** using a temporary Colors/Swatches tab group. Existing T-063 compact workspace **75/75** native checks, T-078 dock-layout **82/82**, standalone **38/38**, Object Editor standalone **25/25** and documentation checks also passed with pinned `4.8.beta2.official.cafc17a19` locally. These suites remain separate and should not be called full release coverage.
- Out of scope: interactive group drag/reorder (T-080), floating hosts (T-081), cross-container docking (T-082), persistence and hands-on owner review (T-083). No owner UX gate was self-approved. Earlier deferred Atlas native/legacy checks and Web export were **not** reclassified as passed.
