# Nested Object Assets with cycle-safe rendering and editing

**Status: In Progress — owner wants reusable objects containing other reusable objects (2026-11-02).** This expands the object reference graph, not the raster painting engine. Sequence after flat Object Asset instances, without stalling the standalone Drawing vertical slice.

## Contract
- A reusable Object Asset may have child **Object Asset instances** with a stable child asset ID and parent-local transform/visibility. Child instances share the same source/instance semantics already used on Atlas maps.
- The source's child-reference graph must be **acyclic**. Reject A→A and A→B→…→A on creation, Save and asset reload; do not recursively render corrupted graphs.
- Keep each child instance selectable and transformable without modifying child source artwork. Editing a child source uses its own dedicated Object Editor tab and explicit Save; published child changes invalidate parents and their placements transitively.
- If a child source is deleted, offer the same remove-reference / retain visible `NULL` placeholder / cancel policy as for top-level Atlas instances; placeholders keep stable transforms and asset IDs.
- Asset Save As creates a new parent asset. Whether it preserves child links to the existing sources (recommended) or deep-duplicates the dependency graph must be specified under T-051; no implicit full-graph copy.

## Implementation
1. Extend Drawing's generic reusable object-instance layer/record with stable reference IDs and local 2D transform; keep Atlas campaign types out of Drawing.
2. Maintain dependency edges and reverse edges for incremental cache invalidation; guard load, paste, Save As and child insertion with cycle detection and a practical tested recursion/render budget.
3. Use the same object renderer and hit-testing for nested child instances and Atlas placement, but correctly compose transforms, alpha, selection hierarchy and layer/group order. Selection of child vs parent must be explicit.
4. Scope source editor draft changes to current tab; published Save refreshes transitive cached previews without changing other asset IDs.
5. Test chains A→B→C, shared child B in many parents/maps, self/indirect cycles, corrupted cycles on disk, missing/null child reference, negative coordinates and nested transforms.
6. Test undo/redo context after nested selection, Save As through a nested placement, source Save invalidation and broken child references. Keep data changes atomic.

## Acceptance
Nested objects render and edit without duplicate drawing implementations, source identity remains explicit, no cycles or infinite recursion, placeholders are safe, published child changes propagate only on Save, and project copying preserves nested references.

## Not decided
Depth/performance caps, nested Save As parent/child copying policy, and detailed interaction for “edit child source” versus “edit its parent transform.” These need prototypes/owner acceptance, not silent assumptions.

## 2026-11-03 engineering milestone — persistent cycle-safe child references

**Status: In Progress, not accepted as nested rendering/editing.**
`AtlasObjectChildGraph` provides bounded, validated parent→child dependency
edges in Atlas's existing `atlas-objects-v1` registry. Flat old indexes retain
the same schema and load without migration. Each parent can hold at most 64
child-instance records (stable child ID and generation, published source ID,
invertible parent-local transform, visibility, NULL flag, primitive metadata
and child revision). The graph is limited to 20,000 edges and a **provisional**
16-link dependency depth. These budgets are defensive engineering limits,
**not** an approved interaction or final performance policy.

`AtlasObjectLibrary.attach_child`, `transform_child`, `detach_child`,
`children_for_asset` and `dependent_sources` use a distinct optimistic
`children_revision`, preserve immutable pixel-source versions and publish
registry edits atomically. The validator rejects malformed records, duplicate
child IDs, self-links, indirect cycles and excess depth on edits **and saved
snapshot load**. It uses a bounded iterative graph walk, not recursive
renderer calls. A failed edit, stale registry handle or injected publication
failure leaves the live graph unchanged. Published source Save preserves the
current child references even when the pixel draft was opened earlier.

The existing Atlas source-delete Remove/NULL/Cancel policy now also covers
nested references in a **single** index transaction. Its confirmation records
nested binding revisions, refuses stale confirmation and preserves child
instance identity/transform on NULL. The source-manager dialog counts nested
references explicitly. A missing source appears as a NULL child on reload;
it is **not** silently reconnected by name. The library exposes transitive
reverse dependencies so future renderer/thumbnail invalidation can be wired
without scanning all map placements.

**Conservative incomplete-feature boundary:** nested-source Save As and
portable export currently return explicit `NESTED_SAVE_AS` or
`NESTED_EXPORT` errors, rather than silently discard links or assume
an unapproved shallow/deep copy policy. These commands still work for flat
sources. The child graph currently lives in Atlas's authoritative registry;
portable nested-source interchange and child source editing are **not yet
implemented**. In particular, nested children **are not rendered or hit
-tested**, nor do they yet have editor selection, source/parent navigation,
undo/redo or source Save-driven preview refresh. T-065's existing owner UX
acceptance does not constitute approval of this new behavior. These are
requirements for later T-064 work before closure.

**Evidence:** `tests/object_child_graph_smoke.gd` passes **56/56** checks
with real immutable source revisions and disk-backed index reloads, and is
included in fast Godot CI. It covers A→B→C, shared child instances, self and
indirect cycles, file relocation, malformed snapshot rollback, depth/child
limits, stale writers, publication refusal, preserved pixel drafts,
conservative Save As/export rejection, stale nested Delete confirmation,
Remove and NULL policy persistence. Existing flat-asset and campaign tests
must remain green. Physical pointer/Windows review and renderer/UX acceptance
have **not** been claimed.

## 2026-11-03 engineering follow-up — bounded nested rendering and hit paths

**Status remains In Progress.** The Atlas-side `AtlasObjectLibrary` now uses
one ordered, bounded source traversal to composite published parent, child and
grandchild artwork with parent-local `Transform2D` composition. Child layers
paint over parent artwork, later siblings paint over earlier siblings, and
nested `NULL` children retain a visible local 16×16 placeholder marker. The
flat asset path remains unchanged. `render_instance` and `hit_test` include
nested pixels, while `hit_test_path` exposes a stable ordered child-ID path
without mutating selection or source documents. `composed_bounds` includes
transformed child frames beyond the parent's guide rectangle. Atlas's shared
composition adapter uses those bounds and invalidates cached frames on
`child_graph_changed` and explicit published asset Save.

**Defensive limits, not approved UX defaults:** A source render has at most
1,048,576 output pixels; traversal caps visible child nodes at 2,048 and
sampling plus destination visits at 4,194,304 pixels. Invalid/tiny composed
transforms, unbounded sample rectangles or oversized graphs fail closed with
structured errors. Source graph cycles are still rejected by the persisted
registry validator, plus a separate traversal-path guard.

`tests/object_child_render_smoke.gd` passes **36/36** Godot 4.8 beta 2 headless
assertions and is fast-CI-gated. It verifies layered RGBA output, A→B→C
transform composition, negative coordinates, 90° rotation, sibling overlap,
path-based hit detection, reload, transient drafts vs published Save,
transitive preview invalidation, missing child NULL markers and render limits.
Flat T-060/T-055 regressions retain their existing contracts.

**Still unimplemented:** nested child selection and transform actions in the
live editor UI, child-specific history context/undo/redo, Save As/export
source-graph copying policy, independent native pointer verification and
physical performance assessment. The provisional budgets need profiling;
this milestone does **not** fulfill all T-064 acceptance criteria or close it.

## 2026-11-03 engineering follow-up — nested child transform inspector and local history

**Status remains In Progress.** The Atlas Object Manager now offers **Nested children…**
for a published source, opening an in-app child inspector. It lists stable
child instances, selects one explicitly, moves by parent-local unit steps,
rotates by 15°, and routes **Edit child source** through the existing separate
Object Editor publisher (never through parent raster painting). Keyboard
shortcuts include Alt+arrow for child translation, Ctrl+Z and Ctrl+Shift+Z/
Ctrl+Y for **child transform history only**; the Atlas map timeline is not
silently reused. The interface shows concise names, with stable IDs in
tooltips. A new campaign/parent binding resets that inspector's selection
and history; an unavailable child cannot open an editor tab.

`AtlasObjectChildEditSession` scopes undo and redo to one authoritative
parent source and uses `transform_child` for every forward and replay change,
so child optimistic revisions always **increase**, including on undo. Replay
checks the child ID, generation, source ID, current transform and expected
parent graph revision. A concurrent child edit, deletion, rejected registry
publication or campaign switch cannot be overwritten or inserted as a phantom
history step. Explicit **Reload parent** discards stale in-memory history;
a new transform after undo discards the abandoned redo branch. The transform
changes the published child **placement**, not the immutable child Drawing
source or an open draft. Existing graph validation, cycle/depth budgets and
transitive preview invalidation remain authoritative.

**Evidence:** `tests/object_child_edit_smoke.gd` passes **45/45** headless
checks covering durable transforms, local selection, undo/redo, branch
replacement, invalid/nonfinite input, atomic publication failure, external
writers, separate child source navigation, keyboard actions and campaign
rebinding. `tests/object_child_edit_native.gd` passes **10/10** under native
Xvfb/Mesa, including a screenshot of the actual inspector. The headless
witness is required in fast desktop CI; the native witness stays targeted.

**Still outstanding:** drag/viewport child hit-path selection, child
attach/remove and source editing integration with the full nested Object
Editor workflow, consistent project copy/Save As and portable export
policies (owner decision under T-051), physical pointer/Windows testing,
additional undo/redo actions and final interaction/performance review.
This is a bounded engineering milestone, **not** T-064 acceptance or owner
UX approval, and does not complete any other ticket.


## 2026-11-03 engineering follow-up — reversible child attachment and removal

**Status remains In Progress.** The existing Atlas Object Manager → **Nested
children…** inspector now offers an explicit, searchable published-source picker
(first 128 matching available sources; never suggests the parent itself),
**Attach source**, and **Remove selected**. These actions edit the parent's
published child *instances*, not any child raster data. A new child receives a
fresh ID/generation; removing the reference retains its source. The same
parent-scoped history now interleaves structural and transform operations:
Undo/Redo reverses attachment/removal at the original sibling position with
the **same ID and generation**. Restoring a removed instance increments its
optimistic child revision. The UI labels now say "Undo/Redo child edit" to make
that broader contract explicit.

`AtlasObjectLibrary._restore_child_snapshot` is a guarded, narrowly scoped replay
primitive: it rejects malformed saved records, UI-only status fields,
unavailable linked sources, invalid sibling positions, duplicate instance
identities, new dependency cycles and stale registry publication. All changes
pass through the existing validated graph transaction, so transitive render
cache invalidation continues to work. Session history checks source identity,
generation, unchanged child content and the parent graph revision; failed
attachments, rejected removals, concurrent edits and failed durable writes
do not create partial changes or phantom Undo entries. A new branch after Undo
continues to discard obsolete Redo actions. An explicit parent reload or
campaign switch clears in-memory history.

**Evidence:** `tests/object_child_structure_smoke.gd` passes **45/45**
headless checks for mixed structural/transform history, ordering, stable
identity, reload, invalid sources/transforms, cycles, concurrent changes,
publication rollback and real inspector callbacks/search. It runs in fast
push CI together with the existing **45/45** edit-history and **56/56**
cycle-graph suites. The extended native
`tests/object_child_edit_native.gd` passes **16/16** Xvfb/Mesa checks,
including the source selector, attach/remove, structural Undo/Redo and native
screenshot; this native witness remains targeted, not push-CI-gated.

**Still open:** integrated Atlas canvas child hit-path selection and pointer
transforms, Save As/export graph-copy semantics (the policy remains undecided),
whole-project copy/reload acceptance with nested object editors, physical
Windows/Linux and owner interaction review. The structural editor is an
engineering prototype; T-064 is **not Done**, no owner approval is implied,
and no other ticket was completed.

## 2026-11-03 engineering follow-up — explicit nested canvas hit selection

**Status remains In Progress.** The Atlas main canvas now distinguishes a
normal click (select the top-level linked Object placement) from **Alt+click**
(select the topmost visible nested child under that pointer). A child or
grandchild hit resolves the canonical `AtlasObjectLibrary.hit_test_path()`
against the active map/floor/detail and selected root instance; the Atlas
editor rechecks the current published registry and walks stable child IDs to
find the *immediate parent source* owning the selected child. It opens the
**existing** Object Manager → Nested children inspector and selects that child
without creating another registry or editing source pixels. A repeated hit on
the same parent preserves the inspector's structural/transform Undo history.
A stale parent refuses re-selection until explicit Reload, rather than silently
clearing history. Missing/hidden ancestors, wrong map/detail, nonfinite or
transparent points, stale registry bytes and forged instance IDs fail closed.

**Evidence:** `tests/object_child_canvas_select_smoke.gd` passes **21/21**
headless checks and is fast-CI-gated; the native Xvfb/Mesa run passes
**22/22** with a screenshot of the selected grandchild inspector. Its native
input witness dispatches real Godot UI mouse events to the canvas press handler,
not a physical OS mouse drag; it does **not** establish hardware pointer UX
acceptance. The existing T-064 graph/renderer/editor suites and Atlas
composition remain separate regression obligations.

**Still open:** direct canvas pointer manipulation of selected child transforms,
Save As/export graph-copy policy (requires the recorded product decision),
project-copy validation for nested registries, and physical Windows/Linux
interaction/performance review. No owner decision or manual gate was changed.


## 2026-11-03 engineering follow-up — verified independent Objects-component copies

**Status remains In Progress.** `AtlasObjectLibrary.copy_objects_to(destination_campaign_path)`
now offers an explicit source-controlled copy of the currently published
`Objects/` component into a **different, existing campaign directory**. It
preserves the registry bytes and the exact current `.drawing` source revisions,
including child-instance IDs, sibling order, source versions, parent-local
transforms, NULL bindings and Atlas placement references. No graph is flattened,
no child artwork is duplicated under new IDs, and unsaved drafts are excluded.
The destination campaign `.scn` is a separate responsibility of the campaign
saver: this API is **not** a full project Save As or an external single-source
export and does not decide the unresolved nested Save As policy.

The copy refuses missing/corrupt current source revisions, a modified source
index, unsafe/symlinked or nested output directories, and an existing Objects
destination. It stages verified source checksums and the index under a private
sibling directory before renaming to `Objects`; failure discards only the
staged copy. No source registry mutation or overwrite is performed. Historical
unreferenced revision files are intentionally excluded; a full backup/archive
still requires the campaign saver to include its own history and snapshots.

**Evidence:** `tests/object_nested_project_copy_smoke.gd` passes **37/37**
headless Godot 4.8 beta 2 assertions on a real copied branching graph,
published source hashes, stable deep hit paths and map bindings, independent
child edits and source revisions, fresh-process-style reload, NULL deletion,
destination collision/misplacement, and external index changes. It is required
in fast push CI. This is a component portability milestone, not final product
copy UX acceptance or proof of symlink/race resistance on all platforms.

**Remaining T-064 work:** direct pointer transform gestures, an owner-selected
nested Save As/export dependency policy, end-to-end campaign Save As/copy
integration, and physical Windows/Linux interaction and performance checks.
Do not mark T-064 Done or claim owner signoff for this checkpoint.

## 2026-11-03 engineering follow-up — transactional nested-child canvas dragging

**Status stays In Progress, no owner acceptance inferred.** The Atlas canvas
now distinguishes **Alt+click** (select the existing nested child inspector)
from **Alt+drag** (move the child in that inspector's parent-local history).
Instead of opening a separate OS popup at mouse-press time and interrupting
pointer capture, it captures a validated published hit path and defers focus
until mouse release. A screen-space line and endpoint guide display the
uncommitted offset. The source's actual image/pixels and the map placement
remain unchanged during preview.

On release, `AtlasEditor._on_object_child_drag_requested()` requires the
exact press-time source index hash, instance record, map/floor/detail context
and original nested hit path, then composes the root and ancestor transforms
to convert the displacement into the **immediate owning parent's** local
coordinates. Only the shared `AtlasObjectChildEditSession.set_selected_transform()`
publishes the resulting child transform and one history action. Clicking under
the 4-screen-pixel drag threshold still opens the inspector without a transform.
Invalid/nonfinite requests, source or instance changes, Escape, focus loss,
mouse exit, tool changes and navigation changes cannot publish a partial drag.

**Evidence:** `tests/object_child_canvas_drag_smoke.gd` passes **31/31**
headless checks and **32/32** in a native Xvfb/Mesa screenshot run, covering

subthreshold Alt+click, cancelled previews, map/tool/focus changes, changed

## 2026-11-03 engineering follow-up — explicit repair of retained nested NULL children

**Status remains In Progress; no owner gate was waived.** Deleting a nested
source with the existing retain-NULL policy previously left a selectable,
well-formed child tombstone but offered no equivalent of top-level Object
repair. The existing `Nested Object instances` inspector now has a **Repair
NULL with source** action beside the bounded published-source picker. It is
enabled only when a NULL child and a verified candidate source are selected;
ordinary live children cannot be rebound through repair. The user explicitly
chooses the replacement; source names are never used for automatic matching.

`AtlasObjectLibrary.repair_child_placeholder()` checks both the parent's
`children_revision` and the child's stable generation/revision, requires
an available checksum-verified replacement, preserves the original source ID
in `null_origin_source_id` metadata, and publishes through the existing
atomic/cycle-checked `_replace_children()` path. Identity, sibling order,
local transform, visibility and pixel-source revisions are unchanged. The
parent-scoped child edit session records rebinding as a single undoable action
alongside translation, rotation, attach and detach. Undo restores the NULL
binding and its original metadata; redo restores the selected replacement,
with monotonically increasing child revisions. Cycle violations, conflicting
writers, full metadata and publication failures leave the index and history
unmodified. Any new explicit repair also invalidates the undone redo branch.

**Evidence:** `tests/object_child_null_repair_smoke.gd` passed **45/45**
headless Godot 4.8 beta 2 checks (and **46/46** with native
Xvfb/Mesa inspector screenshot capture) for real source deletion, direct/indirect
cycles, stale identities/revisions, missing choices, forced publication
failure, visible nested pixels, repeated Undo/Redo interleaved with transforms,
registry reopen and live inspector button activation. It is in required fast
CI. Native UI/screenshot testing is targeted and does not replace owner
hardware review. Existing T-064 and T-060/T-062 regressions remain separate.

**Remaining acceptance:** nested source Save As/portable export's still
undecided reference-copy vs deep-copy contract and UX, full portable campaign
Save As integration, and physical Windows/Linux interaction and performance
validation. No other ticket status or manual review decision changed.


## 2026-11-03 engineering follow-up — complete saved portable campaign copy

**Status: In Progress; one T-064 milestone, no owner approval.** The prior
`copy_objects_to()` helper intentionally copied only the current published
Objects component. `AtlasCampaignStore.copy_portable(source_path, destination_path)`
now supports copying a complete, **previously saved** T-066 portable campaign
into a new sibling project folder, without changing object or document IDs.
It copies immutable sparse Drawing manifests/chunks and older generation
files, Object sources including retired immutable revisions, licensed fonts,
the authoritative root and its independently valid backup. The transitional
Object registry filename is retargeted when the new campaign `.scn` basename
differs, but nested source IDs, child instance identities, transforms and
map placements are untouched. The operation rejects source recovery-only
roots, uncheckpointed Object index differences, symlinked components and
linked paths, existing destination folders, missing/changed files and staged
copy corruption. Staging is in the destination's parent folder so publication
uses one directory rename after full `AtlasCampaignBundle.load()` verification.
A failure removes the private staging directory without creating an externally
loadable partial project. Source data and live editor drafts are not mutated.

**Evidence:** `tests/object_nested_campaign_copy_smoke.gd` passes **46/46**
