# Reserve Atlas history during non-Drawing command application

**Bounded T-148 child.** T-245 reserves the host command log during a
Drawing session publication, but ordinary `AtlasEditHistory.execute()` still
invokes caller-owned `context_provider`, `AtlasEditCommand.apply()` and
synchronous `changed` observers before the command's history append or
revision bookkeeping finishes. These callbacks could insert a nested command,
undo/redo a different command, reset history, or overwrite its dirty/save
checkpoint. Asset rebind and cross-document transfer apply callbacks had the
same hole.

## Acceptance

- [x] Reserve all host timeline entry points throughout ordinary command
  capture, application, append, synchronous notification, and revision update;
  include transfer and Save As asset-rebind publication.
- [x] Reject nested execute, Drawing publication, selection-history changes,
  Undo/Redo, reset and saved/external-state markers without disturbing the
  outer command. Preserve normal recursion guards during replay.
- [x] On rejected command apply, release the reservation; valid later
  commands and chronological Undo/Redo remain available.
- [x] Reproduce the issue against the previous implementation; pin the
  exact-count regression in required fast CI and run neighboring Atlas/global
  native-history, transfer, asset, ownership and replay suites.

## Completion — 2026-11-22

The 206-check Atlas regression fails **60/206** checks on the previous code
and passes **206/206** with the reservation, including real successful Save As
asset rebinding and copy transfer. Existing Drawing T-245 (126), global
history (101), Atlas native-history (43), ownership, transfer and replay
regressions pass. See [execution evidence](../evidence/T-246-2026-11-22-atlas-command-reservation.md).

**Scope:** Synchronous mutations through `AtlasEditHistory` entry points;
it does not guard direct writes to campaign objects or finish universal Rust
raster authority. T-148 remains In Progress, T-149 Blocked, and hosted CI /
owner-hardware signoffs remain unverified.
