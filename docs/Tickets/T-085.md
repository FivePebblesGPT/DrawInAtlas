# Live stroke preview, continuous pointer sampling and edit latency

**Status: In Progress (2026-11-06).** Detached preview, bounded pointer queue and Linux software framebuffer witness implemented; physical Windows/Linux reference-display evidence and T-086 viewport latency work are outstanding. Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
On native hardware the owner reports about one-second delays, **no in-progress stroke preview**, and fast-movement strokes looking like simplified straight lines. `DrawingCanvas.paint_to` stages edits, while `_draw()` renders only committed `DrawingDocument` pixels. Synchronous `paint_path` may also stall the UI input path; latency causes must be instrumented, not assumed.

## Engineering tasks
1. Record timestamped pointer samples without blocking new input while raster work is pending. Preserve ordering, source-space mapping, interpolated coverage and once-per-gesture alpha semantics; define cancellation, exit/reentry, zoom during gesture and race conditions.
2. Render a transient uncommitted stroke **during mouse-down** and maintain a brush-footprint cursor. Do not publish history or modify durable layer tiles per sample.
3. Reconcile the preview with the published result atomically on mouse-up; cancel removes all pending pixels without ghosts.
4. Instrument sample arrival, brush staging, preview availability, commit and presentation path; compare before/after under normal and rapid movement.
5. Keep a GDScript baseline; optimize limited kernels only if measured, using T-084/T-068 evidence.

## Acceptance / verification
- [x] First dab and subsequent pixels are visible **before button release**, including erasing, with exact preview-versus-commit compositor bytes (headless model + Xvfb/Mesa witness; owner hardware pending).
- [x] Rapid looped/diagonal/self-crossing strokes at 100%, 50%, 25% preserve delivered samples and endpoints (software frame test; not proof of uncoalesced OS hardware motion).
- [x] Cancel, leave canvas, tool/layer/zoom change, invalid edits and undo preserve canonical pixels, revisions and one-step history in regression tests.

## Boundaries

- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.

## 2026-11-06 implementation checkpoint — live detached preview and bounded input

**State: In Progress, not owner/hardware accepted.** Implemented exclusively in
canonical `addons/drawing/`; standalone and Atlas continue to share the code.
No native C++ backend or committed-pixel mutation was added.

- `DrawingEditSession` now keeps a separate per-source-tile patch indexed by
  local pixel offset. `DrawingRenderer.render(..., preview=...)` composes those
  substitutions **at the correct visible raster layer**: eraser reveals lower
  paint, lower-layer edits remain hidden by upper layers, and a stale/unrelated
  session fails closed. No preview bytes enter `DrawingDocument`, undo history or
  `.drawing` persistence before the one normal `commit()`.
- `paint_path` no longer duplicates three growing dictionaries on every motion;
  a touched-pixel journal reverses only pixels modified in the failing call.
  In-place preview metadata is likewise undone. Existing non-brush edit APIs
  rebuild the preview index on their exceptional rollback path.
- `DrawingCanvas` draws an immediate stationary dab and brush-footprint cursor;
  otherwise handlers **enqueue source-space float samples with arrival timestamps**.
  The drain advances at most 12 segments/frame of at most 24 source px each,
  retaining every delivered point and ordering. Short releases finish immediately;
  long releases finish across frames, then publish exactly once. Godot input
  coalescing is disabled only while a stroke is owned and restored on commit,
  cancel or teardown. Color, width and tool are frozen for the captured stroke.
  Esc cancels; leaving the canvas retains captured motion/release; switching
  document, layer, tool or zoom cancels safely. Revision conflicts fail closed.
- Per-gesture metrics expose `down_us`, first stage, first preview draw
  submission, first `frame_post_draw`, release, commit, candidate-stage CPU
  duration, queued sample count, maximum queue, and every received sample's
  arrival-to-staged completion time. **`frame_post_draw` is not physical
  input-to-photon latency**, and these timestamps do not expose OS driver
  samples that never arrived in Godot.

## 2026-11-07 checkpoint — long-stroke backpressure and byte-exact batching

**Status remains In Progress.** Owner PR #13 testing reported several-second
release latency on long strokes. At the remote branch head
`116afa125cdc068517f87d4d15ef34425a3a69e9`, the canvas drained at most
12 source-space segments per frame (24 source px per segment). Even a path
whose raster CPU work totals only tens of milliseconds could therefore require
70 rendered frames to publish one gesture. This was reproducible with an
840-motion looping test on Xvfb/llvmpipe; **no physical hardware acceptance is
claimed**.

The same canonical `addons/drawing/canvas.gd` now feeds adjacent swept
waypoints to one `DrawingEditSession.paint_path` call (up to 16 points, reduced
for wide brushes by a conservative footprint estimate). It processes up to
256 segments per idle/release drain, but checks an approximately **6 ms CPU
soft deadline between atomic batches**. No pointer samples are simplified,
coalesced, skipped or re-ordered. The initial stationary dab still stages
synchronously; the mouse-release handler has the same bounded drain as an idle
frame, and the original session publishes a single history event only after
all queued samples finish staging. Large individual paint batches can exceed
the soft deadline, so it is **not a real-time guarantee**. `drain_calls` and
`max_drain_cpu_us` are now recorded alongside the existing stage and
release-to-commit timestamps.

**Native, real synthetic-pointer framebuffer regression:** the expanded
`drawing/tests/live_stroke_native.gd` exercises three independent
840-motion / 844-segment long, looping, alpha-blended strokes at each zoom,
with every delivered timestamp, exact rendered RGBA8 parity against a
single-call independent path oracle, one history publication and one Undo.
It also retains the existing 100/50/25% held-button preview, eraser, cancel,
outside-canvas and tool/zoom/layer-switch checks. The long-stroke test fails
if the fixed-12/frame backlog returns, without imposing a hardware timing
threshold on the required CI. On the local software driver the new path
passed **118/118** assertions. The unmodified baseline failed the **nine new

## 2026-11-07 checkpoint — selection changes cancel queued Brush/Eraser without mixed authorization

**State remains In Progress; no owner device evidence or review approval.** The
live Brush/Eraser queue already froze color, width and standalone frame extent
at pointer-down, but each later `paint_path()` batch read the **current mutable
selection mask**. Replacing the selected region while a long stroke was queued
could therefore rasterize earlier pixels under one mask and trailing pixels
under another, yet commit both as one Undo action. This is an edit-authorization
race, not a change to the settled selection mask/contour UI of T-088/T-096.

The canonical `addons/drawing/canvas.gd` now snapshots the exact boolean
selection (including operations, inverted state, explicit pixel mask and
*enabled-empty* deny-all) at pointer-down. Every staged batch reads this
immutable snapshot, not a later selection. A real change through
`set_selection_mask`, `clear_selection` or the legacy `selected` rectangle
setter cancels the entire in-flight edit **immediately**, restores global
accumulated-input settings, drops the sample backlog and emits an explanatory
status error. Reassigning an equivalent mask is permitted, including a
rectangle-expression mask containing holes. A final content-publication guard
also rejects in-place mutations that bypassed the supported setter; this
full mask comparison occurs **once at commit**, not on every paint batch.
Cancelling never publishes source pixels or history, while a stable selection
still commits as one Undo step. Brush/Eraser widths, source bounds, floating
Move and clipboard semantics are otherwise unchanged.
