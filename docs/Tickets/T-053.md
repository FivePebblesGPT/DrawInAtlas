# Build standalone Drawing application and pinned reusable package

**Status: PLANNED; blocked by T-051/T-052.** An Atlas-only test scene does not satisfy physical independence.

## Plan
1. Give Drawing its own Godot project, main scene, assets, tests and export/build instructions. Package reusable editor/runtime separately from the app shell. Repository/release topology approved in T-051.
2. Split current AtlasCanvas's drawing gesture/controller and renderer from link/fog/token/projector/grid UI. Preserve one shared painting implementation for standalone and embedded modes.
3. Build familiar reduced Paint.NET/PhotoCraft-like layout: canvas, palette, layers, properties, new/open/save, pan/zoom, snapping and undo/redo. Do not invent the owner's forthcoming full feature list (T-059).
4. Standalone Drawing can save/reopen an artwork file without Atlas; define a file format and failure/recovery expectations.
5. Prove the package works in a separate tiny consumer project and with a pinned revision, without copying app menus or bootstrap scenes.
6. Add native real-pointer/framebuffer and independent build/launch checks.

## Minimum demo
New Drawing -> paint -> erase -> select/move -> add/manage layers -> undo/redo -> save/reopen -> same artwork.

## Acceptance
Independent launch/export/test and independent consumer; Drawing renderer does not require AtlasCanvas, campaign, navigation, token, fog or projector. Owner verifies real editor UX. No old-save migration.
