# Standalone Drawing project inside monorepo and reusable package

**Status: PLANNED.** Physical independence is satisfied by two Godot projects **within the same Git repository**, not by a scene in Atlas and not by creating another repository.

## Plan
1. Design safe layout relative to current Atlas-root `project.godot`: an independent Drawing `project.godot`, own main scene/tests/export settings, a single canonical Drawing package and repeatable packaging/copy/link build step. Avoid ambiguous `res://`, nested-import and Godot global class-name collisions.
2. Prove a clean checkout/build containing only Drawing project + shared Drawing package, with Atlas scenes, autoloads and plugins omitted. Build a minimal separate consumer project using the produced package.
3. Extract rendering, pan/zoom, pointer gestures, selection and editing controls from `AtlasCanvas` without carrying its grid links, tokens, fog, projector or navigation controllers.
4. Implement familiar reduced Paint.NET/PhotoCraft-style app shell: new/open/save, tool palette, layer/group sidebar, canvas, snapping, zoom, undo and layer operations. Comprehensive feature list still awaits T-059.
5. Implement independent Drawing save/open with documented fresh file-format ownership. Both standalone app and Atlas consumer use the same underlying library, never manually synced forks.
6. Add real pointer, headless, native framebuffer and clean package-consumer checks. Start with desktop targets; Web remains a separately recorded release decision.

## Minimum end-to-end witness
Launch Drawing alone -> create document/layer group -> paint/erase -> select/move -> undo/redo -> save -> reopen -> exact alpha/pixels and layer identity.

## Acceptance
No Atlas source needed to launch, export or run Drawing tests; package works at the revision checked into the monorepo; package layout does not break the existing Atlas Godot root import. Owner usability review follows.

## Owner's proposed workspace shell — 2026-11-01
Implement and visually validate the uploaded [[DRAW_MODULE_UI_SPEC]] through [[T-063]]: one top row with fixed menu commands, `BarDivider`, and horizontally scrollable context-sensitive tool options; no extra quick-access toolbar. Preserve document tabs, tool rail, Colors/Layers/History dock, status and dirty indicator. This UI remains **proposed**, not signed off; T-059 will record the full feature inventory. The reusable library should serve the standalone Drawing application and the Object Editor ([[T-062]]) without duplicating painting code.
