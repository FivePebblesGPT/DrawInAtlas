# Build a standalone Drawing workspace and separate renderer/gestures

## Status
**PLANNED / BLOCKED by T-051 and T-052.** Do not replace the full Atlas canvas in a single change.

## Why
`AtlasCanvas` currently combines drawing render caches, gesture state, link hit-testing, zoom dispatch, grid overlays, fog/token tools and projector frame controls. The rendering core cannot yet be reused cleanly without those responsibilities.

## Implementation plan
1. Extract drawing-layer rendering/texture invalidation and read-only rendering into a Drawing renderer with an explicit surface, authored-detail level, camera and visibility request.
2. Extract brush/shape/selection/object gesture state into a Drawing input controller with typed intent signals, cancel/commit and frozen press-time context; Atlas-specific tools and hit targets stay with Atlas adapters.
3. Create a scene such as `tests/fixtures/drawing_only.tscn` (final location subject to T-051) that can paint, erase, pan, zoom, select layers/objects, undo/redo and show D0 content without constructing campaign/navigation controllers. Use standard Godot scene and GDScript conventions.
4. Maintain `AtlasCanvas` as a temporary compatibility facade while existing Atlas scenes/tests are migrated incrementally; keep current capture semantics working until T-055 replaces the capture adapter.
5. Add independent headless and native renderer/pointer tests for actual cursor coordinates, focus loss, cancellation, transparent blending, signed chunks, retained textures and separate drawing workspaces.

## Acceptance
- Launchable Drawing-only scene with no `AtlasCampaign` or navigation bootstrap.
- One successful hands-on brush/erase/select/undo flow and native framebuffer witness, not only script-level tests.
- Drawing renderer neither draws nor owns map links, hex overlays, fog, projector frames or tokens.
- Existing `tests/raster_rendering_visual.gd`, `tests/drawing_performance_visual.gd`, `tests/editor_modules_smoke.gd` and related tests remain valid and passing.
- Any compatibility facade is clearly marked and has a removal gate, not silently made permanent.

## Non-goals
No new atlas navigation, model migration or feature-level redraw of all tools.
