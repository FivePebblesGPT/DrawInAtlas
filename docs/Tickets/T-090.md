# Responsive workspace, menu semantics, document tabs, brush wheel and icons

**Status: In Progress (2026-11-07 corrective toolbar checkpoint);** original 2026-11-06 engineering scope was Done, but the handoff reports an unresolved visual toolbar issue. Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
At nondefault resolutions the app shows side black bars; menus mix object/file actions into Window; document tabs have detached global +/× controls; brush-size wheel scrolling is swallowed by tool-option navigation. Custom tool SVGs exist despite a bundled icon addon, but their authorship is unknown.

## Engineering tasks
1. Correct Godot window stretch/aspect and sizing for resizable desktop widths, heights, UI scales and minimum limits; keep the canvas in the remaining client area.
2. Preserve one menu+context-options row but organize File/Edit/View/Image/Layers/Select/Window/Help by real command semantics; Object file actions under File/Object where appropriate, Window only workspace controls.
3. Close directly from each document tab with the current dirty/unsaved guard; drop the global + control while keeping File > New/Ctrl+N.
4. Revisit `editor_top_bar.consume_option_wheel`: wheel on brush size must adjust its numeric value; reserve Shift+wheel/other cues for scrolling crowded tool options. Document keyboard brush-size controls.
5. Audit `addons/at-icons/` and existing `addons/drawing/icons/` for an appropriate consistent icon family and license; avoid assuming custom SVG generation provenance.

## Acceptance / verification
- [x] No pillarboxing/black bars or clipped document controls on resized desktop; test 800×600, 1280×760, large and 150–200% UI scale.
- [x] Menus place commands logically with discoverable shortcuts; tab close/dirty prompt and Ctrl+N work.
- [x] Mouse wheel on Brush px changes value reliably; options overflow still works without stealing field input.
- [x] Tool icons are a cohesive, legible, licensed set and consistent in pressed/disabled/focus states; native screenshots and pointer validation.

## Boundaries
- Preserve the one canonical Drawing package shared with Atlas, byte-exact saved RGBA8, source identity, one undoable content transaction per gesture and signed sparse coordinates.
- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.
- Do not mark complete merely because earlier T-053/T-063/Docking smoke tests pass. Report hardware, Godot version, viewport, zoom, timing and limitations for applicable evidence.

## Implementation and verification — 2026-11-06

**Engineering state: Done (not owner UX approval).** Updated only the canonical
`addons/drawing/` shell and standalone `drawing/project.godot`; Atlas consumes the
same workspace code. `canvas_items` stretch now uses **aspect `expand`** and a
minimum physical 800×600 window. Resizing intentionally changes the *logical*
viewport dimensions rather than insisting they equal physical pixels; the
canvas and dock fill the expanded client without fixed-aspect black gutters.
The tool-options viewport updates overflow chevrons when *its viewport* resizes,
not only when its content resizes. The one-row menu/options layout is retained.

The eight menus remain File/Edit/View/Image/Layers/Select/Window/Help, but all
Object-source file operations and Close tab moved to **File**. Window now holds
workspace/dock and document-navigation controls only. Every TabBar tab owns an
inline × (including nonactive tabs); the detached global + and × are gone.
File → New / Ctrl+N and the existing dirty-save/cancel close state machine are
unchanged. Because Godot 4.8-beta2's theme close button does not reliably fire
on forwarded synthetic viewport clicks, close-glyph hit-testing is also routed
through `_input`, before TabBar input processing, then marked handled. Godot's
`tab_close_pressed` signal remains connected for native/accessibility input.

A normal wheel increment/decrement on hovered **Brush px** changes the actual
SpinBox value (and therefore canvas brush width), clamped to 1–96. Shift+wheel,
horizontal wheel and the visible chevrons scroll the crowded tool-options strip;
`[` and `]` change Brush/Eraser px in steps of 1 when a text editor is not focused.
No document edit, transaction or revision is created by changing brush width.

The six existing provenance-unknown `addons/drawing/icons/{brush,eraser,select,
move,text,pan}.svg` graphics were replaced byte-for-byte by the **MIT-licensed
`addons/at-icons/control`** brush/eraser/selection_square/move/text/hand family.
The license is copied verbatim to `addons/drawing/icons/LICENSE.at-icons.txt`
and staged alongside the assets in standalone and third-party consumers.
Focus, pressed and disabled treatments remain Godot `Button` theme states,
with existing keyboard-focus and descriptive tooltips; no fabricated SVG origin
or external runtime addon dependency is introduced.

**Software-only evidence:** Godot `4.8.beta2.official.cafc17a19`, Linux X11,
Mesa llvmpipe (OpenGL compatibility), screenshot-native root windows
**800×600, 1280×760 and 1920×1080**, plus **150% and 200% content scaling**.
`drawing/tests/responsive_workspace_native.gd` exercises *29* checks including
optional **five framebuffer PNGs**, physical-window edge pixels, native wheel,
keyboard width, real nonactive-tab close/cancel/re-save, menu separation and
imported icon state; without screenshots it runs **24** checks. The previous
T-063 native compact regression continues to pass **75/75**, keyboard **8/8**.
`tests/test_t090_responsive_workspace.py` has seven fast contract tests,
including six byte-identical licensed assets and fail-closed native log parsing.
`tests/test_drawing_contract.py` now enforces license staging byte equality;
`tests/test_godot_ci_fail_late.py` permits **46** bounded steps. Fast CI runs the
Python contracts; `.github/workflows/godot-native-t090-workspace.yml` is
explicitly on-demand, imports assets first and records full logs/PNG screenshots.
Godot/Mesa shutdown RID/texture leaks are counted separately after a positive
native marker; they are not claimed fixed or silently removed.

**Unverified:** Native Windows and physical Linux GPU, varied monitor DPI,
keyboard layouts, real hardware input-to-photon timing, and owner visual UX
approval. The relevant owner findings **#03, #04, #06, #08 and #09 remain
PENDING** in the runbook, and T-056/T-059/T-065/T-083 `manual_review: true`
gates remain untouched. This ticket has no direct owner-review dependency.
