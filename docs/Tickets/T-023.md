# Bucket tool with clear fill boundaries

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 16.

## Acceptance
- Agree contiguous/tolerance/alpha behavior and which layer/content plane is filled, using familiar editor references.
- Selection masks bound the fill; empty/unbounded regions have a predictable, documented policy.
- Preview/error feedback, cancellation and undo do not leave partial mutations.
- Verify chunk borders, transparent pixels and save roundtrips; simplify the implementation through [[T-033]].

## Review candidate (2026-10-30) — awaiting acceptance of fill policy

Implemented the policy and preview implementation in [[BUCKET_WORKFLOW]]. The specific contiguous/global, premultiplied-alpha tolerance, replacement-vs-compositing and release-to-commit choices must be reviewed with the owner; **do not check off T-023 solely because the automated implementation passes**. Behavior is opt-in where possible: default is exact-match contiguous on the active raster layer, with 0% tolerance; terrain retains its existing exact-palette semantics. No native-save schema or existing paint content was modified.

- Raster: 4-connected contiguous or global among *stored* pixels of the active raster layer; normalized premultiplied RGBA seed tolerance 0–100%, alpha replacement, Shift temporarily inverses global mode, 262,144-pixel transaction limit.
- Terrain: contiguous exact palette on the layer's own square/hex content grid, max 8,192 cells; empty background requires a finite cell edit mask. No raster options are offered for terrain.
- Pointer press creates a **visible detached preview**; release commits one command, Escape/tool/layer change/outside-board/focus loss cancels without mutation. Error messages explain unbounded/no-op/locked/hidden and limit failures. Old direct `fill_at(point)` remains available for code callers.
- New tests: `tests/bucket_smoke.gd` **32/32**, including alpha, tolerance, global/signed chunk borders, finite masks, safety limits, raster and terrain previews, undo/redo and native roundtrip; `tests/bucket_visual.gd` **19/19**, including real framebuffer preview/cancel/release, Shift-global, no stale outside-board commit, visual color boundary and 800×600 layout. Both are CI-gated.
- All **36/36 applicable headless suites** and **20/20 native framebuffer suites** passed; Godot 4.8 beta2 import/parser, explicit typing, main-scene launch, non-threaded Web release export and **4/4** source/exported-pack save interoperability passed. Native checks were batched to avoid aggregate execution timeouts.
- Remote CI, browser runtime, external code review and owner's actual usability/policy acceptance have not been performed. The source-only simplification [[T-033]] remains separately scheduled.

## Stale-preview safety follow-up — 2026-11-01

The original 2026-10-30 implementation notes above are a historical review
snapshot: the palette-cell terrain authoring model has since been retired by
[[T-050]], and Bucket now targets raster pixels only at the presented D-level.
The current interaction/policy reference is [[BUCKET_WORKFLOW]].

- Guarded pending raster fills with the source board ID, floor ID, active
  layer ID, and content-addressed `AtlasRasterLayer.to_dict()` snapshot. A
  preview computed at pointer-down is discarded if the same layer has been
  edited, its metadata has changed, or navigation/active-target context has
  changed by release. It cannot replace newer bytes or add an undo entry.
- `tests/bucket_smoke.gd` now covers history-replaced images, in-place image
  mutation, active-target switches, floor switches with reused layer IDs,
  and preservation of unrelated-layer edits; `bucket_visual.gd` includes a
  true native press/release with an interleaved history command. Unchanged
  targets retain their ordinary release-to-commit/undo behavior.
- This is a defensive correctness improvement, **not** approval of the
  contiguous/global, tolerance, alpha replacement or release-to-commit UX
  decisions. T-023 stays open in [[Index]] pending explicit owner review.
