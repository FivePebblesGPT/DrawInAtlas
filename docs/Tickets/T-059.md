# Drawing feature inventory and familiar standalone UX

**Status: FEATURE INVENTORY APPROVED BY OWNER (2026-11-02); IMPLEMENTATION AND HANDS-ON UX VALIDATION PENDING.** Product inspiration: reduced-feature Paint.NET/PhotoCraft, not full parity. See **[[DRAWING_FEATURE_INVENTORY]]** for the **approved** Essential/Later/Skip scope, rationale, shortcuts, and acceptance flows. The inventory is a scope contract, **not evidence of implementation**.

## Plan
1. **COMPLETE:** Owner approved the documented **[[DRAWING_FEATURE_INVENTORY]]** matrix (Essential/Later/Skip) on 2026-11-02. Record any implementation-level undecided tool edge behaviors or shortcuts as bounded tasks, not as a reason to reopen inventory approval.
2. Cover common Drawing features independent of Atlas: snapping, generic layer groups, one-text-per-layer lifecycle, rasterization, selection, masks, image files, navigation, undo and open/save.
3. Prototype UX at small and large documents: thousands of text layers must remain navigable via grouping/virtualization, with selection state distinct from the map floor group.
4. Define usability acceptance flows in standalone Drawing, and Atlas integration flows for shared vs copied art, switching floor/detail, blank high-detail UI and global cross-map undo.
5. **NEXT:** Decompose the approved Essential baseline into bounded implementation tickets and defer Later items. The minimal T-053 vertical slice must not wait for full feature completeness.

## User-supplied UI proposal — 2026-11-01
The uploaded **[[DRAW_MODULE_UI_SPEC]]** is now part of the repository as a **proposed design**, not a finished or signed-off implementation. It specifies fixed menus and scrollable tool controls on the *same* top row with `BarDivider`, plus document tabs, compact left tool rail, right Colors/Layers/History dock, and cursor/dimensions/zoom status. Commands and keyboard shortcuts replace a redundant quick-access toolbar. [[T-063]] owns implementation/overflow/input acceptance in three phases; the complete tool feature list was **not yet available at the time of this UI proposal**; it is now recorded as a separate **approved feature inventory** in [[DRAWING_FEATURE_INVENTORY]]. The distinct workspace-layout UX spec remains proposed pending native validation.

## Round 7 — historical UX choices (before the 2026-11-02 inventory proposal)
- Object Editor runs as a **dedicated document tab** using Drawing (T-062). Asset Browser is a normal dock peer (T-065) with the same tabbing, resizing and visibility behavior as Colors/Layers/History.
- Show project-side `Objects/` files as browsable objects, including unreferenced saved variants, missing/`NULL` proxies and child references. Asset deletion choice is explicit: remove references, keep NULL placeholders or cancel.
- The user accepted blank high-level artwork with visible grid/navigation overlays; app-wide selection-history setting OFF by default; camera focus on undo without changing zoom; configurable entrance double click. These are not pending generic suggestions.
- At this round the Draw tool/feature list (effects/brush variants/import/export/etc.) was **not yet provided**. The subsequent **[[DRAWING_FEATURE_INVENTORY]]** now contains an explicit *proposal*; **[[DRAW_MODULE_UI_SPEC]]** remains a separate workspace design, not the feature inventory.
