# Drawing feature inventory and familiar standalone UX

**Status: PROPOSED FEATURE MATRIX RECORDED — AWAITING OWNER SCOPE/UX SIGN-OFF (2026-11-02).** Product inspiration: reduced-feature Paint.NET/PhotoCraft, not full parity. See **[[DRAWING_FEATURE_INVENTORY]]** for the candidate feature choices, rationale, shortcuts, and acceptance flows. The list is documented, **not yet approved or implemented**.

## Plan
1. Review the documented **[[DRAWING_FEATURE_INVENTORY]]** matrix (Essential/Later/Skip), settle disputed tool behavior, keyboard shortcuts and discoverability rules, then record explicit owner scope approval.
2. Cover common Drawing features independent of Atlas: snapping, generic layer groups, one-text-per-layer lifecycle, rasterization, selection, masks, image files, navigation, undo and open/save.
3. Prototype UX at small and large documents: thousands of text layers must remain navigable via grouping/virtualization, with selection state distinct from the map floor group.
4. Define usability acceptance flows in standalone Drawing, and Atlas integration flows for shared vs copied art, switching floor/detail, blank high-detail UI and global cross-map undo.
5. Open bounded implementation tickets once the owner agrees the feature matrix. The minimal T-053 vertical slice should not wait for full feature completeness.

## Acceptance
Owner approves a finite feature inventory and can perform representative pointer/keyboard workflows. No test-count-only UX signoff. A documented proposal alone does not satisfy this acceptance gate.

## Proposed comparison feature inventory — 2026-11-02
- **[[DRAWING_FEATURE_INVENTORY]]** records **99 recommended feature decisions** grouped into workspace/documents, painting, selection/transform, layers/text/object editing, effects/color and file interchange, with per-feature Paint.NET/PhotoCraft references and reasons to keep as Essential, defer as Later or Skip.
- The reference list is **comparative inspiration**, not a claim that identical features exist in both products. Existing approved Atlas contracts take precedence; proposals for advanced brushes, masks, effects and formats remain candidates until the owner approves them.
- It separates the **minimum T-053 witness** from the larger reduced-feature baseline, identifies shortcuts/discoverability principles and defines pointer/keyboard acceptance flows for text, thousands of layers, source Save/Save As, retained variants, sparse maps, global undo and portable recovery.
- **Next:** owner reviews scope and prioritization; open bounded implementation tickets only after accepted choices. Do not block T-053's minimal vertical slice on the entire inventory.

## User-supplied UI proposal — 2026-11-01
The uploaded **[[DRAW_MODULE_UI_SPEC]]** is now part of the repository as a **proposed design**, not a finished or signed-off implementation. It specifies fixed menus and scrollable tool controls on the *same* top row with `BarDivider`, plus document tabs, compact left tool rail, right Colors/Layers/History dock, and cursor/dimensions/zoom status. Commands and keyboard shortcuts replace a redundant quick-access toolbar. [[T-063]] owns implementation/overflow/input acceptance in three phases; the complete tool feature list was **not yet available at the time of this UI proposal**; it is now recorded as a separate *proposed* matrix in [[DRAWING_FEATURE_INVENTORY]].

## Round 7 — historical UX choices (before the 2026-11-02 inventory proposal)
- Object Editor runs as a **dedicated document tab** using Drawing (T-062). Asset Browser is a normal dock peer (T-065) with the same tabbing, resizing and visibility behavior as Colors/Layers/History.
- Show project-side `Objects/` files as browsable objects, including unreferenced saved variants, missing/`NULL` proxies and child references. Asset deletion choice is explicit: remove references, keep NULL placeholders or cancel.
- The user accepted blank high-level artwork with visible grid/navigation overlays; app-wide selection-history setting OFF by default; camera focus on undo without changing zoom; configurable entrance double click. These are not pending generic suggestions.
- At this round the Draw tool/feature list (effects/brush variants/import/export/etc.) was **not yet provided**. The subsequent **[[DRAWING_FEATURE_INVENTORY]]** now contains an explicit *proposal*; **[[DRAW_MODULE_UI_SPEC]]** remains a separate workspace design, not the feature inventory.
