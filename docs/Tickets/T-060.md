# Reusable Object Assets, live Atlas instances, Save and Save As

**Status: PLANNED.** Owner clarified 2026-11-01 that reuse is principally of authored objects, not entire live-linked map documents. See [[T-062]] for the Object Editor.

## Ownership and vocabulary
- **Object Asset:** reusable source authored with the Drawing engine. It may contain raster, semantic drawing and text layers, with an **asset-local coordinate system** and stable asset ID. Layer content is the source of truth. Exact supported content is T-051 design work.
- **Object Instance:** placement in an Atlas map's floor/detail context, with its **own instance ID**, source asset ID, world transform, selection/visibility and optional per-instance metadata. Moving/rotating an instance **never edits the source asset**.
- **Save source:** in the Object Editor, saving the source commits/persists asset content and updates linked instances' visible artwork.
- **Save As:** creates an independent new Object Asset with a new source ID. **If the Object Editor was entered through a specific Atlas instance, automatically rebind that originating instance to the new asset** (Variant B); other linked instances stay attached to the original. **If opened independently**, Save As only creates/switches to the copy, with no Atlas rebind.
- **Background world Drawing** is distinct from placed object instances. Do not infer user approval for linked whole-map canvases.

## Plan
1. Provide stable `ObjectAsset` handles and `ObjectInstance` references, asset-local transforms, one-source/many-instances resolution and read-only render queries.
2. Reuse Drawing's canonical document/layer/renderer infrastructure for object source authoring; do not implement a second painting engine or force Atlas-map types into Drawing.
3. Implement source Save, source edit invalidation, Save As deep-copy/new IDs and **context-sensitive Atlas instance rebinding**. When entered through an instance, perform source creation + captured instance rebind atomically under Atlas history, with expected-instance/source/revision validation and no partial commits. Independent Save As has no instance side effect. Define live preview versus Save visibility and registry/disk persistence boundaries.
4. Implement Atlas instance placement, select/hit-test, move/rotate/scale and source edit opening; instances are not rasterized into map background automatically. Source edits update all linked instances. Instance transforms do not.
5. Keep per-asset/instance revisions and transaction authority to reject stale or replaced same-ID instances; define broken links and deletion policy before acceptance.
6. Test: castle source -> place instances A/B in distinct maps -> edit source + Save -> both reflect edit; enter editor **through A** -> Save As Variant B -> **A automatically points to B, other placed instances still point to original**, original source unchanged; undo/redo restores A's asset link and selection/mode. Save As from an independently opened source produces Variant B but changes no Atlas instance; instance transform remains independent.

## Acceptance
Object asset vs instance boundaries are explicit in API and UI. Source Save updates all linked instances; **Save As from an instance automatically rebinds that instance only**, while Save As from standalone doesn't rebind. The new source has a distinct ID and cannot mutate the old source. Binding changes are atomic and undo/redo-capable with valid mode/selection restoration. No historical save migration required.

## Open design decisions
Object Editor location and mode, nested object assets, external file sync, live-update timing and per-instance overrides belong in T-051. **Save As instance rebinding is decided.** The owner-approved policy is **keep the independently saved Variant B in the asset library after undo**, even when unreferenced. Redo uses the same stable asset ID; deleting B is a separate explicit action. Detail of library/project dirty state still needs an implementation contract.

## Round 6 — non-destructive undo of Save As (approved 2026-11-02)
- The Save As operation commits one new independently saved Object Asset B and rebinds originating instance A to B. **Undo restores A→original**, but **does not delete B** from the asset library. B remains reopenable and reusable with no instance references.
- **Redo restores A→same B** (not a freshly generated asset). Repeated undo/redo must not create extra copies or change B's content/ID.
- The project/asset-library persistence system must record retained B faithfully. If B is project-owned, undo cannot falsely declare a clean pre-Save-As savepoint when new B remains. If B is saved in an independent library, differentiate the library's persistence from the Atlas project's binding savepoint.
- No zero-reference automatic deletion. Explicit user Delete is a separate undo/safety design; if B disappears before redo, fail or invalidate redo safely instead of re-creating it invisibly.
- Test A/B/source identity, asset library entry count, reload after undo, stable redo, and failure/atomicity of staged Save As with a stale instance.

## Round 7 — adjacent Objects folder and Save-only publication
- Object sources are **separate files in `Objects/` adjacent to the campaign file**, referenced via relative portable paths and stable asset IDs. This changes the historical single-file campaign promise; copying the project requires its Objects folder. Reject escaping traversal and ambiguous same-name replacements; safe broken-reference behavior is required.
- **Staging:** Object Editor edits stay in a private working document until the user presses Save. All linked Atlas instances show the last committed source. Save atomically publishes the new version and invalidates all dependent instance previews. Cancel never modifies the published source. Save As through an instance still creates B and rebinds that instance only; undo retains B in `Objects/`.
- **Delete source prompt:** Delete and remove dependent instance placements, Delete and retain `NULL` placeholders, or Cancel. A `NULL` instance preserves original asset key/path and instance transform/identity, paints an explicit missing-object witness and must not call renderer on a nonexistent asset. Do not silently relink to a different asset with the same filename. Nested dependents need the same policy (T-064).
- **Overrides:** placed instances only override transform/visibility initially. No per-instance raster paint overrides.
- **Nested child assets:** intended as a feature; canonical Asset IDs + dependency graph, guard self/indirect cycles, bounded render traversal, missing-child placeholders and transitive cache invalidation. Implement via T-064; do not block ordinary flat Object instances on advanced recursion.
- **Portable project tests:** rename/move enclosing directory with `Campaign file + Objects/`; load all links and NULL placeholders, run Save As/undo/redo, detect missing files without data loss; reject malicious or external relative escapes. Ensure Save failure does not publish half-written content or half-rebind a map instance.
