# Shared linked versus independently copied Drawing assets

**Status: PLANNED. Owner approved **both** reuse modes.** Exact external-file semantics still need T-051 approval.

## Distinction
- **Link:** new Atlas binding references the same stable source Drawing asset ID. Editing through any map updates the asset and all other bindings, without duplicating canonical pixels.
- **Copy:** create a new source Drawing asset ID with independent pixel/object/layer data at copy time. Later source edits do not update it, and editing the copy never mutates the original.
- **Placement:** every map binding has its own Atlas-world transform, layer-group association, visibility/edit rules and possibly detail association. A linked asset's local coordinates are not assumed identical to the location of each world-map instance.

## Plan
1. Define `DrawingAsset` identity and Atlas `AssetBinding`/instance ID separately; specify ownership, references, save location and reference counts/deletion behavior. Drawing remains ignorant of Atlas map IDs.
2. Expose generic Drawing `duplicate_document_or_layer` (deep copy, new IDs) and handle-based editing, not a link-specific Drawing class.
3. Add Atlas UI affordances labeled clearly `Link artwork` versus `Duplicate artwork`, with the user's intended post-action editable target explicit.
4. Test live link in two maps with different transforms: edit via map A; B updates; global undo recorded on A updates both and navigates to A. Duplicate it; edit copy; source unchanged.
5. Test identity preservation on save/open, rename/move, source deletion, broken references, asset replaced with same ID, cycles (if references can be nested), clipboard import and undo/redo. For external live files, define refresh/conflict policy **before** implementation.
6. Scope initial linked assets to the approved registry/file ownership model; do not silently introduce filesystem watchers/network sync.

## Acceptance
No accidental copy on link, no accidental shared mutation on copy, no duplicate canonical layer storage for links; placements can vary independently; undo works with multiple bindings; dangling references are safe and visible.
