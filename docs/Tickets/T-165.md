# Fail closed on divergent attached-native direct raster publication

**Split from T-148.** T-162 made current Rust stores authoritative for
ordinary recorded/unrecorded `_publish_edit` and `_publish_tile_edit`. But
`_install_prepared_edit` still used `native_store != null && native_revision ==
expected` to *choose* adoption. When a previously attached store was behind or
ahead, it silently fell through to the historical Godot-only publisher,
advancing document pixels/history without touching Rust. The next native
stroke could rebase and discard unrelated canonical sources/tokens.

## Acceptance

- [x] Once Rust is attached, a direct pixel or tile-local publication must
  reject if native and Godot base revisions differ, for both recorded and
  non-historical mutations. Rejection precedes lazy source resolution, does
  not mutate dirty tiles, history, pixels, native source, or either revision.
- [x] Recheck the same native revision **after all potentially reentrant lazy
  callbacks**, immediately before adoption. A loader advancing Rust's
  revision cannot turn a prepared external edit into a Godot-only commit.
- [x] Preserve the existing `adopt_external_edit` and `adopt_untracked_edit`
  behavior when revisions match; retain explicit checked rebase/retry for
  a behind store, and preserve genuinely native-absent historical publishing
  pending T-150. An attached native-ahead store must not be replaced.
- [x] Prove the old fail-open behavior with an identical negative-control
  fixture. Run real Hokusai/native, Rust offline unit/strict Clippy/build,
  Drawing/Atlas/Object and graphical 96px regression witnesses.
- [x] Update the required-native CI test loop, ABI, parent T-148 and Kanban
  Index. Keep T-095's physical-device/manual gate and T-149 block intact.

## Evidence and disposition

The [T-165 execution evidence](../evidence/T-165-2026-11-16-attached-revision-fence.md)
records the fail-first and positive fixture, raw process logs and checksums.
This closes only the attached *direct publisher* revision fence; T-148 still
requires universal Rust-owned raster producers/host history. It does not
unblock T-149 or assert T-095 hardware acceptance.
