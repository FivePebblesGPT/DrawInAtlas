# Optimize the highest measured native Brush bottleneck

**Goal:** Optimize the single largest **measured** post-consolidation CPU/critical-path bottleneck from T-151, not the already-retired Legacy pixel loops or a speculative new rasterizer.

**2026-11-17 current-sprint work:** [T-185](T-185.md) re-profiles the app as it
stands; [T-186](T-186.md) then targets a declared comparable 250ms benchmark
milestone, with 200ms preferred. This is distinct from this ticket's later
post-consolidation checkpoint and does not constitute physical owner approval.

## Deliverable

- Use T-151's ranked native-vs-FFI-vs-document-vs-display attribution to select one bounded architectural improvement. Candidate examples **only if evidence supports them**: batch or retained tile-buffer handoff, native tile copy-on-write/publish/undo, mask/blend SIMD, avoiding duplicate RGBA conversions, tile display invalidation or texture upload pacing.
- Before implementation, reproduce the hotspot with the exact accepted native stroke workload and capture a negative control. Preserve each brush mode's own semantics and output, coherent preview/commit/save/Undo, deterministic transaction cancellation, image-frame/selection authority and source ownership.
- Measure before/after cold/warm 96px complete gesture, first preview, release→commit, worst/p95 frame CPU, native/FFI transfer bytes, per-stage CPU, settled display, RSS/texture counts; test dense and sparse input cases to detect regressions. Keep experiments only if the chosen target improves under matched conditions without hiding new stalls.

## Acceptance

- [ ] Demonstrate a meaningful, repeatable improvement of T-151's measured dominant stage, supported by baseline/candidate source hashes, raw logs and independent correctness/negative controls.
- [ ] Run native Godot framebuffer, history/persistence, mask/eraser, queued-input and standalone regressions; no cross-backend pixel matching is required, but changed output must meet each mode's own verified behavior.
- [ ] Report total gesture/first-visible and per-frame p50/p95 against the initial Hokusai baseline and 100ms reference-hardware objective. If no acceptable optimization survives testing, document rejection evidence and keep T-095 open rather than claiming success.

## Boundaries

One measured bottleneck per implementation ticket; if several independent bottlenecks remain, split them into new consecutively numbered tickets. Actual physical-device owner approval remains governed by T-095, not this engineering slice.
