# Organize authored detail and editable objects in a compact layer hierarchy

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 15.

## Work
Replace the confusing separate “Linked maps…” experience and duplicated grid-like options with a compact layer/detail/object hierarchy, considering the requested cascade/dropdown presentation. The battlemat-container proposal is superseded by [[T-012]].

## Acceptance
- Agree what relationships still need links in the revised model; hex detail must not imply a document per hex.
- Clearly expose the explicit editing target, separately authored detail groups and editable path/text objects.
- Distinguish layer/detail settings, grid settings and any genuine navigation relationships; do not retain a battlemat entry type.
- Show the necessary actions alongside compact layer/object entries without recreating the oversized form elsewhere.
- Demonstrate discoverability and space usage with the user before treating the UI as accepted.

See [[LAYER_HIERARCHY]] for proposed relationship semantics and explicit unresolved product acceptance. Existing linked-map metadata and legacy placement editing remain accessible from the inline Edit action. The inspector's duplicate Linked maps button is hidden. ## Large Objects-layer hierarchy follow-up — 2026-11-01 (acceptance pending)

The previous hierarchy listed only the **oldest 80** Objects-layer strokes.
This meant newly authored text/paths beyond that count were absent from the
sidebar, and selecting an omitted object on the canvas left no corresponding
highlighted row. This was an implementation usability gap, not a decision to
increase the stored object limit.

- The Tree now keeps a bounded **oldest 40 / newest 40** window with a clearly
  labeled nonselectable gap for the omitted middle. Newly authored objects are
  therefore represented without rendering every object in a large layer.
- When the canvas selects one valid omitted object, the hierarchy pins exactly
  one additional row in canonical stroke-index order, expands its layer and
  scrolls it into view. Deselection or a stale selection snapshot removes the
  pin and returns the highlight to the explicit editing layer; no history,
  map navigation, or save format is changed.
- The headless hierarchy witness now checks large-layer bounds, both ends of
  the list, omitted-row disclosure, canonical-index selection, refresh,
  deselection and stale snapshot behavior. The native framebuffer witness
  checks the compact 800×600 viewport and records
  `layer-hierarchy-overflow-800.png` with the temporary row visible.

**Owner review still needed:** accept/reject the 40/40 window and the temporary
selection row, plus the original category, link and compact-space choices.
The T-018 checkbox stays **unchecked** until this review is given.

## Inline map-link action-safety follow-up — 2026-11-01 (acceptance pending)

A link-row button previously dispatched its stored ID directly. If a marker,
legacy footprint, arrival camera, destination label/floor or map was changed
while the sidebar remained visible, a click on the old row could focus, open
Edit, or enter the *new* destination without the user having reviewed it.

- Each row now stores an immutable snapshot of the current link/footprint and
  the resource identities of its source document, source floor and destination.
  Focus, Edit and Enter reject a stale or removed link, replacement with a
  reused ID, changed placement, or changed destination before emitting any
  navigation event.
- A rejected click leaves the current camera/document untouched, shows a
  short message and schedules a safe hierarchy redraw. The user must select
  the refreshed row for a subsequent valid action. The new guard does not
  change native saves, navigation semantics, or the map-link schema.
- `tests/layer_hierarchy_smoke.gd` now checks **44 assertions** including
  stale Focus/Edit/Enter, revised labels, footprints, arrival positions,
  deleted/replaced links, and successful explicit retry. The native witness
  checks **17 assertions**, including unchanged camera and refreshed tooltip.
- Full local regression: **58/58 headless** suites and **34/34 native** suites
  passed in batches. Godot import/launch, Web release export, all **4/4**
  source/export-pack save-portability checks, explicit typing, and
  `git diff --check` passed. Archive restoration is checked at packaging.

**Owner acceptance is still required** for the broader hierarchy labels,
category/link semantics, the 40/40 object list and compact-space usability.
Keep T-018 unchecked in `docs/Index.md` until that acceptance is given.

## New architecture consequence — 2026-11-01
The target layer sidebar must handle **one layer group per Atlas floor**, a distinct authored-detail selector, shared versus copied artwork bindings, and **one editable text object per layer**. This can create many layers; measure virtualization/selection performance instead of assuming the old 40/40 Objects-stroke window solves the new layer tree. See [[E-009]], [[T-058]], [[T-060]], [[T-061]]. The historical T-018 UI remains an unaccepted candidate, not confirmation of this new behavior.
