# Organize authored detail and editable objects in a compact layer hierarchy

## Source
[[ManualReview_2026-10-30#Usability testing|Usability testing]], item 15.

## Work
Replace the confusing separate “Linked maps…” experience and duplicated grid-like options with a compact layer/detail/object hierarchy, considering the requested cascade/dropdown presentation. The battlemat-container proposal is superseded by [[T-012]].

## Acceptance
- Agree what relationships still need links in the revised model; hex detail must not imply a document per hex.
- Clearly expose the explicit editing target, separately authored detail groups and editable path/text objects.
- Distinguish layer/detail settings, grid settings and any genuine navigation relationships; do not retain a battlemat entry type.
- Show the necessary actions alongside compact layer/object entries without recreating the oversized form elsewhere.
- Demonstrate discoverability and space usage with the user before treating the UI as accepted.

## Implementation candidate — 2026-10-30

Implemented a compact interactive hierarchy candidate in the Layers sidebar without altering map, layer, stroke, link or save schemas. See [[LAYER_HIERARCHY]] for proposed relationship semantics and explicit unresolved product acceptance. Inline object selection and separate independent-map link actions are covered by new headless/native regression suites wired to CI. Existing linked-map metadata and legacy placement editing remain accessible from the inline Edit action. The inspector's duplicate Linked maps button is hidden. Grid settings remain in the toolbar popup.

**Do not close this ticket until the owner has reviewed the screenshots and approved the hierarchy, labels, link relationships, actions, and space usage.** This work also does not pre-accept future path/text UI from T-026/T-027.

## Large Objects-layer hierarchy follow-up — 2026-11-01 (acceptance pending)

The previous hierarchy listed only the **oldest 80** Objects-layer strokes.
This meant newly authored text/paths beyond that count were absent from the
sidebar, and selecting an omitted object on the canvas left no corresponding
highlighted row. This was an implementation usability gap, not a decision to
increase the stored object limit.

- The Tree now keeps a bounded **oldest 40 / newest 40** window with a clearly
  labeled nonselectable gap for the omitted middle. Newly authored objects are
  therefore represented without rendering every object in a large layer.
- When the canvas selects one valid omitted object, the hierarchy pins exactly
  one additional row in canonical stroke-index order, expands its layer and
  scrolls it into view. Deselection or a stale selection snapshot removes the
  pin and returns the highlight to the explicit editing layer; no history,
  map navigation, or save format is changed.
- The headless hierarchy witness now checks large-layer bounds, both ends of
  the list, omitted-row disclosure, canonical-index selection, refresh,
  deselection and stale snapshot behavior. The native framebuffer witness
  checks the compact 800×600 viewport and records
  `layer-hierarchy-overflow-800.png` with the temporary row visible.

**Owner review still needed:** accept/reject the 40/40 window and the temporary
selection row, plus the original category, link and compact-space choices.
The T-018 checkbox stays **unchecked** until this review is given.
