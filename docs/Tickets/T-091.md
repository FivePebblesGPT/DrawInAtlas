# One-group floating dock UX, edge resize and persistent width

**Status: In Progress (2026-11-06).** Newly scoped corrective work from the owner's first hands-on standalone Drawing review. Source observations are in [the owner review](../DRAWING_USABILITY_REVIEW_2026-11-05.md). Existing earlier "Done" tickets retain their original, narrower acceptance; this ticket does **not** inherit their UX approval.

## Problem / scope
Owner screenshot rejects nested multi-group floating hosts, redundant 'Floating panels (1 groups)' and 'Split 2' title rows, oversized chrome and inert-seeming corner-only resizing. The owner expects **one tabbed group per floating host**, with grip, close and tabs on a single compact header. Dock width is not reliably restored in the observed build despite T-083 persistence metadata.

## Engineering tasks
1. Revise `DrawingDockLayout` / `DrawingFloatingHost` so each floating container hosts exactly one group; when detaching/merging groups choose explicit host behavior without creating nested group headings.
2. Header contains move handle, tabs and close only; minimize decorative labels and redundant resize bar. Retain subtle textarea-like corner indicator, but support intuitive mouse resizing from all sides/corners.
3. Preserve panel IDs, order, visibility, cancel/rollback, keyboard focus, cross-container drag and redock; adapt T-078–083 model tests to new owner-corrected UX.
4. Persist splitter width on **actual drag changes** as well as shutdown and restore after layout is valid; handle different resolution/DPI, minimize/expand and recovery of old multi-group settings.
5. Coordinate with T-083's still-unapproved owner gate rather than declaring that earlier engineering evidence signed off the new design.

## Acceptance / verification
- [x] Floating group shows exactly one compact header/one tab strip/one active panel; multi-group floating host is impossible.
- [x] Resize works from all four edges and corners; closing/hiding/redocking cannot strand or duplicate panels (native software pointer and model witnesses).
- [x] Set dock width → restart → recover exact usable width; clamp/migrate safely on new resolution and corrupted settings.
- [ ] Native screenshot **and physical Windows/Linux pointer/focus** validation at normal/narrow/HiDPI; software-only native screenshot complete, physical hardware and T-083 owner acceptance outstanding.

## Boundaries
- Preserve the one canonical Drawing package shared with Atlas, byte-exact saved RGBA8, source identity, one undoable content transaction per gesture and signed sparse coordinates.
- Add headless model tests and **actual native pointer/framebuffer tests** where interaction or visible pixels are involved; source/README checks alone are insufficient.
- Do not mark complete merely because earlier T-053/T-063/Docking smoke tests pass. Report hardware, Godot version, viewport, zoom, timing and limitations for applicable evidence.

## T-091 engineering checkpoint — 2026-11-06

**Implemented locally, physical-hardware acceptance outstanding; no owner approval.**
`DrawingDockLayout._valid()` now rejects more than one group in any floating
container, including restore and drag preview/commit. An occupied host accepts
single tabs or a **deliberate whole-group merge into its one tab strip**; a
second independent floating group must use a **separate in-app host**. A
floating tab split (Arrange/`Ctrl+Alt+S`) creates a new host and never a
second nested local group. Source panel IDs remain unique and history/document
bytes are untouched. Keyboard tab order and whole-group redock are retained;
**Shift+drag the grip** to redock a whole floating group, or drag the grip
normally to move its host.

`DrawingFloatingHost` now displays one 34px-height grip–scrollable tabs–×
header and an active panel body. Removed the stacked `Floating panels (...)`,
`Split ...`, collapse and redundant bottom resize bar. An unobtrusive painted
lower-right diagonal cue remains; pointer resize hit zones cover **all four
edges and all four corners**, with correct opposite-edge anchoring, minimum
size, offscreen clamping, Esc/cancel behavior and in-app focus/z-order.
Hit-testing the actual tab rectangles at the viewport input stage avoids a
Godot 4.8 beta synthetic scrolled-tab dispatch mismatch; keyboard `Button`
activation is still supported. Floating collapse metadata is preserved for
redock but the floating host itself always displays its active panel.

`DrawingDockPersistence.recover()` migrates old multi-group floating
containers to uniquely named, staggered sibling hosts while preserving group
IDs, member and active-tab order, visibility and the original frame scale;
malformed/doubly owned snapshots still fail closed. The preferred expanded
splitter width is captured **on actual SplitContainer drag**, saved before
shutdown, and re-applied after valid layout. Narrow window clamps and
unrelated saves never overwrite that preference; it is restored on an expanded
viewport, while min/max controls and corrupt width values are normalized.

## 2026-11-07 corrective checkpoint — repeated tabs and tall-host redocking

**State: In Progress; no owner/physical approval.** This checkpoint follows the
PhotoCraft/PR #13 owner handoff and addresses the reported duplicate floating
chrome after adding a second tab and inaccessible redocking when the floating
host is much taller than the dock target. It builds on remote PR head
`116afa125cdc068517f87d4d15ef34425a3a69e9` plus the prior local T-085
commit, without merging PR #13 or changing the canonical model/persistence
schema.

**Cause and fix:** `DrawingFloatingHost.render()` previously called
`queue_free()` on old `FloatingGroups` frames and header `TabStripScroll_*`
controls but left them *attached* until the next frame. A second synchronous
layout refresh could therefore display multiple strips and compete for panel
space. It now reparents any remaining active real view to the workspace stash,
**detaches** both obsolete chrome subtrees before queuing deletion, and builds
one frame/strip from the current single-group model. Views are never copied or
freed; repeated render calls within one frame keep exactly one visible active
panel. Necessary active-panel vertical scrolling is still supported rather
than hidden by force.

A normal floating grip drag still moves the host over the canvas, but hovering
the right dock now **previews a whole-group insertion/merge** and mouse-up on a
valid target commits the existing `DrawingDockDrag` transaction. The dock is
hit-tested directly even when the oversized source host overlaps it (no
fictitious height-match requirement). Crucially the group drag is begun
**before** the dock target kind is calculated, since tab vs group inference
depends on `source_kind()`. Leaving the target, Escape, and invalid release
cancel without mutating the layout; Shift+grip and keyboard redock continue
to work. The move gesture no longer needs to guess whether an overlapping
host covers the destination.

**Regression and verification, Linux Debian 13 software X11:** Godot
`4.8.beta2.official.cafc17a19`, Mesa 25.0.7 llvmpipe, 1280×800 Xvfb,
normal content scale. New `dock_grip_redock_native.gd` passes **53/53**
viewport pointer, model-snapshot, panel-identity, stable one-strip chrome,
Escape and framebuffer-readback checks; optional two PNG captures pass
**55/55**. It covers two synchronous workspace renders plus a direct host
render before a display frame, native tab switching, normal grip movement,
a **720px-high host** redocked onto a much shorter right-side dock target,
and canceled hover. The original T-091 native suite passes **36/36**; T-081
floating native **54/54**, T-082 cross-dock native **57/57**, and T-083
persistence native **63/63**. T-091/T-081/T-082 headless models pass
**42/42**, **64/64** and **66/66**. The on-demand T-091 native workflow now
runs both screenshot-capable native witnesses, validates each log independently

## 2026-11-07 viewport-edge resize anchoring checkpoint

**Engineering fix, not physical owner acceptance; status remains In Progress.**
On a floating host resized from its left/top edge beyond the client margin,
`_resize_from_pointer()` previously expanded the requested rectangle and passed
it to `set_host_rect()`. That method correctly clamps *whole host* positions for
restore/move, but on a resize it translated the opposite, ungrabbed edge.
Right/bottom overdrags could also push the original left/top anchor to make
room for an oversized frame. The visible panel therefore shifted while the
user was dragging only one edge.

The floating-host resize path now clamps each **moving edge** to the client
margin and per-axis minimum before computing dimensions from the fixed opposite
anchor. Ordinary host restoration/movement still uses `set_host_rect()`;
resizing preserves the previous finite/minimum-size and small-client safeguards.
The algorithm handles all edges and corners independently, and does not alter
layout group ownership, dock state persistence or document content.

**Pinned local evidence:** Godot `4.8.beta2.official.cafc17a19`, Linux
Xvfb/Mesa software renderer at 1280×800 app content area. Six new headless
left/right/top/bottom/corner boundary cases raise the T-091 model to
**54/54**, including exact fixed-edge and client-margin assertions. Four
real viewport-dispatched pointer overdrags raise the native witness to
**44/44**; the fail-closed native log checker now requires all 44 assertions.
Negative controls with the pre-fix floating-host source fail **6 model** and
**4 native** anchor assertions; the production fix passes. Existing eight
normal edge/corner pointer tests and neighboring dock/drag/persistence tests
remain required; any test failures are reported separately. The on-demand
T-091 native workflow uses the expanded witness, not an invented physical
owner run. Neighboring T-081/T-082/T-083 model/native and T-091 grip-redock
suites also passed. The required T-091 fast-CI step passed in a selected
