# Movable, resizable in-app floating tabbed panel containers

**Status:** Done (engineering; 2026-11-03). See [PhotoCraft-style docking scope](../DRAWING_DOCKING_SPEC.md).

## Scope

- Introduce a **Godot Control-based**, in-app floating container; **not** a native OS window, popup requiring desktop window management, or a second copy of a panel.
- Floating containers share the T-078 group model and T-080 tab behavior. They can host multiple ordered tabs/panels (and, when supported by the group model, multiple groups), with active tab, independent collapse state, title/close affordances, drag handle, focus/z-order, and resizable frame.
- Support moving/resizing and reordering/grouping tabs **inside** a floating host. Provide a programmatic/command-based way to instantiate a floating host for tests; full mouse drag from/to a dock remains the next ticket (T-082).
- An attached panel's dock icon must be absent **only while ownership is transferred**; a group transferred to a floating host removes all its member icons from the originating dock. Closing/hiding a floating host must not silently reattach its members or destroy edit state; Window/panel-list recovery remains available.
- Clamp floating hosts to the application client area, maintain usable minimum sizes, avoid the canvas swallowing drag/focus input and respect independent Drawing/Atlas module embedding.

## Acceptance

1. Native tests create a floating container containing two different tabs, switch and reorder them, resize and move it, and demonstrate independent focus/z-order (including overlapping canvas).
2. Check the dock no longer shows icons for floated panels; other group icons remain. Reopening a hidden host returns the same tabs in the same order without copies or OS-native windows.
3. Input/focus/hit targets remain usable at small resolution and HiDPI; invalid geometry and repeated hide/show are safe.
4. T-078 invariants and T-080 regression tests pass. Explicitly defer drag from dock and redock alignment hints to [T-082](T-082.md).

No separate manual gate until final T-083 review.

## Implementation and verification — 2026-11-03

- `addons/drawing/floating_host.gd` implements `DrawingFloatingHost : PanelContainer`, **within the same Godot application**. A title bar with a focusable move grip, hide button and scrollable group/tab body, plus a focusable resize grip, provides pointer control. Raising a clicked exposed host respects z-order when another host overlaps. Geometry is clamped to the current Drawing `Control` viewport, including invalid/nonfinite/offscreen dimensions; application resizing reclamps existing hosts. The floating frame is transient until T-083.
- `addons/drawing/workspace.gd` exposes `float_group(group_id)`, `move_group_to_floating(group_id, host_id)`, `hide_floating_host()`, `show_floating_host()` and Window-menu commands **Float selected dock group** / **Show hidden floating panels**. `DrawingDockLayout` stays the sole panel/group/container registry. Transfers run through the existing `DrawingDockDrag` validation and commit; the panel's **original `Control` instance** is reparented, not duplicated. Hidden hosts retain their ownership and tab state; Window recovery never implicitly re-docks. A failed float can remove its empty container without affecting a populated one.
- Floating groups preserve ordered tabs and each group's collapse/active selection; floating tabs drag to local insertion hints and support Esc/invalid-target cancellation. Each group offers Arrange actions for tab left/right, splitting, whole-group move and merge; focused floating tabs also support `Ctrl+Alt+Left/Right/S`, and focused group handles support `Ctrl+Alt+Shift+Up/Down`. Multiple ordered groups can coexist in one floating host. The model's source/destination validation also supports **command-driven** insertion of whole groups into an existing host. Full pointer transfer **between** dock and floating hosts, redock hints and cross-host drops belong to T-082.
- `drawing/tests/dock_float_smoke.gd` passed **64/64** headless ownership/transaction checks, including source/destination icons, group order, active/collapsed state, model snapshot round trip, unique ownership, stale and invalid transfer rollback, and empty-host cleanup. It is added to fast push CI.
- `drawing/tests/dock_float_native.gd` passed **55/55** X11/Mesa Godot **4.8 beta 2** native checks: two/three tabs, exact pointer reorder and Esc rollback with visible hints, real move and resize gestures, overlapping hosts' independent focus/z-order, hiding/recovery, multiple groups, split/merge, keyboard reorder, narrow viewport, 1.5× content scale, nonfinite geometry, and unchanged Drawing revision/dirty state. An actual native insertion screenshot was inspected; it does **not** imply owner approval. All hosts remain in the application Control tree, not native OS windows.
- Regression evidence on the same staged source: T-078 **82/82**, T-080 headless **60/60**, T-079 native **40/40**, T-080 native **68/68**, T-063 native **75/75**, native keyboard **8/8**, standalone Drawing and Object Editor smoke tests passed. Other expensive legacy/native/Web suites remain deferred per `docs/CI_TESTING.md`; they are not claimed passed. Owner manual gates T-056/T-059/T-083 remain open.
