# Make raster Open validate and decode one bounded byte snapshot

**Status: Done — 2026-11-14, bounded engineering hardening only.** This is a narrow follow-up to [T-120](T-120.md), whose unified Open read the file's size and 16-byte header using one file handle, closed it, then invoked `Image.load_from_file(path)` on a **second read**. The path could name different content when the decoder ran, defeating the connection between the inspected bytes and the imported bytes. It also performed redundant I/O. This ticket does not change the menu, raster representation, supported types or owner review gates.

## Acceptance and implementation

- [x] Read a source file **once** into a snapshot, checking the 64-MiB encoded cap before allocating the buffer and requiring exact read length. No second path-based decoder call; no streamed partial tab or Object publication on error.
- [x] Check format-specific PNG/WebP/JPEG magic bytes and decode from **that same snapshot** using Godot's corresponding buffer loaders. Reject obviously too-short PNG input without calling its noisy decoder; preserve errors for unsupported/corrupt/oversized inputs.
- [x] Preserve existing 4096px-per-side/16,777,216-pixel decoded geometry limits, canonical straight RGBA8 `DrawingRasterImport.import_image`, empty-frame behavior, `.drawing` save identity and source-file immutability.
- [x] Add a deterministic byte-snapshot replacement-file witness plus end-to-end workspace opening and failure rollback. Run existing T-120/T-093/T-090 headless and T-120 native-X11 regression tests, strict logs, typing and independent package-consumer tests.
- [x] Attach to the existing T-093 fast-desktop CI step without increasing the **46 required-check IDs**, retaining the fail-late strict log checker. Do not self-approve physical-device or hosted-CI acceptance.

## Verification and review boundary

[Local execution and negative-control evidence](../evidence/T-121-2026-11-14-raster-snapshot.md). The new Python source/CI contract initially failed **three** cases against pre-change code. The candidate passes `t121_raster_snapshot_smoke.gd` **24/24** with a strict post-success leak-aware log check, plus T-120 **34/34** model and **24/24** real Xvfb interaction, T-093 **56/56**, T-090 **32/32**, eight source/CI Python contracts, strict explicit typing and three independent consumer checks. No hardware interleaving or double-open race was artificially claimed reproducible: the deterministic test holds the original captured buffer, replaces the underlying pathname and verifies the buffer decodes its original bytes while a new request decodes the current file. This directly checks snapshot semantics, while the one-path-read guarantee is verified by the source contract.

Source byte acquisition remains subject to ordinary OS read semantics if another process rewrites the **same underlying file during the single read**; this ticket does not claim a POSIX/Windows atomic filesystem snapshot. Native rendering is software Xvfb/Mesa, not owner physical UX, Windows/macOS or input-to-photon evidence. T-056/T-059 and unrelated performance/native-backend gates remain unchanged.
