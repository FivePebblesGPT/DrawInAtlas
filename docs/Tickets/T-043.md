# Verify privacy-filtered player output and previews

## Source
[[E-007]]; archived acceptance requires secrets to be absent from projected output, not merely hidden in GM controls.

## Acceptance
- Exercise secret layers/rooms, private tokens/labels, fog and cached previews across view/detail changes.
- Assert that forbidden content/data never reaches player-facing render/export/capture inputs.
- Include cache invalidation, audience changes and frozen imagery in the acceptance matrix.
- Demonstrate a native GM/player session with clear evidence and recorded remaining platform limits.

## Engineering acceptance matrix — 2026-11-01 (independent acceptance pending)

`tests/player_privacy_acceptance_smoke.gd` and
`tests/player_privacy_acceptance_visual.gd` exercise the *isolated* T-039/T-040
player-rendering proof with authored D0 and D1 artwork. They are CI-gated,
including a native second-OS-window framebuffer check on X11/Mesa. The main
editor still does **not** publish automatically. See
[[PLAYER_OUTPUT_WORKFLOW]] and [[PLAYER_PROJECTION_CONTRACT]] for the
unapproved publication-policy decisions.

| Case | Boundary being asserted | Evidence |
| --- | --- | --- |
| Private raster and secret floor | Only explicitly granted, correct-floor layers reach a detached campaign; no source map identity, private graph or grid metadata | Headless sanitized campaign/dictionary and native renderer-input checks |
| Fog across D0 and D1 | Revealed cells retain pixels; re-hidden/never-revealed cells are transparent **before** native capture | Headless decoded chunk checks; native player texture + OS framebuffer pixels |
| Labels and private tokens | GM token grants always reject; fogged Objects/text grants reject the **entire** publication | Headless and native deny tests; sanitized input text checks |
| Previews and audiences | `AtlasPreviewCache` audience labels are explicitly not authorization; poisoned `player` cache entries do not flow into the sanitized projection | Headless cache/projection isolation checks |
| Freeze and revocation | Camera freeze may keep the last authorized image, but explicit policy invalidation clears both texture and OS framebuffer | Native two-window tests |
| In-flight edits | Source pixels, visible-layer permissions, LOD, fog and replaced floors invalidate pending GPU readback | Native deferred-mutation tests and existing T-042 fog tests |
| Source immutability | Projection does not rewrite GM resources; detached decoded pixels do not alias GM images | Headless document/pixel assertions |
